### 第一版做什么、不做什么

**做**：

- 核心：内核、协议、存储、上下文投影、压缩、权限与三个平台的沙盒
- 头：终端界面、网页、命令行（`miyu ask`、`miyu stdio`）、终端无缝集成（fish 完整；bash 和 zsh 只做 command not found）
- 软件：基础系统 13 件，可选软件包（联网、记忆、知识库、产物、长期目标、定时、语音、生图、通讯平台桥）
- 多用户：账号、组、属主权限、管理能力、分享
- 模型：供应商、池、挡位，借用 agent CLI 的订阅
- 人格与预设：出厂 Miyu、软件工程师；功能全开、开发
- 通讯平台：只接 QQ（OneBot v11）
- 知识库：Markdown、纯文本、PDF、网页 HTML
- 语音：桌面助手、听写、QQ 语音；合成用 MiMo、MiniMax、macOS 的 `say`
- 平台：Linux x86_64 与 arm64、macOS arm64、Windows x64；安装脚本加 GitHub Releases、AUR、Homebrew、deb、rpm

### 约定

- 每份文档末尾的“决定”一节，记录已定项、未选项和重开条件。没有满足重开条件，就不推翻已定项。
- 重开条件写「无」，意思是不因为方便而重开，不是不因为事实而重开。原型的实测推翻了哪一条，就照实改，记下测到的数字（2026-09-25 补）。
- 技术选型按推荐直接定，并在“决定”里留痕；产品与体验上的取舍，由项目主人拍板。
- 先后（2026-09-26 项目主人）：核心先做好；头随时能换，简陋能用就行。头的样子定到「差不多是这个感觉」为止，细节以后打磨。
- 叫法（2026-09-25 项目主人定）：权限叫「权限级别」，模型叫「挡位」；进程外的第三方软件叫「扩展」；「能力」分两种，给人的叫「管理能力」，给扩展的叫「扩展能力」；抓网页、搜索的软件包叫「联网」；好感度不做。资源的所有者叫「属主」，「主人」只指绑定了平台账号的机器主人。
- 旧版 Miyu 只是参考：它的实测数据可以当证据；它的做法、参数和产品口径不照搬，要么从原则重新推出，要么重新请项目主人确认。
- 图用 mermaid。
- 每一个设计都有图纸（2026-09-26 项目主人定，`00-设计理念.md` 第四节「设计有图纸」）。图纸按设计的种类有几种样子：
  - 机制和架构：设计文档的正文、表格和 mermaid 图。
  - 数据格式（事件、协议、配置）：格式说明，加上每一种的样本文件。测试拿样本逐字节比对。
  - 给模型看的字：原文存档，加上请求形状探针的存档（`26-提示词.md` J4）。
  - 界面：标到每一格的版式图。缩进几格、空几行、用什么字符和颜色、每一种状态长什么样，都要画出来。演示程序照图纸做，代替不了图纸。
