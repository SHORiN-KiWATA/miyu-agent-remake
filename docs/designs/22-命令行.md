## 命令行（草案）

状态：O1 到 O6 已定（2026-09-25）。其余内容为草案。

### 一、它是什么

`miyu` 这一个程序里有三样和命令行有关的东西（`12-进程形态与分发.md` R2）：

| 用途 | 命令 | 说明 |
|---|---|---|
| 单次对话 | `miyu ask` | 最薄的头：连上核心，发一条消息，打印回复，这一回合结束就退出（`04-核心协议.md` 第三节）。它也是协议的参考实现，端到端测试都用它来驱动核心 |
| 给别的软件用 | `miyu ask --format json`、`miyu stdio` | 让别的程序拿 Miyu 当后端（第四节） |
| 管理 | `miyu config`、`miyu kb`、`miyu venue`…… | 看和改配置、会话、场所、知识库、记忆、软件包（第五节） |

终端无缝集成是另一个头，但它建在命令行上，所以也写在这里（第七节）。

### 二、仿 Linux：命令行的规矩

命令行本来就是 Linux 的地盘，照它的老规矩来（O1）：

| 规矩 | 做法 |
|---|---|
| 结果走标准输出，进度和诊断走标准错误 | `miyu ask "…" > answer.md`，文件里只有她的回答；她做了哪些步骤，印在终端上，不进文件 |
| 标准输入能接管道 | `cat build.log \| miyu ask "为什么失败"`：管道进来的内容作为一个附件 |
| 不是终端就不上色、不画动画 | 输出重定向时只剩纯文字；遵守 `NO_COLOR` |
| 退出码说明成败 | 见下表 |
| 查询类的命令都有 `--format json` | 给脚本用；JSON 的结构带版本号，只加字段，不改含义 |
| 给人看的跟随语言，给程序看的恒为英文 | 提示和报错跟着界面语言；JSON 里的键、事件的名字恒为英文（`00-设计理念.md` 第三节） |
| 不认识的子命令就报错 | `miyu hello` 回一句「没有 hello 这个子命令。想和她对话，用 miyu ask "…"」，绝不当成对话发出去（`12-进程形态与分发.md` R4） |
| 有补全 | 装了终端无缝集成就带着补全；只想要补全的，用 `miyu completions <shell>` |

退出码：

| 码 | 意思 |
|---|---|
| 0 | 成功 |
| 1 | 出错了：核心、模型或工具出了问题，标准错误里写明是哪一样、怎么办 |
| 2 | 用法不对：不认识的子命令，或者参数不对 |
| 3 | 被打断了：按了 Ctrl+C，或者到了 `--timeout` |
| 4 | 要人回答，但这里没有人能回答（第三节） |
| 5 | 没有可用的模型：没配，或者全在冷却 |

### 三、`miyu ask`

```text
$ miyu ask "cargo test 为什么挂了？"
· 运行命令 cargo test -p miyu-kernel
· 读取 crates/kernel/src/projection.rs
测试挂在 projection::keeps_prefix_stable：工具结果按到达顺序排了，
不是按调用顺序。改成按调用顺序就好。
```

前两行走标准错误，后面的回答走标准输出。

| 选项 | 做什么 |
|---|---|
| `--session <名字或编号>` | 接着某个会话说。不写就开一个新会话（O2） |
| `--continue` | 接着上一次 `miyu ask` 的那个会话说 |
| `--persona`、`--preset` | 开新会话时用谁、以什么方式工作；它们钉在会话上，接着旧会话时不能改（`16-人格与预设.md` Y5） |
| `--model` | 这一次用哪个模型（`15-模型与供应商.md` 第六节） |
| `--file <路径>` | 附上文件，可以写几个 |
| `--format text\|json\|stream-json` | 输出的格式，默认 `text` |
| `--tools <名单>` | 只开这几件工具，是这个会话里临时收紧的一项（`14-配置.md` 第三节） |
| `--no-memory` | 这一次不召回、也不记下记忆 |
| `--timeout <时长>` | 到时间就打断这一回合，退出码是 3 |

- **默认开新会话**（O2）。新会话标成「一次性」，留在会话列表里，但折叠起来，不挤占侧栏；多久清理掉是一个配置项。
- **她自己在 shell 里跑 `miyu ask`，不会接进她正在跑的那个会话**：不写 `--session`，永远是新会话。旧版考虑过让一个环境变量当默认的会话，那样她调用自己时就会递归进正在跑的会话，没有采纳。
- **要人回答的时候**（O3）：
  - 标准输入是终端：当场问你，确认和提问都一样；
  - 不是终端，例如在脚本里：要确认的操作一律拒绝，并告诉她原因；她的提问得到「这里没有人能回答」；最后退出码是 4。这和无人值守的场所是同一个规矩（`11-权限与沙盒.md` A11）。
- **等子代理回报完才退出**：子代理都在后台跑（`02-内核.md` 第七节），只等第一轮，真正的回答还没出来就退出了。所以 `miyu ask` 等到这一轮结束、派出去的子代理都回报完、被回报叫醒的那几轮也结束，才打印并退出。
- **后台命令不等**：放到后台的命令可能是一直开着的服务。`miyu ask` 退出以后它照常跑，结果回到那个会话里（`04-核心协议.md` 第三节），用 `miyu session show` 看得到。等子代理的时候按 Ctrl+C 也是这样：不等了，后台的照常跑。
- **Ctrl+C** 打断这一回合；再按一次，不等回合收尾，直接退出。

### 四、给别的软件用

两种接法，按需要选（O4）：

- **简单的**：`miyu ask --format json` 或 `--format stream-json`。

```text
$ miyu ask --format json "现在几点？"
{"text":"现在是 15:04。","session":"0192f3a0","usage":{"input":1830,"cache_read":1792,"output":12}}
$ miyu ask --format stream-json "总结一下 README"
{"type":"turn.started","seq":42}
{"type":"tool","name":"read","summary":"读取 README.md"}
{"type":"text","delta":"README 讲了三件事："}
{"type":"text","delta":"安装、配置和第一次对话。"}
{"type":"turn.ended","reason":"completed"}
```

  这里的事件是给脚本用的简化形状，不是核心协议本身。它的结构写成文档，带版本号。
- **完整的**：`miyu stdio`，在标准输入输出上直接说 Miyu 协议（JSON-RPC 2.0，每行一条消息，`04-核心协议.md` 第二节）。它替调用方连上核心、出示本机令牌，之后原样转发，像用 `nc -U` 连一个 Unix 套接字。别的程序不用自己去找套接字、读令牌。
- 沙盒里的命令跑 `miyu stdio` 连不上：它读不到本机令牌（`11-权限与沙盒.md` 第五节）。
- 程序驱动的会话，用 `--persona`、`--preset`、`--tools` 收紧；想给这个会话临时换一段人设，就开会话时指定一个人格。旧版做过「替换系统提示词」「追加系统提示词」两个选项，这里由临时的人格来承担，不另开一条口子。

- **管理命令只是协议的客户端**（O5）：它们调的方法，和终端界面、网页用的是同一组，例如 `config.set`、`kb.add`。命令行能做的，别的头也能做；反过来也一样。
- 需要管理能力的命令，缺能力时报错，并说明缺的是哪一项（`06-多用户与身份.md` 第四节）。

### 六、`status` 与 `doctor`

```text
$ miyu status
核心    运行中 · 按需 · 已运行 2 小时 · 内存 18 MB
会话    3 个活动，其中 2 个在跑回合
子进程  天气扩展 · embedding worker
端点    deepseek-v4 正常
```

```text
$ miyu doctor
Miyu 0.1.0 · Ubuntu 24.04 · Linux 6.8 · x86_64
沙盒
  ✓ Landlock 可用，ABI 4
  ✗ 不能创建网络命名空间
    Ubuntu 24.04 起，要装 AppArmor 配置才能创建。沙盒里的网络现在是全关的。
    修复：sudo miyu sandbox setup
模型
  ✓ deepseek-v4 连通，320ms
  ✗ claude-opus 认证失败：密钥过期了
    修复：在设置里重新填写密钥
```

- `miyu status` 读的是核心的 `kernel.status`（`04-核心协议.md` 第九节），像 `/proc`：只报现在的状态，不做检查。
- `miyu doctor` 一项项地查：沙盒、数据根的权限、核心和命令行的版本是否一致、每个供应商通不通、语音的模型下载了没有、通讯平台的桥连没连上、连的是哪个实现和版本（`18-通讯平台.md` 第十一节）。每一项没过的，都跟着一行「修复：」。有一项没过，退出码就不是 0。

### 七、终端无缝集成

**以旧版现成的 fish 配置为底；bash 和 zsh 第一版只做 command not found 式的对话**（O6，项目主人 2026-09-25）。

- **装**：`miyu shell-init fish` 输出脚本，装进 shell 的配置目录，Miyu 升级以后自动更新。更新时顺着符号链接写，不把你的链接换成普通文件；旧版就出过这个事。
- **fish**，沿用旧版：
  - 回车时判断这一行是命令还是一句话：是能执行的命令，就照常执行；不是命令、看起来是一句话、或者是多行，就交给她；
  - Ctrl+J 换行，用来写多行的话；
  - Ctrl+V 粘贴图片和文件，在命令行里显示成占位符，例如 `[Image 1: 截图.png]`，和终端界面里一样（`13-终端界面.md` 第十节）；
  - 找不到命令时，也兜底交给她。
- **bash、zsh**：找不到命令时，把这一行交给她。
- **她在哪个会话里**：终端会话，一个一直续下去的会话，终端里说的话都进它。它用哪个人格、哪个预设，是个人设置里的一项。旧版叫「终端集成会话」；旧版的默认模式，现在就是这一项里的预设。
- **她在哪个目录干活**：每一轮开始时，工作目录换成你说这句话时 shell 所在的目录；沙盒的边界、仓库里的项目配置，都跟着这个目录走（`11-权限与沙盒.md` 第四节、`14-配置.md` 第三节）。
- **输出**：不是全屏，直接印在 shell 里，和终端界面的时间线是同一套样子（`13-终端界面.md` 第三节），只是不能点开。思考边想边出；转轮和活动区的每一帧都用同步输出包起来。旧版一开始每帧先擦再写，屏幕一闪一闪。
- **提问和确认**：当场在 shell 里问你。
- **Ctrl+C** 打断这一回合。

### 八、决定

**O1. 输出的规矩**

- **已定：结果走标准输出，进度和诊断走标准错误；不是终端就不上色、不画动画；退出码分六种；查询类的命令都有带版本号的 `--format json`。**
- 未选：怎么方便怎么印。脚本里拿不到干净的结果，也分不清是成功还是出错。
- 重开条件：无。

**O2. `miyu ask` 接哪个会话**

- **已定：默认开新会话，标成一次性、在列表里折叠；`--session`、`--continue` 接着说；不拿环境变量当默认的会话。**
- 未选：默认接着终端会话。脚本之间会串话，她自己调用自己时还会递归进正在跑的会话。
- 重开条件：无。

**O3. 没人能回答时**

- **已定：不是终端时，要确认的操作一律拒绝，提问得到「这里没有人能回答」，退出码是 4。**
- 未选：一直等着。脚本就卡死在那里。
- 重开条件：无。

**O4. 给别的软件用**

- **已定：两种接法：`--format json`、`stream-json` 给脚本；`miyu stdio` 直接说 Miyu 协议给程序。临时的人设用临时人格，不另开替换系统提示词的口子。**
- 未选：另造一套对外的接口。那样就有两套协议要维护。
- 重开条件：无。

**O5. 管理命令**

- **已定：只是协议的客户端，和别的头调同一组方法。**
- 未选：命令行直接读写文件或数据库。那样它和核心会各有一套规矩。
- 重开条件：无。

**O6. 终端无缝集成**

- **已定：以旧版的 fish 配置为底；bash、zsh 只做 command not found 式的对话；一个一直续下去的终端会话；每一轮的工作目录跟着 shell 走（2026-09-25 项目主人定）。**
- 重开条件：有人需要 bash、zsh 也像 fish 那样整行判断。

**后续再定**

- 一次性会话多久清理：配置项的默认值，实测后定
- `stream-json` 事件的完整清单：随协议的实现定
