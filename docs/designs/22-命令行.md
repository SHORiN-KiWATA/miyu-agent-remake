## 命令行（草案）

状态：O1 到 O6 已定（2026-09-25；O3 于 2026-09-28 改）。其余内容为草案。

### 一、它是什么

`miyu` 这一个程序里有三样和命令行有关的东西（`12-进程形态与分发.md` R2）：

| 用途 | 命令 | 说明 |
|---|---|---|
| 单次对话 | `miyu ask` | 最薄的头：连上核心，发一条消息，打印回复，等这一回合和它派出去的子代理都回报完就退出（第三节）。它也是协议的参考实现，端到端测试都用它来驱动核心 |
| 给别的软件用 | `miyu ask --format json`、`miyu stdio` | 让别的程序拿 Miyu 当后端（第四节） |
| 管理 | `miyu config`、`miyu kb`、`miyu venue`…… | 看和改配置、会话、场所、知识库、记忆、软件包（第五节） |

终端无缝集成是另一个头，但它建在命令行上，所以也写在这里（第七节）。

### 二、仿 Linux：命令行的规矩

命令行本来就是 Linux 的地盘，照它的老规矩来（O1）：

| 规矩 | 做法 |
|---|---|
| 结果走标准输出，进度和诊断走标准错误 | `miyu ask "…" > answer.md`，文件里只有她的回答；她做了哪些步骤，印在终端上，不进文件 |
| 标准输入能接管道 | `cat build.log \| miyu ask "为什么失败"`：管道进来的内容作为一个附件 |
| 不是终端就不上色、不画动画 | 输出重定向时只剩纯文字；遵守 `NO_COLOR` |
| 退出码说明成败 | 见下表 |
| 查询类的命令都有 `--format json` | 给脚本用；JSON 的结构带版本号，只加字段，不改含义 |
| 给人看的跟随语言，给程序看的恒为英文 | 提示和报错跟着界面语言；JSON 里的键、事件的名字恒为英文（`00-设计理念.md` 第三节） |
| 不认识的子命令就报错 | `miyu hello` 回一句「没有 hello 这个子命令。想和她对话，用 miyu ask "…"」，绝不当成对话发出去（`12-进程形态与分发.md` R4） |
| 有补全 | 装了终端无缝集成就带着补全；只想要补全的，用 `miyu completions <shell>` |

退出码：

| 码 | 意思 |
|---|---|
| 0 | 成功 |
| 1 | 出错了：核心、模型或工具出了问题，标准错误里写明是哪一样、怎么办 |
| 2 | 用法不对：不认识的子命令，或者参数不对 |
| 3 | 被打断了：按了 Ctrl+C，或者到了 `--timeout` |
| 4 | 有几步要人确认，这里不问，没做（第三节） |
| 5 | 没有可用的模型：没配，或者全在冷却 |

### 三、`miyu ask`

```text
$ miyu ask "glob 和 grep 在哪登记的？"
先搜一下登记工具的地方。
· 搜内容 fn tools → 2 个文件
· 读取 crates/miyu-basesystem/src/lib.rs → 37 行

在 crates/miyu-basesystem/src/lib.rs 的 tools() 里，
和 read 一起造好，核心起来时登记进工具目录。
· 输入 3,210 · 命中缓存 2,944（92%）· 输出 186
```

回答那两行走标准输出；她的思考、她做的每一步、最后的用量走标准错误，终端里是灰色（2026-09-28 项目主人定的样子）。

| 选项 | 做什么 |
|---|---|
| `--session <名字或编号>` | 接着某个会话说。不写就开一个新会话（O2） |
| `--continue` | 接着上一次 `miyu ask` 的那个会话说 |
| `--persona`、`--preset` | 开新会话时用谁、以什么方式工作；它们钉在会话上，接着旧会话时不能改（`16-人格与预设.md` Y5） |
| `--model` | 这一次用哪个模型（`15-模型与供应商.md` 第六节） |
| `--file <路径>` | 附上文件，可以写几个 |
| `--format text\|json\|stream-json` | 输出的格式，默认 `text` |
| `--tools <名单>` | 只开这几件工具，是这个会话里临时收紧的一项（`14-配置.md` 第三节） |
| `--no-memory` | 这一次不召回、也不记下记忆 |
| `--timeout <时长>` | 从发出算到全部了结：这一轮、子代理的回报、被回报叫醒的几轮都算在里面。到时间就打断，不再等，退出码是 3 |

- **默认开新会话**（O2）。新会话标成「一次性」，留在会话列表里，但折叠起来，不挤占侧栏；多久清理掉是一个配置项。
- **她自己在 shell 里跑 `miyu ask`，不会接进她正在跑的那个会话**：不写 `--session`，永远是新会话。旧版考虑过让一个环境变量当默认的会话，那样她调用自己时就会递归进正在跑的会话，没有采纳。
- **要人回答的时候**（O3，2026-09-28 项目主人改）：`miyu ask` 里没有提问的工具，也没有确认的界面，标准输入是不是终端都一样。
  - 要确认的操作一律拒绝，告诉她原因，她在回答里说明；最后退出码是 4，标准错误上最后一行说有几步因为要确认没做。这和没有确认界面的场所是同一个规矩（`11-权限与沙盒.md` A11）。
  - 她没有提问的工具（`ask_user`，`10-自带软件.md` 第三节），有问题就在回答里问，你用 `--continue` 接着说。
  - 要事先放行的，用参数多给她几个目录，照 Claude Code、codex 的 `--add-dir`：加进来的目录能读能写，可以写好几次（2026-09-28 项目主人定），随 M5 的沙盒边界一起做（施工 5-10）。当场确认、提问的抽屉在终端界面里（`13-终端界面.md` 第四节，M8）。
  - 为什么：她的提问在回答里问、你下一轮接着说就够了。确认靠下一轮打字放不了行：核心不看聊天内容放行，放行得是你亲手给的，所以一次性的命令照别家的做法，事先给参数，给不了的拒绝。opencode 的 `opencode run`（读过源码）要确认的一律拒绝、这一轮停下，加 `--auto` 才一律允许这一次，提问一律取消；Claude Code 的 `claude -p`、codex 的 `codex exec` 照它们的文档也靠事先给的参数。
- **还没配模型时**：标准输入是终端，先问首次引导的那两件事（`12-进程形态与分发.md` 第七节），问完再发这条消息；不是终端，直接退出，退出码是 5（2026-09-26 补）。
- **等子代理回报完才退出**：子代理都在后台跑（`02-内核.md` 第七节），只等第一轮，真正的回答还没出来就退出了。所以 `miyu ask` 等到这一轮结束、派出去的子代理都回报完、被回报叫醒的那几轮也结束，才打印并退出。
  - 打印的是这期间每一轮的回复，按先后排：第一轮的，和每一轮被回报叫醒的。`--format json` 因此给出一个按轮排的列表（第四节，2026-09-26 补）。
- **后台命令不等**：放到后台的命令可能是一直开着的服务。`miyu ask` 退出以后它照常跑，结果回到那个会话里（`04-核心协议.md` 第三节），用 `miyu session show` 看得到。等子代理的时候按 Ctrl+C 也是这样：不等了，后台的照常跑。
  - 没人看着了，结果只记下、不叫醒她：下次 `miyu ask -c` 接着说时她一起看到（2026-09-29 项目主人定，`02-内核.md` 第七节）。
- **Ctrl+C** 打断这一回合；再按一次，不等回合收尾，直接退出。
- **思考过程和用量**（2026-09-27 项目主人定）：
  - 她的思考边想边印在标准错误上，终端里是灰色；回答照旧走标准输出。重定向、接管道时，文件和下一个程序只拿到回答，思考留在屏幕上。
  - 每次问完，标准错误上最后印一行用量，终端里是灰色，例如 `· 输入 1,830 · 命中缓存 1,792（98%）· 输出 12`。有几轮就把几轮的加起来。
  - 思考、步骤、工具也是正常输出，只是走给人看的那条通道。标准错误这个名字是历史遗留，它装的是写给屏幕前的人看的旁白，不只是报错；在终端里两条通道都显示在屏幕上，看不出区别。
- **施工 3-9 下定的**：
  - 思考和回答之间空一行，写在回答的第一段前面：驱动等流完了才把几块一起收，回答开始时思考那一块还没收（真机验收查出的）。回答说完补一个换行；只想了没答的，思考那一行也收个尾。终端里（标准错误是终端、没设 `NO_COLOR`）思考、用量是灰色，每一段单独包起来，中途退出也不会把终端留成灰的。
  - 用量那一行把这一轮每次请求的用量加起来：输入 = 没命中 + 命中 + 写进缓存，命中率 = 命中 ÷ 输入，四舍五入到百分之一；供应商没报用量的不印。
  - `--continue` 接最新的那个一次性会话；一个都没有的说「还没有 miyu ask 开过的会话」，退出码 1。
  - 核心没在跑、自己也没设 `DEEPSEEK_API_KEY` 的，不拉起，退出码 5；核心在跑的照样连（它可能有 key）。一轮出错时没发出去、认证失败的，也是「没有可用的模型」，退出码 5。
  - `--format json` 最后印一行 `{"session":…,"turns":[{"text":…,"usage":{"input":…,"cache_read":…,"cache_write":…,"output":…}}]}`，出错的再带 `"error"`；标准错误上只印出错。
  - `miyu ask --help` 的说明跟着界面语言。
- **施工 4-5 下定的**（样子是项目主人 2026-09-28 定的）：
  - 一步一行：`· 显示名 参数的值 → 结果那一句`，做完才印，几件同时跑的照做完的先后印。显示名、跟哪个参数、结果那一句都照给人看的字（`26-提示词.md` 第八节）；没有的照她写的工具名、照状态写最泛的一句。
  - 没做成的同一行写原因：「出错：……」「没做：……」，这两个词是红的，别的整行灰。
  - 路径参数（`file_path`、`path`，`10-自带软件.md` 第十节定的名字）在工作目录里的写相对的，在家目录里的写 `~/…`；别的参数照原样。参数的值只取第一行，控制字符换掉，太长的截断：路径留后面（文件名在后面），别的留前面。
  - 工作目录太宽、核心退回账号的工作区时（`11-权限与沙盒.md` 第四节），开头说一句：`· 目录太宽（~），这次在 ~/.miyu/home/admin/workspace 里干活`。核心在造会话、说话的回应里说实际在哪个目录（`04-核心协议.md` 第九节）。
  - 思考、步骤、这一句都是旁白：旁白之间不空行，和回答之间空一行；回答那一行没完就来了步骤，先换行（思考不换：回答之后又来思考，只有出错重试、带着半截接着说的时候）。
  - `--format json` 不印步骤；中间隔着步骤的两次回复，前一次没换行的补一个。
  - 这属于终端集成那一块的输出（第七节），现在先直接印，做前端时再细弄（项目主人）。
- **施工 4-9 定的**：
  - 有几步因为要确认、这里没人能确认被拒的，用量那一行后面再印一行：`· 1 步没做：要你确认，miyu ask 里确认不了`，「没做」是红的，别的灰。
  - 认的是内核在没人能确认时记的那一句（`core/tool-results/unattended`，`02-内核.md` 第六节「确认怎么走」第 2 条）；只读时要写的、碰到数据根的不算。
  - 这一轮照常结束的，退出码 4；被打断、出错、没有模型的照旧，那一行照样印，印在说为什么结束的那一句前面。
  - `--format json` 不印这一行，只看退出码。
- **`miyu undo`、`miyu redo`**（施工 4-7 下，样子是项目主人 2026-09-28 定的，例子见 `docs/construction/4-7-miyu undo、miyu redo（下）.md`）：
  - `miyu undo` 撤掉当前会话的最后一轮，`miyu restore` 在发下一句之前恢复（`02-内核.md` 第六节「撤销与恢复」）。`miyu undo` 也可以写成 `miyu rewind`（2026-09-29 项目主人定：恢复那条原来叫 `miyu redo`，改叫 `restore`；撤销加别名 `rewind`，终端演示那边提的，施工 4-7 补）。当前会话和 `--continue` 一样，是最新的那个一次性会话；`--session` 指定别的。做前端时换成 `/undo`、`Ctrl+R`，这两条命令留给脚本用。
  - 结果走标准输出，写法照上面一步一行：第一行说撤的是哪一轮（那一轮人说的那句话），接着每个文件一行（改回、删掉、移回），没动的同一行写原因，「没动」「出错」是红的；之后又被改过的，下面印差异，一个文件最多 20 行。撤掉的几轮执行过命令的，说一句命令改的文件撤不回（`10-自带软件.md` 第七节）。
  - 差异由核心算好放在回应里（`01-架构.md` D1），头只照着印（`04-核心协议.md` 第九节）。
  - 被接受的退出码 0，有文件没动也是 0；被拒绝的 1。
- **`miyu compact`**（施工 6-8，命令名 2026-09-29 项目主人定，样子见蓝图 `cli/compact.md`）：把当前会话的上下文压缩成摘要，最近的一段原样留着；后面写的几个词是给摘要的要求（`09-压缩.md` 第二节「手动压缩」）。当前会话照 `miyu undo`，`--session` 指定别的。印的是 `miyu ask` 压缩那一行和用量那一行，都在标准错误上；压好了退出码 0，被拒绝、失败 1，被打断 3，没有模型 5。做前端时换成 `/compact`，这条命令留给脚本用。

### 四、给别的软件用

两种接法，按需要选（O4）：

- **简单的**：`miyu ask --format json` 或 `--format stream-json`。

```text
$ miyu ask --format json "今天星期几？"
{"session":"0192f3a0","turns":[{"text":"今天星期五。","usage":{"input":1830,"cache_read":1792,"output":12}}]}
$ miyu ask --format stream-json "总结一下 README"
{"type":"turn.started","seq":42}
{"type":"tool","name":"read","summary":"读取 README.md"}
{"type":"text","delta":"README 讲了三件事："}
{"type":"text","delta":"安装、配置和第一次对话。"}
{"type":"turn.ended","reason":"completed"}
```

  这里的事件是给脚本用的简化形状，不是核心协议本身。它的结构写成文档，带版本号。
- **完整的**：`miyu stdio`，在标准输入输出上直接说 Miyu 协议（JSON-RPC 2.0，每行一条消息，`04-核心协议.md` 第二节）。它替调用方连上核心、出示本机令牌，之后原样转发，像用 `nc -U` 连一个 Unix 套接字。别的程序不用自己去找套接字、读令牌。
- 沙盒里的命令跑 `miyu stdio` 连不上：它读不到本机令牌（`11-权限与沙盒.md` 第五节）。
- 程序驱动的会话，用 `--persona`、`--preset`、`--tools` 收紧；想给这个会话临时换一段人设，就开会话时指定一个人格。旧版做过「替换系统提示词」「追加系统提示词」两个选项，这里由临时的人格来承担，不另开一条口子。
- **别的 harness 往正在跑的会话里发消息**（2026-09-28 项目主人提，做多代理联动时展开，施工方案 M7）：Claude Code、codex 这类别的 harness 跑着的时候，能给 Miyu 正在跑的某个会话发一条消息，像另一个会话发来的那样进她的会话。协议上已经有底子：`miyu stdio`、`miyu ask --session` 都能说 `session.send`。还要定的几件：
  - **谁发的**：现在本机连上来的都记成管理员本人。别的 harness 发来的要另记一种来处（`03-事件模型.md` 第二节的 `by`），她才分得清是你说的，还是别的代理说的。
  - **发给哪个会话**：要有办法找到「正在跑的那个」，或者由人把会话编号交给它。
  - **回话怎么回去**：订阅那个会话的事件流，或者等这一轮结束拿回答。
  - **口子开成什么样**：`miyu stdio` 已经能用。别的 harness 多半认 MCP，可以再开一个 MCP 服务，给它们一件「给 Miyu 发消息」的工具。
  - **权限**：本机令牌只有本人读得到，沙盒里的命令读不到（`11-权限与沙盒.md` 第五节）。别的代理发来的话，照外面来的话对待，不当成你的指令。
  - **定了**（2026-09-29 项目主人定，M7 施工）：口子是命令行参数，`miyu ask -s <会话编号> --from <名字> <话>`，能跑命令的都能用（Claude Code、opencode、脚本）；来处记成 `harness`，带它报的名字（`03-事件模型.md` 第二节）；会话编号由人交给它；她在忙就排队，等这一轮答完印回答，和平常的 `miyu ask -s` 一样。MCP 服务、`miyu stdio` 不在 M7 做（蓝图 `agents.md` 第十一条）。

- `miyu status` 读的是核心的 `kernel.status`（`04-核心协议.md` 第九节），像 `/proc`：只报现在的状态，不做检查。
- `miyu doctor` 一项项地查：沙盒、数据根的权限、核心和命令行的版本是否一致、每个供应商通不通、语音的模型下载了没有、通讯平台的桥连没连上、连的是哪个实现和版本（`18-通讯平台.md` 第十一节）。每一项没过的，都跟着一行「修复：」。有一项没过，退出码就不是 0。

### 七、终端无缝集成

**以旧版现成的 fish 配置为底；bash 和 zsh 第一版只做 command not found 式的对话**（O6，项目主人 2026-09-25）。

- **装**：`miyu shell-init fish` 输出脚本，装进 shell 的配置目录，Miyu 升级以后自动更新。更新时顺着符号链接写，不把你的链接换成普通文件；旧版就出过这个事。
- **fish**，沿用旧版：
  - 回车时判断这一行是命令还是一句话：是能执行的命令，就照常执行；不是命令、看起来是一句话、或者是多行，就交给她；
  - Ctrl+J 换行，用来写多行的话；
  - Ctrl+V 粘贴图片和文件，在命令行里显示成占位符，例如 `[Image 1: 截图.png]`，和终端界面里一样（`13-终端界面.md` 第十节）；
  - 找不到命令时，也兜底交给她。
- **bash、zsh**：找不到命令时，把这一行交给她。
- **她在哪个会话里**：终端会话，一个一直续下去的会话，终端里说的话都进它。它用哪个人格、哪个预设，是个人设置里的一项。旧版叫「终端集成会话」；旧版的默认模式，现在就是这一项里的预设。
- **她在哪个目录干活**：每一轮开始时，工作目录换成你说这句话时 shell 所在的目录；沙盒的边界、仓库里的项目配置，都跟着这个目录走（`11-权限与沙盒.md` 第四节、`14-配置.md` 第三节）。
- **输出**：不是全屏，直接印在 shell 里，和终端界面的时间线是同一套样子（`13-终端界面.md` 第三节），只是不能点开。思考边想边出；转轮和活动区的每一帧都用同步输出包起来。旧版一开始每帧先擦再写，屏幕一闪一闪。
- **提问和确认**：当场在 shell 里问你。
- **Ctrl+C** 打断这一回合。

### 八、决定

**O1. 输出的规矩**

- **已定：结果走标准输出，进度和诊断走标准错误；不是终端就不上色、不画动画；退出码分六种；查询类的命令都有带版本号的 `--format json`。**
- 未选：怎么方便怎么印。脚本里拿不到干净的结果，也分不清是成功还是出错。
- 重开条件：无。

**O2. `miyu ask` 接哪个会话**

- **已定：默认开新会话，标成一次性、在列表里折叠；`--session`、`--continue` 接着说；不拿环境变量当默认的会话。**
- 未选：默认接着终端会话。脚本之间会串话，她自己调用自己时还会递归进正在跑的会话。
- 重开条件：无。

**O3. 没人能回答时**

- **已定：`miyu ask` 里没有提问的工具（`ask_user`），也没有确认的界面，是不是终端都一样：她有问题就在回答里问；要确认的操作一律拒绝，告诉她原因，退出码是 4；要事先放行的用参数（M5）；提问的工具和确认的抽屉在终端界面里（M8）（2026-09-28 项目主人改）。**
- 未选：标准输入是终端时，确认和提问都在终端里当场问你（2026-09-25 的定论）。她的提问在回答里问、下一轮接着说就够了；别家的一次性命令也不在终端里问人。
- 未选：一直等着。脚本就卡死在那里。
- 重开条件：无。

**O4. 给别的软件用**

- **已定：两种接法：`--format json`、`stream-json` 给脚本；`miyu stdio` 直接说 Miyu 协议给程序。临时的人设用临时人格，不另开替换系统提示词的口子。**
- 未选：另造一套对外的接口。那样就有两套协议要维护。
- 重开条件：无。

**O5. 管理命令**

- **已定：只是协议的客户端，和别的头调同一组方法。**
- 未选：命令行直接读写文件或数据库。那样它和核心会各有一套规矩。
- 重开条件：无。

**O6. 终端无缝集成**

- **已定：以旧版的 fish 配置为底；bash、zsh 只做 command not found 式的对话；一个一直续下去的终端会话；每一轮的工作目录跟着 shell 走（2026-09-25 项目主人定）。**
- 重开条件：有人需要 bash、zsh 也像 fish 那样整行判断。

**后续再定**

- `stream-json` 事件的完整清单：随协议的实现定
