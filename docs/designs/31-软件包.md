## 软件包（二版）

状态：已定（2026-10-11）。方向是项目主人 2026-10-11 定的（设计 `30-插件框架.md` 第十四节）：只有 `miyu pkg install` 一个装法、一切照 pacman 和 Linux，一个文件夹一个包、能带多样东西、记文件和哈希，网上现成的像 `~/.local/bin` 那样自己放；同一天又定软件包系统是框架的一部分，排在性能（V-2 中、下）前面先做，还要考虑 AI 怎么自己给自己装。主会话起草，同一天项目主人当面定了末尾「定了的」八条（F 到 H 和后缀 `.miyu`、`update` 这个名字是当晚补的）；别的是主会话照推荐定的技术形状。

### 一、照 pacman 的几样

| 做什么 | pacman | Miyu |
|---|---|---|
| 装本机的一个包 | `pacman -U <包文件>` | `miyu pkg install <包目录>` |
| 升级 | 装同名的新版本 | 同上：装同编号的新版本就是升级，旧的换下来 |
| 卸 | `pacman -R <包>` | `miyu pkg remove <编号>` |
| 列出装了的 | `pacman -Q` | `miyu pkg list`（不写子命令也是它） |
| 看一个包的信息 | `pacman -Qi <包>` | `miyu pkg info <编号>` |
| 一个包装了哪些文件 | `pacman -Ql <包>` | `miyu pkg files <编号>` |
| 一个文件归哪个包 | `pacman -Qo <路径>` | `miyu pkg owns <路径>` |
| 查装好的文件有没有被改坏 | `pacman -Qk <包>` | `miyu pkg check [编号]`，`miyu check` 也查 |
| 拿新的索引 | `pacman -Sy` | `miyu pkg update`（第八节） |
| 照索引升级装了的 | `pacman -Su` | `miyu pkg upgrade`（第八节） |
| 从软件源搜、装 | `pacman -Ss`、`-S` | `miyu pkg search <词>`、`miyu pkg install <编号>`（第八节） |
| 清下载过的包文件 | `pacman -Sc` | `miyu pkg clean`（第八节） |

- 子命令用词是正式写法，pacman 的单字母开关当别名也认：`-U` 是 `install`，`-R` 是 `remove`，`-Q` 是 `list`，`-Qi` 是 `info`，`-Ql` 是 `files`，`-Qo` 是 `owns`，`-Qk` 是 `check`；软件源那几个 `-Sy` 是 `update`，`-Su` 是 `upgrade`（`-Syu` 两步一起），`-Ss` 是 `search`，`-S` 是 `install`，`-Sc` 是 `clean`；帮助页两种都写（定了的 A；拿索引叫 `update` 不叫 `sync`，2026-10-11 项目主人定）。
- 装、卸之前照 pacman 印一份要做什么（装哪个包、哪个版本、带了哪几样东西、要什么权限、占多大），问一句「接着装？[Y/n]」；`--yes` 或 `--noconfirm` 不问，给脚本用。头上装卸照现在点按钮，不另问（定了的 B）。

### 二、一个包长什么样

一个文件夹就是一个包，文件夹名就是编号：

```text
pudding/
├── package.toml          # 清单
├── skills/
│   └── draw/SKILL.md     # 带的技能，一个技能一个文件夹
├── scripts/
│   └── ocr.py            # 带的脚本
├── mascot.json           # 吉祥物的模型
├── bin/miyu-pudding      # 带程序的（扩展、小程序）放这里
└── page/index.html       # 软件后台页
```

清单：

```toml
[package]
name = { zh = "布丁", en = "Pudding" }
version = "1.2.0"
summary = "…"
author = "…"          # 新的三格，都可以不写
license = "MIT"
url = "https://…"

[mascot]
model = "mascot.json"

[[mcp]]               # 带的 MCP 服务，一个一段
name = "github"
command = ["npx", "-y", "@modelcontextprotocol/server-github"]
```

1. **不再写种类**：包带了什么看清单里有哪几张表。有 `[process]` 的是要核心拉起的扩展，有 `[worker]` 的带小程序，有 `[ui]` 的是界面，有 `[mascot]` 的带吉祥物，技能、脚本看目录里有没有 `skills/`、`scripts/`，`[[mcp]]` 一段一个 MCP 服务。内置包（代码编在核心里）写 `[builtin]`。一个包能同时有好几样（设计 30 第十四节第 2 条）。pacman 的包也只是一组文件加信息，不分种类。
2. **哪几样不能放在一起**：一个包至多一个程序（`[process]`、`[worker]`、`[ui]` 三选一，`[builtin]` 不和它们一起）；别的随意。
3. **开关**以包为单位（设计 30 第十四节第 2 条）；包里的每个技能、脚本、MCP 服务照设计 30 第三节各算一个功能，预设里能逐个关。
4. **现在的清单**（`packages/<编号>.toml` 加同名目录、写 `kind`）照第七节挪。

### 三、装、卸、升级

1. **装**：读、查清单（写错的一处都不装）；编号和出厂的撞了不装；整个文件夹先拷进点开头的暂存处，算好每个文件的哈希，再换进 `packages/<编号>/`；成了才写本地库（第四节）。装不成的什么都不留。
2. **升级**：同编号已经装了的，旧的先挪到点开头的备份处，新的换进去；成了删备份、更新本地库，不成放回去。版本只给人看，不比大小：装哪份就是哪份（降级也照装）。
3. **卸**：卸就是清干净（定了的 H）：整个包目录（连包自己运行时写进去的）、它的状态目录 `state/packages/<编号>/`、系统配置和个人设置里这个包的项都删掉，重装回来从头设。密钥不删：密钥文件里的一条可能别处也在引用，`miyu check` 照旧报引用了却没用上的。项目目录里的 `.miyu/config.toml` 在别人的仓库里，不碰。别的包依赖它的不卸，说清被谁依赖着（照 pacman）。出厂的照现在在家目录记一笔「不要它」。
4. **当场生效**：照现在（设计 30 第九节）。
5. **谁能装**：本机的人；AI 照第六节；扩展进程不能（照现在 `local_only`）。

### 四、本地库（照 pacman 的 `local/`）

- 放在状态目录：`state/packages/local/<编号>/`，一个包两份：`desc`（编号、版本、装的时刻、从哪个路径装的、总大小）、`files`（每个文件一行：相对包目录的路径、SHA-256、字节数）。
- 出厂的包不进本地库：资源目录跟着 Miyu 一起装，归系统的包管理（AUR、Homebrew）管。
- `miyu pkg check`：照 `files` 一个个比哈希，报改了的、少了的、多出来的（多出来的只是提示）。
- `miyu pkg owns <路径>`：路径在哪个包的目录里、本地库里有没有它。
- 两个包抢同一个文件：每个包只往自己的文件夹里放，文件撞不上；撞的只会是名字（两个包带了同名的技能、同名的 MCP 服务），读的时候照现在功能编号撞了的办法报（设计 30 第三节第 3 条）。

### 五、本机自己放的（不归包管理，像 `~/.local/bin`）

1. 网上现成的、没有清单的东西不进包管理，自己放进约定的地方，Miyu 照目录找到就能用（设计 30 第十四节第 6 条）：
   - 技能：`home/<账号>/skills/<名字>/SKILL.md`；
   - 脚本：`home/<账号>/scripts/<文件>`；
   - MCP 服务：个人设置里一张表，一个名字一条命令。
2. 不记文件、不管卸载、`miyu pkg` 不列它们，删掉就没了。`miyu check` 照样查写得对不对（`SKILL.md` 的头、MCP 设置的写法）。
3. 和包里带的同名时，自己放的赢，`miyu check` 报一句被谁盖住了（照 Linux 的 `/usr/local/bin` 排在 `/usr/bin` 前面；定了的 C）。

### 六、AI 自己给自己装

照 Linux：普通用户装软件看权限，AI 在这里就是那个用户；问不问人照会话这时的权限级别（定了的 D），和她碰别的东西一个规矩。

1. **一件新工具**（基础系统里，新功能「软件包」，预设能关；在哪个场所开、哪个场所关，由头和场所规则选预设定，核心不写场所特判，定了的 E）：
   - 查：列出装了的、看一个包的信息、看本机某个包目录里有什么。只读，哪一级都不问。
   - 装、卸，打开她装的带程序的包（扩展）、批它要的能力：

     | 会话的权限级别 | 做法 |
     |---|---|
     | 完全放开 | 直接做，不问人 |
     | 工作区（平常） | 问人一次：卡片写哪个包、哪个版本、带了哪几样、要什么能力、占多大；带程序的另写一句「会在这台机器上跑它的程序」 |
     | 只读 | 不能做 |

     没人能确认的会话照现在的规矩：要问的那一档直接拒（`kernel/asking.md`），完全放开的照样直接做。
   - 装的是本机的一个包目录：她自己写的（在工作区里照包的样子写好）、人给她的路径。软件源以后才有。
   - 包目录在数据根里，文件工具碰不到（`11-权限与沙盒.md`）：这件工具是她装包唯一的门，权限照上面那张表判，不照路径判。
2. **她自己写包**：照现在的技能、脚本、MCP 的写法写进工作区的一个文件夹，加一份清单，再用这件工具装。出厂带一个教她怎么写包的技能（同旧版的 skill-creator、script-creator）。
3. **自己放的目录**：她往 `home/<账号>/skills/` 这些地方写，照现在的文件权限走，不另开口子。
4. **装好以后**：开着的会话下一个回合工具面才换（设计 30 第九节）；技能的清单变了怎么带给她，照 dsh 调研第四节第 3 条做技能时一起定。
5. 人在头上、命令行上装卸不受这张表管：人装就是人批的。

### 七、迁移

1. 出厂的：资源目录里的 `packages/<编号>.toml` 和同名目录挪成 `packages/<编号>/package.toml`，`kind` 去掉、换成对应的表；这一步在仓库里做，不留给装机。
2. 家目录里已经装了的：核心起来时照老写法认出来，挪成新的样子、补本地库（照现在的文件算哈希），记一行运行日志。只挪一次，挪不成的（文件夹里已经有一份清单）记一行警告，原样不动（F-8 上照推荐定：老写法只在开发用的家目录里有，不另报）。
3. 老写法读到哪个版本为止：第一个预览版之前的都没发出去，只在这几个开发用的家目录里有，挪完就不再认（只读一个版本，代码里不留两套）。

### 八、软件源（以后做，2026-10-11 项目主人定了方向）

照 DeepSeek 的 dsh：dsh 不设官方的收录处、谁都能发、不审（插件就是 npm 包，装就是 `pnpm add`），安全靠装的那一刻（装完默认不开、安装脚本要人放行）；它的市场 10-02 才提出来，只定索引的格式，索引谁都能出。项目主人没时间审别人的包，定了自动收录（定了的 F）。

1. **包文件**：一个包打成一个文件 `<编号>-<版本>.miyu`（后缀 2026-10-11 项目主人定，只给软件包用），里面是 zstd 压的 tar，解开就是那个包文件夹，`package.toml` 在最上层；`tar --zstd -xf` 能直接拆开看。
2. **作者发包**：仓库里放一个包文件夹，仓库打话题标签 `miyu-package`；打 tag 发版时用官方给的 GitHub Actions 模板打成 `.miyu` 传进 Release。
3. **官方的索引仓库，全自动**：GitHub Actions 每天跑一次收录：
   - 搜带标签的仓库，下各个 Release 里的 `.miyu`，照 Miyu 读清单的那套查，读不成的不收；算 SHA-256，写进 `index.json`（编号、版本、名字、简介、作者、带了哪几样、要什么能力、下载地址、哈希、来源仓库）。
   - 编号先到先得：第一个收录的仓库占住，记在 `names.toml`，永远跟着这个仓库，作者弃坑也不放给别人（防冒充：不然别人抢到编号发恶意版，装过的人一升级就中）。
   - 黑名单 `blocked.toml`：项目主人手写一行（编号或仓库、一句理由），下次收录去掉，并随索引下发。
   - `official.toml` 列项目主人自己的仓库，这些标「官方」。
   - 索引用 ed25519 签名，私钥在 Actions 的密钥里，公钥编进 miyu；索引和签名放 GitHub Pages。包文件照样从作者的 Release 下。
4. **用户**：
   - `miyu pkg update` 拿新索引、验签，存在本地；`search` 在本地索引里搜。
   - `install <编号>`：照索引下载、比哈希，对不上不装；解开以后照本机包目录那一条装（第三节），装完默认不开；印的那一份写明来源仓库、是不是官方、社区包「没人审过」。
   - `upgrade`：索引写的那一版和装的不一样就换（不比大小，作者撤回新版也跟着回去），照第三节第 2 条的交易；开没开、设置、状态都不动。来源仓库和装的时候不一样的不升。配置 `packages.hold = ["<编号>"]` 的跳过（照 pacman 的 `IgnorePkg`）。从本机文件夹装的不碰（照 `-Qm`）。
   - 下过的 `.miyu` 留在缓存目录（照 `/var/cache/pacman/pkg`），退回旧版不用再下；`clean` 清掉。
   - 镜像：配置里列几个，照先后试；有签名和哈希，镜像改不了内容。
5. **从源里没了**：作者去掉标签、删仓库的，下次收录从索引里去掉，装了的照样用，`list` 标一句「软件源里没有了」；删了某一版的退回剩下的最新一版。被拉黑的，装了的人 `update`、`check` 时提示一句「被拉黑：理由」，照旧开着，关不关、卸不卸他自己定（定了的 G）。
6. **挡不住的**：作者账号被盗、发了恶意的新版，自动收录照收，只能事后拉黑。新版收录以后先晾一段时间（比如 24 小时）用户才看得到，做的时候再问。
7. **依赖解析**：现在的 `[depends]`、`[recommends]` 只认装没装，软件源做的时候再定自动装不装依赖。

### 九、施工拆分（草案）

| 步 | 做什么 |
|---|---|
| F-8 上 | 一个文件夹一个包：新的目录、清单不写种类、一包多样；出厂的挪好；家目录的老写法起来时挪 |
| F-8 中 | 本地库：装时记文件和哈希、升级的交易、卸清干净（包目录、状态、设置）；`miyu pkg info`、`files`、`owns`、`check` |
| F-8 下 | `miyu pkg install`、`remove` 照 pacman 印一份要做什么、问一句，`--yes` |
| F-9 | 本机自己放的：技能、脚本的目录，MCP 的个人设置；同名的谁赢 |
| F-10 | AI 的装包工具：查、装卸、打开她装的扩展，问不问人照会话的权限级别 |
| 之后 | MCP 适配器、技能、脚本（扩展性那一段）照这一版的包来做 |
