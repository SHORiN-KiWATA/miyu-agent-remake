## 软件包（二版）

状态：草案（2026-10-11 主会话起草）。方向是项目主人 2026-10-11 定的（设计 `30-插件框架.md` 第十四节）：只有 `miyu pkg install` 一个装法、一切照 pacman 和 Linux，一个文件夹一个包、能带多样东西、记文件和哈希，网上现成的像 `~/.local/bin` 那样自己放；同一天又定软件包系统是框架的一部分，排在性能（V-2 中、下）前面先做，还要考虑 AI 怎么自己给自己装。下面标「待拍板」的是要项目主人定的，别的是主会话照推荐定的技术形状。

### 一、照 pacman 的几样

| 做什么 | pacman | Miyu |
|---|---|---|
| 装本机的一个包 | `pacman -U <包文件>` | `miyu pkg install <包目录>` |
| 升级 | 装同名的新版本 | 同上：装同编号的新版本就是升级，旧的换下来 |
| 卸 | `pacman -R <包>` | `miyu pkg remove <编号>` |
| 列出装了的 | `pacman -Q` | `miyu pkg list`（不写子命令也是它） |
| 看一个包的信息 | `pacman -Qi <包>` | `miyu pkg info <编号>` |
| 一个包装了哪些文件 | `pacman -Ql <包>` | `miyu pkg files <编号>` |
| 一个文件归哪个包 | `pacman -Qo <路径>` | `miyu pkg owns <路径>` |
| 查装好的文件有没有被改坏 | `pacman -Qk <包>` | `miyu pkg check [编号]`，`miyu check` 也查 |
| 从软件源搜、装 | `pacman -Ss`、`-S` | 以后做（第八节） |

- 子命令用词，不用 pacman 的单字母开关：`miyu` 别的命令都是子命令（`22-命令行.md`），一个命令行里两套写法不好记。（待拍板 A）
- 装、卸之前照 pacman 印一份要做什么（装哪个包、哪个版本、带了哪几样东西、要什么权限、占多大），问一句「接着装？[Y/n]」；`--yes` 不问，给脚本用。头上装卸照现在点按钮，不另问。（待拍板 B）

### 二、一个包长什么样

一个文件夹就是一个包，文件夹名就是编号：

```text
pudding/
├── package.toml          # 清单
├── skills/
│   └── draw/SKILL.md     # 带的技能，一个技能一个文件夹
├── scripts/
│   └── ocr.py            # 带的脚本
├── mascot.json           # 吉祥物的模型
├── bin/miyu-pudding      # 带程序的（扩展、小程序）放这里
└── page/index.html       # 软件后台页
```

清单：

```toml
[package]
name = { zh = "布丁", en = "Pudding" }
version = "1.2.0"
summary = "…"
author = "…"          # 新的三格，都可以不写
license = "MIT"
url = "https://…"

[mascot]
model = "mascot.json"

[[mcp]]               # 带的 MCP 服务，一个一段
name = "github"
command = ["npx", "-y", "@modelcontextprotocol/server-github"]
```

1. **不再写种类**：包带了什么看清单里有哪几张表。有 `[process]` 的是要核心拉起的扩展，有 `[worker]` 的带小程序，有 `[ui]` 的是界面，有 `[mascot]` 的带吉祥物，技能、脚本看目录里有没有 `skills/`、`scripts/`，`[[mcp]]` 一段一个 MCP 服务。内置包（代码编在核心里）写 `[builtin]`。一个包能同时有好几样（设计 30 第十四节第 2 条）。pacman 的包也只是一组文件加信息，不分种类。
2. **哪几样不能放在一起**：一个包至多一个程序（`[process]`、`[worker]`、`[ui]` 三选一，`[builtin]` 不和它们一起）；别的随意。
3. **开关**以包为单位（设计 30 第十四节第 2 条）；包里的每个技能、脚本、MCP 服务照设计 30 第三节各算一个功能，预设里能逐个关。
4. **现在的清单**（`packages/<编号>.toml` 加同名目录、写 `kind`）照第七节挪。

### 三、装、卸、升级

1. **装**：读、查清单（写错的一处都不装）；编号和出厂的撞了不装；整个文件夹先拷进点开头的暂存处，算好每个文件的哈希，再换进 `packages/<编号>/`；成了才写本地库（第四节）。装不成的什么都不留。
2. **升级**：同编号已经装了的，旧的先挪到点开头的备份处，新的换进去；成了删备份、更新本地库，不成放回去。版本只给人看，不比大小：装哪份就是哪份（降级也照装）。
3. **卸**：照本地库删这个包的文件，删完目录是空的就删目录；本地库里没记的文件（包自己运行时写的）不删，留在原处，`miyu pkg check` 报一句「留下了几个文件」。出厂的照现在在家目录记一笔「不要它」。
4. **当场生效**：照现在（设计 30 第九节）。
5. **谁能装**：本机的人；AI 照第六节；扩展进程不能（照现在 `local_only`）。

### 四、本地库（照 pacman 的 `local/`）

- 放在状态目录：`state/packages/local/<编号>/`，一个包两份：`desc`（编号、版本、装的时刻、从哪个路径装的、总大小）、`files`（每个文件一行：相对包目录的路径、SHA-256、字节数）。
- 出厂的包不进本地库：资源目录跟着 Miyu 一起装，归系统的包管理（AUR、Homebrew）管。
- `miyu pkg check`：照 `files` 一个个比哈希，报改了的、少了的、多出来的（多出来的只是提示）。
- `miyu pkg owns <路径>`：路径在哪个包的目录里、本地库里有没有它。
- 两个包抢同一个文件：每个包只往自己的文件夹里放，文件撞不上；撞的只会是名字（两个包带了同名的技能、同名的 MCP 服务），读的时候照现在功能编号撞了的办法报（设计 30 第三节第 3 条）。

### 五、本机自己放的（不归包管理，像 `~/.local/bin`）

1. 网上现成的、没有清单的东西不进包管理，自己放进约定的地方，Miyu 照目录找到就能用（设计 30 第十四节第 6 条）：
   - 技能：`home/<账号>/skills/<名字>/SKILL.md`；
   - 脚本：`home/<账号>/scripts/<文件>`；
   - MCP 服务：个人设置里一张表，一个名字一条命令。
2. 不记文件、不管卸载、`miyu pkg` 不列它们，删掉就没了。`miyu check` 照样查写得对不对（`SKILL.md` 的头、MCP 设置的写法）。
3. 和包里带的同名时，自己放的赢，`miyu check` 报一句被谁盖住了（照 Linux 的 `/usr/local/bin` 排在 `/usr/bin` 前面）。（待拍板 C）

### 六、AI 自己给自己装（待拍板 D、E）

照 Linux：普通用户装软件要 `sudo`，人输一次密码批准。AI 在这里就是那个普通用户。

1. **一件新工具**（基础系统里，新功能「软件包」，预设能关）：
   - 查：列出装了的、看一个包的信息、看本机某个包目录里有什么。只读，不问人。
   - 装、卸：每一次都要人批准（待拍板 D）。批准卡片照第一节第 2 条那一份写：哪个包、哪个版本、带了哪几样、要什么权限、占多大；带程序的另写一句「会在这台机器上跑它的程序」。没人能批准的会话（群聊、子代理没人看着的）一律拒。
   - 装的是本机的一个包目录：她自己写的（在工作区里照包的样子写好）、人给她的路径。软件源以后才有。
2. **她自己写包**：照现在的技能、脚本、MCP 的写法写进工作区的一个文件夹，加一份清单，再请人批准装。出厂带一个教她怎么写包的技能（同旧版的 skill-creator、script-creator）。
3. **自己放的目录**：她往 `home/<账号>/skills/` 这些地方写，照现在的文件权限走（工作区外要问人），不另开口子。
4. **装好以后**：开着的会话下一个回合工具面才换（设计 30 第九节）；技能的清单变了怎么带给她，照 dsh 调研第四节第 3 条做技能时一起定。
5. 未选：让 AI 不问人直接装纯数据的包（只有技能、脚本、没有程序的）。技能、脚本也能让她做事（脚本照样跑命令），和带程序的差别不大，不该少问一次。（待拍板 D 的另一个选项）

### 七、迁移

1. 出厂的：资源目录里的 `packages/<编号>.toml` 和同名目录挪成 `packages/<编号>/package.toml`，`kind` 去掉、换成对应的表；这一步在仓库里做，不留给装机。
2. 家目录里已经装了的：核心起来时照老写法认出来，挪成新的样子、补本地库（照现在的文件算哈希），记一行运行日志。只挪一次，挪不成的照写错了报，原样不动。
3. 老写法读到哪个版本为止：第一个预览版之前的都没发出去，只在这几个开发用的家目录里有，挪完就不再认（只读一个版本，代码里不留两套）。

### 八、以后

- 软件源：别人发布的包有一个索引，`miyu pkg install <名字>` 从网上下、照签名查；搜索、同步照 pacman 的 `-S`、`-Ss`、`-Sy`。
- 包文件：一个包打成一个文件（照 pacman 的 `.pkg.tar.zst`）传给别人；这一版只认本机的文件夹。
- 依赖解析：现在的 `[depends]`、`[recommends]` 只认装没装，软件源以后才自动装依赖。

### 九、施工拆分（草案）

| 步 | 做什么 |
|---|---|
| F-8 上 | 一个文件夹一个包：新的目录、清单不写种类、一包多样；出厂的挪好；家目录的老写法起来时挪 |
| F-8 中 | 本地库：装时记文件和哈希、升级的交易、卸照库删；`miyu pkg info`、`files`、`owns`、`check` |
| F-8 下 | `miyu pkg install`、`remove` 照 pacman 印一份要做什么、问一句，`--yes` |
| F-9 | 本机自己放的：技能、脚本的目录，MCP 的个人设置；同名的谁赢 |
| F-10 | AI 的装包工具：查、请人批准装卸 |
| 之后 | MCP 适配器、技能、脚本（扩展性那一段）照这一版的包来做 |
