## 技能和脚本

### 是什么

- **技能**：一个文件夹，里面一份 `SKILL.md`（开头几行写名字和一句说明，正文教她怎么做一类事），可以带参考资料、脚本。她平时只看到技能的名字和一句说明，用得上时自己读正文（`10-自带软件.md` 第三节：技能不单独设工具，用 `read` 读）。
- **脚本**：一个可执行文件，开头的注释写说明、参数，接进来就是她的一件工具（旧版 Miyu 的做法，实测好用：旧版出厂 17 个，番剧、天气、各家搜索、抖音下载这类）。

已经定了的（不在这里重定）：

- 技能、脚本和别的软件一样是装好的软件，不住在预设里；每个技能、每个脚本自动算一个功能，预设里能逐个开关（`16-人格与预设.md` Y7，`30-插件框架.md` 第三节）。
- 从哪来：软件包里的 `skills/<名字>/SKILL.md`、`scripts/<文件>`；本机自己放的在家目录里，同名的自己放的赢（`31-软件包.md` 第五节）。自己做出来的在做出它的那个预设里打开（16 第三节）。
- 技能的列表在 system 的「技能与知识库」那一段，排在核心和软件包的几行后面（`26-提示词.md` 第三节）；技能正文是她读进来的工具结果，压缩以后照「用过的技能」重建（`09-压缩.md` 第四节，`10-自带软件.md` 的 `file.read` 效果）。

### 技能

1. **写法**：照公开的 Agent Skills 格式（Anthropic 起的头，现在 Claude Code、Codex、Gemini CLI、Cursor 这些都认）：`SKILL.md` 开头的 YAML 写 `name`（小写字母、数字、`-`，和文件夹同名）、`description`（给模型看，英文，说清是什么、什么时候用，可以带人会说的几个中文触发词）；正文随意。给人看的名字、一句说明放在格式自带的 `metadata` 里（`display_name`、`summary`，照界面语言写几种）：给模型的和给人的分开两格（旧版吃过一格两用的亏，设置页中英混杂）。别的格子照格式认、不用。
2. **她看到的**：system 里技能那一段一行一个：名字、一句说明、`SKILL.md` 的路径。只列这个会话的预设里开着的。说明超过 1024 个字的截断（格式的上限）。
3. **读**：她用 `read` 读那个路径，读技能文件夹里别的文件（参考资料）也一样。技能文件夹在数据根里，文件工具平时碰不到（`11-权限与沙盒.md`），开着的技能文件夹单独放开只读（`session/guard.md` 加一条），不问人。技能里带的脚本照她跑命令的规矩跑（沙盒里能读这个文件夹）。
4. **用过的技能**：她读了某个技能的 `SKILL.md`，执行器在效果里记上（`10-自带软件.md` 的 `file.read`），压缩以后照它重读回来（09 第四节）。
5. **会话中途列表变了**（装了、卸了、她自己写了一个）：见「待项目主人定」第 2 条。

### 脚本

1. **写法**：照旧版的开头注释，旧版的 17 个照搬就能用：

   ```python
   #!/usr/bin/env python3
   # Display name: Bangumi
   # 显示名称：番剧信息
   # Description: Bangumi airing calendar and subjects: what airs today, search, details.
   # 描述：查番组计划的放送日历与条目。
   # Timeout: 60
   # Parameters:
   # { "type": "object", "properties": { "query": { "type": "string" } } }
   ```

   `Description` 给模型（英文），`描述`、`显示名称` 给人（双槽，同技能）；`Parameters` 是参数的 JSON Schema，没写的当没有参数；`Timeout` 是秒，没写的 60。
2. **她看到的**：一件工具，名字是文件名（去掉扩展名，不合 `[A-Za-z0-9_-]` 的换成 `_`），说明、参数照开头注释。单件说明和参数合起来超过工具的预算（550 token）的不收，`miyu check` 报出来（旧版的规矩：重的、低频的放进技能里，由技能正文带路）。
3. **跑**：照开头的 `#!` 起程序（Windows 上照扩展名找解释器）；参数是一份 JSON，交给环境变量 `MIYU_ARGS_JSON` 和标准输入（同旧版）；工作目录是会话的工作区；另给它一个能写缓存的目录（`MIYU_SCRIPT_CACHE_DIR`）。输出照命令的输出交回，退出码不是 0 的算出错。访问类别是执行：照跑命令的规矩进沙盒、问人（`session/guard.md`）。
4. **技能里的脚本**不算工具，不进工具面：由技能正文写怎么跑（她用跑命令的那件工具跑）。

### 待项目主人定

1. **技能照不照公开的 Agent Skills 格式**。推荐照：网上现成的技能（这些家的生态里已经很多）放进文件夹就能用；给人看的名字放在格式自带的 `metadata` 里。另一条：照旧版 Miyu 自己的写法（frontmatter 直接写 `display_name`、`summary`），别家的技能要改一下才认。
2. **会话中途技能列表变了，怎么告诉她**（`30-插件框架.md` 第九节第 5 条留着的这一题，`docs/reviews/2026-09-30-dsh-即插即用调研.md` 第四节第 3 条）。推荐在这一轮的尾巴上追加一份新的完整列表（旧版 Miyu、dsh 都这样），system 里那一段不改：会话中途新做一个技能，前缀缓存不掉。另一条：system 里那一段照新的重写，下一轮整份缓存重算。
3. **脚本当工具，还是像技能那样列出来、她用跑命令的工具去跑**。推荐当工具（旧版的做法）：每个脚本一个开关、群里没有跑命令工具的会话也能用（旧版在 QQ 里用得最多的就是这些）；代价是每个脚本占一份工具面。另一条：列一行名字和说明，她用 `shell` 跑，工具面不涨，但没开跑命令的会话用不了。
4. **本机自己放的目录名**：`home/<账号>/skills/`、`home/<账号>/scripts/`（`31-软件包.md` 第五节先写了这两个，30 第十四节说做到时问）。推荐就用这两个。
5. **出厂带哪几个技能**。推荐两个：写技能的（同旧版 skill-creator）、写脚本和写包的（旧版 script-creator 加上 31 第六节第 2 条要的「怎么写一个包」）。旧版的 17 个脚本放进软件源，不随出厂带（同 Shorin Wiki 的处理，`19-知识库.md`）。
