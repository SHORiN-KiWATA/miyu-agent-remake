## 会话执行工具、改回文件

### 是什么

会话 actor（`session/actor.md`）里碰工具和文件的几件事：照工具名找到那一件，一件一个任务地跑；工具报的效果存成 blob，记下她看过的文件；撤销、恢复时照内核给的几步改回文件，一步一步先核对再动手；派子代理时照父会话填好子会话，经会话表造出来（施工 7-5）；后台命令活过起它的那次调用，由执行器的任务表管（施工 7-3）。

### 在哪

| 代码 | 管什么 |
|---|---|
| `crates/miyu-session/src/tools.rs` | 执行工具的端口：找、派、量用时、叫停、收回报；改回文件交给阻塞线程 |
| `crates/miyu-session/src/sandbox.rs` | 照这一刻实际生效的级别给一次调用写沙盒的规格（施工 5-4 上） |
| `crates/miyu-session/src/agents.rs` | 派子代理：一个会话一份要照抄的，每一次调用一个端口（施工 7-5） |
| `crates/miyu-session/src/job_ids.rs` | 领任务编号（施工 7-5） |
| `crates/miyu-session/src/spawn.rs` | 造子会话、给别的会话发命令的端口 `SessionPort`，会话表交进来（施工 7-5） |
| `crates/miyu-session/src/effects.rs` | 效果存成 blob；她看过的：记下、从日志重建 |
| `crates/miyu-session/src/restore.rs` | 改回文件：一步步先核对再动手 |
| `crates/miyu-session/src/jobs.rs` | 执行器的任务表 `Jobs`（核心里一张）、一个会话 actor 的那一份 `SessionJobs`：报 `restarted`、停下时整组杀（施工 7-3） |
| `crates/miyu-session/src/jobs/run.rs` | 交给一次调用的任务端口：领编号、建输出文件、登记，读输出的线程、等它结束的线程 |
| `crates/miyu-session/src/jobs/output.rs` | 一条后台命令的输出文件：边跑边写，结束了存成 blob、数字 |
| `crates/miyu-session/src/job_ids.rs` | 任务编号的分配器 `JobIds`：一个会话 actor 一份，照日志往后数（施工 7-3、7-5 共用） |
| `crates/miyu-store` 的 `jobs` | 输出文件放在哪：会话目录下的 `jobs/<编号>.out`（`store.md`） |
| `crates/miyu-session/src/blocking.rs` | 在阻塞线程里做完 |
| `crates/miyu-fs` 的 `replace`、`trash` | 写回、进出回收站，和写的工具用的是同一份（`fs.md`） |
| `resources/core/tool-results/unavailable.txt`、`crashed.txt` | 替工具写给她的两句 |

### 对外的样子

都在 crate 里面，不对外。它们交进内核的输入（`kernel/session.md`）：

| 输入 | 带什么 |
|---|---|
| 执行完了 | 调用编号、出没出错、内容块、用时（毫秒，可以没有）、给人看的说法（可以没有）、效果 |
| 执行中的输出 | 调用编号、一段字 |
| 改回了 | 一步一项的结局 |
| 后台命令结束了（施工 7-3） | `job.reported` 的 `by`、`cause`、`body`，交进内核是输入 `JobEnded`，时刻是到 actor 的那一刻 |

交给工具的一次调用（`Call`，`tools/interface.md`）：修正过的参数、这一轮的工作目录、系统的家目录、Miyu 的数据根、她看过的文件、要关进的沙盒（施工 5-4 上）、派子代理的端口（施工 7-5）、任务端口（施工 7-3）。

### 怎么走

**1. 执行一次调用**（动作「执行工具」：调用编号、工具名、修正过的参数、这一轮的工作目录、派出去那一刻实际生效的那一级、这一轮的 `cause`）

1. 照工具名在工具目录里找。目录是核心起来时登记的；工具面是造会话时冻结在快照里的：核心升级拿掉了一件，老会话里她照样会调它。
2. 目录里没有：不派。记一行 `WARN` `unavailable`（`call`、`tool`），当场交回一条出错的结果：一段字是 `unavailable.txt` 换进工具名，说法 `core/tool-results/unavailable`（字段 `name`），没有用时，没有效果。
3. 有：记一行 `INFO` `running`（`call`、`tool`），交给它这一刻的 `Call`：她看过的是这一刻的那一份，之后变了，它拿着的不变。沙盒照下面第 1a 条写，每件工具都带，只有 `shell` 用它。任务端口照这次调用造一个（第 5 条），每件工具都带，只有 `shell` 用它（施工 7-3）。
4. 在它自己的任务里跑，带着会话的 span，马上往下走，不等。内核一起派的几件（例如几件只读的）各跑各的，不排队；派几件由内核定（`kernel/session.md`）。
5. 执行中的输出：一段段送回 actor，这次调用还在跑的，才交进内核（推给头，不落盘）。
6. 跑完了：先在阻塞线程里把效果存成 blob（第 2 条），再送回 actor。看着它的任务、存 blob 的阻塞线程都带着会话的 span，存不进去的那一行有会话编号（施工 4-9 再补四上）。送回来时它还在跑的：先记下她看过的（第 3 条），记一行 `INFO` `ran`（`call`、`took_ms`，出错的多一格 `error=true`，停在改之前的多一格 `stopped=true`），交进内核：出没出错、内容块、说法、效果、停在改之前没有，用时是从派出去到 actor 收到的毫秒数。
7. 工具 panic 了，或者存效果的那个线程 panic 了：记一行 `ERROR` `crashed`（`call`、`tool`、`took_ms`），交回一条出错的结果：一段字是 `crashed.txt` 换进工具名，说法 `core/tool-results/crashed`（字段 `name`），有用时，没有效果。会话照常往下走。
8. 叫停一次调用有两种：
   1. 「叫它停」（`StopTool`）：举起这次调用的旗（`Call.stop`），不掐任务；工具看旗，停在改之前或者做完，照常送回（第 6 条），停在改之前的带 `stopped`。
   2. 「掐掉」（`CancelTool`）：掐掉它的任务，记一行 `INFO` `stopped`（`call`、`took_ms`）。之后什么都不再报：还到的输出、结果、效果都丢掉，内核本来也不理了。掐掉的是叫它停过、还没交回来的写（等满了 10 秒，或者又打断了一次、要重启了），多记一行 `WARN` `cancelled while stopping`（`call`）：它要是后来写完了，这次改动不留效果。
   3. 不在跑的，什么都不做。
9. 会话停了（actor 退出）：在跑的全掐掉。
10. 「掐掉」就是丢掉工具的 future，旗跟着举起来；「叫它停」只举旗。阻塞线程里的活，各件工具自己看旗（`tools/interface.md`）。

替工具写给她的两句，字段照模板转义（`kernel/request.md`），行尾带着文件里的换行：

```text
The tool "{name}" is not available right now.
The tool "{name}" stopped because of an internal error. It may have been partly done.
```

**1a. 一次调用带的沙盒**（`crates/miyu-session/src/sandbox.rs`，施工 5-4 上；`sandbox.md`、`11-权限与沙盒.md` 第四节）

1. 这台机器上的沙盒用不了（核心起来时没探到手段，`core.md`）：不带。执行命令在这之前已经问过人了（`session/guard.md`）。
2. 实际生效的那一级（和权限策略同一个算法：只读开关开着是只读；级别不认识的按只读）：
   - 完全放开：不带。
   - 工作区：能写这一轮的工作目录、加进来的目录（施工 5-10 上）、临时目录；藏数据根。
   - 只读：哪儿都不能写（`/dev/null` 助手总放）；藏数据根。
3. 工作目录、加进来的目录照权限策略的办法换成真实的位置（`~` 接家目录）；换不成的照原样。数据根、临时目录也换成真实的位置。
4. 数据根落在临时目录里（测试、`MIYU_HOME` 指到那里）：藏起来的落在能写的里面，Linux 上挖不了洞，助手会拒绝。这时不放整个临时目录，改放沙盒自己的一个：数据根旁边的 `<数据根>-sandbox-tmp`，环境变量 `TMPDIR` 指过去（`Sandboxed.env`）。
   - 放在数据根旁边，不放在临时目录下面：测试的场地删掉时一起删，也不和别的用户在共用的临时目录里抢名字。
   - 没有就建，只给本人（0700）。已经有的，要是目录、不是链接、和数据根同一个属主、组和别人一点权限都没有；Windows 上只看是不是目录（临时目录在本人的用户目录里）。
5. 工具链的缓存用沙盒自己的一份（施工 5-4 下，`11-权限与沙盒.md` 第四节）：只在工作区这一级。造会话、载入时交进来了沙盒的缓存（`<缓存目录>/sandbox/<属主>`，`core.md`）的，多放它能写，没有就建（只给本人，和第 4 条一样查），再照白名单之后设五个环境变量（`Sandboxed.env`，同名的盖掉）：

   | 变量 | 值 |
   |---|---|
   | `CARGO_HOME` | `<沙盒的缓存>/cargo` |
   | `npm_config_cache` | `<沙盒的缓存>/npm` |
   | `PIP_CACHE_DIR` | `<沙盒的缓存>/pip` |
   | `GOMODCACHE` | `<沙盒的缓存>/go/mod` |
   | `GOCACHE` | `<沙盒的缓存>/go/build` |

   - cargo 的全局配置带过去：你的 cargo 目录（核心的环境里 `CARGO_HOME` 设了、不是空的照它，不然 `~/.cargo`）里有 `config.toml` 的，`<沙盒的缓存>/cargo/config.toml` 是指到它的链接，没有就建上、指错了的换掉；没有的不建。`credentials.toml` 不带：里面是发布用的令牌。
   - 只读这一级不设：哪儿都写不了，照你原来的缓存读。完全放开不进沙盒。没交进来沙盒的缓存的（核心算不出缓存目录、测试）：不放、不设。
6. 在阻塞线程里算，在跑这次调用的任务里：换真实的位置、建目录、建链接都碰磁盘。
7. 写不成（沙盒自己的临时目录、缓存建不成，或者有了却不是只给本人的）：不跑，不会不经沙盒就跑。记一行 `ERROR` `sandbox not set up`（`call`、`error`），再照工具崩了交回（第 1 条第 7 步）。

**1b. 派子代理**（`crates/miyu-session/src/agents.rs`，施工 7-5；`agents.md` 第一条）

1. 任务编号：一个会话一份（`JobIds`），造会话、载入以后照内核的 `last_job_number()`（日志里用过的最大编号，撤掉的、不认识的种类也算，没有是 0）往下数。几次调用一起跑的，各领各的，不重不漏。领了没派成的不回收；载入以后照日志里记下的数，没记下的那几个号没人用过，照样可以再发。
2. 一个会话一份要照抄的（`Agents`）：会话表交进来的端口 `SessionPort`，这个会话的编号、属主、场所、第几层（主会话是 0），快照里有没有人能确认。造会话时照交进来的；载入时属主照交进来的，场所、第几层照 `session.created`，能不能确认照快照。会话表没交端口的（测试里自己造的会话），没有这一份，每次调用的 `agents` 是空的。
3. 每一次调用（第 1 条第 3 步）照这一轮的工作目录、加进来的目录、派出去那一刻实际的权限造一个端口交给工具。
4. 工具调它 `spawn(description, prompt)`：
   1. 领一个编号。
   2. 交给会话表造子会话（`Child`）：父会话和第几层（这个会话的加一），命令编号 `<父会话>/<编号>`，人格软件工程师，属主、场所、能不能确认照这一份，权限、工作目录、加进来的目录照这一次调用的。造不成：记一行 `WARN` `subagent not created`（`job`、`error`），交回派不了。
   3. 把交代作为父会话发来的话（`by` 是这个会话，命令编号 `<父会话>/<编号>/prompt`）经会话表发给子会话，原样一块字。回应不是接受（被拒、子会话停了、核心正在停）：记一行 `WARN` `subagent not given its task`（`job`、`child`、`error`，被拒的写 `the task was refused: <原因码>`），交回派不了；子会话留着，是空的。
   4. 记一行 `INFO` `subagent started`（`job`、`child`），交回编号和子会话的编号。
5. 标题、交代的字一个都不进运行日志。

**会话表那一头**（`crates/miyu-endpoint/src/spawn.rs`、`sessions.rs`）：造会话、载入时交给会话一份端口，拿着核心的弱引用（会话由会话表拿着，再强拿着核心就成了环）；核心没了的说 `the core is shutting down`。造子会话照交来的填：`by` 是父会话，`oneshot` 是假的，时区是核心所在机器这一刻的，模型、工具目录、家目录、沙盒照核心的，沙盒的缓存照属主；造好了放进会话表，工作目录记成交来的那一个（父会话这一轮实际干活的，已经定过宽不宽）。发命令照会话表找会话（没在跑的先载入），停了的从表里拿掉。

**工具面**（`crates/miyu-session/src/open.rs`）：造会话时，只有本机（场所 `local`）、还没到深度上限（`jobs.depth`，第几层小于它）的会话，工具面里有 `agent`；别的拿掉它，别的工具照给。子会话（带着父会话）的 system 在人设后面接上场所说明（`policy.md`「拼」）。

**2. 效果存成 blob**（跑完、交进内核之前，在阻塞线程里）

| 工具报的 | 记进 `tool.result` 的 `effects` |
|---|---|
| 读了：路径、第几行到第几行、整份文件的内容哈希 | `file.read`：照原样 |
| 改了：路径、改前的内容（新建的没有）、改后的内容 | `file.changed`：改前、改后各存成属主的 blob，换成哈希；新建的改前是空的 |
| 移进了回收站：路径、回收站里的位置 | `file.trashed`：照原样 |
| 派出去一个任务（施工 7-5） | `job.started`：照原样 |

- 路径都是换成真实位置以后的，写成字；不是 UTF-8 的地方换成 `�`。
- 存不成的（磁盘满了之类）：照样算出哈希记下，记一行 `WARN` `effect content not stored`（`error`）。撤销时发现 blob 没有，这一步记 `unsaved`（第 4 条）。
- 先落 blob，再写引用它的事件（`store.md`）。
- 工具交回的图片（施工 4-13）：同一个阻塞线程里存成属主的 blob，换成图片块（`blob`、`media_type`、`width`、`height`），照先后接在内容块后面。存不成的：这次调用照崩了算（第 7 条），记一行 `ERROR` `image not stored`（`error`）：少了字节的图，以后每次请求都发不出去。

**3. 她看过的**

每个文件（换成真实位置以后的路径）她最后一次看到的内容哈希。交给每一次调用，写的工具改一个已经在了的文件之前照它核对（`tools/write.md`、`tools/edit.md`）。照效果的先后记，后来的盖掉前面的：

| 效果 | 她看过的 |
|---|---|
| `file.read` | 这个文件记成读的时候整份的哈希：读了哪一段都算 |
| `file.changed` | 记成改后的哈希 |
| `file.trashed` | 拿掉这个文件 |
| 不认识的 | 不动 |

1. 会话里：工具跑完送回来，交进内核之前记下。
2. 载入时：从日志里重建（`session/actor.md` 第 2 条）。先照先后过一遍全部事件，找出现在还撤着的回合：`turn.reverted` 撤掉的加进来，`turn.unreverted` 放回的拿出去；再照先后过每一条 `tool.result` 的效果，属于还撤着的回合的不算。
3. 撤销、恢复落了盘：照日志重算一遍，用的是载入时的同一个函数（`session/actor.md` 第 5 条）。撤掉的那几轮里她读过、改过的不再算，恢复以后又算。

**4. 改回文件**（动作「改回文件」）

1. 内核照撤掉、恢复的那几轮的效果算出几步（`kernel/history.md`）。actor 当场在阻塞线程里照先后一步步做完，等着，不收收件箱；做完把每一步的结局交回内核，记成一条 `files.restored`。
2. 每一步先看原处现在是什么样，不跟最后一层的链接：什么都没有；一个文件（读出来算哈希）；别的（目录、链接）。看不了（例如没有权限）的，这一步 `failed`。只要有东西就行的（移进回收站、原处该是「有东西就行」），不读内容：读不了的文件照样算有东西。
3. 一步没做成，不耽误后面的。

| 这一步 | 怎么走 |
|---|---|
| 写回（`write`：要写回的内容，原处该是什么样） | 原处已经是要写回的内容：算改回了，不重写。不然核对原处；从属主的 blob 取要写回的内容，没有、坏了的 `unsaved`，读不了的 `failed`；上级目录没了的建上，整份写回（先写临时文件、同步，再改名盖上去；原来是只读的不写，`fs.md` 的 `replace`） |
| 移进回收站（`trash`：原处该是什么样） | 原处什么都没有：`missing`。不然核对原处，移进系统的回收站：成了，记下它在回收站里的新位置；这块盘上没有能放的回收站 `unavailable`，不删；挪了却在回收站里找不到 `gone`；出错 `failed`（`fs.md` 的 `trash`）。家目录的回收站照交给工具的那个家目录找 |
| 移回来（`untrash`：在回收站里的位置） | 原处不是空的：`occupied`。回收站里的那个位置没有了：`gone`，看不了的 `failed`。移回来：上级目录没了的建上，改名移回原处，再删掉回收站给它记的那一份；移回来的是一个文件的，记下它的哈希。移回来了、哈希算不出来的（例如读不了），照样是 `restored`，不附哈希 |

核对原处：

| 该是什么样 | 原处现在是 | 结局 |
|---|---|---|
| 空着 | 什么都没有 | 往下做 |
| 空着 | 有东西 | `occupied` |
| 一个文件，内容是这个哈希 | 什么都没有 | `missing` |
| 同上 | 这个哈希的文件 | 往下做 |
| 同上 | 别的内容的文件 | `changed`，附上现在的哈希 |
| 同上 | 目录、链接 | `changed`，不附哈希 |
| 有东西就行（撤销时移回来的是目录，没记哈希） | 什么都没有 | `missing` |
| 有东西就行 | 有东西 | 往下做 |

每一步的结局记下：照哪一条 `tool.result`（序号）的第几个效果（从 0 数起）、路径、做了什么（`write`、`trash`、`untrash`）、结局，和下面几样附项。

| 结局 | 什么时候 | 附项 |
|---|---|---|
| `restored` | 做成了；或者原处已经是要写回的内容 | 移进回收站的，`trash` 是新位置；移回来的是文件的，`hash` 是它的哈希 |
| `changed` | 原处的内容不是她留下的样子 | `found`：现在的哈希（是文件的才有） |
| `missing` | 东西没了 | |
| `occupied` | 原处被占了 | |
| `gone` | 回收站里没有了 | |
| `unsaved` | 要写回的内容当时没存下来 | |

- 核对和动手之间，原处被别的程序占了的，移回来的改名会盖掉它：标准库没有「不盖」的改名（`fs.md`）。

**5. 后台命令**（施工 7-3，`agents.md` 第四条、第八条）

执行器的任务表 `Jobs`：核心里一张，所有会话共用，核心看它空不空闲（`core.md`「停下」）。一个会话 actor 一份 `SessionJobs`，actor 造好时建：任务编号从内核照日志算的用过的最大编号（`Session::last_job_number`，撤掉的回合里用过的也算，`kernel/session.md`）往后数，一个 actor 一个 `JobIds`，工具并行跑时各自领、领到的不一样。表里一项的钥匙是「哪个 actor 的哪个编号」：同一个会话停了又载入，前一个 actor 起的命令还没死透时编号可能重，actor 不会。

1. **收下**（任务端口的 `start`）：领一个编号；在会话目录下建 `jobs/<编号>.out`（没有 `jobs/` 的先建，Unix 上 0700；已经有的清空，`store.md`）；拿着表的锁看 actor 还在不在，在的登记进表（进程、输出文件、交来的那一刻、还没报结束）。建不起来、actor 已经停了的：整组杀掉它，另起一个线程等它（免得留下没人收的僵尸进程），交回出错。收下了起两个线程，都带着派活时的 span：
   - 读输出的线程：一段段写进输出文件，不截。写不进去（磁盘满了之类）记一行 `WARN` `job output not written`，关上文件，之后照读不写：不让命令卡在写满的管道上。
   - 等它结束的线程：等到了，读输出的线程最多再等 0.5 秒（还有东西拿着管道的不等它，记一行 `DEBUG` `job output still open after the command ended`），关上输出文件（之后读到的不再写），整份读出来存成属主的 blob、数有多少个字（读不出来、存不下来的记一行 `WARN` `job output not stored`，两样都不写）。写好 `job.reported`：`exited`，退出码或者信号，用时是从收下到等到的毫秒数，输出、字数；`by` 是起它的那次调用，`cause` 是那一轮的（`kernel/session.md`「回报」第 2 条）。等不了（系统报错）的记一行 `WARN` `job not waited`，退出码、信号都不写。
2. **报给 actor**：拿着表的锁看：还在表里、还没人报过的，记成报了，送进 actor 的收件箱（`Back::Job`）；已经报了（停下时报了 `restarted`）、不在表里的，什么都不做。actor 已经停了、送不进去的，从表里拿掉。拿着锁送，是为了停下时拿到锁的那一刻，自己报了的都已经在收件箱里了。
3. **落了盘才拿掉**：actor 把它写成输入 `JobEnded` 交进内核（时刻是到的那一刻），这一批落了盘才从表里拿掉。表空了，结束的记录一定都落了盘：核心看表空闲退出，不会丢了记录。
4. **有计划地停下**（`session/actor.md` 第 9 条）：拿着表的锁，把这个会话还没报过结束的记成报了（之后它们自己退出了也不再报），在阻塞线程里关上输出文件、整份存成 blob，各写一条 `job.reported`：`restarted`，`by` 是内核，没有 `cause`，用时是到这时的，输出是到这时的，没有退出码、信号（这时还没杀）。在这以前自己退出、已经报了的，照常从收件箱里拿出来一起交。这些都落了盘，才把这个会话还在表里的都拿掉、整组杀掉（阻塞线程里杀：Windows 上要等 `taskkill`），不再收新的。
5. **actor 因为别的停了**（写不进去、panic、没人拿着了）：丢掉它那一份时，不再收新的，这个会话还在表里的都拿掉、关上输出、整组杀掉，不记：再载入时内核补 `aborted`（`kernel/session.md`「载入和崩溃」）。
6. 整组杀照 `tools/shell.md`「后台」第 7 条：已经结束了的不再按编号杀。
