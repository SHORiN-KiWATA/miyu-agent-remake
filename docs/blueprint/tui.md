## 终端界面（演示）

状态：和后端并行做的演示，在分支 `proto/tui-demo` 的 `tui-demo/` 里，不进工作区、门禁不查它。这一页写它现在的样子；和设计 `13-终端界面.md` 对不上的，列在最后一节等拍板。

### 是什么

全屏的终端界面：底下一个圆角输入框，连上核心跟她说话；她的思考和调的工具排成时间线，说话就收起；框下面一行是权限级别、模型和用量。

### 在哪

| 代码 | 管什么 |
|---|---|
| `tui-demo/src/main.rs` | 进出全屏；主循环：终端事件和核心的消息进同一个通道，空闲不重画 |
| `tui-demo/src/app/` | 程序状态：`mod.rs` 状态、事件分给各块、核心的消息；`keys.rs` 按键和斜杠命令的执行；`mouse.rs` 鼠标；`drawer.rs` 抽屉接到程序上（按键、收起、了结） |

| `tui-demo/src/diff.rs` | 编辑、写入的差异：照工具调用的参数比、排成行 |

### 对外的样子

**环境变量**：变量写在命令前面，不 `export`。

| 变量 | 做什么 |
|---|---|
| `MIYU_HOME` | 数据根，照 `store.md` |
| `MIYU_RESOURCES` | 资源目录：读工具的显示名（`resources/software/basesystem/human/zh.json`） |
| `MIYU_CORE_BIN` | 核心没在跑时，拿它拉起来（加上 `core`）。只认它，不去 `PATH` 里找 `miyu`：装着旧版的机器上那是旧版 |
| `DEEPSEEK_API_KEY` | 拉起来的核心继承它 |
| `MIYU_COLOR` | 手动压色深：`truecolor`、`256`、`16`、`none`（见「主题」第 5 条） |
| `NO_COLOR` | 有值就不上色，只留加粗、斜体这些修饰（跨工具的约定，比 `MIYU_COLOR` 优先） |
| `MIYU_TUI_FRAME_LOG` | 量性能用（设计 23「量界面」，2026-10-01 性能体检加的）：给一个文件路径，每画一帧往里追加一行 `距启动的毫秒 准备的微秒 整帧的微秒`。准备是排版、画进缓冲区、宽字清格、换色；整帧再加上比对、写给终端、光标和指针。整帧超过 `slow_frame_ms`（`layout.json`，8 毫秒）的，后面接着写各块各花了多少微秒（`body=…`、`rows=…`、`sidebar=…` 这样，正文、排行、画图、输入框、底栏、侧边栏、运行状态行、`@` 列表），好找慢在哪（2026-10-01 性能体检：release 版流式时偶尔一帧二三十毫秒，当场没找到，加了这个以后又量五次，最慢 12 毫秒，花在一轮结束时的排行和侧边栏）。不给就什么都不记，也不计时 |

**按键**

| 键 | 做什么 |
|---|---|
| `Enter` | 发出去；只有空白的不发。是斜杠命令的执行它 |
| `Shift+Enter`、`Alt+Enter`、`Ctrl+J` | 换行（`Shift+Enter` 要终端认得 kitty 键盘协议）；列表开着时 `Ctrl+J` 是往下选（见下面） |
| 方向键、`Home`、`End` | 移动光标；按着 `Shift` 扩选区；上下移动记着原来的列 |
| `Ctrl+←`、`Ctrl+→` | 按词跳（按着 `Shift` 扩选区）。词是连在一起的一串字母、数字、汉字；连着的一串标点（`--`、`::`、`，`）也算一个；空白不算。所以一串中文到空白或标点为止算一个词（像终端的 `Ctrl+W` 删到空白为止）；不按词义切中文 |
| `Ctrl+W`、`Alt+Backspace` | 删掉光标前的一个词（和 `Ctrl+←` 同一套），连同它后面的空白 |
| `↑`、`↓` | 在第一行按 `↑`、在最后一行按 `↓`：翻输入历史（这次启动以来发过的话和命令，从新到旧；`Ctrl+C` 刚清掉的那一句排在最前面，见 `Ctrl+C`）；翻到最新再按 `↓`，回到翻之前没发的那句。翻出来的那句还没改过时，不弹命令列表、`@` 文件列表，`↑` `↓` 接着翻；改了一个字就照常弹，直接回车照常发出去、执行命令（2026-10-01 项目主人报：往上翻得动、往下翻不回来。查出来是翻到记着的 `/language` 这类命令，框里的字像在打命令，命令列表弹出来把 `↑` `↓` 拿去选命令了；以 `@词` 结尾的话翻出来会弹文件列表，一样） |
| `PgUp`、`PgDn` | 正文往上、往下翻半屏；翻到底又跟着最新的 |
| `Ctrl+L` | 清屏：把正文的视口顶空，往回滚内容还在（照旧版）。清过以后，最底下就是清屏那一刻的位置：往下滚还是空的，往上滚看得到之前的，滚回底又是空的；新的字从空着的视口顶上往下长，运行状态行那一块长出来、视口变矮时也不往上顶（新的字还放得下时照旧从顶上排，放不下了才贴着底边走）。回答进行中不清，提示「回答进行中不清屏」：顶空了下一帧新的字又冒出来 |
| `Tab`、`Shift+Tab` | 轮换权限级别：工作区 → 开放权限 → 只读 → 工作区（告诉核心，见「权限级别」第 2 条）。`Tab` 是 2026-09-29 项目主人加的，`Shift+Tab` 留着；命令列表开着时 `Tab` 照旧补全命令，`@` 文件列表开着时进目录（「`@` 文件列表」第 5 条），历史列表开着时照旧展开 |
| `Ctrl+A` | 光标回到输入框开头（多行的回到第一行开头），选区取消（2026-09-30 项目主人改：原来是全选，照终端的习惯该是回到开头） |
| `Ctrl+C`、`Ctrl+Shift+C` | `Ctrl+Shift+C` 在 kitty、GNOME Terminal、Konsole 里默认被终端拿去复制它自己的选区，传不到程序；kitty 在 `kitty.conf` 里写 `map ctrl+shift+c copy_or_noop`（kitty 自己没有选区时把按键交给程序）。分级：有选区复制（正文的选区优先，其次输入框的）；输入框有字，清空：清掉的那句连同块、附件单独留最近一份，不进输入历史（2026-09-30 项目主人：误按 Ctrl+C，辛苦打的字全没了；进历史的话每清一次都污染历史列表），弹「已清空 · ↑ 找回」；空着、没在翻历史时按 `↑` 先拿回它，再按才进历史；发出去一句话（命令不算）、再清一次，这一份就换掉；在回答时，打断，排着队的消息回到输入框；这一轮是排着的话开的（上一轮答完，核心接着拿排着的开了这一轮）、她还没开口（没说字、没做步，只在想的也算没开口）的，那几句这时已经发给模型、核心不退回，界面打断以后等这一轮结束接着撤掉它，那几句照排着时的样子回到输入框（一句一段，中间空一行），正文里留一行「↶ 已撤销」（2026-09-30 项目主人：排着的话一转眼成了新一轮，按 Ctrl+C 时以为还排着，结果没回来；定只退回排着的，你直接发的那句开的一轮不退；她已经开口的照旧不退，要退得连她说了一半的、做了的一起撤，我定的）；空着时不退出，提示「按 Ctrl+D 退出」 |
| `Ctrl+D` | 输入框空着时退出 |
| `Ctrl+S` | 暂存：输入框有字，存起来、清空；空着，取回来；两边都有，互换。存着东西时，输入框第一行最右边暗色写「> 暂存」。和 `Ctrl+C` 清掉的那一份不重复（2026-09-30 项目主人问过，定两个都留）：这个是有意放一边，看得见，发别的话也留着；那个是误操作的保险，看不见，发一句话就丢 |
| `Ctrl+V` | 读系统剪贴板里的字，照粘贴处理：大段的收成一块（「输入框」第 11 条）；抽屉里写字时接进写的字，历史列表开着时进「历史：」后面（2026-09-29 项目主人：粘贴该是 `Ctrl+V`）。按平台依次试：Linux 有 Wayland 的先 `wl-paste`，再 `xclip`、`xsel`；macOS `pbpaste`；Windows PowerShell 的 `Get-Clipboard`；每个最多等 1 秒。都读不到提示「读不到剪贴板：用终端自己的粘贴（kitty 是 Ctrl+Shift+V）」，空的提示「剪贴板是空的」。经 SSH 连过来时读的是那台机器的剪贴板，要粘手边的东西用终端自己的粘贴。只读字，图片以后再说 |
| `Ctrl+R` | 调出输入历史列表（见「输入历史列表」）；开着时再按往更早的走。恢复撤销只用 `/restore`（2026-09-29 项目主人改：原来照 opencode 是恢复撤销） |
| `Ctrl+Z` | 挂起到后台，回 shell；`fg` 回来接着用（Linux、macOS；Windows 没有作业控制，不做事）。挂起前把终端还原（鼠标、粘贴、键盘协议、指针样子、原始模式、全屏都退掉），给自己发 `SIGTSTP`；回来以后重新进全屏、整屏重画，正文里的图重新传一遍（终端离开全屏时可能把传过的图丢了）。核心在自己的进程组里，不跟着停，回答照常在后台往下走 |
| `Esc` | 由近及远：列表（命令列表、输入历史列表）、后台面板开着的关掉它，焦点在输入框下面的按钮、子代理状态行上的回到输入框，抽屉开着的归抽屉；选中了字（正文或输入框）取消选区；（2026-09-29 修：输入框里有字时，这几样的 Esc 被当成「清空输入框」的第一下，关不掉输入历史列表）在回答时，第一下提示「再按一次 Esc 打断」，1.5 秒内再按一下才打断，排着队的消息接着发；没在回答、输入框有字时，第一下提示「再按一次 Esc 清空」，再按一下清空 |

### 怎么走

**连核心**（照 `cli/ask.md`「怎么走」）

1. 先画后连：界面先画出来，连核心在另一个线程里跑；连上之前发的话排着，连上再发。

**编辑、写入点开的差异**（设计稿「编辑文件的输出」）

头只经协议和核心说话，不读核心的存储（`01-架构.md` 第五节第 1 条），所以差异照工具调用的参数画：

1. 写入：参数 `content` 就是写进去的全部，每一行都是加上的，带行号（从 1 起）。
2. 编辑：参数 `edits` 的每一处，`old_string` 的每一行是删掉的、`new_string` 的每一行是加上的，按行比，没变的行照样写；不写行号（不知道在文件的第几行），行号那一格空着。两处之间一行 `⋯`。
3. 一行：`行号  标记 内容`。行号右对齐，宽度照最大的行号；没有行号的，那一格是空的。
4. 删掉的：标记 `-`，浅红字、暗紫红底；加上的：标记 `+`，浅绿字、暗蓝底；底色只铺到字的末尾（照旧版的配色）。不变的：暗色，标记是空格。
5. 标题后面的 `+N -N` 照同一份差异数。

**输入框**

### 主题

2026-09-29 项目主人定：头里放主题文件，默认 tokyonight night。

1. 一套主题一个文件：`tui-demo/resources/themes/<名字>.json`，一个语义色一格。值有四种写法：`#rrggbb` 真彩色；`idx:N` 256 色的第 N 号；`red`、`darkgray` 这类终端调色板的 16 色名；`default` 终端自己的前景色。背景不画，用终端自己的。
2. 出厂两套：`tokyonight-night`（默认），`terminal`（全用终端调色板，跟着终端的配色走）。
3. 用哪套：`layout.json` 的 `theme`；`/theme` 命令在几套之间轮换，只管这一次启动，提示「主题：名字」。换了以后已经排好的回答也照新颜色重排（排版缓存的键里带着换过几次主题）。
4. 加粗、斜体、变暗这些修饰写在代码里，颜色都从主题来；上面「样子」一节的颜色表写的是语义，具体颜色看主题文件。
5. 色深（2026-09-29，技术上的取舍，照旧版 `terminal/palette.rs` 的探测）：启动时看一次。`NO_COLOR` 有值，不上色；`MIYU_COLOR` 手动压（`truecolor`、`256`、`16`、`none`，写错的当 256）；`COLORTERM` 是 `truecolor` 或 `24bit`，真彩色；`TERM` 空或 `dumb`，不上色；`TERM` 里有 `kitty`、`wezterm`、`alacritty`、`ghostty`、`foot`，或 `TERM_PROGRAM` 是 `iTerm.app`、`WezTerm`、`ghostty`、`vscode`，真彩色（没设 `COLORTERM` 的也是）；`TERM` 里有 `256color`，256 色（macOS 自带的「终端」是这一档）；别的 16 色。
6. 画完一帧、交给终端之前统一换色，主题、流光、吉祥物、Markdown 都在这一处换，各处画的时候不管色深：真彩色原样；256 色把 `#rrggbb` 换成 256 色里最近的（6×6×6 色立方、24 级灰阶各找最近的一个，取更近的，照 tmux）；16 色把 `#rrggbb` 和 16 号以后的 256 色换成 16 色里最近的（照 VGA 那一套、也就是 Linux 控制台的默认色算距离：xterm 默认的红是纯红，粉红的出错色照它算会落到暗灰），写成 16 色的名字（`SGR 31` 这类，认不得 256 色写法的终端也认）；不上色把前景、背景都换成终端自己的，加粗、斜体、下划线照留。图占着的格子不换色：kitty 靠这些格子的前景色认是哪张图，换了就找不到图，只剩留出来的空白。显示得了图的终端虽然都是真彩色，但设了 `MIYU_COLOR`、`NO_COLOR` 的照样压色深（2026-09-30 项目主人照验收命令带着 `MIYU_COLOR=256` 开，图的位置全是空的）。

### 图标

2026-09-29 项目主人定：图标成套，可配置、可切换；以后第一次启动时展示 Nerd Font 的图标，看着不正常就选普通字符那一套。

1. 一套图标一个文件：`tui-demo/resources/icons/<名字>.json`，写每件工具的图标（`tools`，没登记的用 `tool`）、思考的 `think`、出错顶替图标的叉 `error`、暂存着东西时的提示符 `stash`（连同它后面的空格）。时间线的图标、输入框暂存时的提示符都只从当前这一套取，代码里不写图标。
2. 出厂两套：`nerd`（默认，Nerd Font 的字形：执行命令 `$`，编辑和写入铅笔，删除垃圾桶，读文档，找文件和搜内容放大镜，翻历史记录（`history`）钟表倒转的历史图标（`U+F1DA`，2026-09-30 项目主人要给它配一个，我挑的和上面同是 Font Awesome 那一族），派子代理（`subagent`，2026-10-01 核心改名，旧名 `agent` 不认）机器人（`U+EE0D`，同一天项目主人选的），任务（`jobs`）清单（`U+F0AE`）、留言（`send_message`，C-5 改名，旧名 `message_agent` 不认）对话框（`U+F0E5`）（同一天项目主人要给它们配，我挑的，同是 Font Awesome 那一族），列会话（`sessions`，核心 C-3 加的）列表（`U+F03A`，同一族，我挑的；核心给网页的符号是 `≡`，普通字符那一套照下面的规矩不另给），没登记的扳手（`U+F0AD`；2026-09-30 项目主人看过对比页选的：原来是芯片），思考 `\u{f0768}`，出错叉，暂存软盘）；`plain`（普通字符，没装 Nerd Font 也显示得出来：执行命令 `$`，别的工具一律 `⚙`，思考 `✳`，出错 `✗`，暂存 `▤`）。普通字符那一套照设计 13 第三节第 9 条不凑：从不同字表凑来的符号粗细、基线、留白各不相同，排在时间线那一列里参差不齐（旧版的教训），所以不给每件工具找一个像的，只留一眼认得出的几个；以后有了提问的工具，它在这一套里写 `?`（设计 13 的三个符号）。

### 配置与模型（M8，2026-10-01 项目主人定了样子，协议合进来再接）

协议照 `docs/blueprint/config.md`、`models.md`（施工会话定稿）。样子（对比页上逐处定的）：

1. `/model`：在输入框上面开一个框，和 `/language`、`/help` 一个位置、一个样子，开框时向核心要一次 `model.list`（交回来以前写「正在读模型…」）。一行一个挡位、池或模型，照这个先后：配了的挡位（`standard → dev/模型名`，没配的不列；2026-10-01 项目主人定去掉挡位、只留有名字的池，核心改完以后这一类行去掉）、池（`@duo · pin · 2 个成员`）、模型（显示名，没有的写模型名；暗色（`dim`，2026-10-01 项目主人嫌 `faint` 太暗；没有 key 的那行才 `faint`）写引用、窗口：`dev/cline-pass/deepseek-v4.1-flash · 300k`——同一个显示名常有好几个（配置里写的、目录里自带的、几家供应商都有），只写供应商分不出来，2026-10-01 实测）。右边写「当前」（照会话现在用的引用比）、冷却中的「冷却 2m」（黄，照 `until` 算）、没有 key 的暗着写「没有 key」；后两种选了也不换，提示为什么。打字筛（名字、引用）；最多露 `layout.json` 的 `session_rows` 行，滚着看，和会话列表一样。`Enter` 交给核心换（`session.configure`，核心 8-10，下一个回合开始生效），关框，提示「下一轮起用 …」（一般的提示框，不是绿框：2026-10-01 项目主人），底栏当场写成选的那个；`/new` 以后还没开会话时记着，开会话时带上（`session.create` 的 `model`）。`Esc` 关。
2. 换了模型：自己用 `/model` 换的正文里不写（底栏当场就变）；出错自动换到别的端点（`model.changed` 的 `why` 是 `failover`，核心 8-9：钉住的池换到别的成员、而且成了才推，瞬时的、不落盘）写一行暗色的「↻ 换了模型：原来的 → 换成的」（端点/模型），下一行写为什么：照换之前最近一次出错的分类（`error_classes`，例如「被限速了」），没记着的不写这一行。底栏的模型、限额照它当场换。和切权限不画一行是一个道理。
3. 第一次启动、没有可用模型的引导：等以后做 OOBE 时一起做（Nerd Font 图标那一条也在那时）。现在没有模型时照第 7 条。
4. `/settings`：整屏设置页。左边分页，右边分组列表，每项写名字、现在的值，选中的下面写说明；`/` 搜索；改了经核心写盘（`config.set`）。供应商的地址（`base_url`）可能是环境变量引用（核心 8-6 补：`{"env":"X"}`），照「来自环境变量 X」写，不当字符串显示；密钥只写「已设置 / 未设置」，`Enter` 贴新的值（不回显，`secret.set`），从不显示值（核心 8-5 合进 main `4b72441c`：`secret.set {name,value}`、`secret.delete {name}`、`secret.list` 只交名字、设没设、谁在用；控件类型 `secret`）。项目里的配置不在这里改。
5. 花了多少钱：侧边栏「用量」加一行「花费 $0.42 + ¥1.30」（几种币并排、不换算，照核心算好的；算不出的不写，有没价格的写一行暗色「N 次请求没有价格」）；框下面那一行右边也写金额；另有 `/usage` 开框，按天、按模型列这台机器上的用量和花费（`usage.query`）。
6. 接供应商时的「测一次」（`provider.test`，会真发一个请求、花一点额度）：给两个选项「测试连接」「跳过」，旁边暗色注明会花一点额度。
7. 没有能用的模型、全都在冷却：框下面那一行模型那一格变色（黄）写原因，例如「都在冷却，2 分钟后恢复」。冷却（核心 8-9 的 `error.class` 是 `cooling`）出错时向核心要一次 `model.list`，照冷却着的模型里最早恢复的 `until` 算还要几分钟，每帧照现在的钟重算，到点、或者又有一次请求成了，变回原样；要不到 `until` 的只写「都在冷却」。出错那一行照内核自己查出来的写人话「模型都在冷却」（「正文」第 4 条）。
8. 技术细节照图纸：底栏的模型名开会话时照订阅回应里的 `model`（`{endpoint, model, ref}`，轮换的池只有 `ref`），中途照 `model.changed`（`why` 是 `turn` 的只换底栏、限额，不写；是 `failover` 的照第 2 条）、`session.policy_changed` 的 `model` 换（别的头、命令行换的也跟着变，不写）；`session.policy_changed` 的 `replaced`（钉着的模型没了、退回默认，`by` 是内核）写一行暗色的「↻ 原来的模型没了，换回默认：原来的 → 现在的」。会话现在用的引用记着，`/model` 照它标「当前」（核心 8-10，main `169df271`）。
