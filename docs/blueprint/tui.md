## 终端界面（演示）

状态：和后端并行做的演示，在分支 `proto/tui-demo` 的 `tui-demo/` 里，不进工作区、门禁不查它。这一页写它现在的样子；和设计 `13-终端界面.md` 对不上的，列在最后一节等拍板。

### 是什么

全屏的终端界面：底下一个圆角输入框，连上核心跟她说话；她的思考和调的工具排成时间线，说话就收起；框下面一行是权限级别、模型和用量。

**按键**

| 键 | 做什么 |
|---|---|
| `Enter` | 发出去；只有空白的不发。是斜杠命令的执行它 |

| `Ctrl+W`、`Alt+Backspace` | 删掉光标前的一个词（和 `Ctrl+←` 同一套），连同它后面的空白 |
| `↑`、`↓` | 在第一行按 `↑`、在最后一行按 `↓`：翻输入历史（这次启动以来发过的话和命令，从新到旧）；翻到最新再按 `↓`，回到翻之前没发的那句 |
| `PgUp`、`PgDn` | 正文往上、往下翻半屏；翻到底又跟着最新的 |

| `Ctrl+C`、`Ctrl+Shift+C` | `Ctrl+Shift+C` 在 kitty、GNOME Terminal、Konsole 里默认被终端拿去复制它自己的选区，传不到程序；kitty 在 `kitty.conf` 里写 `map ctrl+shift+c copy_or_noop`（kitty 自己没有选区时把按键交给程序）。分级：有选区复制（正文的选区优先，其次输入框的）；输入框有字，清空；在回答时，打断，排着队的消息回到输入框；空着时不退出，提示「按 Ctrl+D 退出」 |
| `Ctrl+D` | 输入框空着时退出 |
| `Ctrl+S` | 暂存：输入框有字，存起来、清空；空着，取回来；两边都有，互换。存着东西时，输入框第一行最右边暗色写「> 暂存」 |

### 怎么走

**连核心**（照 `cli/ask.md`「怎么走」）

1. 先画后连：界面先画出来，连核心在另一个线程里跑；连上之前发的话排着，连上再发。
2. 找数据根、建骨架；给了 `MIYU_CORE_BIN` 的 `connect_or_start`，没给的只连，核心没在跑就说「核心没在跑」。
3. 握手：`head.kind` 是 `tui`，`locale` 是 `zh-CN`，`caps.input` 是 `false`：还没有确认的抽屉，要确认的那一步核心当场拒绝。
4. `session.create`（`cwd` 是启动时的目录），`subscribe`。
5. 发：`session.send` 带 `cwd`；打断：`session.interrupt`，`queued` 是 `return`；撤销、恢复：等回应，回应里的几样照 `protocol/undo.md` 写成一句旁白。
6. 掉了队（`resync`）重新订阅，掉了的不补；核心断开，左下角说「核心断开了」。

**编辑、写入点开的差异**（设计稿「编辑文件的输出」）

头只经协议和核心说话，不读核心的存储（`01-架构.md` 第五节第 1 条），所以差异照工具调用的参数画：

1. 写入：参数 `content` 就是写进去的全部，每一行都是加上的，带行号（从 1 起）。
2. 编辑：参数 `edits` 的每一处，`old_string` 的每一行是删掉的、`new_string` 的每一行是加上的，按行比，没变的行照样写；不写行号（不知道在文件的第几行），行号那一格空着。两处之间一行 `⋯`。
3. 一行：`行号  标记 内容`。行号右对齐，宽度照最大的行号；没有行号的，那一格是空的。
4. 删掉的：标记 `-`，浅红字、暗紫红底；加上的：标记 `+`，浅绿字、暗蓝底；底色只铺到字的末尾（照旧版的配色）。不变的：暗色，标记是空格。
5. 标题后面的 `+N -N` 照同一份差异数。

5. 鼠标：悬停选中那一条，点了等于 `Enter`。
6. 还没发过话时按 `Ctrl+R`：提示「历史发送为空」，不打开（2026-09-29 项目主人：原来写「还没有发过的话」）。

**每一帧**：用同步输出包起来（设计 13 第九节；`CSI ? 2026 h` 开头、`CSI ? 2026 l` 结尾，终端不认就当没有）。传图的那一帧要写几百 KB，不包的话终端边收边画：会闪一下，光标也会先跳到图那里再跳回输入框。画完、交给终端之前还有两道：宽字后面那一格清成空白（ratatui 比对两帧时认定宽字后面那格是空的，不空的话宽字被盖掉时只重写前半格，终端上留下半格空白或残色；`Paragraph` 画宽字不清后面那格，列表、面板盖在别的东西上就会这样，2026-09-29 在 30×7 的窗口里实测到输入框上边框断成几截），再照色深换色（「主题」第 5、6 条）。

**框下面那一行**：左边权限级别和模型，右边用量；还是 0 的格子不写（上下文、累计都是 0 时右边整段空着，2026-09-29 项目主人：全是 0 没必要显示）；左右至少空两列，不叠在一起。放不下时右边从后往前丢：先丢速度，再丢累计，上下文留到最后。左边也放不下（窄过 30 列左右）时截掉加 `…`。

**窗口小的时候**（2026-09-29，第 4 项「退化和边界」，技术上的取舍）：
1. 输入框上面的东西（命令列表、历史列表、后台面板）只用输入框上面剩下的行，不盖输入框；放不下时先去掉空行，再去掉最后那行按键提示，再少露几条（选中的那一条一直露着），最后才去掉标题横线。
2. 提示的小框上面放不下（要三行）就不画，不盖输入框。
3. 抽屉矮到放不下全部时，先去掉按键提示上面那一行空行，选项至少留一行（选中的那一项），问题留它的后半截。
4. 时间线收起那一行放不下时，只有一条命令的短标题截掉加 `…`，后面的次数和用时留着；别的整行截掉加 `…`。
5. 收尾行放不下时只在 ` · ` 处折，折下来的一行以 `· ` 打头；一格比一行还宽的截掉加 `…`（原来照字折，把模型名从中间劈开）。

**命中率的写法**（右下角的 `C`、收尾行的 `C` 都照它，2026-09-29 项目主人定）：命中 ÷ 输入，不算输出。99 以下写整数（`94%`）；99 以上带一位小数（`99.6%`），正好 99.0 的写 `99%`；四舍五入到 100.0 的写 `100%`。

### 主题

2026-09-29 项目主人定：头里放主题文件，默认 tokyonight night。

1. 一套主题一个文件：`tui-demo/resources/themes/<名字>.json`，一个语义色一格。值有四种写法：`#rrggbb` 真彩色；`idx:N` 256 色的第 N 号；`red`、`darkgray` 这类终端调色板的 16 色名；`default` 终端自己的前景色。背景不画，用终端自己的。
2. 出厂两套：`tokyonight-night`（默认），`terminal`（全用终端调色板，跟着终端的配色走）。
3. 用哪套：`layout.json` 的 `theme`；`/theme` 命令在几套之间轮换，只管这一次启动，提示「主题：名字」。换了以后已经排好的回答也照新颜色重排（排版缓存的键里带着换过几次主题）。
4. 加粗、斜体、变暗这些修饰写在代码里，颜色都从主题来；上面「样子」一节的颜色表写的是语义，具体颜色看主题文件。
5. 色深（2026-09-29，技术上的取舍，照旧版 `terminal/palette.rs` 的探测）：启动时看一次。`NO_COLOR` 有值，不上色；`MIYU_COLOR` 手动压（`truecolor`、`256`、`16`、`none`，写错的当 256）；`COLORTERM` 是 `truecolor` 或 `24bit`，真彩色；`TERM` 空或 `dumb`，不上色；`TERM` 里有 `kitty`、`wezterm`、`alacritty`、`ghostty`、`foot`，或 `TERM_PROGRAM` 是 `iTerm.app`、`WezTerm`、`ghostty`、`vscode`，真彩色（没设 `COLORTERM` 的也是）；`TERM` 里有 `256color`，256 色（macOS 自带的「终端」是这一档）；别的 16 色。
6. 画完一帧、交给终端之前统一换色，主题、流光、吉祥物、Markdown 都在这一处换，各处画的时候不管色深：真彩色原样；256 色把 `#rrggbb` 换成 256 色里最近的（6×6×6 色立方、24 级灰阶各找最近的一个，取更近的，照 tmux）；16 色把 `#rrggbb` 和 16 号以后的 256 色换成 16 色里最近的（照 VGA 那一套、也就是 Linux 控制台的默认色算距离：xterm 默认的红是纯红，粉红的出错色照它算会落到暗灰），写成 16 色的名字（`SGR 31` 这类，认不得 256 色写法的终端也认）；不上色把前景、背景都换成终端自己的，加粗、斜体、下划线照留。图不换：显示得了图的终端都是真彩色。

### 图标

2026-09-29 项目主人定：图标成套，可配置、可切换；以后第一次启动时展示 Nerd Font 的图标，看着不正常就选普通字符那一套。

1. 一套图标一个文件：`tui-demo/resources/icons/<名字>.json`，写每件工具的图标（`tools`，没登记的用 `tool`）、思考的 `think`、出错顶替图标的叉 `error`、暂存着东西时的提示符 `stash`（连同它后面的空格）。时间线的图标、输入框暂存时的提示符都只从当前这一套取，代码里不写图标。
2. 出厂两套：`nerd`（默认，Nerd Font 的字形：执行命令 `$`，编辑和写入铅笔，删除垃圾桶，读文档，找文件和搜内容放大镜，没登记的芯片，思考 `\u{f0768}`，出错叉，暂存软盘）；`plain`（普通字符，没装 Nerd Font 也显示得出来：执行命令 `$`，别的工具一律 `⚙`，思考 `✳`，出错 `✗`，暂存 `▤`）。普通字符那一套照设计 13 第三节第 9 条不凑：从不同字表凑来的符号粗细、基线、留白各不相同，排在时间线那一列里参差不齐（旧版的教训），所以不给每件工具找一个像的，只留一眼认得出的几个；以后有了提问的工具，它在这一套里写 `?`（设计 13 的三个符号）。
3. 每一套里的图标都只占一格（暂存的提示符连空格两格），换了套时间线那一列照样对齐。
4. 用哪套：`layout.json` 的 `icons`；`/icons` 命令在几套之间轮换，只管这一次启动，提示「图标：名字」。换了以后已经排好的时间线也照新图标重排（排版缓存的指纹里带着图标那一套的名字）。
5. 权限级别的 `▣` `⏵⏵` `⏸`、收尾行的 `✻`、待办的 `☐` `■` `☑`、进度条、列表记号、`<details>` 的 `▶` `▼` 这些是普通 Unicode，不分套。
