## 施工单 0-3（补）：CI 提速

状态：已完成（2026-10-08 写、施工完；CI run 1171 三台和长跑全绿，长跑只跑了那两条；项目主人 2026-10-08 嫌 CI 太长拖慢开发，问怎么办；主会话量了最近三次 CI、提了四条，项目主人照推荐定做 A、B）。

### 量到的（2026-10-08，run 1163、1166、1167）

| 项 | 一次 | 其中编译 | 真跑测试 |
|---|---|---|---|
| 长跑 | 38～41 分钟 | 38 分钟（release 从零编整个工作区） | 不到 2 分钟 |
| Windows | 33～37 分钟 | 门禁的测试那一步 29 分钟，编译、链接约 24 分钟 | 约 5 分钟 |
| ubuntu、macOS | 14～17 分钟 | 约 9 分钟 | 约 2 分钟 |

根因：长跑为两条随机测试编整个工作区；没有编译缓存，每次从零编几百个第三方依赖；集成测试是 286 个单独的测试程序，Windows 上一个个链接最慢。

### 定了的

- **A（项目主人照推荐定）**：长跑只编有长跑测试的两个 crate（`miyu-kernel`、`miyu-assemble`），只跑名字以 `for_longer` 结尾的（`cargo test --release -p miyu-kernel -p miyu-assemble -- --ignored for_longer`）。别的 `#[ignore]` 是量尺、要外网、要虚拟机的，原来在长跑里跑了也白跑。新加长跑测试照这个后缀命名，放在别的 crate 里的把 crate 加进那一行。
- **B（项目主人照推荐定）**：四项都加编译缓存（`Swatinem/rust-cache@v2`）：第三方依赖的产物照 `Cargo.lock`、工具链、系统分开存，工作区自己的 crate 照旧编。只有 main 上的那一次存，分支照 main 的取：缓存不随分支越攒越多（GitHub 一个仓库 10 GB）。
- 三台加长跑照旧都跑、合并照旧等它们绿（D 没选）。

### 不做什么

- C：集成测试并成每个 crate 一个测试程序（286 个并成十几个，Windows 链接大降，本地门禁也快）：改动面大，以后专门做一步，等项目主人定。
- D：不等慢的几台就合：项目主人没选。

### 验收

1. 这条分支的 CI：长跑那一项从 38～41 分钟降下来（缓存还没存，三台照旧）。
2. 合进 main、main 跑过一次存下缓存以后，下一步的 CI：三台各降多少，记在下面。

### 施工结果

run 1171（这条分支，2026-10-08）：分支不存缓存、main 上还没存过，四项都是「No cache found」，从零编。

| 项 | 以前 | 这次 |
|---|---|---|
| 长跑 | 38～41 分钟 | 3 分 20 秒（两条长跑测试一条 47 秒、一条 60 秒，别的全滤掉） |
| Windows | 33～37 分钟 | 26 分 41 秒 |
| macOS | 14～17 分钟 | 14 分 20 秒 |
| ubuntu | 14～17 分钟 | 11 分 7 秒 |

三台没吃到缓存也快了几分钟：`Swatinem/rust-cache` 顺手设了 `CARGO_INCREMENTAL=0`（CI 上从零编，增量编译只添开销）。一次的数有起伏，看个大概。

缓存的效果（验收第 2 条）：main 的 run 1174 存下了四份（Linux 604 MiB、Windows 568 MiB、macOS 398 MiB、长跑 96 MiB），可之后分支的 run 1177 四项都是「No cache found」，时间和没缓存一样（ubuntu 11 分 39 秒、macOS 12 分 48 秒、Windows 24 分 14 秒、长跑 3 分 14 秒）。

根因（2026-10-08 查 run 1174、1177 的日志）：`rust-cache` 的键里有一段「环境」的散列，它把机器上装着的每个工具链都算进去。除了 `rust-toolchain.toml` 钉住的 1.97.0，GitHub 的机器还自带一个 stable，同一天有的机器是 1.98.1（main 那一次）、有的是 1.99.0（分支那一次），散列就对不上（`ebeb164a` 对 `df5a5e57`）。键的后一半（`Cargo.lock`、各 `Cargo.toml`、`.cargo/config.toml`、`rust-toolchain.toml` 的散列）两边一样。

### 0-3 再补（2026-10-08，主会话）

- 两处 `rust-cache` 都加 `add-rust-environment-hash-key: false`：键里不算环境。钉住的工具链在 `rust-toolchain.toml` 里，已经算在键的后一半，换工具链照样换一份缓存；机器自带的 stable 用不上，不该让它拆开缓存。环境里另一样 `CARGO_INCREMENTAL` 是 `rust-cache` 自己设的常量。
- 万一取到一份别的编译器编的产物，cargo 照指纹认出来、照旧重编，不会编错，只是白取。
- 键变了，main 得再存一次：合进去以后 main 跑一次，再下一步的 CI 量了补在这里。
- 合了（fd2a5d91，CI run 1184 三台和长跑全绿）。
