## 施工单 5-4（下）：权限策略接上沙盒（下）

状态：已完成（2026-09-29：真模型自测在沙盒里编过了；手写 28 个，27 个被测试逮住。5-4（上）漏掉的那一个（核心没把探到的交给协议端点）这一步逮住了；剩下的一个是核心没把沙盒的缓存交给协议端点：真的核心里没有照剧本回的模型，测试看不到，真模型自测看得到（她的 cargo 用的就是沙盒的缓存）；CI 全绿）。

### 目的

沙盒里的命令跑得顺，沙盒用不了时说清楚：
- 工具链的缓存用沙盒自己的一份：工作区这一级，cargo、npm、pip、go 的缓存经它们自己的环境变量指到缓存目录下只给沙盒的一处，沙盒能写；你的 `~/.cargo`、`~/.npm` 照旧只读。cargo 的全局配置照样看得到。
- 协议上报出这台机器的沙盒能不能用、为什么（握手的回应）；`miyu ask` 用不了时，开头说一行原因、后果、怎么修。
- 核心把探到的结果交给协议端点这一环有了测试（5-4 上唯一没逮住的变异）。

### 蓝图改哪几节

- `protocol.md`：握手的回应多一格 `sandbox`。
- `cli/ask.md`：沙盒用不了那一句（一行，最先印，一次）、给人看的字。
- `session/tools.md` 第 1a 条：工作区这一级多放一处能写的（沙盒的缓存），多设五个环境变量，cargo 的全局配置带过去。
- `session/actor.md`：造会话、载入时的格补上沙盒的助手（5-4 上漏写了），多一样沙盒的缓存。
- `sandbox.md`：探到的结果写成「能不能用」（`Availability`）；「还没有的」。
- `core.md`：起来时算出沙盒的缓存放在哪，和探到的结果一起交给协议端点。
- `store.md`：缓存目录有人用了。
- 设计 `11-权限与沙盒.md` 第四节：第一版清单、放在哪；被沙盒挡住时不另加提示（实测）。
- 设计 `26-提示词.md` 第十节：`core/permission-rule.txt` 那一行记上这次实测；原文跟上现在的样子，照旧不拼（原文和指纹随代码一起改）。

### 已定（2026-09-29 项目主人）

- 被沙盒挡住的命令，结果里不另加「是沙盒挡的」那一句：实测 4 次都认得出是沙盒、不绕（设计 11 第四节）。真出现绕沙盒、反复试的，再加。
- `miyu ask` 开头那一句写一行：原因、后果、怎么修放在一起，和「目录太宽」那一句一个写法。

- Windows 上以沙盒用户的身份起命令、还没装沙盒用户时怎么说：5-9。
- `miyu ask --add-dir`：5-10。
- 终端界面里的沙盒状态：M8。

### 验收

1. 测试：握手的回应（能用、找不到助手、助手跑不起来、没有手段）；`miyu ask` 开头那一句（各种原因、只印一次、`--format json` 不印）；执行器写的缓存（只在工作区这一级、五个变量、建出来只给本人、cargo 配置的链接、没有缓存目录时不设）；真的核心握手时报的沙盒（本机和 CI 三台机器各是各的）。
2. 真模型自测：工作区里一个带依赖的 Rust 小项目，让她在沙盒里 `cargo build`：依赖下载进沙盒的缓存、编得过，`~/.cargo` 没被写；只读时编不了。
3. 手写的变异全被测试逮住；`cargo xtask check` 八项全过；三台机器的 CI 全绿。

### 验收结果（2026-09-29）

1. **真模型自测**（本机 Arch，内核 7.2，DeepSeek；key 只放在命令的环境变量里）：数据根、工作区在 `~/.cache` 下，`XDG_CACHE_HOME` 指到一个一次性的目录，不碰真的缓存目录。`miyu ask` 里让她在工作区的一个 Rust 小项目（依赖 `itoa`）里 `cargo build` 再跑：
   - 依赖下载进沙盒的缓存 `<缓存目录>/sandbox/admin/cargo`，编得过，程序印出 `42`；
   - 沙盒的缓存建出来是 0700（`sandbox`、`admin` 两层）；
   - `~/.cargo` 里一个文件都没变（和开始时比，新的文件 0 个）；
   - 跑完停了核心，key 泄露计数是 0。
   - 只读时编不了：`miyu ask` 里开不了只读，由测试守着（只读哪儿都写不了、不放缓存）。
2. **实测定下的**：被沙盒挡住时不另加提示（4 次都认得出，设计 11 第四节）；`core/permission-rule.txt` 照旧不拼，原文跟上现在的样子（85 → 73 个 token，照旧用 DeepSeek 自己的计数量）。
3. **测试**：`Availability` 的写法和读回来；核心探到的四种结果、沙盒的缓存放在哪（`CARGO_HOME` 空的当没设）、算不出来的记一行；握手的回应四种；缓存照属主交给会话，造会话、载入都带；执行器写的缓存（只在工作区这一级、五个变量、0700、cargo 配置的链接：有的建、指错了的换、你的没了就删，令牌不带）；`miyu ask` 开头那一句（每种原因和系统、最先印、和目录太宽那一句连着、给脚本的不印、真的核心握手说用不了时印）；真的 `miyu core` 握手报的沙盒和日志里记下的对得上（5-4 上没逮住的那个变异，这一步逮住了）。
4. **变异**：手写 28 个，27 个被测试逮住。5-4（上）漏掉的那一个（核心没把探到的交给协议端点）这一步逮住了；剩下的一个是核心没把沙盒的缓存交给协议端点：真的核心里没有照剧本回的模型，测试看不到，真模型自测看得到（她的 cargo 用的就是沙盒的缓存）。
5. `cargo xtask check` 八项全过（1248 个测试）；两个目标的交叉 clippy 都过；分支 CI 三台机器全绿，长跑也绿。

我定的（技术细节）：
- 沙盒的缓存放在缓存目录（`store.md` 第 3 条）下的 `sandbox/<账号>/`：和数据根分开，不跟着 `MIYU_HOME` 变；按账号分开。Linux 上缓存目录是 `~/.cache/miyu`，旧版的 `voice-models` 也在里面，重制版只加 `sandbox/`，别的不碰。
- cargo 的配置在 Unix 上是链接，Windows 上照原样拷一份（建符号链接要开发者模式），内容变了再拷。
- 算不出缓存目录时运行日志里的原因写英文（`no home directory`、`no LOCALAPPDATA`），和别的运行日志一样。
- 握手里核心没设沙盒的（测试里）当找不到助手：`helper_missing`。

### 风险

- 第一次在沙盒里编要重新下载依赖、多占一份磁盘（项目主人 2026-09-28 接受）。
- cargo 配置里把 `target-dir` 指到工作区外面、或者用了 `sccache` 这类要写别处的包装的，沙盒里编不了：照被沙盒挡住办，要编就完全放开。
