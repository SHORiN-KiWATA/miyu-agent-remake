## 施工单 8-20：模型调用口

状态：已完成（2026-10-02 施工；项目主人 2026-10-01 定：里面统一、入口分两种；技术细节主会话定）。

### 目的

模型、池要能给会话以外的人调用：以后的通讯平台、看图（8-17）、别的旁路请求。项目主人定的：
- 核心里只有一份调用的底子：解析模型或 `@池`、排候选、出错换端点、冷却、池的指针、思考强度、记用量。
- 上面两个薄入口：
  - 会话用的流式入口：能打断、半截接着说、交限额，就是现在的路由；
  - 一次性入口：发一次、拿整段回答和用量。
- 协议方法 `model.call` 只开一次性的那种。现在连上来的头都能调（它们本来就能经 `session.send` 花额度）；有了扩展以后，前面加一道能力的检查。
- 两个入口都只调底子，不另写挑模型、换端点的逻辑。会话的请求字节一个不变。

技术细节（主会话定）：
- **底子**：从现在会话的路由（`crates/miyu-session/src/route.rs`、`route/`）里拆出和会话无关的那一半：照引用排候选、跳过冷却的、出错照分类记冷却、换下一个、钉住的池换成员、轮换的池的指针、照模型配置的默认强度。冷却表、池的指针本来就是核心一份（`route/shared.rs`），两个入口共用：会话撞了 429，同一时刻的一次性调用自动避开那个端点，反过来也一样。底子放在哪个 crate、叫什么，施工时照分层定，写进「施工时定的」。
- **会话入口**：就是现在的路由，改成调底子。半截接着说（还发给上一次那一个）、打断、交限额、会话给每个模型记的强度，这些只有会话入口有。请求形状探针零变化。
- **回顾、起标题不搬**：它们是内核在会话里开的辅助请求，记在会话的日志里（`model.called` 的 `purpose`），回顾还要复用会话的前缀吃缓存，所以照旧走会话入口。（2026-10-01 跟项目主人说的「回顾、起标题也走一次性入口」，施工前主会话改定为照旧走会话入口：两个入口共用一份底子，统一的目的已经达到；搬过去会让回顾吃不到缓存。合了以后告诉项目主人。）
- **一次性入口**：核心里一个对外的类型，交进去：引用（模型或 `@池`，不写照 `models.chat`）、用途（一个短名字，例如 `vision`、`platform`，记日志、记用量用）、几条消息（`system` 可以有一条；`user`、`assistant` 的字，`user` 可以带 blob 的图）、`max_tokens`（可以不写）。交回：整段回答的字、真发给的供应商和模型、用量。不带工具（第一版；谁要再加）。出错照底子的分类：解析不出 `unknown_model`、没有模型 `no_model`、全在冷却 `cooling`、别的出错 `model_failed`（`data` 带分类、HTTP 状态、原话）。key 的钉法照「用途」算，不照会话编号。
- **协议 `model.call`**（命令）：参数照上面一次性入口的输入（`model`、`purpose`、`messages`、`max_tokens`；图写 blob 的哈希，照这个账号的 blob）；回应 `{"text", "provider", "model", "usage"}`。`purpose` 必写，1 到 32 个小写字母、数字、`-`。不进任何会话的日志。
- **用量**：现在记运行日志一行 `INFO model call purpose=… provider=… model=… input=… output=…`；用量和金额的账本随 8-15，那时两个入口一起记进去。

**主会话合并前实测和补的**（2026-10-02）：
- 经 `model.call` 叫开发端点的真模型：那段时间开发端点整个连不上（最简单的请求等满 60 秒没回，经代理是 HTTP 524），`model.call` 照空闲超时回 `model_failed`（`class` 是 `retryable`），回应形状对。真模型的回答这次没拿到，端点好了以后补在下面。
- 真程序（不经测试工具）：一个钉住的池，第一个成员指到本机连不上的端口，`miyu ask --model @池` 换到了第二个成员（随后第二个成员就是上面那个连不上的端点）。
- 发现测试缺一条：`model.call` 指定池。照着补的时候发现端点测试的工具拼核心时漏登记了池的配置（`PoolSettings`），测试里的核心认不出池、`model.list` 也列不出；真程序是登记全的。主会话补上登记，加一条测试：`model.call` 指定钉住的池，第一个成员回 429，换到下一个答完（`crates/miyu-endpoint/tests/model_call.rs`）。
- 端点好了以后补的（2026-10-02）：经 `model.call` 问开发端点的模型一个字的问题，回「蓝」，带用量；指定一个钉住的池（第一个成员是本机只回 429 的假服务器），假服务器收到一次请求，换到开发端点回「OK」。用的是端点测试的工具（进程内的客户端，不读任何令牌），写成一个不提交的忽略测试，跑完删掉。
