## 施工单 R-5（上）：本机 embedding 的小程序

状态：已完成（2026-10-09 写、施工、自己验收；提交 a31bc96b，CI run 37807252801 三台和长跑全绿（macOS 第一次没领到机器，重跑的）；方向照 `recall.md` 第四条：本机用 bge-small-zh-v1.5、做成可更换的、模型从 Miyu 自己的 GitHub Release 下，都是 2026-10-07 项目主人定的；Release 2026-10-09 项目主人让记忆的会话用 gh 自己建；剩下的是技术细节，照施工方案第一节第 1 条直接做；这条线自己测完就合）。原来的 R-5 拆成三步：这一步是能单独跑的小程序；核心怎么下载、拉起、用它是 R-5（中）；向量存进检索库、两路合并、远程的 `/v1/embeddings` 是 R-5（下）。

### 目的

一个能单独跑的小程序 `miyu-embed`：照清单读一份模型，标准输入一行一句话，标准输出一行一个向量。以后核心照它找相近的记忆和对话，关键词对不上的也找得到。

### 定了的（技术细节）

1. **运行时**：`ort` 钉死 `=2.0.0-rc.13`（ONNX Runtime 1.28），关掉默认的开关，只开 `std`、`download-binaries`、`tls-rustls`：编译时下 pyke 预编好的静态库，静态链接，只在 `miyu-embed` 里。2026-10-09 在仓库外试过（Linux x86_64，release、strip、thin LTO）：程序 23 MB，`ldd` 里没有 ONNX Runtime 的动态库，载入模型 46 毫秒，一句 1 到 2 毫秒，单线程。
2. **模型文件**：`model_quantized.onnx`（Xenova 转的 8 位量化，24 MB）。十句和原版 fp32 的余弦平均 0.991，`model_int8.onnx` 只有 0.970，一样快，挑前一个。2026-10-09 放进 Release `models-bge-small-zh-v1.5`（预发布，不标最新）：模型、`vocab.txt`、FlagEmbedding 的 MIT 许可证、`SHA256SUMS`，下载回来核对过。
3. **分词**：自己写 BERT 的 WordPiece，不用 `tokenizers`：只要这一种，`tokenizers` 依赖多（正则、并行、序列化），二进制大。照原版的配置：
   - 清理：去掉控制字符和 `U+FFFD`，空白一律当空格；汉字（CJK 统一表意文字那几段）前后加空格，一个字一个词；
   - 照空白切，再把标点（ASCII 的标点和 Unicode 的标点类）切成单独的词；
   - 不转小写、不去重音（原版的配置）；
   - 一个词超过 100 个字整个算 `[UNK]`；不然 `##` 前缀贪心最长匹配，有一段配不上整个词算 `[UNK]`；
   - 前后加 `[CLS]`、`[SEP]`；超过清单的 `max_tokens` 的，截掉后面的，留住 `[SEP]`。
   照 Hugging Face `tokenizers` 0.23.2 对一批句子的结果逐个比：标准答案存成测试的数据，生成的办法写在施工结果里。原版不转小写，大写的英文词（`RTX`、`Hello`）、片假名的词都是 `[UNK]`：那一部分靠关键词那一路（`recall.md` 第一条的两两切词管得到日文）；改不改等测评集。
4. **清单**（`resources/models/embed/bge-small-zh-v1.5.toml`：放在模型资料的目录里，不给模型看，不进登记簿）：`id`（向量的模型编号写成 `local:<id>`）、`dims`、`pooling`（现在只有 `cls`）、`max_tokens`；`[[files]]` 每个文件的 `role`（`model`、`vocab`）、`name`、`url`、`sha256`、`size`。向量一律归一化。下载、核对是核心的事（R-5 中），小程序只照 `role` 在目录里找文件、照别的几格算。换模型就是换一份清单；WordPiece 以外的分词、`cls` 以外的取法、转小写，换到那样的模型时再加（现在加就是为以后写）。
5. **协议**：`miyu-embed --manifest <清单> --dir <模型文件的目录>`。
   - 载入成了，标准输出印一行 `{"ready":{"model":"local:bge-small-zh-v1.5","dims":512}}`；清单读不懂、文件没有、模型载入不了，印一行 `{"error":"…"}`，退出码 1；参数写错，标准错误印用法，退出码 2。
   - 之后标准输入一行 `{"id":"…","text":"…"}`，标准输出回一行 `{"id":"…","vector":[…]}`：f32，JSON 的最短写法（读回 f32 一位不差）。读不懂的、跑不了的回 `{"id":"…","error":"…"}`（读不出 `id` 的写 `null`），接着读下一行，不退出。
   - 一次一条、单线程（`intra`、`inter` 都是 1；旧版实测一次 32 条、16 线程时内存冲到 2 GB 不还）。标准输入关了，退出码 0。
   - 给程序看的错误原话一律英文短句；这个协议只有核心读，不给模型看，不进登记簿。
6. **测试用的小模型**：`crates/miyu-embed/tests/fixtures/` 里一份手造的 ONNX（二十来个词的词表、4 维的嵌入表，三个输入都用到，几 KB）和它的清单、词表，协议、截断、出错都在 CI 里跑。真模型的那一条（向量和 Python 的 ONNX Runtime 算的余弦不低于 0.999）标 `#[ignore]`，照环境变量 `MIYU_EMBED_MODEL_DIR` 找文件，验收时跑：测试不联网。

### 不做什么

- 核心下载、核对、拉起、空闲退出，`models.embedding`：R-5（中）。
- 向量存库、补、照模型和字的哈希缓存、两路合并、远程的 `/v1/embeddings`：R-5（下）。
- 发行包带上 `miyu-embed` 和 ONNX Runtime 的第三方声明：随发布那一步。

### 验收

1. 测试先写，没实现时红：分词（标准答案逐个比，还有空字、全是空白、超长的词、截断）；清单（读得出、少格、`role` 重了、`pooling` 不认识）；协议（小模型：`ready`、向量逐个比、坏的一行回错接着读、读不出 `id`、空字、超长截断、标准输入关了退出码 0、清单坏的退出码 1）。
2. 手写变异 15 个左右，全被逮住；`cargo xtask check` 全过；三台机器的 CI 和长跑全绿（三个平台都编得过、链得上 ONNX Runtime 的静态库）。
3. 真模型：`--ignored` 那一条在本机过；量载入、一句的时间和峰值内存，写进施工结果。

### 风险

- `ort` 还是 RC：钉死版本，升级单开一步。
- 编译时要联网下 ONNX Runtime 的静态库（pyke 的 CDN），每个平台几十 MB：CI 第一次编会慢；没网的机器编不了 `miyu-embed`，要先放好库、设 `ORT_LIB_PATH`，写进 `licenses.md`。
- 门禁的许可证一项要查 `ort` 和它编译时的依赖：不在白名单里的当场换开关（例如 `tls-native`），换不了的回来商量。

### 施工结果（2026-10-09）

1. 测试先写：分词、清单、协议、真模型四份（红：编不过，没有这几个模块）。实现以后第一次就全过，39 句标准答案逐个对上。
2. **标准答案怎么来的**：`crates/miyu-embed/tests/fixtures/make.py`（草稿目录里的 Python 虚拟环境装 `tokenizers` 0.23.2、`onnx` 1.23.2、`onnxruntime` 1.30、`numpy`）：`tokens.json` 是 `tokenizers` 对 39 句的结果；`tiny/` 是手造的小模型（21 个词、4 维，输出是每格的嵌入加类型的嵌入，再加照掩码求和的全句，`[CLS]` 那一格随整句变），连同它对六组编号的输出；`real.json` 是真模型对四句的整个向量。字里写着 `[CLS]` 的那一句不进标准答案：`tokenizers` 当成特殊的词，这里照普通的字切（`tokens.rs` 另有一条）。
3. **小模型的输出差一点**：Python 那边是 ONNX Runtime 1.30，这里是 1.28，求和的先后也可能不同，向量照「每格差不过 1e-6」比，不照一位不差比。
4. **清单少了三格**：施工单原来写了 `normalize`、`lowercase`、`strip_accents`。出厂的模型都用不到：向量一律归一化（以后照点积算相似度，第三条第 2 款），不转小写、不去重音是原版的配置；去重音还要多一个 Unicode 规范化的库。换到要它们的模型时再加。
5. **清单放在 `resources/models/embed/`**：资源目录下别处的文件登记簿都要查（给模型看的字），`models/` 是模型资料、不查，清单正是模型资料，门禁不用改。
6. **行尾的 `\r`**：本来写了去掉，变异时发现是多余的：JSON 本来把 `\r` 当空白，去掉那一行，测试照留着。
7. 自己审的时候补了两条：清单的 `dims` 和模型交回来的对不上（每一句回错，说对不上），参数写了两次（退出码 2）。
8. 手写变异 19 个，全被逮住：最长的词 101、格式字符不去、制表换行也去掉、ASCII 的符号不算标点、扩展 B 不算汉字、开头也带 `##`、最短的先配、配不上时留着前面的、截断多留一个、汉字不单独成词、重了的词不拒、`dims` 是 0 不拒、两个同一种文件不拒、不归一化、取最后一个词、维数不查、`id` 不是字也收、参数写两次也收、起不来退出码 2。
9. 真模型（`MIYU_EMBED_MODEL_DIR` 指到从 Release 下回来、核对过 SHA-256 的文件）：`--ignored` 那一条过了，四句的余弦都不低于 0.999。release 编的小程序 29 MB（没 strip），`ldd` 里没有 ONNX Runtime；200 句（15 到 150 个字）一条条送，全部 512 维，峰值内存 62 MB；起来到 `ready` 130 到 580 毫秒，短的一句 4 到 9 毫秒、一百来个字 12 到 25 毫秒。同一台机器上别的会话在编译，数跳得厉害；仓库外单独试的是载入 46 毫秒、一句 1 到 2 毫秒。
