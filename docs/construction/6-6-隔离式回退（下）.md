## 施工单 6-6（下）：隔离式回退

状态：已完成（2026-09-29：摘要回复里调了工具的改发不带工具面的隔离式；真模型上照隔离式的样子发，回的是正经的摘要；变异全逮住；CI 全绿）。

### 目的

fork 式的摘要请求里她调了工具（带着工具面，挡不住，6-3 下实测过），不再当场算一次压缩失败：这一次作废，改发一次不带工具面的摘要请求（隔离式）再压。

### 蓝图改哪几节

- `compaction.md` 第三条第 7 条、第四条（已随这张施工单改）：
  - 隔离式的请求：照平常组装的消息原样、最后接摘要指令，system 换成 `summarize-system.txt` 一句，工具面空的；截短重试照样截。
  - 原来写的压平成一段文字不做了：2026-09-29 实测开发端点，不带工具面的请求里带着以前的工具调用、结果、思考照样收，她只回文字。不收的供应商由那一家的驱动压平，随那个驱动。
  - 思考照驱动平常的设置，不另关（统一的请求里还没有开关）。
  - 作废的那一次照常记 `model.called`（`bad_summary`，原话写明调了工具、改走隔离式）；改走哪种记在回合上，落了盘照常发；一次压缩只改走一次；以前的快照没有那句 system 的，不改走，照失败算。
- `kernel/session.md`、`kernel/request.md`：组装器多隔离式的摘要请求；收回复第 7 条。
- `policy.md`、`store/resources.md`：快照多 `summarize_system`。
- `cli/ask.md`：调了工具、改走隔离式的，印一行灰色旁白「摘要请求里调了工具，改用不带工具的再压」，不印红的压缩失败；不改走的照旧红。
- `summarize-system.txt` 量 token、进登记簿。

### 不做什么

- 驱动不能复用前缀时一开始就走隔离式：随借别家 agent CLI 的驱动。
- 压平成文字：随不收的那一家的驱动。
- 思考的开关：随模型配置。
- 手动压缩（6-8）附的要求在隔离式里也带上：6-8 合进来以后，谁后合谁接上。

### 验收

1. 测试：摘要回复里调了工具，改发隔离式（system 换了、工具面空的、别的消息一样、指令在最后），这一次作废的记 `bad_summary`、原话写明改走；隔离式取到摘要照常写压缩；隔离式也取不出的算失败，熔断照样数；一次压缩只改走一次；旧快照不改走；隔离式里超长照样截短；`miyu ask` 的那一行。随机测试里摘要回复带工具调用的和别的交错。每一条退回改之前的代码会报红。
2. 请求形状探针、组装样本：fork 式的字节不变。
3. 真模型（项目主人给的端点）：试着让摘要请求里调工具，调了的改走隔离式、压成；调不出来的，照组装出来的隔离式请求直接发一次，看回的是摘要。
4. 登记簿对得上；手写的变异全被逮住；`cargo xtask check` 全过；三台机器的 CI 全绿。

### 风险

- 隔离式不命中缓存：system、工具面都变了，整份按没命中的价钱。只在 fork 式调了工具时走，少见。
- 别家的驱动接进来时，没有工具面的工具调用不收：那一家的驱动要压平，不然隔离式照样失败。

### 验收结果（2026-09-29）

1. **测试**：
   - 内核场景（`session/tests/scenario/isolate.rs`，6 条）：调了工具改发隔离式（清单一样、system 换了），作废的那一次原话写着改走，隔离式取到摘要照常压；一次压缩只改走一次，隔离式里又调了工具照失败算；快照里没有那句 system 的当场失败；隔离式超长照样截短、截了还是隔离式；截过的再调了工具，改走隔离式照截过的那一份；取不出摘要（不是调了工具）的不改走。
   - 组装：隔离式的消息和 fork 式的一样，system 换了、工具面空的，截短照样补 `truncated.txt`。快照：出厂的带着那句 system，旧快照读成没有、不改走，读进来再写出去一字不差。`miyu ask`：改走的灰色一行、不印压缩失败，后面照常压好了，中英文。
   - 随机：三分之一的种子带隔离式（全带的话调了工具的都改走了，连续失败、暂停三百例里走不到）；看守查改走的那一次后面这一轮不结束，下一次同一个 N 的摘要请求是隔离式、截到的不变，一次压缩只改走一次，之后截短再发的还是隔离式。三百例走到「调了工具改走隔离式」「隔离式再发」，两万例的长跑也过了。
2. 请求形状探针、组装样本没变：fork 式的字节不变。
3. **真模型**（项目主人给的端点，`deepseek-v4.1-flash`，`MIYU_DEV_WINDOW=45000`）：
   - 先照施工前那样实测：不带工具面的请求里带着以前的工具调用、结果和思考，端点收，她只回文字、没有调工具。
   - 让她一轮里依次读三个约 1.2 万 token 的文件，跑了三次：她都在一步里一起读完，回合中途压（39.2k → 2.6k 上下），摘要请求里一次都没调工具，改走隔离式这条路在真模型上撞不出来。
   - 照施工单退一步：照隔离式的样子直接发一次（`summarize-system.txt` 那一句、不带工具面、那一轮的工具调用和结果、真的摘要指令），回的是先草稿后摘要的一份，三个文件的第一行都在，没有调工具。
   - 数据根里没有 key，用完停掉了核心。
4. **登记簿**：`summarize-system.txt` 22 个 token，照项目主人给的端点量，进了 `26-提示词.md` 第十节，`prompts.md` 重新生成。

**施工中改的**：
