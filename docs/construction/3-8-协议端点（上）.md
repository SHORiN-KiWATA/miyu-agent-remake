## 施工单 3-8：协议端点（上）

### 目的

头和核心之间有了第一截协议：一个连接上说 JSON-RPC 2.0，一行一条消息。先握手（协议版本、本机令牌），然后能造会话、说话、打断；会话表照编号找会话，这次运行里没在跑的，从磁盘载入。这一步跑在任意字节流上，测试用内存里的管道；订阅事件流是 3-8（中），真的本机套接字、命名管道是 3-8（下）。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-endpoint/`（新，第 4 层） | 一个连接怎么说话：读一行、认成 JSON-RPC 请求、先握手、再照方法办、回应写回去。会话表：照编号找会话，没在跑的载入，停了的拿掉。拒绝的原因码和给人看的话（中文、英文） |
| `crates/miyu-session/` | `Handle::environment`：头报上来的工作目录变了，送进会话（`Input::Environment`） |
| `docs/designs/04-核心协议.md` 第九节 | 「先做的几样怎么写」 |
| `docs/designs/01-架构.md` 第九节 | 第 4 层多一个 `miyu-endpoint`，跟 crate 一起进施工的分支 |
| 施工图 | 3-8（上）那一张 |

一个连接怎么走：

1. 读一行，最长 1 MiB；读不懂的回 `-32700`，不是请求的回 `-32600`。
2. 第一条必须是 `hello`：主版本有交集、令牌对上，回选定的版本、核心的版本、你是谁；不然回拒绝、断开。
3. 之后一条条照方法办：`session.create`、`session.send`、`session.interrupt`；不认识的方法回 `-32601`，参数不对回 `-32602`。
4. 命令交给会话，等它的回应：接受的回 `events`，拒绝的回 `-32010` 和原因码。

### 不做什么

- 订阅、推送：3-8（中）。
- Unix 域套接字、命名管道、本机令牌文件、一个数据根一个核心的锁：3-8（下）。这一步令牌由外面交进来。
- 管理员的账号叫什么：首次运行时定（3-9 前后，问项目主人）。这一步由外面交进来。
- 别的方法（`session.answer`、`session.revert`、查询……）：到用它的那一步再写。
- 协议的单一真相源生成 JSON Schema、TypeScript 类型：有了网页头再做。
- 会话空闲一段时间退出：有了订阅、知道谁在看，再定什么叫空闲。

### 我定的

- **新 crate `miyu-endpoint`**：第 4 层。它只认字节流，不管字节流从哪来：3-8（下）的套接字、命名管道，以后的 WebSocket、标准输入输出，都把连接交给它。
- **一个连接一个任务，请求一条条办**：一条命令从收到到回应只等到它的事件落盘，几毫秒，不等回合说完。订阅来了（3-8 中）再加一个写的任务。
- **一行最长 1 MiB**：附件走 `blob.put`，一条消息用不着这么长；超长的当读不懂，回 `-32700` 并断开，不在内存里攒。
- **请求的 `id` 一律是字符串**，照命令编号的写法；数字、`null` 的当不是请求。同一个编号重发，内核照上一次回应（不变量 9）。
- **拒绝的话照头的语言**：`locale` 是 `zh` 开头的写中文，别的写英文。原因码是给程序看的稳定英文。
- **会话表拿 tokio 的锁护着**：载入要读盘，锁在载入期间一直拿着，免得两个连接同时载入同一个会话、起两个 actor（一个会话只能有一个写者，`07-存储.md` 第三节）。会话停了（写不进去、panic），从表里拿掉，下次用到再载入。
- **有没有人能确认**照造会话那个连接握手时的 `caps.input`（`04-核心协议.md` 第九节）。
- **工作目录跟着头走**：`session.create` 必写 `cwd`；`session.send` 可以带 `cwd`，和会话现在的不一样，就先送进会话（到下一个边界才注入，`08-上下文投影.md` C10）。载入时用这一句带的，没带的用 `~`。
- **时区照核心所在的机器**：`jiff` 取系统时区现在的偏移。

### 验收

1. `step/3-8a-endpoint` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`，都在内存里的管道上跑：
   - 握手：第一条不是 `hello` 的、令牌不对的、主版本没有交集的，各回对应的原因码；令牌不对的断开。
   - 造会话、说一句：回应里有新会话的编号和事件序号；磁盘上这一轮说完了。
   - 说给没有的会话：`session_not_found`。
   - 说给这次运行里没在跑的会话（换一张会话表，像核心重启过）：从磁盘载入，接着说。
   - 打断没在跑的回合：`-32010`、`not_running`，中文的话。
   - 读不懂的、不是请求的、没有的方法、参数不对的、太长的一行：各回 JSON-RPC 标准的错。
   - 工作目录变了：带了新的 `cwd`，下一轮的请求里有「工作目录变了」的事实。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --workspace --exclude miyu-http --exclude miyu-session --exclude miyu-endpoint --target` 查 Windows、macOS。

### 风险

- **一条命令卡住，整个连接跟着卡住**：一条条办的代价。命令只等落盘，卡住就是会话出了事，会话停了会回 `session_stopped`。有了订阅再看要不要并发。
- **两个连接同时载入同一个会话**：会话表的锁护着，测试里并发载入同一个会话，只起一个 actor。
