## 施工单 P-1（补）：角色扮演提示和风格锁

状态：已完成（2026-10-07 写、施工完；CI run 1105 三台和长跑全绿；方向是定过的：J10 每 3 轮一条、记成事实、排在触发消息之后（2026-09-26 项目主人定），风格锁只给有 `reminders.md` 的人格（2026-10-07 项目主人定）；技术细节主会话定）。

### 目的

有角色扮演提示的人格（例如主人的 Miyu）聊久了不忘自己是谁：每 3 轮在触发的那句后面追加一条提醒；system 最后带一句风格锁，进了工具循环也不切成助手播报的腔调。软件工程师、空人格都没有这两样，请求一字不变。

### 蓝图改哪几节

- `personas.md`：`prompts/reminders.md` 的读法、快照里存什么。
- `kernel/request.md`：「事实」多一类 `reminder`；「组装」第 6 条加例外：回合开始时注入的提醒排在触发后面。
- `prompts.md`（或 `policy.md`）：system 第 7 块风格锁。
- `26-提示词.md` 第十节登记簿：新的三份字。

### 定了的（技术细节，主会话定）

1. **读法**：人格的 `prompts/reminders.md`，照几层按文件名整份替换（和 `persona.md` 一样）；去掉末尾空白以后是空的，算没有。整份是一条提醒，不拆。
2. **快照**：多一格 `reminder`，造会话时拼好的原文：`core/facts/reminder-open.txt`、提醒原文（不转义：人格作者写的）、`core/facts/reminder-close.txt`。旧版的样子是 `<persona-reminder>…</persona-reminder>`，照搬。没有的不写，以前造的快照字节不变。
3. **内核注入**：`kind` 是 `reminder`、`by` 内核，只在回合开始查（这一轮中途切了级别的边界不查），和环境、权限、编号同一批追加、排在它们后面。有效历史里没有内核记的 `reminder` 就注入；有的，数它后面的 `turn.started` 再加上这一轮，到 3 注入。所以第 1、4、7……轮各一条；压缩替掉、撤掉了带着它的那一轮，下一轮重新注入（和旧版「照最近一份提醒化石数」一样）。间隔是内核的常量 3，不给旋钮。
4. **排法**：渲染时回合开始注入的 `reminder` 排在触发的那句后面（08 C2 唯一的例外）；触发不在这一段里的照先后。挪到的是那个回合开始的位置，日志不动，前缀接得上。
5. **风格锁**：`core/style-lock.txt`，旧版原文一字不改（受 A/B 保护，分号不改）：`<style-lock>Stay in character across tool calls. Tool results are working material; they are not a reason to switch into an assistant reporting tone.</style-lock>`。快照有 `reminder` 的，system 最后一块带它（第 7 块）；没有的不带。子会话的人格是软件工程师，自然没有。
6. **登记**：三份新字登记在 26 第十节，量 token、记指纹。

### 不做什么

- 旧版的自动蒸馏（从人设让模型写提醒）：不做，照搬手写的那一份（J7）。
- 预设关掉角色扮演提示（开发预设）：P-2。
- 改了人格文件下一回合换上：P-1 再补。
- 把 Miyu 的三份字放进主人的数据根：P-1 做完以后单独给命令（Y10）。

### 验收

1. 测试先写：有 `reminders.md` 的人格第 1、4、7 轮各一条、排在触发后面、请求里是最后一块；压缩以后、撤掉带着它的那一轮以后下一轮重来；中途切级别不注入；没有的人格请求一字不变；风格锁在 system 最后，没有提醒的人格不带；以前的快照载入照旧。
2. 手写变异 10 个左右；`cargo xtask check` 八项；三台 CI 和长跑。
3. 自己实测：沙箱数据根里放旧版 Miyu 的三份字，用开发端点跑 5 轮，看请求里提醒在第 1、4 轮、风格锁在 system 末尾。

### 施工结果（2026-10-07 主会话）

1. 人格的 `prompts/reminders.md` 照几层读（`persona.get` 多报它来自哪一层）；造会话时拼成快照的 `reminder`：`core/facts/reminder-open.txt`、原文去掉末尾空白、换行、`core/facts/reminder-close.txt`。包装不存进快照的 `core`：没有提示的人格，快照一个字节不变。
2. 内核 `FactTemplates::with_reminder`、`reminder`：只在回合开始查，排在环境、权限、编号后面；有效历史里没有内核记的这一类就注入，有的数它后面开了几轮（这一轮算在内）到 3 注入。中途切级别的边界不查。
3. 组装：内核回合开始时注入的 `reminder` 排在触发后面（`render.rs` 的 `Place::After`），模块的同类块照别的事实排。
4. 风格锁 `core/style-lock.txt`，旧版原文逐字对过；`CoreLines` 一起读，`Snapshot::with_style_lock` 只给有 `reminder` 的快照接在 system 最后。
5. 三份新字登记、实测：开头 8、收尾 8、风格锁接在 system 末尾 34（`clinepass/cline-pass/deepseek-v4.1-flash`）。
6. 请求探针 `probe_reminder.rs` 和存档 `docs/designs/samples/probe/reminder/`：五轮闲聊，第 1、4 次的最后一块是提示；去掉风格锁和提示，和不带提示的同一份剧本一字不差。随机日志三个种子里一个带提示，五条性质的「回合第一次请求的最后一块」改成「触发那句，有提示的后面跟着它」。
7. 手写变异 13 个：第一轮 12 个逮住，漏的是 `persona.get` 把提示来自哪一层报成示范对话的：测试里两样恰好都在家目录。补了软件工程师只在家目录放提示的一问，再跑逮住，13/13。
8. 自己实测（沙箱数据根，旧版 Miyu 的三份字照主人工作区里现在的样子放进 `home/admin/personas/miyu/`，开发端点，五轮）：日志里提示在第 1、4 轮，原文对；快照的 system 以风格锁结尾；五句回答都在角色里，第 2 轮起缓存命中 95% 以上。顺带看到一处和这一步无关的：第 1 轮她的思考里把示范对话当成了「这段对话里我前面说过的话」（示范对话随 P-1 上进来，排在 system 后面、历史前面，写法照 08 第三节），记下，等主人用自己的 Miyu 试过再看要不要处理。
