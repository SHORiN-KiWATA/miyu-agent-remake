## 施工单 P-3（补）：照人要的改人格、预设的编辑

状态：施工中（2026-10-08 写；项目主人 2026-10-08 看了终端的人格、预设编辑改了方向，终端的会话转来，原话「什么来自、基于，都是毫无意义的设计，你设计的时候必须考虑用户需要什么」；形状和终端界面、网页的会话对过（2026-10-08）；技术细节主会话定）。

### 目的

人格、预设的编辑只给人要看的：名字、说明、写了什么、开了什么、删了会怎样。以谁为底、来自哪一层、编号、分语言的名字都不往界面和协议上露。

### 定了的

项目主人定的（2026-10-08，终端的会话转来）：

1. 不要以谁为底：P-3 上的 `base` 整个撤掉。
2. 名字只存一份、不分语言。
3. 新建不填编号，人看到的只有名字。
4. 新建人格一次填好：名字、人设、示范对话、角色扮演提示。
5. 示范对话照旧版那样一对一对地加、改、删、挪，不进编辑器。
6. 出厂的空人格 `none` 叫「空白」。
7. 新建的预设功能先全开。
8. 预设的功能开关要有看得懂的名字（「显示名称呢？都是英文谁看得懂？」）。
9. 删除按钮：改过的出厂写「恢复出厂」，自己建的写「删除」，没改过的出厂不出按钮（网页的会话转来）。

主会话定的形状（和两个头对过）：

1. `name`、`summary` 写成一句字；以前写成语言表的照样认、照连接的语言挑（出厂的几个照旧带三种语言，界面照连接的语言显示），存的时候整格换成一句字。预设的指纹照以前的写法算，以前造的快照照旧对得上（钉了两个 P-3 补以前的值，另用 Python 照旧的写法独立算过一遍对上）。出厂的软件工程师补上名字、说明：界面只露名字，没名字的认不出。
2. `persona.set` / `preset.set` 不写编号就是新建，核心起 `persona-<n>` / `preset-<n>`（几层里都没有的最小的 n）；新建只删不写的参数不对。占编号：预设照「写新文件、已经有了就换下一个」，人格先建目录占住。
3. `*.get`、`*.list` 去掉 `layers`；`persona.get` 的 `prompts` 改成有没有字；`persona.read` 去掉 `from`，示范对话多 `pairs`；`*.get` 多 `remove`（`restore` / `delete` / `null`）。
4. `prompts.examples` 收 `{"pairs": […]}`，核心写成 `user:` / `assistant:` 的写法（一句里的空行去掉），写了读不回原样的拒绝、说是第几对；空的 `pairs` 等于删掉。空的字（`{"text": ""}`）就是这一段是空的。
5. `preset.get` 的 `software` 改成一个个 `{"id", "name", "summary", "on", "installed"}`，`switches`、`missing` 并进去。内置的五个（基础系统、联网、长期目标、记忆、角色扮演）的名字、说明放在核心给人看的字里，清单装的照它的清单。
6. `persona_invalid`、`preset_invalid` 在 `persona.*`、`preset.*` 里另带照连接语言的 `message` 和 `line`（同 `check`，不带层）。

### 不做什么

- 层只留在核心里：`miyu check` 照旧分层报，诊断用。
- 系统区那一层的改、删：等多用户那次专门讨论。

### 验收

1. 测试先写：一句字的名字、以前的语言表照样读、整格换掉；以前的预设指纹不变；不写编号新建、编号挨着往下起；`pairs` 写回读得出、写不回的说第几对；空的字；`remove` 三种；`software` 的名字和先后；写错的带 `message`。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉两个头。
