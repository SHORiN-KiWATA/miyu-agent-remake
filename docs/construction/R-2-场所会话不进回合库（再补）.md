## 施工单 R-2（再补）：场所会话的回合先不进回合库

状态：已完成（2026-10-09 写、施工、自己验收；提交 f4e96075，CI run 37829248387 三台和长跑全绿；修 bug，2026-10-09 和核心的主会话定：听众随 O 线落地以前，场所会话的回合不进回合库，O 线那一步再接回来。只有技术细节，照施工方案第一节第 1 条直接做；这条线自己测完就合）。

### 目的

群里的人说的话不会在本机会话里被她搜出来。施工 O-4 下以后，场所会话（系统账号名下、记忆归管理员）照人格的范围接上了回合索引，群里的人开的回合进了管理员那一间的回合库；回合库的条目还没有听众（`memory.md` 第九条），`memory_search` 在本机会话里就搜得到群里别人说的话，主人不在那个群也搜得到。

### 蓝图改哪几节

- `memory.md` 第一条第 1 款：只收本机的会话，场所会话先不收、为什么、什么时候接回来；以前进了的载入时拿掉，补齐也跳过。「守着它的」两行，「施工步子」加一行。
- `session/actor.md` 的运行日志表：`memory index not updated` 多一种情形。

### 定了的（技术细节）

1. `memory::connect` 多交会话的场所：不是 `local` 的不接回合索引（记忆的端口照旧，场所会话本来就没有三件工具）。
2. 载入场所会话时，它以前进了那一间回合库的拿掉：`RecallIndex::forget`，只拿掉、不埋墓碑（会话还在，不是删了）。新造的不拿（还没有）。拿不掉的记一行 `WARN memory index not updated`，下次载入再拿。
3. 补齐旧会话（`memory/backfill.rs`）照同一条跳过场所会话。
4. 本机这个场所的写法用 `agents.rs` 现成的 `LOCAL`（放宽成 `pub(crate)`），不另写一份。

### 不做什么

- 回合库带听众、群里的回合接回来：随 O 线（`memory.md` 第九条）。
- 系统账号名下、记忆归管理员的场所会话补齐（O-4 下留下的缺口）：现在场所会话本来就不进回合库，等接回来的那一步一起做。

### 验收

1. 测试先写，修之前红：场所会话里群里的人说一句，回合库里搜不到；照回合库的写法放一条这个会话的进去，载入以后拿掉了。补齐旧会话的测试多造一个场所会话，它说的补不进来。
2. 手写变异几个，全被逮住；`cargo xtask check` 全过；三台机器的 CI 和长跑全绿。

### 风险

- 载入场所会话多开一次回合库（有就开着，开过的不再开）：只在有事件的会话载入时，一次 `DELETE`。

### 施工结果（2026-10-09）

1. 修之前先写的两条都红了：场所会话里群里的人说的一句进了软件工程师的回合库（「群里的不进」）；补齐旧会话把场所会话里说的补了进来（「团子 不该补进人格那一间」）。修完绿。
2. 查的时候核心的主会话以为 `is_person` 不收外部身份；它是收的（照第一条第 1 款「本机的人、群里的人」都算），问题在场所会话接上了回合索引。O 线以后要让群里的回合进库，先给回合库带上听众。
3. 手写变异 4 个，全被逮住：场所会话也接、以前进了的不拿掉、拿掉别的来源、补齐不看场所。
4. 改了核心的主会话的一条测试（`crates/miyu-endpoint/tests/system_account.rs`，施工 O-4 下）：它等群里那一轮把管理员的回合库建出来，照新的规矩群里的回合不进库、库不会建。改成：系统账号、管理员名下都没有为它建的库；直接建一份管理员的，删群会话时照旧在管理员那一份里埋墓碑。测的意思不变（记忆归管理员、系统账号没有自己的记忆、删的时候照记忆归谁去拿掉）。
