## 施工单 5-4（补）：断开的挂载不卡住沙盒

状态：已完成（2026-10-01，主会话做）。

### 目的

合并 8-6 前跑门禁时，`crates/miyu-session/tests/jobs.rs` 的 `a_background_command_stays_in_the_sandbox` 每次都红：沙盒助手报 `cannot confine: landlock: failed to check file descriptor type: Transport endpoint is not connected (os error 107)`。在没改过的 C-5 上也一样红，半小时前同一条还是绿的。

根子：项目主人机器上的 `~/.gvfs` 是一个守护进程没了的 GNOME 虚拟文件系统挂载，按路径 `stat` 得了，打开以后 `fstat` 却报 ENOTCONN。沙盒为了藏数据根，照 `plan` 把家目录下的每一项一级级加「可读」的规则，Landlock 的库加规则时要 `fstat` 这个描述符，查不了，整个规则集就加不上，沙盒起不来，什么命令都跑不了。断开的网络盘、gvfs 挂载在普通用户的机器上不少见，这是真毛病，只是被这台机器的环境撞了出来。

### 改了什么

- `crates/miyu-sandbox/src/bin/miyu-sandbox/linux/landlock.rs`：加「可读」规则时（`plan` 列出来的那些），先自己对打开的描述符查一次元数据，查不了的跳过这一条。它本来就读不了，跳过等于在沙盒里也读不了，不放宽什么。根目录那一条和「可写」的规则照旧，坏了照样报错。
- `docs/blueprint/sandbox/linux.md`：记一句（读的规则跳过查不了的路径）。

### 验收

- 在有断挂载的这台机器上：改之前那条测试每次红，改之后连跑两次绿；把 `describable` 的判断拿掉（变异），又红。CI 的机器上没有断挂载，造不出来，靠这台机器验过，写在这里。
- `CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿（和 8-6 同一次运行）。
- 给模型看的字：没有。
