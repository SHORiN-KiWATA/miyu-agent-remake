状态：已完成（2026-10-04 开工、施工完，项目主人同一天验收通过（头一次 Windows 的 CI 红，修了以后 run 939 三台和长跑全绿）；图纸是 `web-module.md`「九、网页软件：起停、端口、页面、WebSocket」「十一、`miyu web`」，2026-10-01 批准，第十一条 2026-10-04 随 W-8 改过；施工时挪进新页 `web-ui.md`）。

### 目的

网页界面成一个单独的程序 `miyu-web`：自己开一个只听本机的 HTTP 端口，给页面文件，把浏览器的 WebSocket 一帧一条转成核心协议的一行一条，经本机套接字（Windows 上是命名管道）连核心，不读本机令牌。主程序的 `miyu web` 找到它、把参数交给它：确保它在跑，第一次、`--reset` 的带一次性码打开浏览器。媒体地址 `/media` 是 W-10，打包是 W-11。

4. 真机（2026-10-04，本机，Playwright 1.56 带的 Chromium，页面目录指到 proto/web-demo 的 `web-demo/`，模型是 DeepSeek 官方的 `deepseek-v4-flash`，key 只在环境变量里）：
   - `miyu web --print`：核心、`miyu-web serve` 都是它拉起来的，端口 8300，`run/web` 写了；第二次（`serve` 已经在跑）照样交网址；还没设密码的两次都带 `#setup=`。容器里没有 `xdg-open`，不写 `--print` 的也照退回去印网址；`--port 8301` 照用。

   - `miyu web --logout`（核心停着，照样拉起来）：「作废了 1 个登录」；`--reset` 的网址带码、说的是重设。停 `serve`：`run/web` 删了，`state/logs/web.log` 记了 `listening`、`stopped reason=signal`。数据根和输出里搜不到 key。
5. 施工时看到的一处，不归这一步：系统配置里只写一行 `[providers.deepseek]`（空表）的，`models.chat` 指它报 `bad_reference`「供应商 deepseek 没有配」；写上 `keys` 以后好了。验收报告的意见：保持现状，`keys`（哪怕是空的）是 8-11 定的「算配好了」的标记，裸表多半是没写完，报出来比悄悄不带 key 发出去好。
6. 验收（2026-10-04 项目主人的独立验收报告）：本地门禁、真机（Chromium、真 Firefox）、变异抽查都过；CI run 934 Windows 的 `binary_and_oversized_frames_close_the_socket` 稳定失败：发一帧超过 1 MiB，没拿到关闭帧。原因（报告查到的）：tungstenite 读到帧头就报 `Capacity`，帧的正文没读，网页软件排一个 1009 就关套接字，带着约 1 MiB 没读的数据关，系统回 RST，Windows 上关闭帧被丢。修法照报告的第 2 条做在网页软件里，不只改测试（只改测试，真浏览器照样和 RST 赛跑）：发完关闭帧先关写的一半，把浏览器还在发的读掉、扔掉，读到头或者满 2 秒再放（定长的缓冲，不占内存；`web-ui.md`「施工时定的」第 10 条）。本机用原始字节的客户端发超长帧、先不读等服务端关：改以前 5 次都被重置（3 次连帧都没发完），改以后 5 次都是 1009 加正常的读到头。照这个探法补一条测试 `an_oversized_frame_is_closed_without_a_reset`（读到头要在 1 秒内：服务端关了写的一半），加两个变异（不读掉就放、读掉但不关写的一半），都逮住。测试 19 条，变异 35 个。
7. 报告另记的：出厂端口 8300 在验收机上被旧版 Miyu 的守护占着，`miyu web` 照规矩说端口被占（停旧守护或者 `--port`）；`resources/web/pages/` 还没有页面，不设 `MIYU_WEB_PAGES` 的全 404，等 M9、W-11；网页演示的页面握手还没带凭据，是「不做什么」里列明的页面工作。
