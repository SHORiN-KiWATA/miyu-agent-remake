## 施工单 3-9：主程序和拉起核心（上）

状态：已完成（2026-09-27：三台机器的 CI 全绿、长跑也绿、测试全过，照施工方案第一节第 1 条算验收通过）。

### 目的

`miyu` 这个程序有了。核心是一个单独的进程（`miyu core`，由头拉起，平时不用人敲）：起来时建好数据根的骨架和管理员 `admin` 的家目录，运行日志写进 `state/logs/core.log`，从环境变量拿模型，在套接字上等连接；没有头连着、也没有在跑的回合，空闲一段时间自己退出。头连的时候核心没在跑，就把它拉起来，等它说好了再连。下一步（下）在这上面做 `miyu ask`。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-core/`（新，第 4 层） | 核心进程：起来的先后、说「好了」、空闲退出、从环境变量拿模型 |
| `crates/miyu/`（新，第 6 层） | 主程序：按子命令分发。`miyu core` 由头拉起，不写进帮助；不认识的子命令报错、退出码 2 |
| `crates/miyu-ipc/` | 头这一边：连不上就拉起核心（拉起锁、管道、等核心说好了）；核心说的那一行；单实例锁单独拿得到（先拿锁、再装日志） |
| `crates/miyu-kernel/` | 会话空不空闲：没有在跑的回合，也没有结束了、`turn.ended` 还没落盘的 |
| `crates/miyu-session/`、`crates/miyu-endpoint/` | 看得出还有没有在跑的回合、还有几个连接；收到停的信号时全部有计划地停下 |
| `crates/miyu-store/` | 管理员的家目录；两个进程同时第一次建骨架也都成（施工中查出的 bug） |
| `docs/designs/01-架构.md` 第九节 | 第 4 层多一个 `miyu-core`，第 6 层是 `miyu` |
| `docs/designs/12-进程形态与分发.md` 第二节 | 拉起时握手的细节 |
| 施工图 | 3-9（上）那一张 |

核心起来的先后（`miyu core`）：

1. 找数据根，建骨架。
2. 拿锁：已经有一个核心在跑的，说一声 `running` 就走（施工中改的：先拿锁再装日志，免得两个核心写同一份日志）。
3. 装运行日志，记一条「起来了」；管理员 `admin` 的家目录，没有就建；找资源目录。
4. 换本机令牌、在套接字上等连接（施工 3-8 下）；模型：设了 `DEEPSEEK_API_KEY` 的，接 DeepSeek 官方；没设的，每次请求都回「没有可用的模型」。
5. 往标准输出写一行，告诉拉起它的头：好了、已经有一个在跑了，或者起不来和为什么。
6. 一个个接连接；空闲够久了就退出、收到停的信号就停，记一条「停了」和为什么。

头拉起核心：

1. 先连：连上了就用。
2. 连不上（核心没在跑）：拿 `run/spawn.lock` 这把拉起锁，免得几个头同时拉起好几个核心；拿到以后再连一次，别的头可能刚拉起来。
3. 还是连不上：拉起 `miyu core`，把一根管道的写端给它当标准输出，等它写来的那一行，不轮询。
4. 放开拉起锁，连上。

### 我定的

- **两个新 crate**：`miyu-core` 在第 4 层，装核心进程怎么起、怎么停；`miyu` 在第 6 层，只按子命令分发。头拉起核心的那一段放在 `miyu-ipc`：每个头都要，怎么启动核心由调用的一方给（主程序给的是自己加上 `core`）。
- **核心说好了，写一行**：图纸原写「写一个字节」。改成一行，`ready` 是好了，`running` 是已经有一个核心在跑（头照样去连它），`error <原因>` 是起不来（头把原因照原样打出来）。什么都没写就退了的，头报「核心没起来」，并说去看 `state/logs/core.log`。
- **清旧套接字的是核心**：图纸原写由头清。核心拿着锁才清（施工 3-8 下），头不碰。
- **拉起的核心跟终端脱开**：标准输入、标准错误接空，标准输出是那根管道；Unix 上自成一个进程组，终端里按 Ctrl+C 打不到它；Windows 上不带控制台窗口、自成一组。工作目录设成数据根，不占着头的当前目录。
- **等核心说好了最多等 10 秒**；拿拉起锁最多等 10 秒。
- **空闲退出**：没有连接、也没有在跑的回合，连续 10 分钟就退出。每 30 秒看一次，不另起忙循环。10 分钟以后放进配置。
- **没设 `DEEPSEEK_API_KEY` 的核心照样起来**：请求模型时当场回「没有可用的模型」（`no model: set DEEPSEEK_API_KEY`），分类是认证失败，内核不重试。头先看自己的环境变量，核心没在跑、自己也没设的，直接报错、退出码 5，不拉起：这是 `miyu ask` 的事，随 3-9（下）。
- **空不空闲**：内核的会话没有在跑的回合、也没有结束了还没落盘的就是空闲；会话 actor 每送完一批输入写一次，actor 退出了（写不进去、panic）写成不忙，停了的会话不拦着核心空闲退出。协议端点每个连接开始时数上、走的时候减掉，连接的任务被叫停也减。
- **收到停的信号**（SIGTERM、Ctrl+C）：先让在跑的会话有计划地停下，跑到一半的回合记成「重启了」，下次载入接着干。拉起的核心自成一组，终端里的 Ctrl+C 打不到它，要明着发。
- **先记「停了」，再放锁**：停之前记一条，那时锁还在手里，下一个核心起来之前这一份日志还是它一个人写。
- **运行时两个线程**：接连接、会话、请求都是等 I/O，两个够用，占用也低。
- **拉起之前要有骨架**：拉起锁放在 `run/` 里，头拉起核心之前先建好骨架（建两次也不出错），`miyu ask` 在 3-9（下）这么做。两个进程同时第一次建骨架都要成（施工中查出的 bug：其中一个会被误认成「认不出是 Miyu 的数据根」，或者撞上别处刚写下的标记报错；修法是再看一眼标记，别处刚写下的也算）。
- **界面的字先写在代码里**：`miyu` 不认识的子命令、只敲了 `miyu` 时的两句，照 `LC_ALL`、`LC_MESSAGES`、`LANG` 说中文或英文；做界面语言的那一步挪进资源文件（`00-设计理念.md` 第六节）。`miyu ask` 在（下）之前也是「没有这个子命令」。
- **Windows 上丢掉还在等连接的管道，管道名会多留一小会儿**：句柄要等取消了那次等待才真关上。核心进程随后就退出了，系统替它全关掉；进程里跑的测试等到连不上为止。
- **交叉 clippy** 还要排除 `miyu-core`、`miyu`：它们依赖的 HTTP 那一块本机交叉编译不了，CI 上真编。

### 验收

1. `step/3-9a-core` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 真的进程（`miyu` 的测试，拉起测试构建出来的 `miyu core`）：头拉起核心，等到 `ready`，连上、握手，管理员叫 `admin`、家目录建好了；再连一次，不再拉起；两个头同时连，只拉起一次（数着拉起的次数）；资源目录指错了的，头收到 `error` 和原因；一声不吭就走了的（例如不认识的子命令），头报「没说话」，不干等；已经有一个在跑、还没开始等连接的，拉起的那一个说 `running` 就走，头等到连上那一个；已经在跑的，再起一个 `miyu core`，它写 `running` 就走、不写日志；空闲了自己走，运行日志里 `starting`、`stopped reason=idle` 各一条。
   - 进程里（`miyu-core` 的测试，请求模型照剧本回）：空闲够久了就退出，锁放开了、连不上了；有头连着不退，头走了才退；头走了、这一轮还在跑的不退，打断以后才退；空闲的钟从最后一个头走的时候算起；收到停的信号先停会话，跑到一半的回合记成「重启了」；没设 key、key 是空白的，每次请求都记一次出错的 `model.called`（认证失败、`no model: set DEEPSEEK_API_KEY`、没发出去）。
   - 内核：空闲只在没有回合、也没有结束了还没落盘的时候。会话：一轮在跑时算忙；写不进去停下了，不再算忙。协议端点：连着一个就不空闲，走了才空闲；头走了、回合还在跑的不空闲，打断以后空闲；全部停下时跑到一半的回合记成「重启了」。
   - 数据根：几个进程同时第一次建骨架都成（8 个线程一起建，30 次）；管理员的家目录建两次也不出错，Unix 上 0700。
   - 核心说的那一行：`ready`、`running`、`error <原因>` 读回来一样，原因里的换行换成空格，读不懂的当起不来；头这一边听得到每一种，没说话就走的是「没说话」，等太久的是「等太久」。
   - 命令行：不认识的子命令报错、退出码 2，中文、英文各一句，不拉起核心；只敲 `miyu` 说现在用什么；`--help`、`--version` 照常。
3. 故意改坏 22 处，全部有测试变红。
   - 写改坏清单时先查出、补上的测试缺口 4 处：空闲的钟从最后一个头走的时候算起（不重置的话，头一走就退）；两个头同时连只拉起一次（原先只看日志里只有一条「起来了」，不拿拉起锁也过：第二个核心说 `running` 就走，不写日志）；一声不吭就走的（不放下命令里的写端，头就一直等到 10 秒超时）；在跑、还没等连接的（不等的话当场报连不上）。
   - 数据根同时建骨架的 bug，退回修复前，并发的测试 3 次跑 3 次红。
   - 测不到、没列进改坏清单的，照实记：拉起的核心跟终端脱开（终端里按 Ctrl+C 打不打得到它，测试里造不出终端）；运行时开几个线程；停的信号是真的 SIGTERM、Ctrl+C（测试里换成一个一发就停的信号）。
4. `cargo xtask check` 七项全过；推之前本机用交叉 clippy 查 Windows、macOS。

### 风险

- **测试里拉起真的进程**：用测试构建出来的 `miyu` 程序当核心，每个测试一个临时数据根；进程要收拾干净，测试结束时核心要么空闲退出、要么被关掉。
- **Windows 上脱开终端**：只能在 CI 上看。
