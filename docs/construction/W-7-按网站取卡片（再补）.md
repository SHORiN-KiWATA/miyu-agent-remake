## 施工单 W-7（再补）：按网站取卡片

状态：待施工（2026-10-02，项目主人要的：链接卡片支持 YouTube、B 站视频、维基百科和 ArchWiki 这类 wiki 站；网页的会话实测、提了建议；技术细节主会话定）。在 W-7 补（解压、head 后面的标签）合了以后做，改的是同一批文件。

### 目的

网页的会话照 main 实测（2026-10-02）：
- YouTube：og 就够了。
- B 站：没有卡片（真原因是页面压着发、我们没解，W-7 补修了；基本的 og 卡片 W-7 补以后就有）。项目主人要的封面、UP 主、时长要走 B 站的接口。
- 维基百科：有标题和图，描述是空的（维基百科没有 `description` 的 meta），标题带「 - Wikipedia」「 - 维基百科，自由的百科全书」。
- ArchWiki：只有标题，没有描述、没有图。
- 有的站被人机验证页拦住，卡片标题成了「安全检查」：出了一张假卡片。

要做的（主会话定）：
- **按站取的一层**：`miyu-net` 里多一层「站」：先照地址认是不是认得的站，认得的照它的办法取；不认得的照现在的 og 办法。站的办法都只经现在的抓取（同一个地址闸、同一套代理、同样的时限和上限），不另开客户端。
  - **B 站**：认 `bilibili.com/video/BV…`、`/video/av…`、`b23.tv/…`（短链照现在的规矩跟到跳转后的地址再认）。调 `api.bilibili.com/x/web-interface/view?bvid=…`（或 `aid=…`），带浏览器的 `User-Agent` 和 `Referer: https://www.bilibili.com/`；拿标题、简介、封面（照图的规矩存成 blob）、UP 主（`owner.name`）、时长（`duration`，秒）。接口说视频不存在、被删了的（`code` 是 -404、62002 这类，表放 `link_preview.json`）：不出卡片，`no_preview`（主会话实测：删了的视频页的 og 简介是没填的模板，满是 `{$0}`）。接口连不上、别的出错：退回取页面的 og。页面 og 的简介里还带着 `{$0}` 这种没填的模板的，那一格当没有。
  - **MediaWiki 站**：认法是页面 `<head>` 里 `<meta name="generator" content="MediaWiki …">`，或者 `link_preview.json` 里列的主机（维基百科各语言、`wiki.archlinux.org` 这类）。
    - 维基百科：REST 的 `/api/rest_v1/page/summary/<标题>`，拿 `extract`、`thumbnail`、`title`。
    - 别的站：`api.php?action=query&prop=extracts|pageimages&exintro&explaintext&titles=<标题>&format=json&redirects=1`；没有 TextExtracts 扩展的（回应里没有 `extract`），退回读正文 `.mw-parser-output` 里第一段非空的 `<p>`（去标签、收拢空白）。
    - 标题照 API 的；页面标题里「 - 站名」那段尾巴去掉，站名放进 `site`（照 `og:site_name`，没有用 API 的站名）。
  - **YouTube**：认 `youtube.com`、`www.youtube.com`、`m.youtube.com`、`youtu.be`。YouTube 的 `<head>` 里有 `<title>`，`og:*` 和 `itemprop` 那几个 `<meta>` 却在 `</head>` 后面（频道页 `og:title` 在第 77 万字节左右）：W-7 补的规矩「有 `<title>` 就停」在它身上读不到 og。YouTube 这一站不照那条停：读到找到 `og:title` 为止（视频页再加上 `itemprop="duration"`），最多 `max_bytes`。普通网页照旧，不为它们多下载（2026-10-02 主会话实测 W-7 补以后：频道页只有标题，没有简介和图）。
    - 时长从 `<meta itemprop="duration" content="PT…">` 读（ISO 8601 的时长换成秒），读不到不写。频道名照 `<link itemprop="name">` 或者 og 里有的，读不到不写。
- **人机验证、挡爬虫的页面**：认出来就不做卡片：`card` 是 `null`、`why` 是 `no_preview`，记一次 `no_preview`。认法放在 `link_preview.json` 里一张表（标题完全对上的几种：`Just a moment...`、`Attention Required! | Cloudflare`、`安全检查`、`Access denied` 这类；响应头 `cf-mitigated: challenge`；403、503 回的 HTML），以后加不用改代码。
- **卡片多三格**，没有的不写：`kind`（`"video"`、`"article"`、`"page"`：B 站、YouTube 是视频，MediaWiki 是文章，别的是页面）、`duration`（视频的秒数，整数）、`author`（UP 主、频道名）。
- 站的规矩（认哪些主机、接口地址的样子、人机验证的表）放在 `link_preview.json`，代码里只有「怎么取」。

### 不做什么

- 别的站（推特、知乎……）：以后照同一层加。
- 登录才看得到的内容：不做。

### 验收

1. 测试（先写，退回改之前的代码要红）：全在本机假服务器上（假的 B 站接口、假的 MediaWiki API、假的维基 REST），照 W-7 测试的口子把它们当公网：
   - B 站：BV、av、短链跟跳转都认；接口成了的卡片带封面、UP 主、时长、`kind: video`；接口失败退回 og；
   - MediaWiki：维基 REST 的 `extract`、缩略图；别的站的 `api.php`；没有 TextExtracts 退回第一段 `<p>`；标题去尾巴、站名进 `site`、`kind: article`；
   - YouTube：时长从 ISO 8601 换成秒；读不到不写；
   - 人机验证：表里的标题、`cf-mitigated`、403/503 的 HTML 都回 `no_preview`，不出卡片；
   - 不认得的站照旧 og、`kind: page`；
   - 所有站的请求都过地址闸（站的接口指到内网的被拒）。
2. 给模型看的字：没有。请求形状探针零变化。
3. 真网络（主会话合并前做）：一个 B 站视频、一个 YouTube 视频、一个维基百科条目（中、英各一）、一个 ArchWiki 页面都出像样的卡片；一个被人机验证拦住的站不出卡片。
4. 手写变异 15 个左右，挑关键的，全被逮住；`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
5. 协议回应多了格：合了主会话告诉两个头，附 sha 和形状。
