## 施工单 1-1：编号与时间

状态：已拍板（2026-09-26），施工中。

### 目的

内核有了最底层的几个类型：七种编号和时间。每一种都能照图纸写成 JSON、从 JSON 读回来，写法不对的读的时候就拦下。后面所有的事件都用它们。

### 图纸

`03-事件模型.md` 第二节「编号和时间的写法」，这一步新画的：每种编号在 JSON 里长什么样、规则和例子。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-kernel/src/id.rs` | 会话编号、序号、回合编号、命令编号、调用编号、账号、内容哈希 |
| `crates/miyu-kernel/src/time.rs` | 毫秒精度的 UTC 时间 |
| `crates/miyu-kernel/src/lib.rs` | 挂上这两个模块 |
| `crates/miyu-kernel/Cargo.toml` | 依赖 `serde`；测试用 `serde_json` |
| `docs/designs/01-架构.md` | 白名单加上 `serde` |
| 施工图 | 1-1 那张图纸 |

每种都带测试：照图纸的例子写出去、读回来一字不差；每一条规则各有一个坏例子，证明读的时候拦得下，报错说清是哪里错。

### 不做什么

- 事件：从 1-3 开始。
- 生成编号：UUIDv7 要用随机数和时钟，这是核心进程的事，内核只读、只写。
- 算哈希：这一步只有内容哈希的写法，算哈希留给用到它的那一步。

### 要拍板的

1. **账号名怎么起。** 推荐：小写英文字母开头，只用小写字母、数字、`-`、`_`，最长 32 个字符，像 Linux 的用户名；Windows 保留的几个名字（`con`、`nul` 这些）不能用。显示给人看的名字另起，可以用中文。
   - 理由：账号名会出现在路径 `home/<账号>/` 里，三个平台都要能用。macOS 和 Windows 的文件名默认不分大小写，`Alice` 和 `alice` 会落到同一个目录，所以只用小写。
   - 另一种：账号名也能用中文。三个平台的文件名都支持中文，但 macOS 会把同一个字换成另一种编码方式存，比较名字时容易出错。
   - 定了：照推荐。它相当于 Linux 的登录名，跟 hostname 一样是给机器用的名字（2026-09-26 项目主人）。

### 我定的

- **会话编号只查写法，不查是不是第 7 版**：生成是核心进程的事，内核读的时候只管读得懂。
- **回合编号单独一个类型，不和序号混用**：在 JSON 里它们都是数字；在代码里是两种东西，传错了编译器会拦下。
- **调用编号写成 `call_44_1`**：各家供应商都接受这些字符（Anthropic 只收字母、数字、`_`、`-`）；带着序号，一个会话里不会重复。
- **命令编号最长 128 字节**：它会写进每一条事件的 `cause`，不能让一条命令塞进一大段字。
- **时间的换算自己写**：公历日期和 Unix 时间互转，二三十行，不引入 chrono、time 这类库。我们只要这一种写法。
- **白名单加 `serde`**：编号和时间要能写成 JSON、从 JSON 读回来，Rust 里这是标准做法。`serde_json` 这一步只在测试里用，1-3 做编解码时再进白名单。
- **读和写一样严**：只认自己写出去的那种写法。以后要是真得放宽，格式演进的规则允许加一种新写法（`03-事件模型.md` 第八节）。

### 验收

1. `step/1-1-ids` 分支的 CI：三台机器全绿。本地也可以跑 `cargo xtask check`。
2. `cargo test -p miyu-kernel`：看测试名，每种编号都有「照样本读写一字不差」和「坏写法被拦下」。
3. 读 `03-事件模型.md` 第二节新加的表，看每种编号的样子对不对。

### 风险

- 读得严：以后哪一种写法要放宽，得加新写法，不能改旧的。这是有意的：日志写进硬盘以后，每个版本都要读得懂。
