## 施工单 O-23（下）：判官接上

状态：已完成（2026-10-09；只有技术细节，照施工方案第一节第 1 条直接做；接在 O-23 上后面，核心的 O-24 `venue.records`、8-20 补 `model.call` 在后台答已经合了）。

### 目的

O-23（上）把要问判官的两条路（别人的 @、续聊、刚说过话、抽样、违规旗）只记了一笔、不回。这一步接上判官：照 `chat.md` 第六条拼请求、经核心的 `model.call` 问、读回答、照第三条算分，判了要回的经 `session.respond` 开一轮；同一个人 7 秒内补发的照第四条顶替（接过去或者几条一起重判）；`ext.onebot.chat.decided` 记全。做完以后，群里的「看情况插话」就是旧版那个效果了。

### 蓝图改哪几节

`docs/blueprint/onebot.md` 第一条「群里怎么叫她」接着写：

1. **判官的说明**：资源 `software/onebot/judge/` 的十三份，桥起来时读（同 O-21 的出厂数据），`JudgeTexts::new` 查过，写坏了是打包的错、起不来。
2. **问判官**：`venue.records {session, msg, count: Params.judge.records}` 拿群聊记录和这一条；`Ask { persona: None（判官先不带人格，等项目主人定）, records, current, decoded: Base64::reveal(正文), mode }`；`request` 拼好；`model.call {purpose: "judge", model: Params.judge.model（没写的不带，照核心的 models.chat）, max_tokens, messages}`。超时照 `Params.judge.timeout`（只查违规的照 `moderation_timeout`），判不了的重试 `retries` 次。全局最多同时问几个、排队等多久：`bridge.json` 新加两格（出厂 4、15 秒，18 第七节）。
3. **读回答、算分**：`read(answer, mode, reason_chars)`；读不出、超时、出错、排队等不到的当判不了、照不回算（18 第七节）；`score(...)` 定回不回。
4. **顶替**（`supersede`）：还没回完的（`Pending`）照日志投影 `Committed`（判过要回、还没进哪一轮 `triggers`、`turn.joined.triggers` 的），`Judging` 只在桥的内存里（重启就丢，窗口只有 7 秒，不补判）。`Inherit`：这一条照 `session.respond {to: [这一条]}` 并进去；`Rejudge`：放下在判的那一次判官请求（回来的回答不用），几条一起重判。
5. **额度满了**（`rate_full`）的这段时间不抽样、不问判官。
6. **线路规程**（场所规则的 `discipline`，18 第七节那张表）：`every-message`、`when-called`、`chatty`、`wake` 四种照 18 分开走（哪些条件成立、要不要问判官、主回合还是只记下）；O-23（上）没看它，这一步补上。
7. **记判断**：`ext.onebot.chat.decided` 补全：判的是哪几条、成立的条件和加分、走的路、判官的回答和理由、算分的每一项、结论；判不了的写为什么；用的模型、耗时。
8. 「守着它的」「施工时定的」补这一步的。
