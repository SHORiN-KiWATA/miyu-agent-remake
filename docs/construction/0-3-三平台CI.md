## 施工单 0-3：三平台 CI

状态：已拍板（2026-09-26），施工中。

### 目的

每次推送，GitHub 在 Linux、macOS、Windows 上各跑一遍 `cargo xtask check`。三个平台从第一个提交起就一起守住（`12-进程形态与分发.md` 第八节）。

### 图纸

这张施工单本身：跑什么、在哪跑、什么时候跑，见下面两节。

### 做什么

| 文件或操作 | 内容 |
|---|---|
| 公开前的清理（单独一个提交） | 证据索引里的本机路径换成说明文字；`13-终端界面.md` 里的私有画布链接注明读者看不到；施工单 0-1、0-2 验收步骤里的绝对路径改成相对仓库根目录 |
| 新建仓库 | `SHORiN-KiWATA/miyu-agent-remake`，公开。简介写明是临时仓库，做完并进 `miyu-agent`；关掉 issue、wiki、projects，免得攒下搬不走的东西 |
| `.github/workflows/ci.yml` | 推送到 main 或 `step/` 开头的分支时触发，也能手动触发。三台机器：`ubuntu-24.04`、`macos-latest`（Apple 芯片）、`windows-latest`，各跑 `cargo xtask check` |
| `.gitattributes` | 所有文本文件一律 LF |
| 施工的规矩第 2 条、`AGENTS.md` | 每一步的分支推上去跑 CI，三个平台全绿算验收的一部分；验收通过才合进 main、推 main |
| `docs/construction/README.md` | 记下临时仓库和以后并进 `miyu-agent` 的打算 |
| 施工图 | 0-3 的图纸 |

### 不做什么

- 缓存编译产物：现在编一次只要几秒，慢了再加。
- 拉取请求触发：现在没有别人提 PR，有了再加。
- 发布：临时仓库不发 Release，发布从并进 `miyu-agent` 以后开始。

### 拍板了的

1. 仓库名 `miyu-agent-remake`，公开（2026-09-26 项目主人）。
2. 提交历史不改：清理只改现在的文件，以前的提交里留着几行本机路径，里面没有密钥（2026-09-26 项目主人）。

### 我定的

- **Linux 钉 `ubuntu-24.04`**：发行构建以 glibc 2.39 为基线（`12-进程形态与分发.md` R11），CI 用同一个系统。macOS、Windows 用 `-latest`，它们没有这样的基线要求。
- **每台机器跑的就是 `cargo xtask check`**，和本地验收同一条命令，不在 CI 里另写一套。
- **`.gitattributes` 一律 LF**：Windows 检出时默认会把换行改成 CRLF，以后按字节比对的样本文件就对不上；日志文件的换行本来就一律是 `\n`（`07-存储.md` 第三节）。
- **CI 只有读仓库的权限**（`permissions: contents: read`）：公开仓库，给多少用多少。
- 推送由我来做；这张施工单拍板了，就是同意这一步的推送。

### 验收

1. 打开 https://github.com/SHORiN-KiWATA/miyu-agent-remake ：简介写着临时仓库，没有 issue、wiki。
2. `step/0-3-ci` 分支最近一次的 CI：三台机器都是绿的。命令行里看：`gh run list --repo SHORiN-KiWATA/miyu-agent-remake --limit 3`。
3. 读清理那个提交：`git show <提交号>`，看换的说明文字对不对。

验收通过后，我把分支合进 main、推送 main，main 上的 CI 再跑一遍；然后删掉分支，本地的和 GitHub 上的都删。

### 风险

- macOS、Windows 的机器可能有本地碰不到的问题，例如路径分隔符、换行。碰到了就在这一步里修，修法写进这张施工单。
