## 施工单 O-30：为什么叫你、回谁

状态：实测完，不加（2026-10-10；「每个回合都写明为什么叫她、回谁」是 18 第十七节已定的（Q5），规则进 system、标记进事实是 08 C3；这一步只有技术细节，照施工方案第一节第 1 条直接做。给模型看的字照 00 第三节：先实测证明不加不行，再加。实测没有标记也一样好，标记不加，蓝图、代码、资源都没改，见「实测结果」）。

### 目的

群里开的一轮，她现在只看到群聊近况和最后那条触发，不知道这一轮为什么开：是有人 @ 她（必须回），还是她刚回过这个人、他接着说（多半回），还是抽样、刚说过话（可回可不回，没话说就 `skip_reply`）。也不知道几条触发里该回哪一条（并进来的、顶替的）。这一步在桥开这一轮时（`session.respond` 的 `facts`）交一块短标记：回哪一条、为什么开。

### 先实测

在加字以前，用开发端点做一次对照（不进仓库的脚本，草稿目录），同一组群聊请求有标记、没标记各跑一遍，看两件事：
1. **该不该开口**：抽样、刚说过话开的一轮，这一句跟她无关、她插一句没意思的情形，她用 `skip_reply` 的比例；冲她来的情形她不该 `skip_reply`。
2. **回对人**：触发的那条是引用了别人一句问话的，她回的是触发的人还是被引用的人；几条并进来的，回的是不是最后那条。
每种情形至少 10 个、每个跑 2 遍以上；记下比例和花了多少 token。**没标记也一样好的，就不加，这一步只记实验结果、停下来报告。**

### 实测结果（2026-10-10）

**怎么测的**：开发端点（magpie 网关的 `clinepass/cline-pass/deepseek-v4.1-flash`），照核心给群会话拼的样子手拼请求：system 是人格（旧版的 `persona.md` 原文）接 `core/venues/group.txt`；tools 只有 `skip_reply`（`software/onebot/tools/skip_reply.json` 原文）；本轮 user 是几块字：`env` 事实、（有标记的）标记、`[Prior group chat records]` 加近况一行一条、触发一行一条（编号照 QQ 的 10 位数）。温度默认，一次请求只看第一步（调没调 `skip_reply`、说了什么）。五种情形，每种 10 个不同的例子，四个条件各跑 2 遍：
- **N** 没标记；**M** 有标记 `<turn reply-to="msg=…" why="…"/>`，system 不改；**R** 没标记，system 末尾加一句引用的规矩（`A reply-to line marks a quote: the quoted message is its author's, not said to you.`）；**MR** 有标记，system 末尾加一段说明标记怎么读加同一句引用的规矩（`Each turn opens with <turn reply-to=... why=...>: answer that message. why=direct means someone called you; for other reasons nobody did, so use skip_reply unless you have something worth adding.` 接上一句）。
- A 抽样（`sampled`）：两个人在说私事、对暗号，触发的那句和她无关；A 刚说过话（`after_speaking`）：她刚答过一句，后面两个人转去聊自己的事；A 冲她来（`direct`，对照）：@ 她问一句。前两种调 `skip_reply` 算对，第三种调了算错。
- B 引用：触发的人 @ 她说一件事，同时引用了别人问第三个人的一句；B 并进来：A @ 她、B 插一句（多半是问群里的话）、A 接着问正事，三条一起开的一轮，回的是最后那条。她没调 `skip_reply` 的回话另用一个模型（`clinepass/cline-pass/deepseek-v4-pro`）当裁判，盲判（裁判看的群聊不带标记、不带规则）：回的是触发的人（对）、把被引用的问话当成问她的（错）/ 主要回 B 插的那句（错）、两边都回了、别的。裁判判下来不是「对」的几条和每个条件随手挑的一组「对」的，自己读过一遍，和裁判一致。

**结果**（调 `skip_reply` 的次数 / 20；B 是裁判的结论）：

| 情形 | N 没标记 | M 有标记 | R 只加规则 | MR 标记加规则 |
|---|---|---|---|---|
| A 抽样，该不说 | 18 | 14 | 19 | 20 |
| A 刚说过话，该不说 | 20 | 15 | 19 | 19 |
| A 冲她来，不该不说 | 0 | 0 | 0 | 0 |
| B 引用：回对人 / 当成问她 / 两边 / 不说 | 18 / 0 / 1 / 1 | 20 / 0 / 0 / 0 | 20 / 0 / 0 / 0 | 20 / 0 / 0 / 0 |
| B 并进来：只回 A / 主要回 B / 两边 / 不说 | 15 / 0 / 4 / 1 | 20 / 0 / 0 / 0 | 15 / 0 / 5 / 0 | 20 / 0 / 0 / 0 |

- 没标记她已经分得清：抽样、刚说过话的 40 次里 38 次不说；冲她来的 20 次一次没误用；B 的 40 次里没有一次把被引用的问话当成问她的、没有一次主要回插话的人。
- 只加标记（M）反而更爱插话：该不说的 40 次里 11 次开了口（N 是 2 次），`why="sampled"` 没有说明，她把这块标记读成了「轮到你说了」。要标记管用得在 system 里配一段说明（MR），配上了也只和没标记打平（39 比 38）。
- 标记唯一的差别是 B 并进来时「两边都回」从 4–5 次变成 0 次：她顺带答了 B 插的那句（「今天周六。500 以内的键盘……」），不算回错人；没标记的两次「不说」各 1 次（冲她来的，不该），差 5 个百分点，在两遍的波动以内。
- 都没到施工单定的线（差 20 个百分点以上，或者某种情形没标记经常错）。

**标记多少 token**（照 `measure.py` 的办法，接在 `hi` 和一个换行后面，带行尾换行，编号 10 位数）：`why="direct"` 16、`sampled` 17、`after_speaking` 19；字段空的模板 10。每一轮开头一块，进了历史留到压缩。要它管用还得配 system 里那段说明 65（只有引用规矩那一句是 21）。

**花了多少**：一共约 570 次请求：主实验 400 次（输入 659,488、输出 119,552 token，每次输入约 1,650，大半是人格）；裁判 159 次（一次网关 500 重跑；输入 53,300、输出 92,454）；量 token 8 次；先试两次、列模型一次。脚本在草稿目录，不进仓库。

**没测到的**：只测了这一个模型；工具面只有 `skip_reply`（真的场所会话有十六件）；近况短（两到四条）；一轮只看第一步。

**结论**：不加。没标记她回得对、该不说的也不说；只加标记更糟，加标记再配说明也只是打平，每轮多十几个 token、system 多 65 个，换不来什么。蓝图、代码、资源都不改。重开条件：真群里的日志看到她回错人（把被引用的话当成问她的、回了插话的人），或者抽样、刚说过话开的一轮她老是硬说；换了更弱的模型。那时照这一节的情形和条件再测一遍。

**给核心的 system 规则**（`core/venues/group.txt`，核心的字，这一步不改）：引用的那句规矩（`A reply-to line marks a quote: the quoted message is its author's, not said to you.`，21 token）这次没有显出用处：没它 B 引用也没有一次当成问她的。建议先不加，等真群里看到这个错再加，字可以用这一句。标记要是以后加，system 里必须配一段怎么读它（上面 MR 那段，65 token），不配的会让她更爱插话。
