## 施工单 8-3：写配置

状态：待施工（2026-10-01，图纸 `docs/blueprint/config.md` 项目主人批准）。

### 目的

头和命令行能改配置，改的都是同一份文件，由核心经手（`14-配置.md` G4、G5、G6）：
- 只改那一项，别的字节一个不变，注释和排版都留着；
- 先写临时文件再替换，顺着符号链接写；
- 写之前查有没有被手改过，带版本号，防两个头同时改；
- 改动记进系统日志、账号日志（`journal.jsonl`）；
- 项目配置的信任有了命令 `config.trust`。

命令行有 `miyu config set`、`unset`、`edit`、`trust`。另外登记终端界面要的一项 `tui.startup`（2026-10-01 项目主人要）。

### 不做什么

- 监视文件、当场生效、`config.changed` 推给头：8-4。「改了以后头跟着刷新」是 8-4 的事。
- 密钥、`miyu login`：8-5。
- 设置页：M9。

### 验收

1. 测试（先写，退回改之前的代码要红）：照「守着它的」标 8-3 的行。
   - 改一项、加一项、删一项只动那一项（前后字节比），注释、排版、换行照原文件。
   - 顺着链接写；崩在改名前原文件不变；权限位留着。
   - `config.set` 每一种拒绝；`expect`、`version` 对不上；写之前发现手改过先重读；一次几项全收或者全不收；写不成什么都没变。
   - 日志记一条，和样本一样。
   - `config.trust` 信任、不信任、内容变了再问。
   - 四个子命令两种语言；`tui.startup` 进清单，三种语言齐全。
2. 手写变异 15 个左右，挑关键的，全被逮住；`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
3. 给模型看的字：没有，请求形状探针零变化。
4. 协议有新方法：合了告诉两个头，附 sha 和形状。
