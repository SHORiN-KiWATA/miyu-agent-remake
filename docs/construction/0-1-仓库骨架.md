## 施工单 0-1：仓库骨架

状态：已拍板（2026-09-26），施工中。

### 目的

仓库变成一个能编译的 Rust 工作区，施工和写代码的规矩写进仓库。这一步不写任何功能代码。

### 做什么

| 文件 | 装什么 |
|---|---|
| `Cargo.toml` | 工作区。成员都放在 `crates/` 下；统一的版本号、许可证、Rust 版本；统一的 lint（见「我定的」） |

| `README.md` | 仓库首页：Miyu 是什么、现在在施工、文档在哪 |

- 门禁（层序检查、文件行数检查）：0-2 做。
- CI：0-3 做，要先有 GitHub 仓库。
- 任何类型和逻辑：从 1-1 开始。
- 发行构建的配置（LTO、strip 这些）：`23-性能预算.md` 说原型阶段实测再定。

   - 定了：照推荐。

### 我定的

- **Rust edition 2024，依赖解析用第 3 版。** 新项目用最新的写法。
- **工具链钉死 1.97.0，不跟着 stable 漂。** clippy 每个版本都会加新的检查，跟着漂的话，哪天 Rust 一升级，没改一行代码 CI 也会变红。升级工具链单独做一步。
- **crate 统一叫 `miyu-<名字>`，放在 `crates/` 下。** 主程序 `miyu` 以后也放在这里。
- **lint 一开始就收紧**，现在代码是零，收紧不花成本：
  - 禁止 `unsafe`。以后沙盒助手要调系统接口时，只在它自己的 crate 里放开。
  - 不许不理会 `Result` 这类必须处理的返回值，也不许用 `let _ =` 或 `.ok()` 把错误悄悄扔掉（`00-设计理念.md` 第四节「不吞错误」）。真要扔，写 `#[expect(..., reason = "...")]`，理由就写在代码里。
  - 非测试代码不许 `unwrap`：内核从磁盘读到坏数据时，要报错，不能直接崩。`expect` 允许，它的说明文字写的就是「为什么这里不会失败」。
  - clippy 默认的那一套全开，警告在 CI 里当错误。更严的 `pedantic` 不开，误报太多。
- **worktree 放在仓库里的 `.worktrees/`**，所以 `.gitignore` 要忽略它。这一步自己的 worktree 是 `.worktrees/0-1-skeleton/`。
- **这份施工方案（`docs/construction/` 下的两份）先单独提交到 main**，等你批准方案之后、0-1 开工之前。它是文档，不属于 0-1 的代码。

### 风险

- 1.97.0 在别的机器上要先下载，rustup 会自动处理。本机已有的 stable 就是 1.97.0，但 rustup 把它们当成两个工具链，所以还是会下载一次。
- lint 太严，以后写代码会被频繁拦。缓解：每条都写了理由；真碍事的时候按「决定留痕」的规矩改，不悄悄加 `allow`。

### 附录：AGENTS.md 草稿

```markdown
# 给在这个仓库里干活的 AI

你是顶级的 Rust 工程师，也是顶级的 AI loop、AI Agent、AI Harness 设计师。

## 先读什么

- `docs/designs/`：设计文档，按编号读。它是决定的真相源，每份末尾的「决定」一节写着已定项、未选项和重开条件。
- `docs/construction/`：施工方案，和每一步的施工单。
- 旧版 Miyu 只是证据：它的实测数据可以引用，做法和参数不照搬。

## 施工的规矩

1. 一步一张施工单，先商量、拍板，再动手。
2. 一步一个工作树：从 main 开分支 `step/<编号>-<名字>`，检出到 `.worktrees/<编号>-<名字>/`。验收通过才提交，合成一个提交快进合进 main；不满意就删掉工作树和分支。
3. 每一步做完，仓库是绿的：编译、测试、门禁全过。
4. 先写证明它对的测试。修 bug 先写能复现它的测试，修之前它必须是红的。
5. 施工中发现设计有问题，停下来先改设计文档。
6. 不为以后写代码：这一步用不到的类型、字段、配置项不写。

## 代码的规矩

- 依赖只朝一个方向：crate 按层排，低层不许引用高层；内核和策略模块不碰任何 I/O（`00-设计理念.md` 第四节、`02-内核.md` K1）。
- 一个模块一种职责；加东西只登记，不改中心；能替换的接口都有契约测试；模块只拿自己的那一块。
- 文件小，不许出现包揽一切的上帝文件。
- 不吞错误：要么处理，要么如实上报。
- 朴素优先于巧妙。只有被测量证明是瓶颈的地方才允许技巧，并写清原因。
- 无硬编码：数值、文字、名单是数据，住在代码之外。
- 给模型看的字一律英文短句；中文只留给人格侧的字（`26-提示词.md` J3）。
- 注释用中文，名字用英文。

## 三个平台

- Linux、macOS（Apple 芯片）、Windows 上都要成立。平台差异关在边界上；代码问「这里能不能做」，不问「这是不是 macOS」。
- 路径、换行、编码都不写死。

## 测试

- 测试一律把 `MIYU_HOME` 指到临时目录，绝不碰真实数据。
- 量尺类的测试标 `#[ignore]`；断言结果，不断言耗时。

## 协作

- 用中文回复。每次回复末尾报总体进度和把握，用百分比，附上依据。
- 先定位问题、找到根因，再提方案，标出推荐项，拍板以后再动手。
- 不确定的点问项目主人，附推荐。技术细节按推荐定并留痕；产品和体验的取舍由项目主人拍板。
- 做完给出清楚的、能照着做的验收流程。
- 项目主人验收通过才提交。第一次发布以后，准备发布的改动在提交时记进 `next-release-note.md`，作为下次发布说明的草稿。
- 灵活用子代理节省上下文、提高速度，但不要滥用并行。
```
