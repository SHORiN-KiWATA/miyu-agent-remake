## 施工单 R-7（上）：合并

状态：已完成（2026-10-10 写、合；方向照 `memory.md` 第七条，2026-10-07 项目主人定；R-7 拆成上、下：上是合并本身，下是有了摘要以后常驻的那一块换成「摘要加之后新记的」（2026-10-09 项目主人定）；事件、配置项、`Extraction` 多的一格发核心的主会话看）。

### 目的

抽取只往里加，不去重、不改旧的。隔一段时间、攒够几个会话，把新记的和相关的旧记忆放在一起理一遍：重复的作废、被推翻的作废、相对的日期改成绝对的，写一段新的摘要。这一步摘要只记下、不交给她（R-7 下）；作废、改了的当场就从摘要那一块、搜的结果里没了。

### 蓝图改哪几节

- `memory.md` 第七条写细（什么时候、交什么、交回什么、怎么落、出错、日志）；「对外的样子」记忆日志多两种事件；「在哪」「守着它的」。
- `config.md`：`memory.merge_every`、`memory.merge_sessions` 两项（照 `MemorySettings` 的那几项写）。
- `26-提示词.md` 第十节：合并那一次请求的几份字，量 token 登记。

### 定了的（技术细节照推荐定）

1. **什么时候**：一间（房间）一把锁。每次抽取记下以后看一眼：这一间上次合并以后有新记的（现在算数、听众合、出处活着，不算合并自己改出来的那几条）；那以后抽过的会话（`ext.memory.extracted` 里不同的会话）够 `memory.merge_sessions`（起点 5）；离上次合并过了 `memory.merge_every`（起点 24 小时；没合并过的不看时间）：都够了就在后台合。同一间同一时刻只有一个；核心退了的这一回不合，下次抽完再看。
2. **交什么**：一条 user，指令在前，后面三块：现在的摘要（没有的写没有）、上次合并以后新记的（旧的在前）、每条新记的照关键词和意思搜出来的相关旧记忆（每条最多 3 条，去重，不重新记的）。一条一行，照 `memory_search` 的写法（`m12 feedback 2026-10-08: …`，换进去的字转义成一行）。最多 32 KiB：新记的放不下的照先后取老的，合完马上接着合剩下的。发出去以前遮 key（同抽取）。
3. **交回**：一个 JSON 对象 `{"revised": [{"id", "text"}], "retired": [{"id", "why"}], "summary": "…"}`，读法在 `miyu_recall::merge`：从第一个 `{` 到最后一个 `}`，读不成对象的整次失败；`id` 不是这一次交进去的、正文空的或超过 120 字的、`why` 空的那一条丢掉，别的照收；同一条又改又作废的照作废；`summary` 空的当没写，超过 600 字的截在句子边界上。
4. **怎么落**：落的时候还算数、听众合的才落。改的记成 `ext.memory.saved`（`replaces` 那一条，类、出处、听众、`about` 照旧的，`by` 是记忆模块，和原文一样的不记）；作废的记成 `ext.memory.retired`（`why` 照它写的）；摘要记成新的一种 `ext.memory.summary`（`text`、`upto`：合到记忆日志的第几条），不是一条记忆，不进记忆库；最后记 `ext.memory.merged`（`upto`、交了几条、改了几条、作废几条）。改的、作废的、摘要再遮一遍 key。
5. **模型**：`memory.organizer`（没写的照 `models.chat`），经一次性入口，用途 `memory`，记在会话属主的账上；不给工具、不设输出上限。
6. **出错**：不动真相，下次抽完再来；同一间连着三次不成的记一条 `ext.memory.merged` 标失败（`failed: true`），这一批跳过，记 `WARN memory merge failed`。
7. **日志**：`INFO memory merge started room=… given=…`、`INFO memory merged room=… revised=… retired=… took_ms=…`、`WARN memory merge failed room=… tries=… error=…`。
8. **配置项**：`memory.merge_every`（时长，`24h`，1 小时到 720 小时），`memory.merge_sessions`（整数，5，1 到 100）；两层、下一个回合生效，同抽取那几项。名字「多久归纳一次」「攒几次聊天再归纳」（设置页的字，项目主人验收时可改）。

### 不做什么

- 常驻的那一块交摘要（R-7 下）。
- 群里的记忆（听众不止属主）的合并：随 O 线。
- 排名（R-4 下）；人看合并改了什么的界面（头的事，`memory.list` 带 `forgotten` 看得到作废的、改掉的）。

### 验收

1. 测试先写，没实现时红：
   - `miyu_recall`：交回的读法（坏 JSON、不认识的编号、超长、空的 `why`、又改又作废、摘要截断）；底账记得上次合并、摘要、那以后抽过几个会话。
   - 会话（真会话、整理记忆的是假服务器）：够会话的才合、不够的不合；合过的、时间没到的不再合；交的那一条（指令、摘要、新记的、相关的、不交作废的和听众不合的）；落（改的指着旧的、类出处听众照旧，作废的带为什么，摘要、合并的记号）；放不下的分两次；出错不动真相、三次跳过。
2. 手写变异 15 个左右，全被逮住；`cargo xtask check` 全过；三台机器的 CI 和长跑全绿。
3. 真模型试几批（开发端点）：重复的作废了没有、推翻的作废了没有、改的对不对、摘要像不像、花多少 token，写进这一页。
4. 事件、配置项、`Extraction` 多的一格合之前发核心的主会话看。

### 风险

- 合并改坏了记忆（作废了不该作废的）：只追加，原文都在，`forgotten` 看得到；真模型多试几批再合。
- 一次合并交几十条、等十几秒：在后台，不挡会话；问句的向量一条最多等 1 秒。

### 验收记录（2026-10-10）

- 实现时改的一处（写进蓝图第七条第 6 款）：「同一批连着三次不成」原来照这一批合到哪认，测试里抽了三次、每次都多了新记的，永远到不了三次。改成同一间连着三次：这一批从哪起只在成了、跳过了的时候变，这两种时候都重新数，照起点认是多余的（变异测出来的）。「放不下的接着合」也不另记还剩没剩：接着合的那一次找不着新记的就停。
- 真模型试两批（开发端点 magpie 网关的 `clinepass/cline-pass/deepseek-v4.1-flash`，聊天和整理记忆同一个，临时数据根，人先记几条，再聊一轮，闲了抽、抽完合）：
  - 第一批七条（重复的「养了一只猫」「养了一只橘猫，叫团子」，推翻的「住在大阪」「上个月搬到了东京」，相对日期的「明天要去京都出差」，一条 feedback，一条不相干的）：聊天那一轮她看着摘要那一块自己用 `forget` 作废了「住在大阪」，抽取就整段跳过了；合并交了还算数的六条，作废了「养了一只猫」（「m2 已更具体地说明同一件事」），把「上个月」改成「2026年9月」、「明天」改成「2026年10月11日」；摘要「用户养了一只橘猫，叫团子；2026年9月搬到了东京，2026年10月11日要去京都出差；周末写Rust；希望回答先说结论，再给依据。」。一次请求输入 400、输出 793 token，4.5 秒。
  - 第二批九条（不冲突的「喜欢喝乌龙茶」「下午不喝咖啡」，中英两句一个意思的「回答要短」「The user prefers short answers」，推翻的「显卡是 RTX 4090」「上周把显卡换成了 RTX 5090」，相对日期的「下周三有一个面试」，两条不相干的）：不冲突的两条都留着；作废了英文那一条（「与 m3 重复」）、4090 那一条（「被 m6 取代」）；「上周」改成「2026年9月28日至10月4日那一周」、「下周三」改成「2026年10月14日」（试的那天是 2026-10-10 星期六，都对）；摘要照中文写、五句。输入 459、输出 2994 token（多是这个模型的思考），13 秒。
  - 结论：重复的、推翻的作废得对，改的日期都对，没有乱改不冲突的；摘要像「她对你的了解」。输出 token 随模型想多少浮动，在后台、记在用途 `memory` 名下。
