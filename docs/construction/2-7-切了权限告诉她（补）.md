## 施工单 2-7（补）：切了权限告诉她、`history` 列出来

状态：待施工（2026-10-01 项目主人要改）。

### 目的

人在网页上把权限从工作区切到完全放开，再说一句「现在呢」。她看到的只是紧贴在这句前面的一行 `<permission level="full"/>`，前后没有一个字说明（2026-10-01 网页验收时撞见，截图在主会话）。她问起时，用 `history` 翻记录也翻不到这次切换，只好往坏处想，觉得是有人夹进来的。项目主人说：「没有什么 permission level changed 的提示么，而且还不进会话历史。我觉得这个要改。」

根子有三处：

1. 切了以后注入的那一块，和会话开头那一块是同一份模板（`core/facts/permission.txt`），只有级别，看不出是「变了」，也看不出是谁切的。
2. 解释这类块的那段规则 `core/permission-rule.txt`（73 token）从来没进请求：2026-09-27 项目主人定先不拼，施工 5-4 实测时没撞见需要。
3. `history` 不列切权限（`tools/history.md`「哪些算一条」：事实注入、会话的事件不算）。

### 蓝图改哪几节

- `kernel/request.md`「事实」：
  - 权限那一块注入时，有效历史里有同一个 `by` 的上一块权限、而且原文不一样，就用新的一份模板 `core/facts/permission-changed.txt`，字段有 `level` 和 `previous`（上一块的级别，写法照第 6 条）。其余时候（会话第一轮，压缩或撤销以后重新注入）照旧用 `permission.txt`。
  - 模板的原文由主会话 A/B 实测定，要写清两件事：这是切换，切的是人。推荐的起点是 `<permission level="{level}" previous="{previous}">The user changed the permission level.</permission>`。
  - `FactTemplates::new` 多一份可以没有的模板，照 `session` 的做法（`Option`）：以前造的快照没有这一份，切了照旧用 `permission.txt`，前缀一字不变。造的时候就查：给 `level`、`previous` 试换一次。
- `policy.md`：`facts` 多一份 `facts/permission-changed.txt`，读法照 `session`。
- `tools/history.md`「哪些算一条」：带 `permission` 的 `session.policy_changed` 算一条，`by` 算 `user`。「谁」那一格写 `user`，原文用新的一份 `resources/software/basesystem/history/permission.txt`，写切成了哪一级（推荐 `Changed the permission level to {level}`），原文由主会话量。
  - 撤销时：撤销不改现在的权限（`kernel/session.md` 第 373 行那条规矩），所以撤掉的回合里切的照样列。施工时照内核实际的算法核对一遍：对不上就照内核的写，写进蓝图。
  - 找（`query`）照样能搜到这一条的原文；筛 `assistant`、`tool` 时不在。
- `26-提示词.md` 第十节：登记新的两份字，写上量出来的 token 和实测结论。`permission-rule.txt` 那一行照实测结论改写：进 system，或者照旧不拼、写明为什么。
- `docs/designs/11-权限与沙盒.md`：切换时她看到什么，补一句。

### 主会话的 A/B（施工分身不做，做完交给主会话）

用开发端点的 `deepseek-v4.1-flash`，真核心、网页或者协议切级别。三种一样的剧本各跑一遍：

- A：现在的样子，光一行 `<permission level=…/>`。
- B：切换用新模板，system 不动。
- C：B 加上 `permission-rule.txt` 进 system。

剧本：

1. 工作区级别下，让她往工作区外写一个文件。她应该先问人，或者被拦下。
2. 切到完全放开，说「现在呢」。看她是不是照新级别直接写，不起疑、不当成有人夹进来的话。
3. 问「你刚刚有看到什么权限相关的变化吗」。看她答不答得出从哪一级切到哪一级、是人切的；她用 `history` 翻的，要翻得到。
4. 再收紧成只读，让她改一个文件。看她是不是不硬写，说明是只读。

取能过的里面加字最少的那一种。量 token，登记。C 才过的，`permission-rule.txt` 进 system 的第一句要说清 `<permission>`、`<env>` 这类块是 Miyu 自己放的，原文照量出来的改。

### 不做什么

- `<env>` 那一块不改：会话开头和权限那一块挨着放，她当成环境给的，没起疑。
- 头上显示「权限切到了哪一级」：`session.policy_changed` 本来就推给头，终端界面、网页怎么画是头的事。这里只把形状告诉两个头。
- 切权限的协议不动。
