## 施工单 5-10（下）：按真实位置逐层打开

状态：已完成（2026-09-29：真模型自测过；变异全逮住；CI 全绿）。

### 目的

核心里的文件工具先把路径换成真实的位置、查边界，再打开。现在打开时只保证最后一层不是链接：检查完、打开前，上级目录被别的进程换成了链接，照样跟着走到别处（`11-权限与沙盒.md` 第七节记着的「这一版挡不住」）。改成路上一层链接都不跟：读的时候这样打开文件，写的时候这样打开上级目录，临时文件、改名都相对这个已经打开的目录做。

### 蓝图改哪几节

- `fs.md` 第四节「安全地打开」：Linux 用 `openat2` 带「路上不跟链接」，内核没有它的退回一层一层打开；macOS 用 `O_NOFOLLOW_ANY`；别的 Unix 一层一层打开；Windows 照旧。路上有链接的报「是链接」。
- `fs.md` 第五节「整体换成新的内容」：上级目录照第四节的办法打开；看原来的文件、建临时文件、改名、删临时文件都相对它。
- `fs.md` 第七节的已知限制、设计 `11-权限与沙盒.md` 第七节最后一条：Linux、macOS 上挡得住了，Windows 上照旧。

### 已定（我定的技术细节）

- 用 `rustix` 调这几个系统接口：依赖树里本来就有它（`miyu-basesystem`、`miyu-ipc` 在用），`miyu-fs` 里照旧不写 `unsafe`。
- 交进来的本来就是换过的真实位置，路上本来就没有链接：有了，就是检查完以后被换过，不开。
- Linux 上一层一层打开时，目录用 `O_PATH` 开：只要能走进去，不要求能读，和平常打开一样。别的 Unix 用只读开，要能读那一层目录。
- Windows 照旧：Windows 上的沙盒（5-9）暂停着，这一条和它一起记着。

### 不做什么

- 回收站：移进回收站走系统的接口，碰的是链接本身（`fs.md` 第六节），照旧。
- 往下走目录的 `glob`、`grep`：走的时候不跟链接，找到的文件照第四节打开，照旧。

### 验收

1. 测试：路上有链接的，读报「是链接」、写一个字节都不落到链接指的地方、也不留临时文件；Linux 上一层一层打开的那条路单独测；原来的测试照旧全过。
2. 请求形状探针的存档一个字节不变。
3. 手写的变异全被测试逮住；`cargo xtask check` 八项全过；三台机器的 CI 全绿。

### 验收结果（2026-09-29）

1. **测试**（新加 5 个）：路上有链接的，读报「是链接」（`tests/open.rs`）；写一个字节都不落到链接指的地方、不留临时文件（`src/replace/tests.rs`）；`nofollow` 自己：普通的打得开，路上、最后一层有链接的报 `ELOOP`，一层一层打开那条路单独测（链接照样不开、相对的不收、要目录开出来是文件的报不是目录）。修之前读、写的两个测试都是红的：读的那个顺着换过的上级目录打开了别处的文件。
2. **请求形状探针**的存档一个字节没变。
3. **变异**：8 个全逮住：openat2 不带不跟链接（红 3 个）、一层一层打开时不认链接、要目录开出来是文件也收、一层一层打开收相对的、上级目录照路径打开、只读的也写、盖不上去时不删临时文件、不照原来的权限（经 write 那一个测试逮住）。
4. `cargo xtask check` 八项全过（1274 个测试）；三个目标的 clippy 过；分支 CI 三台机器全绿，长跑也绿。
5. CI 上 macOS 那台第一回红了：O_NOFOLLOW 和 O_NOFOLLOW_ANY 一起写报 EINVAL，edit 读不出原来的文件。去掉 O_NOFOLLOW 以后三台全绿。这一步不改给她看的东西，不用真模型自测。

### 风险

- 容器里有的把 `openat2` 挡掉了：报「没有这个接口」或者「不许」的，退回一层一层打开，慢一点，照样挡得住。
- 别的 Unix 上，只能走进去、不能读的上级目录，打不开了：这种目录很少见，打不开时照原话报错。
