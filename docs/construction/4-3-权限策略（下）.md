## 施工单 4-3：权限策略（下）

状态：施工中。

### 目的

执行前的链有了默认的实现：权限策略。每个调用在派出去之前，照这几样判出放行、问人还是拒绝：
- 实际生效的权限级别；
- 这件工具要碰哪些路径，在边界表的哪一片（4-3 上）；
- 是读还是写，还是执行命令。

判法照 `11-权限与沙盒.md`：
- **数据根**：谁都不能碰，哪一级都拒绝。
- **完全放开**：别的都放行。
- **工作区这一级**：
  - 边界里的读写都放行；
  - 越界的读、写到只能读的地方，问人；
  - 执行命令，M5 之前放行（项目主人定）。
- **只读**：读照工作区的规矩；执行命令没有沙盒，每条都问人（A12）；写入内核早已拦下。

她给的工作目录太宽（系统的家目录、根目录，或者碰到数据根），就不拿它当工作区，退回账号的工作区 `home/<账号>/workspace/`（11 第四节）。

这一步还没有真的工具（第一批在 4-4），测试用会报路径的假工具。

### 不做什么

- 记住的放行规则（本会话都允许、这个工作区以后都允许）怎么照日志去用：人能回答确认以后才有用，随 4-9。这一步只提规则。
- 执行命令的放行规则（照命令开头记）：随 4-8 的 `shell`。只读时执行命令先只能选这一次或拒绝。
- 头上说一句「工作目录太宽，改用了……」：随 4-5 显示工具步骤。
- 联网、对外发消息的判法：做到那几件工具时再定（M4 里没有）。
- 成员：M4 只有管理员。

### 我定的

- **工具报它要碰的路径**：`Tool` 多一样，照这次调用的参数交回要碰的路径和是读是写，只看参数、不碰磁盘；默认一条都没有（例如执行命令）。换成真实的位置、查边界是链的事，工具不自己判。
- **一次调用碰好几条路径**：每一条判一次，照最严的合：有一条拒绝就拒绝，有一条要问人就问人。
- **判法**（M5 之前还没有沙盒）：

  | 这一条是 | 完全放开 | 工作区 | 只读 |
  |---|---|---|---|
  | 数据根里的 | 拒绝 | 拒绝 | 拒绝 |
  | 能读能写那几片里的读、写 | 放行 | 放行 | 读放行；写早被内核拦下，走到这里也拒绝 |
  | 只能读那几片里的读 | 放行 | 放行 | 放行 |
  | 只能读那几片里的写（`.git` 钩子、系统目录） | 放行 | 问人 | 拒绝 |
  | 边界以外的读 | 放行 | 问人 | 问人 |
  | 边界以外的写 | 放行 | 问人 | 拒绝 |
  | 执行命令（不报路径） | 放行 | 放行（项目主人定） | 问人（A12） |

- **路径换不成真实的位置**（指向不存在处的链接、没有家目录却写了 `~`、Unix 上还不存在的目录往上走）：拒绝，写明是哪一条、为什么。连它落在哪都说不清，没法问人。
- **拒绝时写给她的话**：数据根的，`"{path}" is inside Miyu's own data, which no tool can read or change.`；说不清在哪的，`Can't tell where "{path}" points: {reason}.`。和执行器替工具写的那两句一样放进快照；只读时的写，用内核现成的那一句。
- **问人时提的放行规则**：越界的那几条，照是读是写，各列出它们所在的目录（是目录的就是它自己）。本会话都允许、这个工作区以后都允许放行的就是这些目录。只读时执行命令的，先不提规则，只能选这一次或拒绝。
- **给头看的说明**：哪件工具，每一条路径、是读是写、在哪一片（边界以外、只能读）。头在 4-9 照它画确认的样子。
- **模块编号是 `permissions`**：拒绝的结果、问人的请求，`by` 都是它。
- **工作目录太宽**：头报来的是系统的家目录、根目录，或者包含数据根、落在数据根里（账号自己的工作区除外），就退回账号的工作区 `home/<账号>/workspace/`，没有就建。她看到的工作目录就是退回以后的这一个。
- **家目录**：核心起来时读一次，交给每个会话（`~` 照它换，工具链目录在它下面）。测试里换成临时目录里的一个假的家。

### 验收

1. `step/4-3b-guard` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 判法表的每一格（纯的判法，不碰磁盘）；几条路径照最严的合。
   - 会话里（假工具，临时目录里的家、工作区、数据根）：工作区里读写放行、真的跑了；越界的读问人，请求里有提的规则和说明，没人能确认的会话里被拒绝；数据根里的拒绝，结果写明是数据根，谁拒的是 `permissions`；完全放开越界也放行，数据根照样拒绝；只读时执行命令问人，工作区这一级执行命令放行；写 `.git/hooks` 问人；指向不存在处的链接拒绝、写明为什么；相对路径照这一轮的工作目录接。
   - 工作目录太宽：造会话时报来家目录、根目录、数据根里的，退回账号的工作区，目录建好了，她看到的工作目录是它；项目目录照旧。
3. 故意改坏一些地方，全部有测试变红。清单施工时列，照实记。
4. `cargo xtask check` 七项全过；推之前本机用交叉 clippy 查 Windows、macOS。

### 风险

- **每个调用都换一遍边界表**：十几个目录各换一次真实位置，调用不频繁，先不存；实测慢了再按工作目录存一份。
- **4-4 起真的工具接进来以后，`miyu ask` 还答不了确认**：越界的读会一直等着。4-4 里让 4-9 之前的 `miyu ask` 说自己没法确认，要问人的一律拒绝、告诉她原因（`22-命令行.md` O3 的做法）。
