### 不做什么

- `trash`：4-6（下）。撤销：4-7。
- 改完以后给她看改动的那几行：Claude Code 现在也只说一句改好了。她知道自己改成了什么，要看再读。
- 宽松匹配以后照文件原来的引号风格改写 `new_string`（Claude Code 会把直引号换回弯引号）：先不做，4-10 实测时看会不会出问题。
- 缩进不一样也算对得上的更宽松的一层（opencode 有九层）：图纸只定了三样，先照图纸做。

### 我定的

- **参数**：
  - `file_path`，`edits` 是一个列表，每一项 `old_string`、`new_string`，还有 `replace_all`（不写是 `false`）。
  - `replace_all` 是 Claude Code 有的：改名这类要把每一处都换掉，一处一处写太费事。写了它的那一项，对得上的每个地方都换，用不着唯一。
  - 照 Claude Code 的习惯写成一处的（顶层直接写 `old_string`、`new_string`、`replace_all`，没有 `edits`），当成只有一项的 `edits` 认；`edits` 写成一个对象而不是列表的，也认；`file_path` 写成 `path`、`filePath` 的也认，和 `read`、`write` 一样。`edits` 被写成一段字符串的，内核修正参数时已经还原了（施工 2-4）。
- **说明三句**：在一个文件里做精确替换，一次可以改几处；要先读过这个文件；每一处的 `old_string` 要和文件里的一字不差，连缩进，不带读出来的行号那一截，而且只对得上一个地方，除非写了 `replace_all`。
  - `write` 的说明补上第三句「只改一部分的用 `edit`」（施工 4-6 上说好的）。
- **找位置**：每一处都对照原文件找，不是改完一处再找下一处。
  - 先精确：只把文件里的 CRLF 当 LF 看。她读到的每一行已经去掉了行尾的 `\r`（施工 4-4 上），照她读到的写，CRLF 的文件才对得上。
  - 精确的一个都对不上，再宽松：另外还不管每一行末尾的空白，弯引号、各种破折号、各种空格当成普通的，做 NFKC 规范化（参考 pi）。
  - 哪一层对得上几个就是几个：精确的对得上两个，报不唯一，不往宽松那一层找。
  - 宽松只影响找位置：对上的那一段换成 `new_string`，别的地方一个字节不动。
- **改**：
  - 几处对上的位置有重叠的，一处都不改，说是哪两处。
  - 从后往前换，先换的不影响后换的位置。
  - `new_string` 里的换行照文件的换行写：文件是 CRLF 的，单个换行换成 CRLF。文件别的地方原样，编码、BOM 照原来的（施工 4-6 上的「文件的写法」，这里只换编码和 BOM，不整份换换行）。
  - 有一处出错的，一处都不改：要么全改，要么全不改。
- **改之前核对**：和 `write` 一样（施工 4-6 上），「她没读过」「读过以后被改了」挪成共用的，两件工具说同两句话，`write` 那两份字挪进 `common/`，字一个不改。
- **不改的**：
  - 文件不存在（照共用的那一句，带上相近的名字）、是目录、不是普通文件；
  - 不是 UTF-8、也不是带 BOM 的 UTF-16：解不开的字节改完写回去就坏了，说不是文本、要整份写的用 `write`；
  - `old_string` 是空的：新建文件用 `write`；
  - `old_string` 和 `new_string` 一样：什么都不会变。
- **没对上的，说最接近的在哪**（图纸要求的）：拿 `old_string` 第一行不空的那一行，跟文件里每一行比像不像（两个字一组，比有多少组相同），最像的那一行过了一半，就把从那一行起、和 `old_string` 一样多的几行照 `read` 的样子带上行号给她（最多 10 行），她照着改。没有像的只说没找到。
- **不唯一的，说在哪几行**：最多列 10 个行号，让她多带几行上下文，或者写 `replace_all`。
- **哪一处**：出错的都说是第几处（从 1 数起），只有一处的也这样说。
- **结果**：改好了说一句，路径照结果的规矩写；报 `file.changed`；给人看的「改了 3 处」。
- **给人看的字**：显示名「编辑」，后面跟 `file_path`；没对上的「第 2 处没找到」，不唯一的「第 1 处对得上 3 个地方」，重叠的「第 1 处和第 2 处重叠了」。

### 验收

1. `step/4-6b-edit` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 参数：`edits`、写成一处的、`edits` 写成一个对象的都认；什么都没给的报参数不对。
   - 找位置：精确；CRLF 的文件照 LF 写的对得上；行尾空白、弯引号、破折号、全角空格对得上；精确的不唯一不往宽松找；宽松也对不上的给最接近的几行；不唯一的给行号；`replace_all` 全换。
   - 改：几处一起改、从后往前、对照的是原文件；重叠的一处都不改；有一处出错一处都不改；宽松对上的那一段换掉，别的地方一个字节不动；CRLF 的文件里新加的行是 CRLF，原来的混着的换行不动；BOM、UTF-16 照原来的。
   - 不改的：没读过、读过以后被改了、不存在、目录、不是文本、`old_string` 空的、改前改后一样。
   - 效果和说法：报的 `file.changed` 改前改后对得上；给人看的说法，中文、英文两份字里都有。
   - 会话里用真的工具：她读了再改，日志里的效果对得上，blob 存着改前改后的内容。
3. 故意改坏若干处，全部有测试变红（清单写完测试以后补）。
4. `cargo xtask check` 七项全过；推之前本机用交叉 clippy 查 Windows、macOS。

### 风险

- **宽松匹配对错了地方**：只在精确的一个都对不上时才用，而且宽松那一层也要唯一；对上的是哪几行，结果里不说。4-10 实测时看有没有对错的。
- **工具面又多一件**：前缀从下一个会话起变；`write` 的说明也改了一句。登记簿记下；预算 4-10 定。
- **新加一个 crate**：NFKC 规范化用 `unicode-normalization`（Rust 里通用的那一个），只在基础系统里用。
