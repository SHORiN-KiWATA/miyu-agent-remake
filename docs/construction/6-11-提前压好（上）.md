## 施工单 6-11（上）：提前压好、到线换上

状态：施工中（2026-10-08 写；项目主人 2026-10-07 提、同一天照推荐定，`09-压缩.md` 第十节、Z11；技术细节主会话定）。

### 目的

用量过了起压线，就在后台把尾巴前面那一大段压好；到了压缩线，尾巴放得下就直接换上，不再停下来等摘要。到线以前前缀一个字节都不改。

### 开工前量的 G

照旧版的 `cache-usage` 日志离线量（2026-10-08，不算 codebuddy，只算一轮里接着往下的那几步，尾巴放宽的效果没算进去，只作参考）：

| 压缩线 L | 提前量 G | 起压到到线之间长出来的超过 T + G 的 | 起压到到线中间走了几步（中位） | 起压到到线用时（中位） |
|---|---|---|---|---|
| 80K | 4K | 50% | 1 | 98 秒 |
| 100K | 9K | 37% | 1 | 112 秒 |
| 130K | 16K | 22% | 1 | 137 秒 |
| 167K | 16K | 21% | 1 | 49 秒 |

窗口 200K 上下的会话，大约五次里有四次用得上；中间多半只隔一步、一两分钟，摘要请求来不来得及写完要真会话量（6-11 下）。G 先照设计定的 min(16000, L/4 − T)。

### 这一步做什么

1. **起压**：每次发主请求之前，和查压缩线同一处。用量在 [L − G, L) 之间、开关开着、熔断没暂停、没有一次在路上、手里没有一份还用得上的，就照现在的切法（同一个尾巴预算 T）切出 N，发一次旁路请求，主请求照发、排在它前面。G = min(lead, L/4 − T)，`lead` 是策略里的数，出厂 16000；G 是 0 的不提前压。
2. **请求**：和当场压的 fork 式摘要请求一样（有效历史到 N 的投影加摘要指令，看不了图的照样换成转述），走旁路请求那一路：`Action::Aside`，`purpose` 是 `compaction`，名字是 N。不碰「上一次请求」，不算步数。
3. **收**：说完了记一条 `model.called`：不带回合编号，`purpose` 是 `compaction`，`seen` 是 N，**不带 `compaction` 那一格**。取到了摘要只放在内存里，不另记事件。
   - 调了工具、策略里有隔离式的：照隔离式再发一次（同一个 N），只再一次。
   - 出错、取不出摘要的：扔掉，不重试，不数进熔断；执行器的那一行收场记成 `WARN`。
4. **到线**（自动压缩），**手动压缩没附要求的**：手里有一份压好的，而且还用得上（见下），N 以后的尾巴不超过 T + G 的，换上：
   - 照现在的规矩交执行器重读 N 以前读过、改过、尾巴里没碰过的文件（重读放在换上这一刻做，原文是最新的；没有候选的当场写）；
   - 重读回来了写 `context.compacted`（`upto` 是 N、摘要是那一份，`trigger`、`refills` 照这一次的），照常压后重建、比事实；
   - 推 `compaction.done`，多一格 `prepared: true`，`usage`、`duration_ms` 是提前那一次的；不推 `compaction.progress`。
   - 等重读的这一会儿是一个新的阶段（「换上」）：打断、重启照「准备好」收拾，那一份扔掉。
5. **用不上的**，扔掉，照现在的办法当场压：
   - 还在路上（6-11 上照当场压，晚到的扔掉；等它、接着推进度是 6-11 下）；
   - 尾巴超了 T + G；
   - 作废了：有效历史里 N 以前的变了（撤销撤到了 N 或更早、清空、中间压过一次），检查点和 N 以前还算数的事件序号算一个指纹，起压时记下，换上前比；
   - 开关这一轮关着；被动压缩；手动压缩附了要求的。
6. **开关** `compaction.prepare`：默认开，系统配置、个人设置两层，下一轮生效，设置页「高级」里一组「压缩」。会话 actor 在回合开始冻结配置时读它，跟着 `TurnStartHooksDone` 交给内核（多一格 `prepare`）；不开回合的手动压缩照上一轮的。
7. **运行日志**：`compacted` 那一行多一格 `prepared=yes`（换上的才写）；`took_ms` 照旧是摘要请求的用时。起压时记一行 `compaction request`（旁路请求照用途记的那一行），收场照旁路请求的写法。

### 主会话定的技术细节

1. 重读放在换上的那一刻，不在起压时：起压到到线中间她还在干活，shell 改的文件内核看不到，起压时读的会过时。执行器的重读是当场读完就送回，多出来的阶段只有一眨眼。
2. 作废照指纹认，不一处处挂钩子：撤销、恢复、清空、压缩、撤掉压缩都会改有效历史里 N 以前的样子，比指纹一处管全。
3. `lead` 放在策略快照的压缩数里，和尾巴一样：以前的快照读成出厂的 16000；快照的字节多一格（新造的会话才有）。
4. `took_ms` 不改成「换上那一刻花了多久」（设计写的）：那一刻只等一次本地重读，几毫秒；省下多少等照日志里前后两次主请求的间隔量（6-11 下），`took_ms` 留着照旧对摘要请求的用时。
5. 测试里策略的 `lead` 写 0 就不提前压，原来的测试一个字节都不变；随机测试另配一份提前压的（三个种子里有一个开着，另用一串随机数）。
6. 手里那一份用不上了（作废了、尾巴已经超了 T + G）的，下一次过起压线时扔掉、照新的 N 另压一份：尾巴只会越来越长，留着它到线也用不上。
7. 被动压缩不经过换上那一处（它照自己的切法当场压），换上的只有自动压缩和没附要求的手动压缩，不另判 `trigger`。

### 头要知道的

- `model.called` 多一种 `purpose`：`compaction`。不带回合编号、不带 `compaction` 格，可能落在一轮的中间，也可能最后没换上。照带 `purpose` 的辅助请求算用量、画时间线，不画「压缩失败」。
- `compaction.done` 多 `prepared: true`（没有就是当场压的）：前面没有 `compaction.progress`，直接印「上下文已压缩」。
- 设置页多一项 `compaction.prepare`，照配置清单画。
- 6-11 下还会有：到线时它还在路上的，从那一刻起推进度，第一条的 `written` 不一定是 0；它出了错改当场压，`written` 会变小。

### 不做什么

- 到线时在路上的等它回来、接着推进度（6-11 下）。
- 真会话量 G、省下的等、白花的次数（6-11 下）。

### 验收

1. 测试先写，退回改之前报红：起压的时机（线下不起、过了起压线起、在路上不再起、压好了不再起、G 是 0 不起、开关关着不起、暂停着不起）；请求和当场压的一样、走旁路；`model.called` 的样子；换上（不请求、重读、`prepared`、`refills`、手动没附要求的也换）；用不上的几种（在路上、尾巴超了、撤销撤到 N、清空、中间压过、开关关了、附了要求、被动）；出错、取不出、调了工具改隔离式；换上那一刻打断、重启；配置项、`TurnStartHooksDone` 的 `prepare`、运行日志那一格。随机测试：提前压、换上和撤销、手动压缩、清空、打断随机交错，看守照规矩查。
2. 请求形状探针不变（探针的策略不提前压）。
3. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。

### 验收结果（2026-10-08）

1. **测试**：
   - 内核（`scenario/prepare.rs`、`prepare_drop.rs`，十二个）：过了起压线旁路发、请求照有效历史到 N、`model.called` 不带回合和 `compaction`；到线换上，只多一次主请求、`prepared`、不推进度；起压线以下、开关关着、G 是 0、小窗口不起；在路上的、压好了还用得上的不再起；在路上的不等，当场压、晚到的只记一条；尾巴超了、撤销撤到 N、清空、开关在到线前关了、附了要求的照当场压，只撤尾巴的照用、撤到 N 的另压一份换上新的；出错、空的扔掉；调了工具照隔离式再来一次（`system` 是隔离式的），隔离式也调了工具的不再来；重读在换上时做，读到的是起压以后改过的。
   - 随机测试：三个种子里有一个开着提前压，看守查一次至多一个在路上、请求的清单、`model.called` 的样子、换上的替代到它的 N 和它的正文、交了重读的后面不跟摘要请求、`prepared` 只在换上时带，载入以后全忘；三百例走到「提前压了」「提前压好了」「提前压没成」「换上了提前压好的」，两万例的长跑本机 38 秒过。
   - 真会话（`miyu-session`）：配置没写（默认开）的过了起压线旁路发一次、到线换上不再请求，`compacted` 那一行带 `prepared=yes`、有 `compaction request`；提前压出错记 `WARN compaction failed`；`compaction.prepare = false` 的照当场压。
   - 配置：`compaction.prepare` 默认开、两层、下一轮生效；Schema 和参考文件的样本重写；快照多 `lead`，以前的读成 16000。
2. **探针**：没变（探针的会话不在起压的区间里）。
3. **变异**：手写 23 个，22 个当场逮住。「指纹不算检查点」没逮住：检查点一换（压缩、清空、撤掉压缩），N 以前还算数的事件序号跟着变，指纹照样不一样，是等价的；留着它当保险。「提前压出错不记 WARN」原来没逮住，在 `prepare_log.rs` 里补了一个出错的会话，逮住。
4. `cargo xtask check` 八项全过。
