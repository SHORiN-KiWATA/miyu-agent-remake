## 施工单 4-9：门禁（三补）

状态：已完成（2026-09-28：三台机器的 CI 全绿、长跑也绿、测试全过，照施工方案第一节第 1 条算验收通过）。

### 目的

补完蓝图时留下两件要写代码的（`4-9-补完蓝图（补）.md`「不做什么」）：
- 给模型看的字没有一页汇总：登记簿（`26-提示词.md` 第十节）只列文件和数字，原文散在 `resources/` 下，要看得一份份打开。项目主人问过「所有 AI 能看到的 prompt 的汇总在哪」。
- 蓝图 README 说「标着样本的块，测试逐字节比对，补完蓝图时把比对做进门禁」，还没做：工具那几页照抄的说明原文、`miyu ask`、`miyu undo` 的两段终端样本，改了一边另一边不会红。

这一步两件都做进门禁的「文档」那一项。

### 蓝图改哪几节

- 新页 `prompts.md`「给模型看的字」：按进到请求的哪里分组，组里照登记簿的先后；每一份写什么时候加进来、多少 token、为什么加、指纹，下面是原文。这一页由 `cargo xtask prompts` 生成；`cargo xtask check` 照资源目录和登记簿重算一遍，和仓库里的不一样就红。
- `README.md` 第三节：「样本」块怎么写：块前一行以 `` 样本 `<路径>` `` 开头，门禁把块里的字和那份文件逐字节比（块里的字加一个换行，就是文件的全部字节）。路径指到 `resources/` 下的，比的就是原文；终端输出这类，路径指到 `docs/designs/samples/` 下的一份，由测试照着造出来比。只是举例、比不了的，写「例子」，不写「样本」。
- `tools/read.md`、`glob.md`、`grep.md`、`write.md`、`edit.md`、`trash.md`、`shell.md`：说明和参数的原文块改成「样本」，指到各自的 `resources/software/basesystem/tools/<工具>.json`。
- `cli/ask.md`、`cli/undo.md`：两段终端样本指到 `docs/designs/samples/cli/ask-text.txt`、`undo-text.txt`；测试照蓝图的场景造出输出，和这两份逐字节比。
- `log.md`：「样子」那一段是举例（时刻、编号是编的），改叫「例子」。

### 要拍板的

- 没有。汇总页照 README 已经定的分组，原文照字节，是技术上的写法。

### 不做什么

- 设计文档里引的原文、样本：4-9（四补）设计只留为什么时一起去掉。
- 给人看的字（`human/`）的汇总：不进请求，不登记（`26-提示词.md` 第八节）。

### 验收

1. `step/4-9k-gate` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`（xtask 的测试也跑）：
   - 汇总页：照一张小登记簿和三份资源生成的一字不差；组照第一次出现的先后、组里照登记簿的先后，每一组、每一份只写一次；原文里有三个反引号的，围栏加长；末尾没有换行的照原样放。在临时仓库里：还没生成的说要生成；资源改了、登记簿改了、页面手改了，都说要重新生成。
   - 样本块：对得上的过；块里多一个字（说从第几个字节起不一样）、少一行空行、指到的文件没有、「样本」后面没写路径、后面没有块、块没有收尾，各报一条；长围栏里的三个反引号不算收尾；「样本会话」这样的正文不算；子目录里的页也查。
   - `ask-text`、`undo-text`：测试照蓝图的场景造出的屏幕，和样本文件逐字节一样（路径照 Unix 的写法比）。
   - 仓库里：生成的 `prompts.md` 一千多行，七页工具说明的样本块和资源文件一字不差。
3. 故意改坏 10 处，10 处有测试变红：页面不一样也算对得上、同一组写两次、围栏不加长、原文末尾的换行不去、组里不照登记簿的先后、块和文件不比、「样本」后面不要空格、见到三个反引号就收尾、子目录不看、从第几个字节算错。写清单时补的测试缺口 2 处：`check()` 本身原来没有测试，改成在临时仓库里查；同一组写两次原来只找了第一次出现的，改成数只有一次。
4. `cargo xtask check` 七项全过（1062 个测试）；推之前用交叉 clippy 查 Windows、macOS。

### 风险

- 改一句给模型的字要多做一步：跑 `cargo xtask prompts` 重新生成汇总页。门禁说清楚该跑什么。
