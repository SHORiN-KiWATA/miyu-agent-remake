## 施工单 O-13（下）：群聊近况

状态：已完成（2026-10-09 合进 main，`b309fbaa`，CI run 1311；2026-10-09 写；格式照 `18-通讯平台.md` 第九节「群聊近况」（2026-10-07 定）和旧版的 `[Prior group chat records]`（`26-提示词.md` 登记簿「群聊近况的格式、缺口提示：照搬」）；O-13 由主会话拆成上、中、下，技术细节主会话定）。

### 目的

她在群里不是每句都回：不冲她来的消息桥记成旁听（O-13 上），不开回合。轮到她说话时，要知道上次说完以后群里聊了什么。这一步把两次回合之间的旁听消息、撤回的标记、别的线替她发出去的话，在开这一轮的那条前面渲染成一块「群聊近况」。

### 这一步做什么

1. **取哪些**：群会话里，开一轮的那条人的消息（`turn.started` 的 `trigger`）前面放一块近况。收的是上一个这样的触发之后、这一条之前的：
   - 旁听的 `message.user`（`venue.ambient`），睡着时收到的（`asleep`）不收；
   - 别的线发进这个群的话（`venue.delivered` 的 `line` 不是这个会话）：写成 `[HH:MM] [you] [msg=<编号>]: <正文>`，带的图每张写一个 `[image]`。主线自己的回复已经是 assistant 消息，不重复。
2. **一行**照 O-13（中）的写法，只要字：带的东西写成 `[image]` 这样的记号，图片块不接进来。
3. **撤回的标记**：这一条之前记下的 `venue.recalled` 撤的是近况里的哪一条，在 `[msg=…]` 后面写 `(recalled)`；撤的人不是发的人、这一条又看得到身份（`show_ids`）的，写 `(recalled by <身份>)`。之后才撤的不改：已经发过的请求里那一块不动。
4. **预算**：从最新往前装，装满 80000 字节就停（照旧版）。前面还有没装下的，块头下面多一行缺口提示，说更早的用 `history` 取。
5. **块的样子**：头一行 `[Prior group chat records]`（`core/venues/recent-open.txt`），有缺口的接缺口提示（`core/venues/recent-omitted.txt`），下面一行一条，照日志的先后。一块是一个文本块，排在回合开始注入的事实后面、触发的那条前面（`18-通讯平台.md` 第九节 C2：触发消息在最后）。一条都没有的不出这一块。
6. **字节稳定**：一块里收哪几条、写什么，只看这一轮的触发以前的日志，这一轮开了以后就定了；以后每次请求重新渲染，一字不差。

### 主会话定的技术细节

1. 「上一次」照上一个由人的消息开的回合的触发算，不照上一次请求看到的最后一条：旁听的从不进上下文，上一轮回合进行中到的旁听也归这一块；手动压缩单开的那一轮、回报开的回合不算界。
2. 近况在组装那一层算（`miyu-assemble` 的 `group.rs`），不另记事件：它是日志的投影，不是注入（18 第九节）。
3. 判断「别的线」要知道这个会话自己的编号：内核的有效历史记下它（`History::own`），造会话、载入时由内核设上；组装器照它比 `venue.delivered.line`。
4. 预算、两句字随群会话进快照（`group.recent`，`{open, omitted, budget}`）：O-13（中）造的群会话快照里没有，读成没有，不出近况，字节不变。
5. 撤回、`[you]` 的写法是格式（代码），和 `reply-to:`、`@mentions:` 一样；块头、缺口提示是句子（资源，登记）。

### 不做什么

- 交给别的线的标记（「另一条线正在回」「你已经回过」）：要桥记支线的事件，等支线（18 第八节）。
- `history` 里群里的消息写上是谁说的：另一步。
- 开一轮的触发有好几条（`turn.started.triggers`）：O-14。

### 验收

1. 测试先写，改之前红：近况只收两次触发之间的旁听、不收睡着的；别的线的 `[you]` 行，自己的不收；撤回的标记（自己撤的、别人撤的、看不到身份的），触发以后才撤的不标；预算装不下的从老的去掉、写缺口提示；放在事实后面、触发前面；没有的不出；私聊、O-13（中）的快照不出；以后的请求里那一块一字不差；载入以后一样。
2. 登记簿：两份字照 DeepSeek 官方量 token、写指纹。
3. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
