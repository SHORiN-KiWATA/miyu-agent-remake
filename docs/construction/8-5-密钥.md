## 施工单 8-5：密钥

状态：已完成（2026-10-01，图纸 `docs/blueprint/config.md` 项目主人批准；验收结果见最后一节）。

### 目的

模型供应商的 key 这类密钥单独放，不写进配置文件（`14-配置.md` G9）：
- 密钥在 `system/secrets.toml`，Unix 上权限 0600，只经核心改；配置里只写引用 `{ secret = "名字" }` 或 `{ env = "环境变量" }`。
- 协议 `secret.set`、`secret.delete`、`secret.list`：只能写、删，从不交出值。
- 命令行 `miyu login`、`miyu logout`、`miyu login --list`（照 opencode、codex，项目主人 10-01 定）：贴 key 不回显。
- 密钥的值不进回应、推送、运行日志、报错、日志文件。

这一步只把密钥存好、引用写法认得出。真的拿它去连供应商是 8-6 以后的事，开发用的 `DEEPSEEK_API_KEY` 这一步照旧。

### 蓝图改哪几节

图纸是 `config.md`，只读标着 8-5 的这几处：
- 「在哪」：`miyu-config/src/secret.rs`、`miyu-store/src/secrets.rs`、`miyu-endpoint/src/secrets.rs`、`miyu-cli/src/login.rs`、`login/`，帮助页 `login.txt`、`logout.txt`，样本 `secret.changed`。
- 「文件」表 `system/secrets.toml` 那一行；类型表「密钥」那一行（这一步加这种类型）。
- 「报错」表 `unknown_secret`、`env_not_set` 两行；「协议」的 `secret.set`、`secret.delete`、`secret.list`、原因码 `unknown_secret`、日志 `secret.changed`。
- 「怎么走」第九条密钥、第十一条 `miyu login`/`miyu logout`；第二条第 1 款（起来时读密钥文件）、第 10 款（`config_errors` 算上密钥文件）、第七条第 3 款（监视加 `secrets.toml`）。
- 「出错」`WARN secrets readable by others`、`INFO secret changed`；「给人看的字」标 8-5 的；「守着它的」标 8-5 的行。
- 成员的密钥放自己家目录：M8 只有管理员，照图纸「谁能改」的说法，多用户那一段再做。

### 不做什么

- 供应商、拿密钥去连模型：8-6 以后。
- 成员自己的密钥：多用户那一段。
- 系统钥匙串（macOS Keychain、Secret Service）：图纸没定，不做。

### 验收

1. 测试（先写，退回改之前的代码要红）：照「守着它的」标 8-5 的行。
   - 写、换、删、列（`used_by`、配置里引用了却没设的也列）。
   - Unix 上 0600，别人读得到的记 WARN。
   - 值不进回应、推送、运行日志、报错、日志文件：整份运行日志和 `journal.jsonl` 里搜不到值。
   - 引用写法：`{ secret = … }`、`{ env = … }` 认得出，没设的报 `unknown_secret`、`env_not_set` 警告。
   - `miyu login` 贴 key 不回显、`--list`、`miyu logout`，两种语言。
   - 手改 `secrets.toml` 被监视看到。
2. 手写变异 15 个左右，挑关键的（泄漏值的那几种一定要有），全被逮住；`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
3. 给模型看的字：没有，请求形状探针零变化。
4. 协议有新方法：合了告诉两个头，附 sha 和形状。

### 风险

- 安全：值漏进任何一处可见的地方都算没做完。测试里的假 key 用一眼看得出是假的字串，别用真的。
- 和 C-4 同时做：那一张碰 `history` 和会话表端口，这一张碰配置、存储、端点的 `secrets`、命令行。冲突多半在 `Cargo.lock`、`protocol.md`、帮助页，主会话合并时解。
