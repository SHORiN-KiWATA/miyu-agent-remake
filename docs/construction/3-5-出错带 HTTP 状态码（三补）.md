## 施工单 3-5（三补）：出错带 HTTP 状态码

状态：已完成（2026-09-30）。

### 目的

模型调用出错时，把供应商回的 HTTP 状态码单独记一格：`model.called` 的 `error`、推给头的重试状态（`status` 的 `retry`）多一个可以没有的 `status`。终端界面要照它分出 429（限速、额度不够）、402（额度用完）、404（端点地址或模型名不对），前面加一句人话（2026-09-30 项目主人定的界面说法，由终端界面演示的会话转来）。现在状态码只埋在原话开头的「HTTP 404: 」里，404 分进 `other`，402 和 401、403 一样分进 `auth`，头分不出来；项目主人 09-29 定过「字符串不当类型」，头不从原话里抠。

### 蓝图改哪几节

- `kernel/events-bodies.md`（`model.called` 的 `error`）、`kernel/events.md`（瞬时的 `status` 的 `retry`）：多 `status`，HTTP 状态码，整数；没有状态的（连不上、流里报的错、内核自己查出来的）不写。形状 `{"class":"other","message":"HTTP 404: …","status":404}`。读到没有这一格的旧日志照读。
- `drivers/openai-chat.md`（出错分类）：有状态码的照写进 `status`；原话开头的「HTTP 404: 」照留（给人看的原话不变）。
- 样本：`docs/designs/samples/events/model.called.jsonl`、瞬时 `status` 的样本各加一条带 `status` 的。

### 不做什么

- 不改分类（404 照旧 `other`，402 照旧 `auth`）：分类管的是内核怎么办（重试不重试），界面的说法照状态码另说。
- `miyu ask` 印出错的说法不动（命令行照旧印分类的说法和原话）；要跟终端界面一样加人话，另开一步问项目主人。

### 验收

1. 测试（先写，退回改之前的代码要红）：驱动的出错分类各状态码都带上 `status`，连不上、流里报的不带；`model.called`、`status` 的读写一字不差，没有这一格的旧样本照读；重试状态照 `model.called` 的带过去。
2. 手写的变异全被逮住；`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。

### 风险

- 构造 `CallError` 的地方多（二十来处），漏一处编译器会拦；和并行的 7-3、7-6 碰到同一个文件的，后合的那一个解。

### 验收结果（2026-09-30）

1. 先加上两格、各处构造先填「没有」，再写测试，这时 4 个红：驱动的出错分类各状态码（400、401、402、403、404、408、413、429、500、503）带上 `status`、原话开头照留，连不上的、流里报的（`code` 是 429 也算）不带；HTTP 执行器回 429 带上，连不上、流里报的不带；会话经假服务器限速，日志里的 `model.called` 带着 429；重试状态照 `model.called` 带过去（429 的带、连不上的不带）。改驱动分类、重试两处以后全过。`model.called` 带 404 的读写一字不差，没有这一格的旧日志照读、写出去还是没有；样本 `model.called.jsonl` 加 118 号带 429 的一条，`status.jsonl` 加 117 号带 429 的一条，44 号那条没有这一格的照旧。
2. 手写 6 个变异全被逮住：驱动不写（3 个测试红）、驱动把流里的 `code` 也写进去（2 个）、重试不带过去（1 个）、`model.called` 没有时写成 `null`（5 个）、重试状态没有时写成 `null`（1 个）、`status` 排到原话前面（2 个）。`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
