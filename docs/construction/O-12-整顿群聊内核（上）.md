## 施工单 O-12（上）：整顿群聊内核：编号和类型

状态：已完成（2026-10-07；只有技术细节，照施工方案第一节第 1 条直接做；分身施工，主会话审；中途主会话闪退一次，分身照记录接着做完）。

### 目的

O 线自查（2026-10-07）查出群聊内核几块的输入类型各写各的，和核心已有的类型重复，编号的写法也没统一；`chat.md` 第七条（和核心的接口，2026-10-07 定）定了编号和投影。这一步照它把编号和类型统一起来，免得接上核心时返工。行为不变（抽样的种子除外，见下），测试照旧守着。

### 蓝图改哪几节

`docs/blueprint/chat.md`：
- 第二条（进站链）、第三条（算分）、第四条（顶替与分派）、第五条（出站）、第六条（判官）的「对外的样子」：
  1. 时刻、时区：`Clock { now, offset }` 的两格换成内核的 `Timestamp`、`UtcOffset`；回复、提示、回合、在判的时刻都用 `Timestamp`；窗口、时长照旧是毫秒数。
  2. 场所编号：`Venue` 多 `id() -> VenueId`、`parse(&VenueId) -> Option<Venue>`，写法 `<平台>:group:<群号>`、`<平台>:private:<对方的号>`（第七条第 1 条）；用到场所编号的地方都是 `VenueId`。
  3. 平台上的人：`ExternalId`（`<平台>:<号>`），`Venue` 旁边一对拼和解。
  4. 群聊内核里的一条消息：内核的 `Seq`（场所主线会话日志里的序号）；`Facts.msg`、`Pending.msg`、`Pending.absorbed`、`Supersede` 里的都换成 `Seq`。
  5. 抽样的种子改成 `SHA-256(场所编号 + "\n" + 序号的十进制)`（第七条第 1 条）。旧日志还没有落地，改了不影响回放；测试里钉的两个值重新另算（用 Python 的 hashlib 另算，写在测试注释里）。
  6. 图的哈希：内核的 `ContentHash`（`Outgoing.images`、`Sent.images`）。
  7. `Reply.to` 改成平台上的人的列表（一轮可以回几个人，第七条第 4 条的投影）；续聊：最近一轮回的人里有这个发的人。
  8. 进站链的 `Inbound` 和算分的 `Facts` 重复的格（发的人、他是谁、正文、是不是冲她来的……）合成一份「一条消息的事实」，两边都用它；只有一边用的格留在那一边。
  9. 违规的门槛只留一份：在 `Chatty` 里，判官的 `Ask` 从它拿，不另存。
- 第一条「施工时定的」第 3 条那张表旁边写明：「离得最近的键名」和配置共用 `miyu_config::problem::nearest`（它改成收一串名字）；`why()` 也共用配置那一份。
- 每条「施工时定的」补上这一步定的，写清是 O 线自查以后改的。
- `docs/designs/18-通讯平台.md` 第一节「代码放在哪一层」：`miyu-chat` 依赖内核、`miyu-config`，外部只用白名单里的（照实写）。第四节规则例子里 `probability = 0.08` 改成千分比 `80`。

`crates/miyu-config/src/problem.rs`：`nearest` 改成收一串名字（迭代器），原来的调用照旧；`parse.rs` 的 `why` 开成公开的（只改可见性）。

### 不做什么

- 停下的规则记名字、旗带上解出来的字、「冲她来」挪进来、构造函数、改名、拆文件：O-12（下）。
- 出厂参数、场所规则覆盖插件参数：O-15。
- 桥（`miyu-onebot`）：O-8 在分支上，等它合了再照这一步改桥里用到的地方。

### 验收

1. 原有的测试照新类型改，行为不变；抽样的种子按新写法重钉两个值；有新的格（`Reply.to` 是列表、`Venue::id`/`parse`）的先写测试，退回改之前的代码要红。
2. 手写变异 15 个左右，全被逮住（编号的拼法、解析、种子的写法、续聊的「包含」、时区换算……）。
3. `CARGO_BUILD_JOBS=5 cargo xtask check` 全过；跑之前看一眼有没有别的门禁在跑，跑的时候撞上了不算、重跑。
4. 分支推上去，三台机器的 CI 和长跑全绿。

### 风险

- 改动面大，几块一起动：一块一块改，每改完一块测试全绿再动下一块。
- 内核的类型不合用（例如 `local_minute` 交回的是字、不是一天里的第几分钟）：在群聊内核里照内核类型的公开方法算，内核缺的只在图纸里记下，不改内核。

### 验收结果（2026-10-07）

1. **测试**：原有的照新类型改，行为不变；新的格（`Venue::id`、`parse`，平台上的人的拼和解，`Reply.to` 是列表）先写、退回改之前是红的。抽样的种子按新写法用 Python 的 hashlib 另算两个值钉住（`qq:group:123456` 序号 7 是 462，`qq:private:10002` 序号 42 是 512）。`miyu-chat` 228 个、`miyu-config` 128 个全过。
2. **变异** 20 个，全被逮住：场所编号种类写死、解析从后面切、解析不查号、拼的时候不查平台、人从最后一个冒号切、种类认反、种子不加换行、种子大端、续聊只看第一个、时区换算反号、纪元前取整、限流窗口远端含、顶替取最早、重判序号先后反、顶替窗口时刻对调、最近一轮不含此刻、闸写不出时放行、门槛写死、去重不看发过的图、最近的名字一样近取后面的。
3. **门禁** 八项全过（跑之前等别处的全工作区测试跑完；中途有一次撞上别的门禁、`miyu-session` 偶发红了一个，不算，重跑全过）。
4. **CI**：三台机器和长跑全绿（run 1087）。
5. **图纸**：内核没有「一天里的第几分钟」，照 `Timestamp`、`UtcOffset` 的公开方法自己算，没改内核，第二条记了一句；18 第一节照实写依赖，第四节 `probability` 改成千分比 80。
