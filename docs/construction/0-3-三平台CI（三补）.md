## 施工单 0-3（三补）：测试并成每个 crate 一个程序

状态：施工中（2026-10-08 写；项目主人 2026-10-08 照推荐定：先做缓存、长跑提速，量了 Windows 还慢再做这一条；0-3 补量出来缓存只省 Linux 两分钟，Windows 还是 25 分钟上下，主会话照推荐接着做；技术细节主会话定）。

### 目的

CI 上 Windows 一次 25 分钟，大头是工作区自己的 crate 和 294 个集成测试程序一个个链接。并成每个 crate 一个程序，链接从几百次降到几十次。

### 定了的（技术细节，主会话定）

1. 每个有集成测试的 crate：`Cargo.toml` 写 `autotests = false`，另列 `[[test]] name = "all", path = "tests/all.rs"`；`tests/all.rs` 一个文件一个模块（`mod <名>;`），`support` 只声明一次，各文件里的 `support::` 换成 `crate::support::`。文件不挪地方：蓝图里测试表写的路径照旧对。
2. 装 tracing 订阅者的（`set_global_default`、`subscriber::set_default`、`subscriber::with_default`）照旧各是各的程序，在 `Cargo.toml` 另列：调用点第一次被碰到时记下谁在听，是全进程的，同一个进程里别的测试同时碰到，这里装的订阅者可能漏听（并的时候 `miyu-http` 的 `log.rs` 就这么红了一次）；全局的一个进程只能装一次。一共 25 个。
3. 不并：`miyu-sandbox`（测的是把进程关进沙盒，另有一个 `tests/macos/main.rs` 的程序）、`miyu-log`（只有一个文件）。
4. 门禁多一项（「测试」那一格）：`autotests = false` 的 crate 里，`tests/` 下每个 `<名>.rs`、`<目录>/main.rs` 要么是 `all.rs` 的一个模块、要么在 `Cargo.toml` 里另列；漏了的报出来（关了自动找以后，漏掉的文件既不编也不跑，门禁原来照样绿）。
5. 转换照脚本做，脚本只改代码里的 `support::`，字面量、注释里的不动（头一回连测试数据里的字也换了，`miyu-assemble` 的存档对不上，换了法子）。
6. `AGENTS.md`「测试」多一条规矩。

### 验收

1. 本机整套测试连跑三次都绿；`cargo xtask check` 八项。
2. CI 三台和长跑：和没并之前（run 1191：ubuntu 9 分 7 秒、macOS 12 分 18 秒、Windows 25 分 36 秒）比，记在下面。

### 施工结果（2026-10-08 主会话）

1. 16 个 crate 并了：集成测试程序从 294 个降到 47 个上下（16 个 `all`、25 个装日志订阅者的、`miyu-sandbox` 的 5 个、`miyu-log` 的 1 个）。文件都没挪，`support::` 换成 `crate::support::` 的只是代码里的。
2. 并的时候撞上的：`miyu-http` 的 `log.rs` 用的是这个线程的订阅者（`set_default`），并进去以后漏听、红了，所以「另列」的条件从全局订阅者扩到这个线程的；`miyu` 的 `dev_home.rs` 里原样编进来的 xtask 模块也叫 `dev_home`，并进去成了 `dev_home::dev_home`，clippy 不让，改名 `xtask_dev_home`。
3. 门禁多的那一项：`xtask/src/test_targets.rs`，三条单元测试（都进了程序、漏了的报出来、没关自动找的不查）。
4. 本机整套测试连跑三次都绿（139、90、207 秒，机器忙闲不一）；门禁八项 156 秒。
5. CI（run 1196，四项都取到了缓存），和没并的 run 1191（也取到了缓存）比：

| 项 | 没并（run 1191） | 并了（run 1196） |
|---|---|---|
| ubuntu | 9 分 7 秒 | 4 分 41 秒 |
| macOS | 12 分 18 秒 | 7 分 54 秒 |
| Windows | 25 分 36 秒 | 15 分 11 秒 |
| 长跑 | 2 分 31 秒（没取到缓存） | 3 分 3 秒 |

一次合并要等的从 25 分钟上下降到 15 分钟上下（等最慢的 Windows）。
