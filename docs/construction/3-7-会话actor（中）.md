## 施工单 3-7：会话 actor（中）

状态：施工中。

### 目的

把内核的会话状态机接上磁盘：一个会话一个 actor，人的命令和执行器的回报都进它的收件箱，一条一条送进内核，内核交出的动作照 `02-内核.md` 第四节的表回。追加的事件写进会话日志、同步到磁盘了，才回应命令、才推给订阅的头。造会话时照人格拼出策略快照、存成 blob；载入时照日志第 1 条的哈希取回来，接着跑。

请求模型交给一个端口。这一步测试里照剧本回，下一步（3-7 下）接上真的 HTTP。

### 拍板的

无：只有技术细节（施工方案第一节第 1 条）。

| `docs/designs/02-内核.md` 第七节 | 「会话 actor 怎么跑」 |
| `docs/designs/07-存储.md` 第四节 | 「写不进去」 |
| `docs/designs/28-运行日志.md` 第二节 | 会话那几行的例子照这一步的写法 |
| `docs/designs/01-架构.md` 第九节 | 第 4 层多一个 `miyu-session` |
| 施工图 | 3-7（中）那一张 |

动作怎么回：

| 动作 | actor 做什么 |
|---|---|
| 追加事件 | 在阻塞线程里写进会话日志、同步，写完送回「落盘了」 |
| 回应命令 | 交给等着这个命令的那一个；同一个编号来了两次，照先后各回一次 |
| 推送事件、推送瞬时事件 | 交给订阅了的头 |
| 跑回合开始的挂接点 | 还没有模块，当场送回「跑完了」，不注入 |
| 请求模型 | 交给端口；它的回报（发出去了、增量、说完了）进收件箱 |
| 到点叫醒 | 起一个定时的任务，到点了送回「到点了」 |
| 不要这次请求了 | 叫端口停下这一次 |
| 跑回合结束的挂接点 | 还没有模块，什么都不做 |
| 工具那四种 | M4 以前工具面是空的，内核发不出来：发出来了就是 bug，记一条 `ERROR`，不理 |

运行日志（来源 `session`，会话编号跟着 span 写在来源后面）：

| 级别 | 这件事 | 键值 |
|---|---|---|
| `INFO` | `created` | `persona`、`venue` |
| `INFO` | `loaded` | `events`：载入了几条 |
| `INFO` | `request` | `seen`、`endpoint`、`model` |
| `INFO` | `ended` | `seen`、`took_ms`、`in`、`hit`、`out`；供应商报了写缓存的，再加 `write` |
| `INFO` | `failed` | `seen`、`took_ms`、`class` |
| `INFO` | `cancelled` | `seen`、`took_ms` |
| `WARN` | `retrying` | `seen`、`attempt`、`limit`、`wait_ms`、`class` |
| `INFO` | `stopped` | 有计划地停下 |
| `INFO` | `closed` | 没有人再拿着这个会话了 |
| `WARN` | `write failed, stopped` | `kind`：出错的种类，例如 `StorageFull` |
| `ERROR` | `kernel bug, stopped` | 无 |
| `ERROR` | `tool action without tools` | `action` |
| `DEBUG` | `input`、`action` | `kind`：哪一种；增量和执行中的输出记在 `TRACE`，发行版里没有 |

### 不做什么

- 真的请求模型（驱动编码、HTTP、解码）：3-7（下）。
- 会话表：照编号找会话、没在跑的载入、空闲一段时间退出（`07-存储.md` 第七节）：随协议端点（3-8）。
- 订阅的补发（从某个序号之后补发）、视图流：3-8 以后、M8。
- 环境变了（工作目录、时区）送进会话：头要用的时候再加。`miyu ask` 每次开新会话，造的时候带上。
- 挂接点的模块、工具：M4 以后。
- 选哪个模型、从配置里读端点：3-9 以前定。

### 我定的

- **一个会话一个 tokio 任务**，收件箱是两条：人的命令一条，执行器的回报一条。拿着 `Handle` 的都放下了，命令那条就关了，actor 退出；回报那条 actor 自己拿着一头，不会自己关。
- **两条都不设上限**：发命令的都要等回应，一个连接自己就刹得住；执行器的回报来自同步的回调（HTTP 读流时交出增量），不能等。
- **当场就能回的输入**（落盘了、挂接点跑完了）不回收件箱，放进本地的队列，先于收件箱里的送：和执行器替身（`miyu-kernel` 的 `testkit`）一个先后。
- **写盘在阻塞线程里做**（`spawn_blocking`）：同步到磁盘可能要几十毫秒，不占异步线程。actor 等它写完才往下走。
- **写盘经一个内部的端口**：平时是会话日志，测试里换成写不进去的，查停下的那条路。不对外。
- **写不进去就停下这个会话**：记一条 `WARN`，写出错的种类，不写路径；等着回应的命令收到「会话停了」。没落盘的不算发生，再载入时照磁盘上的来。
- **内核 panic 也停下**：接住，记一条 `ERROR`，停下这个会话，别的会话照常。
- **推送用 tokio 的 broadcast**：一份推送所有订阅者共用，一个会话发一次。读得慢的订阅者被挤掉了会收到「掉队了」，照 `04-核心协议.md` 第七节当成 resync：停掉这个订阅，头重新订阅。队列 1024 份。
- **请求模型走端口 `ModelPort`**：`model()` 交回端点和模型名，`call()` 马上返回，回报经 `Reports` 送进收件箱，叫停经 `Cancel`。只有明着叫停才算叫停，丢掉不算。3-7（下）接 HTTP，以后资源调度夹在中间。
- **时钟**：系统时间，到毫秒。系统时间往回拨了，照上一次的：一个会话里的时刻不往回走。
- **会话编号用 UUIDv7**（`uuid` crate）：前 48 位是毫秒时间，按时间排得开；随机数取自系统。
- **造会话的先后**：先把策略快照存成 blob（先落 blob，再写引用它的事件），再建会话目录和日志，再交给内核造会话；`session.created` 落了盘才回应造会话的命令，造会话这一步等到这个回应才交回 `Handle`。
- **载入**：打开日志（自检、截尾，施工 3-2），照第 1 条的策略哈希取快照、造策略，交给内核载入。它吐出来的动作照样回：有计划的重启打断了的一轮，接着干。
- **会话的 span**：`error_span!(target: "miyu::session", "session", session = %编号)`，actor 的任务带着它；端口派出去的任务要自己带上当前的 span（下一步的 HTTP 行靠它带上会话编号）。
- **请求的用时**从交给端口算起，到说完、出错或者叫停：人等的就是这么久。

### 验收

1. `step/3-7b-actor` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 造会话：会话目录里的日志第 1 条是 `session.created`，它记的策略哈希在 blob 里；造会话的回应在落盘以后。
   - 说一句：照剧本回一句话。日志里依次有人的消息、回合开始、事实、`model.called`、她的回复、回合结束；订阅者先收到事件，后收到回应；增量也收到了。
   - 重试：剧本先回一次可以重试的错（等得很短），到点以后再请求，说完。
   - 打断：请求停住时打断，端口收到叫停，回合结束。
   - 停下再载入：有计划地停下，从磁盘载入，再说一句，这次的请求接着上一次的往下长。
   - 写不进去：会话停下，等着的命令收到「会话停了」，运行日志里有那条 `WARN`。
   - 掉队的订阅者收到「掉队了」，别的订阅者照常。
   - 运行日志：`created`、`request`、`ended`、`retrying`、`stopped` 这几行照上表写；日志里没有对话的字。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --workspace --exclude miyu-http --target` 查 Windows、macOS。

### 风险

- **当场回的输入和收件箱的先后**：照替身的做法，本地的队列清空了才看收件箱；测试里照替身的剧本跑，查日志的先后。
- **阻塞线程池**：tokio 默认最多 512 个阻塞线程，几千个会话同时写盘也只是排队，不会卡死异步线程。
- **会话停了以后回报还在到**：送不进去，丢掉。定时的任务到点了也一样。
