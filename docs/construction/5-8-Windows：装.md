## 施工单 5-8：Windows：装

状态：已完成（2026-09-29：分身施工，变异全逮住；项目主人在虚拟机桌面上看过管理员确认；合进来以前接上 5-4（上）、5-7，CI 三台机器全绿）。

### 目的

Windows 上装沙盒要的、要一次管理员权限的那件事做出来：建一个专用的低权限沙盒用户（藏起来）。沙盒只管读写权限，不管网络（2026-09-29 项目主人定），所以不装网络规则。做成一个能单独调起的动作 `miyu sandbox setup`，卸载用 `miyu sandbox remove`；安装脚本（R12）做出来以后调它。每条命令具体怎么跑（受限令牌、单独桌面），是 5-9，不在这一步。

### 蓝图改哪几节

- 新的一页 `sandbox/windows.md`：`miyu sandbox setup`/`remove` 的样子和退出码；沙盒用户怎么建、怎么藏、密码怎么存；装好以后记的那份记录；要管理员那一次怎么弹。（README 分页表这一行由主会话合并时加。）


### 不做什么

- 每条命令怎么关进沙盒：受限令牌、访问控制、单独桌面、git 的 `safe.directory`——5-9。
- 权限策略给调用带规格、沙盒用不了改成问人——5-4。
- 安装脚本本身（R12）；这一步只做它以后要调的那个动作。
- Linux 上的 AppArmor 配置怎么装：5-3 定。

### 验收

CI 的 Windows 机器测不了要管理员、要真机的部分，在 Windows 虚拟机上实测：

1. 门禁 `cargo xtask check` 八项全过；两个目标的交叉 clippy 都过。
2. 单元测试：命令行解析、记录文件读写（数据根和 SID 照参数给的）；非 Windows 上 `setup`/`remove` 是空动作、退出 0。
3. 虚拟机上 `miyu sandbox setup`：沙盒用户建出来了、在登录界面藏着、是普通用户不是管理员；记录写在本人的数据根里，只有本人和 SYSTEM 读得到。
4. `miyu sandbox remove`：用户没了、记录文件清了；报告里写清虚拟机上还剩什么。
5. 管理员那一次弹窗：虚拟机的 UAC 设成了管理员免提示（`ConsentPromptBehaviorAdmin=0`），从 ssh 进去本就是提升过的，所以看不到弹窗；报告里说清默认 UAC 的桌面上才会弹一次，怎么在虚拟机桌面上验。

### 验收结果（2026-09-29）

1. **测试**：这一步加了 69 个测试：装沙盒的 48 个（Windows 上才有的 12 个，其中会真建用户的 5 个标 `#[ignore]`、只在虚拟机上跑），`miyu sandbox` 怎么走、说的话 16 个，参数写错时 1 个，主程序 4 个；帮助页的检查跟着加了 `sandbox` 那一页。`cargo xtask check` 八项全过；两个目标的交叉 clippy 都过。
2. **CI**：run 36450719870 三台机器全绿，长跑也绿。前两次 Windows 上红过，都是这一步自己的毛病，改了：主程序照可执行文件的名字说自己（`miyu.exe sandbox …`），clap 的名字定死成 `miyu`，另加一条拷一份改名跑的测试，Linux 上也照得出来；CI 上跑测试的是内置管理员，系统把它的 SID 写成 `LA`，比访问控制改成比它本身、不比写法。
3. **虚拟机上真装真卸**（Windows 11 专业版，中文，26200；ssh 进去是提升过的，走的是「是管理员」那一路）：
   - 装：印一句、退出 0；账号启用、说明 `Miyu sandbox`、密码不过期、自己改不了密码、只在 `Users` 组、登录界面藏着；记录一行，访问控制是受保护的「SYSTEM + 本人」；密文头上的标志是机器范围，解开 32 个字符，照它以沙盒用户登录成功（profile 建出来了）。
   - 再装：SID 不变、密码换了。卸：账号、profile 目录和它的登记、`UserList` 里那个值、记录都没了；再卸也成。
   - 给的地方不是数据根：说一句、退出 1，账号没建、一个字节没写；拼得进访问控制的 SID 不收。
   - 提升那一路：在桌面会话里用没提升的令牌（`Administrators` 只用于拒绝、中等完整性）跑 `setup`、`remove`，`runas` 起了提升过的自己、印出结果、退出 0（这台虚拟机设成了管理员免提示，所以没弹窗）。提升过的自己没成（事先放一个叫 `miyu-sandbox` 的管理员账号）：等它的那一个照它写下的原因说「已经有管理员账号」、退出 1，原因读了就清，那个账号一点没动。
4. **变异**：手写 35 个，全被测试逮住（Linux 上 27 个，Windows 虚拟机上 8 个）。另有一个等价的：访问控制去掉「受保护」那一位，建出来照样是受保护的（带着访问控制新建的文件本来就不继承），留着它只为写明意图。
5. **虚拟机上留下的**：测试建的账号、profile、计划任务、临时文件都清了。留着的：`SpecialAccounts\UserList` 这把钥匙（第一次藏用户时建的，里面我们那个值卸的时候删了，钥匙是系统的位置，不删）；`C:\Users\shorin\src\remake` 这份源码和编出来的东西；第一次编译装上的工具链。
6. **弹一次管理员确认**（2026-09-29 项目主人在虚拟机桌面上看过）：UAC 改回默认，在没提升的 PowerShell 里跑 `setup`，弹了确认，点「是」装好（中文界面印「沙盒用户建好了。」，退出 0），登录界面上没有这个用户；再跑一次点「否」，印「要管理员权限：用管理员身份跑 miyu sandbox setup。」；`remove` 点「是」撤掉，`Get-LocalUser miyu-sandbox` 找不到。

### 风险

- 沙盒用户的密码要存起来给 5-9 登录用：DPAPI 加密（机器范围：提升可能换了一个管理员账号），存进本人的数据根（沙盒读不到），文件的访问控制只给本人和 SYSTEM。
- `miyu sandbox` 子命令要动 `crates/miyu/src/main.rs` 的分发（可能和 5-4 同碰一个文件）：只加一条分发臂，别重排。
