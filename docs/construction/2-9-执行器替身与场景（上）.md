## 施工单 2-9：执行器替身与场景（上）

状态：施工中。

### 目的

一个守规矩的执行器替身：照剧本回模型、回工具、回执行前的链、回挂接点，替会话落盘，把真会话一整轮一整轮地跑完。拿它写场景：一段段对话从头跑到尾，每一段查整份日志。

2-9 拆成两半：（上）执行器替身与场景；（下）请求形状探针和随机日志改用真会话跑，照图纸推日志的假内核退役。1-14 做探针的时候还没有回合状态机，只能照图纸推出日志来；现在有了，探针该查真内核记下的日志。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-kernel/src/testkit.rs`、`testkit/script.rs` | 剧本：模型每次请求说什么（说一句、调几件工具、出错；说到一半停住，等放行）；每次调工具怎么回（结果、出错、问人；跑到一半停住）；链怎么判；挂接点交回什么。默认放行、不注入 |
| `crates/miyu-kernel/src/testkit/stage.rs` | 执行器替身：照 02 第四节的表回每个动作。人的每个动作（说一句、急着插话、打断、回答确认、回答提问、切权限、撤销、恢复、换工作目录、过一段时间）以后，一直跑到没事可做；停住的请求、调用，等剧本放行。有计划地重启、崩了再载入 |
| `crates/miyu-kernel/Cargo.toml`、`src/lib.rs` | `testkit` 开关；内核自己的测试里总是编进去 |
| `crates/miyu-kernel/src/session/tests/scenario.rs`，按需拆几份 | 场景，见下 |
| 施工图 | 2-9（上）那一张；2-9 拆成两格 |

场景，每段查整份日志（一条一行：序号、种类、`by`、`turn`）、请求了几次、命令的回应：

1. 问一句、答一句。
2. 两件只读的工具一起跑，结果倒着回来；工具在跑时说了一句，下一步听到了。
3. 请求在路上时说了一句，再打断，排着的接着发，下一轮由它触发。
4. 切成只读，写文件的调用被拦下，她换个说法说完。
5. 要确认：允许这一次；拒绝并写了理由，她接着干。
6. 她问一组题，你回答，工具拿到回答写成结果。
7. 走到步数上限；请求出错。
8. 撤销上一轮，恢复，再说一句。
9. 跑到一半有计划地重启，再起来接着干；崩了再载入，那一轮收尾，你再开口接着说。

### 不做什么

- 探针、随机日志改用真会话：2-9（下）。
- 随机测试的整理（输入列成一个枚举、每一步查九条不变量、合进 main 前长跑）：2-10。
- 替身不模拟写盘失败、网络断开：那是存储执行器（3-2）、HTTP 执行器（3-5）的事。
- 真的工具、真的驱动：M3、M4。

### 我定的

- **替身放进内核，挂在 `testkit` 开关后面，不另开 crate**：组装那边的测试要用它（2-9 下），可分层表规定工具 crate 不许被别的 crate 依赖（`01-架构.md` 第九节规则 5）。内核自己的测试里总是编进去。它不做 I/O，纯逻辑门禁照样查它。
- **替身照 02 第四节的新表回**，不多送、不乱送：乱送的、先后错了的，交给随机测试（2-10）。
- **一块内容一次送完**（开始、全文、结束），不逐字送：逐字拼接 2-2 测过了，场景看的是一整轮。
- **追加的事件马上落盘**：落盘前后的先后 2-1 测过了。
- **时钟**：每送进一条输入往后走一秒；「过一段时间」手动拨。日志读起来像真的，重跑还是一样的字节。
- **剧本用完了还要请求模型、调工具，当场 panic**，写明是第几次请求、哪次调用：那是剧本写错了，不是内核错。
- **`ask_user` 拿到回答以后的结果**：替身写一句英文「The user answered: …」，真的写法随 M4 的 `ask_user` 定。
- **载入要用的策略**：策略里有组装器，不能复制，替身留一个「造策略」的函数，重启、崩了再载入时各造一份。

3. 故意改坏替身和内核的几处，场景、替身的测试变红（施工时列出）。

### 风险

- **替身比真执行器宽松，场景就测不出真执行器会碰到的问题**：替身照 02 第四节的表逐条做；表没写到的，先补表再写替身。
- **场景把日志写死了，内核一改就得跟着改**：这就是图纸的用处。改的时候对照图纸，确认是有意改的。
