## 施工单 8-11（再补）：`miyu setup` 改成常用的几家加自定义

状态：施工中（2026-10-08 写；项目主人 2026-10-08 在通讯平台的会话里试 `miyu setup`，原话「一点都不考虑用户需要什么」，转来以后同一天在这里定了；技术细节主会话定）。

### 项目主人定的（2026-10-08）

1. 先给常用的几家，可以选一家，也可以选「自定义」。几家照推荐：DeepSeek、OpenAI、Anthropic、OpenRouter、Kimi、智谱、通义、opencode Zen；本机跑着 Ollama、LM Studio 的另列一行。
2. 自定义：依次填 base URL、接口协议（OpenAI 兼容、Anthropic、OpenAI Responses，就是核心现在会说的三种）、key。
3. 填完去取模型列表让人选；取不到列表的印「未获取到模型列表」，让人自己填模型名（「你为什么执着于说人话，这是软件啊！`未获取到模型列表`不就好了吗！！」）。
4. 环境变量里已经有 key 的，那一家后面标「已找到 key」，选它不用再贴。

### 这一步做什么

**核心**

1. 常用的几家放在资源目录 `resources/models/featured.toml`：照先后一家一项，`catalog` 是目录、档案里的编号，写了 `catalog_zh` 的中文界面用它（国内的地址：Kimi、通义），名字一句字或者照语言的表。
2. `provider.catalog` 多一个参数 `featured`（布尔，不写是假）：写了的不看 `query`、`limit`，照这份的先后交回目录、档案里有的那几家，每一家的写法照原来的，`name` 换成这份写的（照这个连接的语言挑），`id` 是照语言挑好的那个编号。目录里没有的跳过。头的第一次引导照它列，和 `miyu setup` 一样。

**`miyu setup`**

3. **选一家**：`provider.detect`、`provider.catalog {"featured": true}`，列成一张表：常用的几家（找到了 key 的后面接「已找到 key」，已经配好的接「已配好」），本机跑着的服务（「本机」），最后一行「自定义」。不再搜整份目录。`--provider` 照旧能写目录里的任何一家。
4. **自定义**：问「Base URL：」，再列三种接口协议选一个，再问 key（不显示，直接回车是不要 key：本机的服务、不要 key 的中转）。配置里的编号照地址的主机名起（`api.example.com` 是 `example`，本机的、IP 的是 `local`），撞了的往后加 `-2`、`-3`；写 `driver`、`base_url`、`keys`。
5. **取模型列表**：`provider.test`。列不出来的（`stage` 是 `list`）印「未获取到模型列表」，问「模型名：」，拿它再试一次；读到头、空的是「没选」。列出来的照原来选。试不通的照原来那一行说哪一步不通、回到上一步。
6. 给人看的字照短的软件说法（「已找到 key」「已配好」「本机」「自定义」「未获取到模型列表」「模型名：」「Base URL：」「接口协议：」），两种语言。

### 主会话定的技术细节

1. 常用的几家住资源目录、经 `provider.catalog` 交出去：两个头的第一次引导和 `miyu setup` 列的是同一份，改它不用改代码。
2. Kimi、通义照界面语言挑地址：中文界面用国内的（`moonshotai-cn`、`alibaba-cn`），别的用国际的。智谱目录里只有国内的一个。
3. 自定义的编号由核心这边（`miyu setup`）照地址起，不让人填：照 [[design-for-user-needs]]，能定的不让人填。
4. 搜整份目录那一步去掉：项目主人要的是几家加自定义；目录里别的几家照旧能经 `--provider` 和配置文件用。
5. 填了模型名试通的，不再列模型、不再问，也不说「照 models.dev 的目录列」：人已经说了用哪个，列不出的再列是空的。
6. 自定义的 key 试不通，回到贴 key（和目录里的一家一样）；空 key 的不带 `key`，配置里写 `keys = []`。
7. 「核心看不到」那一句的办法改成「选这一家、把 key 贴进来」：已经没有「从目录里选」这一步。
8. 出厂的 `featured.toml` 写的每一个编号，照出厂的目录快照和档案都要是能用的（`miyu-core` 的测试守着）：写错了不报错、只是那一家不见了或者标成用不了，不守就发现不了。
9. 真跑时 OpenRouter 标成「用不了：认不出它的接口」：目录里它的包是自己的（`@openrouter/ai-sdk-provider`），`[npm]` 推不出驱动。档案补 `[providers.openrouter] driver = "openai-chat"`（它的接口是 OpenAI 兼容的，地址照目录）；没有 key，只试过列模型是通的。

### 头要知道的

- `provider.catalog` 多参数 `featured: true`：交回常用的几家，照先后，名字照连接的语言。第一次引导照它列，加上 `provider.detect` 的 `local` 和「自定义」。

### 不做什么

- 头里的全屏引导（各个头自己做，照同一组方法）。
- 引导建第一个人格（OOBE，头里做，`persona.set` 不写编号新建）。

### 验收

1. 测试先写：`provider.catalog {featured}` 的先后、名字照语言、中文挑国内的、目录里没有的跳过；`miyu setup`：常用的几家那张表（已找到 key、已配好、本机、自定义）、选常用的一家贴 key 选模型写配置、找到 key 的不问、自定义三步写配置（编号照主机名、撞了往后加）、取不到列表印那一句再问模型名、空 key 的不写密钥。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
