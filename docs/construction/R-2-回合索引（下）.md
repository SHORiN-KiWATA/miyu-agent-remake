## 施工单 R-2（下）：补齐旧会话

状态：已完成（2026-10-08 写、施工、自己验收；提交 0dbe8fc8，CI run 37792607575 三台和长跑全绿；只有技术细节，照施工方案第一节第 1 条直接做；项目主人 2026-10-08 说这条线自己测完就合）。

### 目的

人格那一间的回合库是新建的、重建过的（升级了库的版本、坏了删掉重建），以前的会话说过的话补回去：她用 `memory_search` 搜得到，记忆的出处照墓碑判得了活不活。现在只有载入的那个会话自己补，没载入的旧会话一直缺着。

### 蓝图改哪几节

- `memory.md`「怎么走」第一条第 9 款写细：什么时候补、补哪些、照到的位置不往回挪、出错；「在哪」「守着它的」；第 8 款的运行日志多两行。
- `recall.md`：检索库的 `apply` 照到的位置不往回挪。
- `session/actor.md` 运行日志的表：回合库开库的几行挪到记忆这一页记。

### 定了的（技术细节）

1. **什么时候补**：回合库的登记（`RecallIndexes`）多一样「第一次开的时候告诉谁」，会话那一层登记它；开库的四处（会话写回合、搜以前的对话、判出处活不活、删会话）都从登记过，谁先开都算。人格那一间这一回是新建的、重建过的，起一个后台线程补；会话那一间不用（只有它自己，载入时本来就整份补）。开库的运行日志也挪到这里记，一处。
2. **补哪些**：这一间的账号的会话目录里，一个个读日志，照最近一次换上的快照：主会话、范围是 `persona`、人格是这一间的，照载入时那一套补（`Turns::connect`：照到的位置以后的补，一条都没照过的整份补）。在跑的会话照样补，不另判。
3. **照到的位置不往回挪**：检索库写一批时，这个来源照到的位置已经在这一批以后的，整批不写。会话自己写的总是往前；补的那一批读日志在前、写在后，可能落后，落后的不该把撤销了的又放回去。
4. **出错**：一个会话读不了、快照取不出，记一行 `WARN memory index not backfilled session=… error=…`，跳过；补完记一行 `INFO memory index backfilled persona=… sessions=…`（补了几个会话）。
5. `Memory` 改成照数据根造（`Memory::new`），端点、测试都照它造。

### 不做什么

- 从回收处恢复的会话补上、揭掉整个会话的墓碑：会话还不能从回收处恢复，随恢复那一步。
- 别的账号名下、记忆归这个账号的会话（系统账号的场所会话）：随 O-4。

### 验收

   - 检索库：照到的位置在后的一批不写，照到的位置不往回挪。
   - 会话（真会话、真回合库）：两个跟着人格的会话各说过一轮，停下；删掉回合库，一个新的登记第一次开这一间，后台补完两个会话的都搜得到；子会话、范围 `off` 的、别的人格的、只在会话里的都不补进来；再开一次不再补。
   - 读不了的会话记一行、跳过，别的照补。
2. 手写变异 12 个左右，全被逮住；`cargo xtask check` 全过；三台机器的 CI 和长跑全绿。

### 风险

- 会话多的账号补得慢：在后台，搜得到多少算多少（第 9 款）。
