### 验收（我用真模型自测；项目主人照着做一遍）

数据根是临时目录，不碰 `~/.miyu`；程序用仓库里编好的 `target/debug/miyu`。不设 `MIYU_DEV_*`。key 都照环境变量取，不进仓库、日志、提交、这一张。

手上的 key：项目主人的 opencode Go；DeepSeek 官方的一个（`openai-chat` 和它的 Anthropic 兼容接口 `/anthropic` 都能接）；开发用的 Responses 中转站。没有 Anthropic、OpenAI 官方的 key：三种接口照手上的接，结果里写明接的是哪一家。

1. **第一次接入**：空的数据根，`miyu ask "…"` 没有模型，先走 `miyu setup`：找到环境变量里的 key、选 opencode Go、试一下、选模型；写进配置的只有 `keys` 和 `models.chat`，外加三个空的池。接着照常答。
2. **三种接口只用配置**：配置里再加 DeepSeek 官方（只写 `keys`）、它的 Anthropic 接口和 Responses 中转站（写 `driver`、`base_url`、`keys`）。三种接口各问一轮带工具的：读两个文件、算一个数。`model.called` 的端点、模型、用量对；请求里没有开发用的东西。
3. **会话里换模型**：同一个会话 `miyu ask -c --model …` 换到另一种接口的模型，下一个回合用上，接着上文说，记一条 `session.policy_changed`。
4. **池里出错换下一个**：配一个池，第一个成员的 key 写错，第二个是好的：请求换到第二个、出一条通知、写错的那个记冷却；第二次请求不再先试坏的。
5. **思考强度**：配置里给一个模型写 `effort`，请求照它带；改了下一个回合生效。
6. **金额**：`usage.query` 照模型、照天的合计，和 `model.called` 里每一次的金额、照目录价格手算的对得上；本机没有的价格不算。
7. **一次性入口**：起标题、回顾走一次性入口，记进用量。
8. 数据根、日志里没有 key。
9. CI：main 上三台机器和长跑全绿。
10. **项目主人真人试**：照上面走一遍，用自己的 key 和常用的模型。

### 风险

- 花的钱：几十次请求，Go 是订阅额度，中转站是开发用的。
- 真模型的表现有随机性：一次没做对不算过也不算不过，照实记，多跑一次看。

### 验收结果

**真模型自测**（2026-10-04，主会话，程序从 main 8d3170c 编（8-14 补在里面），数据根是临时目录，界面中文）：

1. **第一次接入**：空的数据根，`miyu ask "读一下 a.txt 和 b.txt，把三个数加起来告诉我。"`：说「还没有模型，先接上一个。」，找到 `OPENCODE_API_KEY`（OpenCode Go、OpenCode Zen 各一条，另有容器里的 `GITHUB_TOKEN` 认成 GitHub Copilot），选 Go，试通（推荐的是 `longcat-2.5-preview-free`，1355 毫秒），列出 36 个模型，敲名字选 `deepseek-v4.1-flash`，写好了接着答：读两个文件，答 6。配置里只有 `[providers.opencode-go] keys = [{ env = "OPENCODE_API_KEY" }]`、`models.chat` 和三个空的池。另一次直接回车用推荐的 `longcat-2.5-preview-free`：它把很长的工作目录抄错了一个字、没找到文件（模型的事，照实记）。
2. **三种接口只用配置**（手改系统配置，核心当场换上）：DeepSeek 官方只写 `keys`（驱动、地址照档案）；DeepSeek 的 Anthropic 接口写 `driver = "anthropic"`、地址、`catalog = "deepseek"`；Responses 中转站写驱动和地址。三家各问一轮「读 a.txt、b.txt，beta 乘 gamma」：都读了两个文件、答 6，命中缓存 90%、94%、48%。
3. **会话里换模型**：Responses 中转站的那个会话 `-c --model ds-anthropic/deepseek-v4-flash`：记一条 `session.policy_changed`，下一回合走 `anthropic`，接着上文答 7（6 + alpha）。
4. **池里出错换下一个**：池 `m8` 的第一个成员拿 Go 的 key 连 DeepSeek 官方：401 `auth`，记冷却 600000 毫秒、`failover from=ds-bad/… to=deepseek/…`，这一次照常答 391；接着问的那一次直接发给第二个，没再试坏的。换端点的通知是瞬时的 `model.changed`，命令行不印（给界面的，随 M9）。供应商在 401 的原话里带了 key 的末四位（它自己打了码），原样进了 `model.called`。
5. **思考强度**：给 DeepSeek 的 `deepseek-v4-flash` 写 `effort`，`off`、`high` 轮流切，每次看到 `config changed` 马上问，各三次：`off` 每次没有思考、输出 1 个 token；`high` 每次输出 2 个（思考是空的，题太简单），三秒后再问一次有一句思考。改了下一个回合就用上。
6. **金额**：`usage.query` 照模型分组，五家的金额和每次 `model.called` 冻结的加起来一分不差，照目录价格手算也对：DeepSeek (2940×0.15 + 29440×0.003 + 170×0.6)/10⁶ = 0.00063132 美元；Anthropic 接口 0.000233238；中转站 glm (2395×0.15 + 2240×0.03 + 110×0.5)/10⁶ = 0.00048145；Go 0.000478596。出错的那次没有金额。
7. **一次性入口**：`miyu recap` 走一次性入口，答对；用量里用途 `recap` 一行，(158×0.15 + 892×0.6)/10⁶ = 0.0005589。
8. 数据根、仓库里找不到三个 key；用完停掉核心。
9. CI：main 上 8-14（4dd627a）、施工图（0f741a0）两次全绿；8-14 补（5981953）、文档（8d3170c）在跑。
