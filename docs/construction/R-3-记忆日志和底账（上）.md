## 施工单 R-3（上）：记忆日志和底账

状态：施工中（2026-10-07 写；方向 2026-10-07 项目主人定：记下的记忆分四类、只追加、带出处和听众，出处死了就看不见、不写撤回；只有技术细节，照施工方案第一节第 1 条直接做）。

### 目的

记下的记忆有了真相和底账：一个账号、一个人格一份记忆日志（`ext.memory.saved`、`ext.memory.retired`），照它算出每一条现在的样子，派生一份能按关键词找的记忆库；回合库里另记撤销了的回合、删掉了的会话，一条记忆的出处活不活照它判。还没有人往里写：R-3（中）的 `remember`、`forget`、`memory_search` 第一个用。

### 蓝图改哪几节

- `memory.md`（已改）：「对外的样子」的记忆日志（事件改成 `saved` 加可选的 `replaces`，不另立 `revised`）、底账、记忆库；「怎么走」第二条第 3、4 款（出处活不活：回合库里的墓碑）；「在哪」；施工步子把 R-3 拆成上中下。做完照做好的写「守着它的」。
- `recall.md`：检索库多一张墓碑表 `buried(key)`，`Edit` 多 `Bury`、`Unbury`，版本 3。
- `memory.md` 第一条第 5 款：`TurnFeed` 恢复时多交一条 `Restored`（不管人开的不是，都要揭掉墓碑）。

### 定了的（技术细节）

1. **事件的格**放 `miyu-recall` 的 `memory.rs`（纯逻辑，白名单的 `serde`、`serde_json`）：`Saved { class, text, sources, audience, replaces, about }`、`Retired { id, why }`、`Source { session, turn }`、`MemoryId`（`m<序号>`）、`MemoryClass`（四类，不认识的原样留着）；`to_event`、`from_event`（不是记忆的、读不懂的交回 `None`，坏的照「坏数据不报错崩」记下来交给调的一方）。
2. **底账** `MemoryBook`：`see(&Event)` 一条条算；`get(id)`、`all()`（照编号）；每条记着被谁改掉、作废了没有。改一条不存在的、作废一条不存在的：记下这条事件，不影响别的（日志是真相，底账不拒）。
3. **记忆日志的登记** `MemoryLogs`（`miyu-store/src/memory.rs`）：照（账号、人格）开 `home/<账号>/modules/memory/<人格>/`，用 `SessionLog`（没有就建）；一份一把锁，追加时照锁里的下一个序号写，所以几个会话同时写也不乱序。追加以后更新底账、记忆库（一个事务，照到 `log`）。打开时照日志算底账、补记忆库。
4. **墓碑**：检索库多 `buried(key TEXT PRIMARY KEY)`；回合库里撤销的回合埋 `会话/回合`，删掉的会话埋 `会话/`；`RecallIndexes::alive(账号, 人格, 出处)`。`TurnFeed` 在恢复时交 `Restored(回合)`，写的一方照它揭掉。

### 不做什么

- 工具、端口、软件包：R-3（中）。协议、命令行、范围、清空：R-3（下）。
- 从回收处恢复的会话揭掉墓碑：R-2（下）。

### 验收

1. 测试先写，没实现时红：
   - `miyu-recall`：`Saved`、`Retired` 写成事件、读回一字不差；不认识的类原样留着；底账：记、改（旧的标成被改掉）、作废、改一条不存在的不碍事；`TurnFeed` 撤销交 `Remove`、恢复交 `Restored`（增量和铺回两种）。
   - `miyu-store`：记了、关了重开底账还在、记忆库搜得到；日志最后半行坏了照会话日志的规矩截掉；几个线程同时记，序号连续不重；记忆库删掉、落后了，打开时照日志补；墓碑埋、揭、`alive`。
   - `miyu-session`：撤销一轮那一轮的出处死了、恢复活回来，不是人开的回合也算；删会话（端点测试）那个会话的出处死了。
2. 手写变异 12 个左右，全被逮住；`cargo xtask check` 全过；三台机器的 CI 和长跑全绿。

### 风险

- 记忆日志和会话日志用同一套写法：`SessionLog` 的检查（例如段的大小）对记忆日志也合适，量一下一千条记忆的日志多大。
- 墓碑每撤销一轮多写一行：撤销很少见。
