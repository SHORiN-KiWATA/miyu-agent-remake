### 验收（我用真模型自测；项目主人照着做一遍）

数据根放在 `~/.cache/miyu-m7/home`，不碰 `~/.miyu`；程序用仓库里编好的 `target/debug/miyu`（连同 `miyu-sandbox`）。窗口给 `MIYU_DEV_WINDOW=300000`。工作目录里放一个小项目：一份会失败的测试脚本（跑二三十秒、最后报一条失败）和几份要查的文件。

1. **后台跑测试被叫醒**：让她把测试放到后台跑、先去干别的；测试结束她被叫醒，用 `jobs` 读输出，说清哪条失败了。
2. **并行派两个子代理**：让她同时派两个子代理各查一件事；`miyu ask` 等到两份回报和叫醒的几轮都印完，最后一行用量是加起来的。
3. **孙代理和留言**：让她派一个子代理，交代里要它再派一个孙代理干一小块，并且缺一样非问不可的东西；孙代理的编号带前缀（`j1.1`）；该问的经 `message_agent` 一层层问上来，人答了以后接着干，最后一层层报上来、只报一次。
4. **撤销时停掉**：一轮里放一条长命令到后台、派一个还在干活的子代理，`miyu undo`：说「停掉了 2 个任务」，进程都没了，不叫醒她；`miyu restore` 不重起。
5. **人停的**：`jobs` 的 `stop` 由她自己停的不叫醒；（能发 `job.stop` 的头，网页演示已测过「The user stopped this.」，这里不重测）。
6. **别的 harness**：她跑长活时，另一个终端 `miyu ask -s <会话> --from claude-code "…"`；她分得清不是人说的；`--from` 按 Ctrl+C 不打断她那一轮。
7. **量**：整个会话每次请求的缓存命中（`model.called` 的用量），工具面的 token（`agent`、`jobs`、`message_agent` 和 `shell` 的后台参数都在），和登记簿、预算对得上。
8. 会话、数据根里没有 key；用完停掉核心，后台命令跟着没了。
9. CI：main 上三台机器和长跑全绿。Windows 上偶尔不稳的两条（`crash.rs` 的心跳、`reports_come_up_one_layer_at_a_time` 的十秒）照实记几次红几次绿，要放宽另开补的施工单。

### 风险

- 花的钱：几十次请求，子代理各自有前缀，按 DeepSeek 的价钱几毛钱。
- 真模型的表现有随机性：一次没做对不算过也不算不过，照实记，多跑一次看。

### 验收结果

**真模型自测**（2026-10-01，主会话，程序从 main 154a2ce 编（7-8、7-9、7-10、7-2 补都在），开发端点的 `deepseek-v4.1-flash`，窗口 300000，数据根 `~/.cache/miyu-m7/home`）：

1. **后台测试把她叫醒**：让她把 `./test.sh` 放到后台（j1），同时派一个先睡 45 秒的子代理读 `notes/` 三个文件（j2）。结果对：失败的是 `test_parse_date`，她还看出这是脚本里写死的。看到的行为：她知道结束会自己回报，还是前台跑了一条 `sleep 26` 去等，再用 `jobs` 读输出；j2 报回来以后，她把三个文件自己又读了一遍核对。
2. **并行两个子代理**（j3、j4）：`miyu ask` 等到两份回报、各印一行「报回来了」；「备份」6 次、第二条待办「清理旧日志」都对。这一轮输入 22,255、命中缓存 96%。
3. **孙代理和留言**：j5 派了孙代理 j5.1（第二层）读 `config.txt`，j5 经 `message_agent` 把「改成多少」问上来，文件一个字没改。`miyu ask -c "port 改成 8080。"`：她转给 j5，`miyu ask` 当场退出（7-9 只等这一次派的）；j5 改好、报了回来，只记下、没叫醒她，下一句「改好了吗」她才看到。→ 开了 7-9 补（留了言的子代理也等），合并前照这一套重走：`miyu ask` 等到「· j1 报回来了」和她核对文件的那一轮才退出。
4. **撤销时停掉**：一轮里放 `sleep 600` 到后台（j6）、派一个前台睡 120 秒的子代理（j7），`--timeout 40s` 退出码 3；`miyu undo`：「停掉了 2 个任务」，两个进程都没了，不叫醒她；`miyu restore` 以后也没重起。
5. **她自己停的**：放 `sleep 300` 到后台（j8）再用 `jobs` 停掉，回报带 `by_model`，没开新的一轮。
6. **别的 harness**：她前台跑 `sleep 40` 时，另一个终端 `miyu ask -s <会话> --from claude-code --timeout 5s "…"`：退出码 3，「· 等到时间了，她那一轮还在接着跑」，她那一轮照常跑完；她说出那句是 claude-code 发的，去核对了一下，没照着改。
7. **量**：主会话 28 次请求，输入 202,375、命中缓存 195,712（96.7%）；子会话 22 次 90.9%，低于 80% 的两次都是子会话的第一次请求。工具面 11 件 1967 token，和登记簿（7-7 的 1966，合并时 `message_agent` 改一个词多 1）对得上。
8. 会话、数据根里没有 key；停掉核心以后，后台命令一个都没留下。
9. CI：main 从 7-8 合进来（0e0c5cf）起连着全绿；Windows 上偶尔不稳的两条（`crash.rs` 心跳、`reports_come_up_one_layer_at_a_time` 十秒）只在分支上各红过一次，重跑就绿，main 上没红过，先不放宽。
