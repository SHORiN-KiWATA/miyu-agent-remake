## 施工单 2-7：提问（下）

状态：施工中。

### 目的

工具在跑的时候能请内核问你一组题，停下来等你回答，你的回答交回给工具。你不想答，就是打断，这一轮停下。她在等你回答（提问或者确认）的时候你直接发了一句话，等的那个作废，这句马上给她。没有人能回答的地方，她拿到「这里没有人能回答」。

### 不做什么

- `ask_user` 这件工具本身：题目怎么写进工具的参数、回答怎么写成给她看的结果：M4。这一步由执行器替身扮演。
- 抽屉的样子、「不回答」用哪个键、几组题怎么排给人看：M8。
- 子代理能不能问你：做子代理时（M7）再定。三家里 Claude Code 不给子代理这件工具，codex 只让主会话问。
- 等太久自动往下走（Claude Code 能设，默认不设）：不做。
- 子代理、后台命令的回报在等人回答时到了，算不算「来了一句话」：M7。这一步只管人发来的消息。

### 拍板的

- **不回答就是打断，这一轮停下**：项目主人 2026-09-26 选「这一轮停下」，备注「这就像是回答被中断了？」。所以「不回答」发的就是 `session.interrupt`，内核不另加命令。
- **等人回答的时候来了一句话，等的那个作废**：项目主人 2026-09-26 选「作废，这句马上给她」，提问和确认都一样。
- **题数不设上限**：项目主人问「这东西还要有上限的吗？」。上限是 Claude Code 自己定的（一次 1 到 4 道），opencode 没有上限，codex 只是建议不超过 3 道。内核不设；要不要劝她少问，写进 `ask_user` 的说明（M4）。
- 先读了三家的源码（2026-09-26，codex d7b07d4 的 `request_user_input`、opencode 2.0.8 的 `question`、Claude Code 2.1.280 的 `AskUserQuestion`）：
  - 不回答：三家都是这一轮停下。
  - 有题在等时直接发消息：三家的输入框都被关掉或者藏起来；Claude Code 远程、无头时，来了新消息题目就作废，消息照常给她。
  - 照三家一样定的：题目的样子（问的话、短名字、选项带一行说明、能不能多选、总能自己写）；不设超时；等人回答时打断就是取消；题目和回答都不给模型看。

### 我定的

- **题目是内核认识的结构**：头要照它画抽屉，内核要照它查回答对不对得上。题目的说明、选项的说明内核不看。
- **回答照题目的先后一道一条**，选的写选项的标题；有几道不答也行。
- **答完了落了盘再交给工具**：和允许了落了盘再派同一条。
- **作废、打断、没人能回答，都由内核写结果**，同时叫执行器停下那个调用：三句放在 `resources/core/tool-results/`。之后工具再交回来的结果，当过时的不理。
- **来了一句话才作废，急着插话不另算**：作废的是在等人回答的（提问、确认）；急着插话的，还没跑的照旧跳过（2-5）。
- **命令「回答」分成两种**：回答确认（2-7 中）和回答提问，在内核里是同一个命令的两种写法；答错了种类的（对着提问答确认），原因码 `not_asking`。

### 验收

1. `step/2-7c-question` 分支的 CI：三台机器全绿。
2. `cargo test`，新加的测试：
   - 两种新事件的写法；不写的格子不写；账本拦下对不上调用的题、同一个调用两组在等的题、对不上题的回答、答两次；结果了结题目。
   - 工具问人：记题目，`by` 是那次调用，这个调用停下；不是在跑的调用问的，不理。
   - 人回答：记回答，`by` 是回答的人，落了盘才交给工具；工具交回结果，这一步照常往下走。同一个调用答完了还能再问。
   - 回答被拒：对不上题目的几种（题数、没有的选项、单选选了几项、同一项选两次）；不在等的；对着提问答确认、对着确认答提问。先答者胜：答过了再答，拒绝。
   - 没有人能回答的会话：不记题目，当场跳过，写明这里没有人能回答。
   - 打断：在等人回答的补「没回答：被打断了」，叫执行器停下；之后工具交回的结果不理。
   - 来了一句话：在等人回答的提问补「没回答：你发了一句话」、在等人确认的补「已跳过」，`by` 是说话的人；这句话进下一次请求；别的在跑的照常跑完。急着插话的也一样。
   - 样本会话接着往下的几条读写一字不差；整个会话组装出来的请求里没有题目和回答，工具的结果在里面。
   - 随机一串输入加上工具问人和回答：原来的规矩照查，再查回答交给工具之前已经落了盘、题目对得上在跑的调用、作废和打断都写对了 `by`；还要走到过问人、人回答、答错被拒、来了一句话作废、打断时在等人回答、没人能回答。
3. 故意改坏几处，每一处都有测试变红（施工时列出清单）。
4. `cargo xtask check` 七项全过。

### 风险

- **在跑的调用多了两个状态**：打断、急着插话、来了一句话、工具交回结果，都要照顾到。漏一处就有调用没结果，或者结果写了两条。随机测试查每个调用都有且只有一个结果。
- **2-7（中）的做法跟着改**：以前等确认的时候来了一句普通的话，这句排队、确认接着等；现在确认作废。2-7（中）的测试和随机测试的看守要跟着改。
