## 施工单 V-2（上）：量法照真用

状态：2026-10-11 合了（ccd48edf，CI run 1649）。

### 起因

V-1 的量尺里模型没有窗口、假模型报的用量是写死的：大会话一直不压，一万条事件整份组装，真用时到不了（会话到线就压）。超了的几处里有的是量法造成的，先把量法改成照真用，再一项项查。

### 这一步做什么

1. 假模型（`miyu-perf` 的 `fake.rs`）：用量照请求体、正文的字节数估，四个字节一个 token；请求体带出厂摘要指令那一句的回一段摘要。
2. 沙盒（`sandbox.rs`）：模型 `perf/perf-model` 的窗口写成 200000，压缩线 170000。
3. 图纸 `perf.md`「怎么走」第 3、4 条照改。
4. 照新的量法量一次，存进 `docs/perf/2026-10-10-linux-x86_64-v2上.{json,md}`（V-1 那一份留着对照）。

### 量到的（2026-10-11 凌晨，同机还有别的会话在编译，盘忙）

| 项目 | V-1 | V-2 上 | 预算 |
|---|---|---|---|
| 重启后打开大会话 p95 | 107.0 ms | 102.2 ms | 60 ms，超 |
| 大会话说一句到模型收到请求 p95 | 24.8 ms | 19.0 ms | 5 ms，超 |
| 追加一条事件并同步 p99 | 2.4 ms | 30.4 ms | 20 ms，这次超（盘忙，待复量） |
| 核心空闲 PSS | 31.8 MB | 31.9 MB | 30 MB，超 |
| 载着大会话的核心 PSS | 111.1 MB | 53.9 MB | 无 |

- 说一句到收到请求从几百条事件到一万条一直在 11 ms 上下，和会话多大无关：大头不在组装，要拆开看落盘同步、编码各占多少（V-2 中）。
- 打开大会话 100 ms 上下，压不压都一样：读整份日志、重放，要查（V-2 中）。
- 空闲内存超 2 MB：二进制从 46.5 MB 长到 49.0 MB，要查常驻的是什么（V-2 下），或者照 23 F1 实测后校准预算，那要项目主人定。
