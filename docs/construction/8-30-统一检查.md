## 施工单 8-30：统一检查 `miyu check`

状态：已完成（2026-10-07 写、施工完；CI run 1097 三台和长跑全绿；项目主人同一天提、定：一个命令查完手写的所有文件，不另开分开的 check 命令，`miyu config check` 并进来、去掉；排在 P-1 上后面；技术细节主会话定）。

### 目的

人改了配置、放了人格文件，想知道写没写错：敲一个 `miyu check`，一次查完 Miyu 读的、人手写的所有文件，每处错误印出哪个文件、第几行第几列、错在哪、怎么改，有错退出码不为 0，像 `nginx -t`。以后预设（P-2）、软件包清单（9-1）、软件包自己的文件（例如通讯平台桥的 `venues.d`）做出来时各自接进来。

### 蓝图改哪几节

- 新页 `cli/check.md`：命令、选项、印法、退出码。
- `cli/config.md`：去掉 `check`（帮助页、命令表、「怎么走」第 6 条挪走）；`cli/main.md` 的命令表。
- `protocol.md`：新方法 `check`；`config.check` 留着（头保存以前查一段字用）。
- `config.md` 第十条第 7 条改指 `cli/check.md`；`personas.md`「怎么走」加查法。

### 定了的（技术细节，主会话定）

1. **核心查，命令行只印**：新方法 `check {cwd?, file?}`，核心照磁盘上现在的字查，交回 `{"problems": [...]}`，一处一格：`file`（照 `config.get` 的写法：数据根里的相对数据根，项目配置 `~/…`，出厂的人格写真的路径）、`line`、`column`（整份的问题没有）、`level`（`error`、`warning`）、`message`（照连接的语言，带改法）、`kind`（`config`、`secrets`、`persona`）。以前 `miyu config check` 是命令行读字、一份份交 `config.check`；挪进核心以后，人格、以后的预设一个口子查完，命令行不用认识每一种文件。
2. **不写 `file`**：系统配置、管理员的个人设置、`cwd` 的项目配置（没写 `cwd` 的不查项目配置）、密钥文件（只报问题，不经协议交出密钥的字）、三层里所有的人格（每一层的 `persona.toml`、`prompts/examples.md`）。还没有的文件跳过。
2a. **人格的错带代码**：`miyu_policy::persona::Problem` 多 `code`、`detail`，给人看的那一句放进 `core/human/<语言>.json` 的 `persona-problems/<code>`（三种语言）；英文的 `message` 照留，协议的 `persona_invalid` 照旧用它。
3. **写了 `file`**：照它在哪认是什么：`system/config.toml`、`home/<账号>/settings.toml`、某个目录下的 `.miyu/config.toml`、`secrets.toml`、某一层 `personas/<编号>/` 里的文件。认不出的回 `unknown_file`（「Miyu 不读这个文件」），没有、读不了的报一条读不了。
4. **人格的问题按层报**：同一个人格三层各查各的，每层自己的文件写错就报那一层的那一份，不因为上面一层盖住了就不报（找人格时叠到第一处错就停，查的时候要全）。
5. **印法照原来的 `miyu config check`**：标准输出一处一行 `<文件>:<行>:<列> <级别>：<那一句>`，文件在家目录下的写成 `~/…`；级别「错误」红、「警告」黄；最后一行合计，没有问题的印「没有问题」。`--format json` 原样 `{"problems": [...]}`。有错误退出码 1，只有警告、没有问题的 0。
6. **`miyu config check` 去掉**：敲了的照未知子命令报（`miyu config` 的帮助里没有它）。`config.check` 方法留着。
7. **软件包的检查随 9-1**：包在清单里声明怎么查（一条命令，输出照第 1 条的格子、JSON 一行一处），`miyu check` 挨个调、合在一起印。通讯平台的桥打算出 `miyu-onebot check`，多带 `rule`、`source` 两格（和通讯平台的会话对过的现状，9-1 画清单时再对形状）。
