## 施工单 8-29：开发用的 key 改名 `MIYU_DEV_API_KEY`

状态：已完成（2026-10-07 写、施工完；技术细节的一步，CI run 975 三台和长跑全绿；项目主人同一天问「这个环境变量为什么是 DEEPSEEK_API_KEY，不应该是 DEV_API_KEY 吗」，定照推荐改成 `MIYU_DEV_API_KEY`；技术细节主会话定）。

### 目的

`cargo xtask dev-home` 造的数据根，key 照 `{ env = "DEEPSEEK_API_KEY" }` 取。这是 3-9 只认 DeepSeek 官方时留下的名字。现在开发端点是一个 OpenAI 兼容的中转，不是 DeepSeek 官方；名字照用途叫，和另外三个开发变量 `MIYU_DEV_BASE_URL`、`MIYU_DEV_MODEL`、`MIYU_DEV_WINDOW` 排在一起。

### 蓝图改哪几节

- `models.md`「怎么走」第十条第 2 条、文件表 `crates/miyu/tests/dev_home.rs` 那一行、决定表 `dev-home` 那一行。

### 定了的（技术细节，主会话定）

1. 只改 `xtask/src/dev_home.rs` 的 `KEY_ENV`：程序里本来就没有这个名字，核心、头都不动。
2. 不留旧名字：已经造好的开发数据根，`system/config.toml` 里的 `{ env = "DEEPSEEK_API_KEY" }` 自己改一行，或者重造。
3. 「找现成的」照旧会找 `DEEPSEEK_API_KEY`：那是 DeepSeek 官方的变量，来自目录，和开发端点无关。

### 验收

1. `crates/miyu/tests/dev_home.rs` 照新名字改，改之前红（两条）、改之后绿。
2. `cargo xtask check` 八项、三台机器的 CI 和长跑。
3. 合进 main 以后告诉两个头：开发数据根的 key 改叫 `MIYU_DEV_API_KEY`，老的数据根改配置里那一行。
