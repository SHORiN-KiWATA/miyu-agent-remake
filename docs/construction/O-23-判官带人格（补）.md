## 施工单 O-23（补）：判官带人格

状态：已完成（2026-10-09；项目主人 2026-10-09 定：判官也带人格，给一个开关，默认开；经核心的主会话转达）。

### 目的

O-23（下）的判官先不带人格（`Ask.persona` 传 `None`），判「这个人格愿不愿意开口」时看不到她是谁。项目主人定了带：判官的请求里接上这个群会话所用的人格的说明（`chat.md` 第六条：`persona-open.txt`、人格的说明、`persona-close.txt`，O-11 就留好了），加一个开关，默认开，可以按场所关（某个群想省 token 就写一条场所规则关掉）。

### 蓝图改哪几节

`docs/blueprint/chat.md` 第八条：`[judge]` 那张表加一项 `persona`（开关，出厂 `true`）：判官带不带人格的说明；场所规则写 `judge = { persona = false }` 关掉。施工时定的补一条（2026-10-09 项目主人定，默认开）。

`docs/blueprint/onebot.md` 第一条「群里怎么叫她」问判官那一条：

1. 人格是哪一个：这个群会话实际用的人格，照订阅回应里的 `persona`（没有这一格的是无人格，判官不带）。
2. 原文：`persona.read {"persona": <编号>, "prompt": "persona"}`（核心现成的，扩展能调；读到的是属主那几层叠好的、现在文件里的那一份，不是会话快照里冻着的）。读不到的（人格删了、读出错）这一次不带人格，运行日志记一行，照样问判官。
3. `judge.persona` 是假的、或者没有人格的：`Ask.persona` 传 `None`，那一段整个不出现（同现在）。
4. 原文要不要在桥里记一阵：施工时定（同一个人格一分钟里读一次就够），写进施工时定的。

`docs/designs/26-提示词.md` 第十节：判官 `persona-open.txt`、`persona-close.txt` 已经登记了（O-11），这一步不加新的给模型看的字；人格原文是人格自己的，不登记。量一次带人格以后判官请求多了多少 token（拿出厂样本人格 engineer 量），写进 `onebot.md` 施工时定的（`docs/designs/18-通讯平台.md` 第七节「已知的代价」旁边补一句）。

### 不做什么

- 照会话快照里冻着的那一份人格：要核心另开口，项目主人没要求。
- 只带人格的一段（精简版）：项目主人定的是带人格，没说精简；要精简另议。

### 验收

1. 先写测试，退回改之前要红：群会话有人格时判官请求里有 `persona-open`、人格原文、`persona-close`；`judge.persona = false` 的群没有；无人格的群没有；人格读不到的照样问判官、不带、记一行日志；参数 `judge.persona` 的读法和按场所改（群聊内核的测试）。
2. 手写变异 8 个左右，全被逮住。
3. 门禁八项全过；三台机器的 CI 和长跑全绿。
4. 量 token：带人格以后判官请求多多少，记下来。

### 验收结果（2026-10-09）

**改了什么**：群聊内核 `[judge]` 加一项 `persona`（开关，出厂 `true`，`defaults.toml` 补一行），`Judge::persona`；桥订阅群会话时照回应的 `persona` 记下这个群会话用的人格（`judges.rs`），问判官的任务拿到群聊记录以后读 `persona.read {persona, prompt: "persona"}`、原文交 `Ask::persona`（新文件 `core/route/persona.rs`），`judge.persona` 关了的、无人格的不带、不读；读不到的这一次不带、记一行 `WARN persona not read`、照样问判官。图纸：`chat.md` 第八条（表、`Judge`、守着它的、施工时定的第 24 条），`onebot.md` 第一条第 1 条、第 12 条第 3 款、`bridge.json` 那张表、守着它的、施工时定的第 102 到 104 条，`18-通讯平台.md` 第七节「判官带人格」一条。

**第 4 条（原文记不记）定了**：记 60 秒，几个问判官的任务共用一份；读不到的不记，下一次再读（`onebot.md`「施工时定的」第 103 条）。60 秒是数据，放 `bridge.json` 的 `judge_persona_seconds`，照群成员名字缓存 `member_names_seconds` 的先例（是桥这个进程的，不按场所改）：这一处在施工单列的几节以外，多动了 `bridge.json`、`tuning.rs` 和它的测试。

**量 token**：「`persona-open.txt` + 样本人格 `engineer` 的人设 + `persona-close.txt`」接成一份，照登记簿的办法（单句接在 `hi\n` 后面）在开发端点的 `deepseek-v4.1-flash` 上量：15 个（两次一样；标签各 4 个、人设那一句 7 个）。真人格照它人设的长度多（旧版 Miyu 的人设 1403 个）。没有新的给模型看的字：两个标签 O-11 就登记了。

**测试**（先写，退回改之前红）：

1. 群聊内核：`params/tests.rs`（出厂开着、写成假的读成假的、写成字的 `wrong_type`、缺了报缺；出厂的一份多 `persona: true`）、`rules/tables/tests.rs`（`judge = { persona = false }` 只关写了的那个群、只改这一项；每一项落在自己那一格多 `persona = false`）。只加了结构体那一格、没加声明时 4 个红。
2. 桥的单元测试 `ask/persona_tests.rs`（夹具在 `ask/tests.rs`，核心那一头是测试、钟停住）：有人格的先拿记录、再 `persona.read`，原文紧跟 `system.txt` 夹在两个标签中间；59 秒不再读、满 60 秒再读、别的人格另读；`null`、空的字不带、照样记下；`unknown_persona` 不带、照样问、不记下（两次都读）；读的时候核心断开了交回空的。
3. 集成测试 `judged_persona.rs`（真核心、真桥，系统区装上样本人格；`judged.rs` 的几样夹具开给它用）：设了 `engineer` 的群，判官的 system 开头是 `system.txt`、`persona-open.txt`、样本的人设、`persona-close.txt`、`reply.txt`；同样的人格写了 `judge = { persona = false }` 的、无人格的、会话造好以后人格删了的都不带，删了的照样问、运行日志有 `persona not read`。改之前红在第一处断言（system 里没有人格）。`tuning.rs` 多 `judge_persona_seconds`（出厂 60 秒、少了这一格读不进）。

**手写变异 11 个，全被逮住**：声明不看值；出厂关着；不看 `judge.persona` 开关；订阅回应的人格不记；拿到人格不带；满 60 秒还算记着（`<` 改 `<=`）；读不到的也记下；空的人设也带；读到的不记；读错了提示词（`examples`）；记多久的单位错（毫秒）。

**门禁**：`CARGO_BUILD_JOBS=5 cargo xtask check` 头一趟「行数」没过：`ask/tests.rs`、`tests/judged.rs` 加了人格的测试以后过了 500 行，人格的测试拆进 `ask/persona_tests.rs`、`tests/judged_persona.rs`（照 `decide/follow_tests.rs` 的做法）；拆完再跑八项全过。

**CI**：三台机器和长跑全绿（run 1364）。

**没动的、要主会话知道的**：核心的 `venues.md`「判官看的群聊记录」第 4 条还写着「判官的人格说明先不带（`Ask.persona` 是 `None`）：带不带、带哪段等项目主人定」，这一步定了，那一条该改成「判官带这个群会话所用的人格的说明，桥经 `persona.read` 读（`onebot.md` 第一条第 12 条第 3 款）」；是核心的图纸，这一步没动。
