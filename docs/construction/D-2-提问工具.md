## 施工单 D-2：提问工具 `ask_user`

状态：待验收（2026-10-07 写、施工完；项目主人同一天定：提问、确认、待办三样提前做，做好了通知头去适配；题数不设上限、字段名照 Claude Code 是 2026-09-26、09-28 定的；选项的 `preview`、回答的 `notes` 是 2026-09-29 定的；技术细节主会话定）。

### 目的

她能在干活中途问人一组题、等人回答，回答成了这次调用的结果（`10-自带软件.md` 第三节）。头早就看得到 `question.asked`，D-1 起能用 `session.answer` 回答；这一步补上会问的工具，和事件里的两格。

### 蓝图改哪几节

- 新页 `tools/ask_user.md`：是什么、在哪、参数、结果的样子、谁的工具面里有、怎么走、给人看的字、守着它的。
- `tools/interface.md`：端口表多一个提问的端口 `QuestionPort`（`Call::questions`）。
- `kernel/events-bodies.md`：`question.asked` 的选项多 `preview`，`question.answered` 的回答多 `notes`；`03-事件模型.md` 第三节的样本对上。
- `session/tools.md`：执行器怎么造提问的端口、怎么把题交给内核、回答落了盘怎么送回工具、调用了结了怎么收。
- `kernel/asking.md`「还没有的」去掉提问工具、`preview`、`notes` 两条。
- `26-提示词.md` 第十节登记新加的给模型看的字；附录的草稿换成定稿。

### 定了的（技术细节，主会话定）

1. **参数**照 Claude Code 的 AskUserQuestion：`questions`（必填）；每道 `question`（必填）、`header`、`options`、`multiSelect`；每个选项 `label`（必填）、`description`、`preview`。题数、选项数都不设上限（2026-09-26 项目主人定）；选项可以一个都没有（人自己写，内核本来就收）。工具名和 `multiSelect` 照它；内核记的照事件原来的 `multiple`。
2. **说明**照 `26-提示词.md` 附录的草稿：推荐的放第一个、标 `(Recommended)`；不要自己加「其他」，人总能自己写。参数说明每格一句，名字看得出来的不写。
3. **结果**（给她看的）：英文，一道一行 `"<问的话>" = <回答>`：选了的照标题、逗号隔开，自己写的接在后面，备注写成 `(note: …)`，没答的写 `(no answer)`；最后一行说照这些回答接着做。照 Claude Code 的结果改成一行一道，长回答也读得清。
4. **端口**：`miyu-tool` 定 `QuestionPort`（交一组题，等回答），执行器照每一次调用造一个。工具交题 → actor 记下回信的口子、交给内核 `ToolAsks` → 内核记 `question.asked`、等 → `session.answer` → `question.answered` 落了盘内核出 `AnswerTool` → actor 照调用编号把回答送回。调用先了结的（打断、来了一句话、收紧成只读），内核照原来的规矩补结果，actor 丢掉回信的口子，工具那一头当没答收场，结果不再记。
5. **谁有**：只有有人能回答的本机主会话（`attended`，造会话时定的工具面）。子会话不给（`agents.md` 已定：问父会话），`miyu ask`、场所会话（QQ）不给（`10-自带软件.md` 第三节、`11-权限与沙盒.md` A11）。
6. 访问类别 `read`：只问人，什么都不改，只读开着也能问。
7. `preview` 是一段文字画（代码片段、界面草图），头照等宽字显示，核心不解读、原样记。

### 不做什么

- 待办 `todowrite`：D-3。
- Claude Code 2.1.280 新加的 `kind`（填数字、填字的题）、整组的 `title`：等头要了再加。
- 提问时的超时：不设，人不回就一直等（`02-内核.md` 第六节「提问怎么走」）。

### 验收

1. 测试先写，退回改之前要红：
   - 工具：参数读不成的、题目一道都没有的报参数不对，端口一次都不问；回答写成结果的几种（选一项、多选、自己写、备注、没答）一字不差；没有端口的照「这里没人能回答」出错。
   - 执行器：交题以后内核记 `question.asked`，回答落了盘工具收到；打断时工具收场、结果不记两次。
   - 协议真核心：假模型调 `ask_user`，头订阅看到 `question.asked`（带 `preview`），`session.answer` 交回答（带 `notes`），她收到的结果对；`bad_answer`（选了没有的选项）。
   - 工具面：主会话有、子会话没有、`miyu ask` 的会话没有。
   - 事件：`preview`、`notes` 读写，以前的日志照旧读得懂。
2. 手写变异 12 个左右，全被逮住；`cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
3. 给模型的字：开发端点实测 `ask_user.json`、结果几句的 token，登记；工具面多了这一件，请求形状探针只多这一件。
4. 真模型：开发端点上让她遇到要人拿主意的事，看她调不调 `ask_user`、题写得像不像样；合进 main 以后告诉两个头：`question.asked` 的 `preview`、`question.answered` 的 `notes`、`ask_user` 的显示名。

### 风险

- 工具在等人时被丢掉（打断、核心停）：回信的口子跟着丢，工具当没答收场；内核那边照原来的规矩补结果，不会记两次。
- 工具面变了：新会话的前缀多一件，开着的会话快照里冻着原来的工具面，一个字节不变。
