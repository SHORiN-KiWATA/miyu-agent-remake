## 施工单 3-4：流式解码、出错分类与驱动接口（下）

状态：施工中。

### 不做什么

- 真的发请求、读流、空闲超时、重试和退避：3-5 HTTP 执行器。这一步只给出分类和要等多久。
- 驱动规格里的 `models`（模型资料）、`cache`（缓存类型）：配置和模型资料的那几步。
- 正文里夹着 `<think>` 标签的供应商、OpenRouter 的 `reasoning_details`、Gemini 的思考签名：接到它们的时候再做。
- `retry-after` 写成 HTTP 日期的：大模型的接口没见过这样写的，碰到了再加。

### 我定的

- **SSE 自己写，照 WHATWG 的 EventSource 规矩**：`data:` 后面的一个空格去掉；几行 `data` 用换行接起来；空行结束一条；`event:` 记下名字（这类接口用不上，留着给以后的驱动）；`id:`、`retry:` 不理。`\r\n` 被切在两片之间，不多出一个空行。一行收全了才解 UTF-8，一个汉字被切开也不坏。流断在半条上：最后一条照样交出来。
- **正文、思考各只开一块**：这类接口的正文、思考本来各是一整段，编码时照原样接回去（3-4 上）；切成几块没有好处，只会让回放的字节跟着分块的方式变。
- **工具调用按 `index` 认**：没有 `index` 的，按 `id` 找；都没有的，接在最近的那一次上（opencode 的做法）。工具名到了才开始这一块，之前的参数先攒着；`id` 一到就写进私有数据，一块只写一次。
- **什么算说完**：见到 `finish_reason`，或者见到 `[DONE]`。两样都没见到流就断了，算可重试的错：回复没收全。`length` 算正常说完：工具调用的参数要是被截断了，执行时照「参数不是一个 JSON 对象」报给模型（内核已有的那一句）。
- **出错的六类照 opencode 的先后**，说法的清单用 opencode 和 pi 的并集，全部小写以后找子串，不用正则：纯逻辑层的白名单里没有正则的库，这些说法用子串就认得出来。
- **额度用完算认证失败**：内核的六类里没有「额度」，重试没用，要换 key 或者充值，和认证失败的处理一样。人看的原话照原样留着，写明是额度。
- **限速要等多久**：`retry-after-ms`，`retry-after` 的秒数（可以带小数），原话里的 `try again in 20s`、`try again in 500ms`。都没有就不写，由执行器退避。
- **原话最长 2000 字节**：出错页可能是一整页 HTML，日志里不该塞这么多；在字的边界上截。
- **流的样本是手写的**：照各家文档和调研里的写法造，覆盖 DeepSeek（思考、`prompt_cache_hit_tokens`）、OpenAI（`cached_tokens`）、Moonshot（用量在 `choices[0]` 里）、工具调用分好几片、编号晚到、网关的噪声、流里报错、流断了。解出来的写成一行一条的文字，和样本逐字节比对。

### 验收

1. `step/3-4b-decode` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - SSE：`\n`、`\r\n`、`\r` 三种换行；注释；几行 `data`；`\r\n` 切在两片之间；汉字切在两片之间；流断在半条上。
   - 流的样本逐字节比对；每一份样本，从每一个字节处切开喂，解出来的都和一次喂完的一样。
   - 解出来的增量交给内核的累积器，一次对不上的都没有；拼出来的回复再编码回去，工具调用用的是供应商的编号，正文、思考照原样。
   - 出错分类：一张表，各家真实的写法（状态、头、响应体）对应到六类和要等多久；原话截到 2000 字节，截在字的边界上。
   - 驱动的接口：`OpenAiChat` 编码、解码、分类都照着接口走一遍。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --target` 查 Windows、macOS。

### 风险

- **各家的流有我们没见过的写法**：样本照文档和调研造，不是抓的真流量。3-9 真对话时会抓到真的，那时补进样本。
- **超长、内容策略的说法认不全**：认不出的落到「其他」或「可重试」，不会误判成别的；认出的说法照调研的清单，两家参考实际在用。
- **子串比正则宽**：先排除限速的说法，再认超长；表里放几条限速的原话，查它们不会被当成超长。
