## 施工单 1-11：模板与转义

状态：已完成（2026-09-26 项目主人验收通过）。

### 目的

给模型看的字能用模板拼出来了：模板里标出要换的字段，换进去的每个字段都先转义。不可信的文字（昵称、群名片、正文）进了请求，伪造不了标签，也伪造不了记录行（`08-上下文投影.md` C7）。以后组装请求（1-12）、事实注入（1-13）、模块自己的事件怎么进上下文（`05-内核接口.md` 第五节第 4 条），都用这一套。

### 图纸

- `08-上下文投影.md` 第五节「模板与转义怎么写」，这一步新画的：模板的写法；为什么每个字段都转义；转义的规矩；报错的几种情况。
- `旧版证据索引.md`：旧版 `safe_prompt_field` 的做法和它的漏洞（引号），登记在 08 §五 C7 那一行后面。

### 不做什么

- 真正的模板（稳定区、各种事件的渲染、检查点外面的包装）：1-12 组装请求。
- 事实块里写什么：1-13 事实注入。
- 群聊近况的格式：做通讯平台时定。这一步给的转义，一行一条的记录和标签的写法都防得住。
- 模块清单里声明的模板，装模块时先查一遍：做扩展的那一步。

### 要拍板的

没有。这一步全是技术细节，照图纸来。

### 我定的

- **只有 `{名字}` 一种写法**：不做条件、循环、过滤器（`05-内核接口.md` 第五节第 4 条：模板只做字段替换，不含逻辑）。要一个 `{` 本身就写两遍，和 Rust 的格式化字符串一样，写过 Rust 的人一看就懂。
- **每个字段都转义，不分可信不可信**：可信的字段（编号、身份）本来就没有要转的字，转了也不变；分成两种写法，就会有人在该转的地方用错。要是以后真有一段要原样放进去的字，那时再加一种写法。
- **转义照 JSON 字符串的写法，引号、`&`、尖括号写成 `\u` 的样子**：转出来是一行字，没有引号、没有尖括号，放在标签的属性里、放在一行一条的记录里都安全。旧版这样转过群聊记录（`旧版证据索引.md`），模型读得懂。没选 HTML 那种 `&lt;` 的写法：它不转换行，一行一条的记录还是能被伪造。
- **字段用 `BTreeMap` 传进来**：纯逻辑的层不许用 `HashMap`；字段少，查起来也快。
- **报错写中文，写明哪里坏了**：模板是出厂的数据或者模块带来的，坏了是写模板的人要改，报给写模板的人看。

### 验收

1. `step/1-11-template` 分支的 CI：三台机器全绿。
2. `cargo test -p miyu-kernel template::`：换字段、写大括号、各种字的转义、伪造的例子失效、坏模板报错。
3. 读 `08-上下文投影.md` 第五节「模板与转义怎么写」。

### 风险

- 模型读 `<` 这样的写法，可能不如读原样的字顺。防：只有不可信的字段里真出现了这几个字才会转，平常的中文聊天里很少见；1-14 的探针和以后的评测会看到真实的样子。
- 以后有人写的模板把字段放在属性以外、没有边界的地方（例如一段裸的正文），转义也管不了别人怎么读。防：规矩写在图纸上，1-12 写出厂模板时照着写，审模板时照着查。
