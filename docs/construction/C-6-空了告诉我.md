## 施工单 C-6：空了告诉我

状态：施工完，待主会话实测（2026-10-01，图纸 `docs/blueprint/cross-session.md` 项目主人批准；分身施工，给模型看的字主会话量过）。

### 目的

她给别的会话派了件事、想等它做完，不用一直去翻：`send_message` 多一格 `notify_when_idle`，订「空了告诉我」。那个会话空下来（这一轮结束、它派的子代理都报完），这边记一条 `peer.idle`、叫醒她，通知带那一轮最后回复的第一行。照 Claude Code 的做法（设计 29，项目主人定）。
- `message` 改成可以不写：只订不发。
- 订了 12 小时（`peers.watch_hours`）还没等到的作废；那个会话删了、找不到的记 `gone`。作废、不在了只记下，不叫醒。
- 载入、恢复撤销以后照日志再订。
- 订子代理、订父会话的整次拒，留言也不发（图纸「起草时定的」第 18 条）。

C-5 实测时看到：她拿到「存下了」的回执以后，还 `sleep` 着等对方回话。有了这一格，她就有正经的等法。C-7 再看她会不会用。

### 2026-10-01 追加：空了先不发，等下一次忙完

真模型实测撞见：她只订不发话，那个会话当时闲着，通知当场就来了、带的是它上一轮的旧回答；之后那个会话干完了新的活，她却收不到。工具说明写的是「下一次干完」，和「当场发」对不上。项目主人定：订的时候对方闲着，等它下一次干完才通知；订的起算时刻之后对方已经干完过一轮的（带话又订的情形），照样当场发，不白等 12 小时。写进 `cross-session.md`「起草时定的」第 66 条。

**改了什么**：`crates/miyu-session/src/actor/watchers.rs`——名单 `Waiters` 从 `BTreeMap<SessionId, Timestamp>` 改成 `BTreeMap<SessionId, Waiter>`，`Waiter` 多一个「上膛」的标记；`actor.rs` 的 `Actor` 多两样内存状态：`busy_seen`（上一批送完时还忙不忙）、`finished_at`（最近一次从忙变空的时刻）。`add_waiter`：这个会话正忙着，或者起算时刻不晚于 `finished_at`，当场上膛；不然不上膛。`after_batch`：忙着的，`busy_seen = true`、名单上的都上膛；闲着、刚才还记着忙过的，清掉 `busy_seen`、记下 `finished_at = Some(now)`。`notify_if_vacant`：空了，给上膛的发通知、清掉；没上膛的留着。`handle.rs`、`actor/mail.rs` 的说明跟着改；`docs/blueprint/session/actor.md`「被等的名单」第 1、3 款和它的表也跟着改（没在施工单原来的写死范围里，是同一处机制的说明，留着不改会和代码对不上）。
