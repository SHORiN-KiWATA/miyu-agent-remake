## 施工单 9-1（补）：包的配置项能是列表

状态：已完成（2026-10-07 写、施工完；CI run 1134 三台和长跑全绿（run 1130 的 Windows 红在一条与这一步无关的测试抖动上，修了以后重跑）；起因是通讯平台的会话要把 `onebot.trusted`（平台身份的列表，只能写在系统配置）挪进桥自己的清单，9-1（下）的 `[settings]` 没有列表；配置清单本来就有列表（`Kind::List`，供应商的几个 key 就是），这一步只是给包开放；技术细节主会话定）。

### 目的

包的配置项能是「一串同类型的值」：一串平台身份、一串关键词、一串密钥。写法、查法、设置页的样子和核心自己的列表一样。

### 蓝图改哪几节

- `packages.md`「配置项」：`type = "list"` 和 `element`；出错那张表多 `bad_element`。

### 定了的（技术细节，主会话定）

1. **写法**：`type = "list"`，`element` 写元素的类型，必写：`bool`、`int`、`option`、`text`、`name`、`url`、`secret` 之一，不能再是 `list`（配置清单的规矩：列表的元素不能是列表）。叫 `element` 不叫 `of`：`config.schema` 里列表那一格就叫 `element`，两头一个词。
2. **元素带的几格写在同一张表里**：`element = "int"` 的 `min`、`max`，`element = "option"` 的 `choices`，`element = "text"` 的 `max`，管的是每一个元素。别的类型照旧不收这几格，`element` 只有列表能写。
3. **默认值**：TOML 数组，每一个照元素的类型查；空数组也算。元素是密钥的不能写默认值（同密钥）。
4. **设置页**：控件是列表（`list`），同核心自己的列表；`config.schema` 照旧写 `element`，元素是选项的多 `options`。
5. **出错**：少了 `element` 报 `missing_key`；`element` 写错、写成 `list` 报新的 `bad_element`；`type` 写错的那句话多列 `list`。

### 不做什么

- 列表的长度上下限、不许重复：核心自己的列表也没有，要的时候两边一起加。
- 把 `onebot.*` 挪进桥的清单：通讯平台的会话自己的一步，删核心的 `OnebotSettings` 要在同一个提交里（不然编号撞了核心的模块，整份 `settings_taken`）。

### 验收

1. 测试先写：每一种元素读对（带 `min`、`max`、`choices`、`max` 的照元素查）；默认值照元素查、空数组收、密钥的列表不能有默认值；写错报对代码；拼成配置项是 `Kind::List`、控件是列表；真核心走一遍：`config.schema` 有 `element`、写进系统配置读得到列表、写错 `check` 报。
2. 手写变异 8 个左右；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉通讯平台的会话（`onebot.trusted` 照这个写）、两个头（包的配置项也会有 `list`，控件同核心自己的列表）。

### 施工结果（2026-10-07 主会话）

1. `miyu-config`：`package/settings.rs` 多 `SettingKind::List`；读类型拆成 `kind`（`type`、列表的 `element`）和 `scalar`（不是列表的那几种和它们带的几格），列表和单个值共用一份。默认值改成照类型一层层查（`fits`），密钥、密钥的列表不能写。拼成配置项时元素也留在进程里（`leaked`）。
2. 问题代码多 `bad_element`，三种语言的话齐了；`bad_type`、`bad_default` 那两句跟着多说列表。
3. 顺带（终端界面的会话 2026-10-07 提的）：`crates/miyu-endpoint/tests/packages.rs` 原来断言出厂的只有网页，终端界面要出厂 `tui.toml` 就会红。改成只看出厂的网页和测试自己放的几份；草稿在测试里改叫 `term`，撞不上出厂的 `tui`。放一份 `resources/packages/tui.toml` 实测过：原来的测试红三条，改后的全过。
4. 手写变异 10 个，全被逮住；其中「默认值里不合的元素丢掉不报」第一版写成了编不过的代码，重写成编得过的再跑，逮住。
