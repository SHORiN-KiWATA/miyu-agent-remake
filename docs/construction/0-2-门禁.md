## 施工单 0-2：门禁

状态：已完成（2026-09-26 项目主人验收通过）。

### 目的

把三条只写在文档里的约定，变成机器每次都查的门禁：依赖只朝一个方向；纯逻辑不碰 I/O；文件要小。以后每一步验收，只要跑一条命令：`cargo xtask check`。

### 图纸

- `01-架构.md` 第九节「代码的分层」：这一步新画的，包括六层的表、五条规则、白名单和行数上限。门禁直接读这一节。
- `00-设计理念.md` 第四节「依赖与接口的规矩」第 1 条。

### 做什么

| 文件 | 装什么 |
|---|---|
| `Cargo.toml` | 工作区成员加上 `xtask` |
| `.cargo/config.toml` | 别名：`cargo xtask` 就是运行门禁程序 |
| `xtask/Cargo.toml` | 门禁程序。只依赖 `serde_json`，用来读 `cargo metadata` 的输出 |
| `xtask/src/main.rs` | `check` 命令：依次跑格式、clippy、三道门禁、测试，最后打一张结果表 |
| `xtask/src/drawing.rs` | 读图纸：从 `01-架构.md` 第九节读出六层、每层有哪些 crate、白名单、行数上限 |
| `xtask/src/layers.rs` | 分层门禁：每个 crate 都登记了；只依赖同层和更低层；纯逻辑的层只用白名单里的外部 crate；没有 crate 依赖工具 crate |
| `xtask/src/purity.rs` | 纯逻辑门禁：扫内核、模块两层的 `src/`，找文件、网络、子进程、环境变量、线程、时钟、标准输入输出 |
| `xtask/src/size.rs` | 行数门禁：每个 `.rs` 文件不超过上限 |
| `Cargo.lock` | 多出 `serde_json` 和它的依赖 |
| `docs/construction/施工图.html` | 施工图进仓库：顶上是整张架构图，没拼的虚着，拼上的画实（2026-09-26 项目主人要的）；下面每一步一张图纸，0-2 那张跟着定稿 |
| `docs/designs/架构全图.html` | 只加一行注释：施工图顶上那张图照抄这里的布局，这边改了那边跟着改。图本身不动 |

每道门禁都带单元测试：喂一份故意违规的假数据，证明它拦得住；再喂一份合规的，证明它不误拦。

### 不做什么

- CI：0-3 做。
- 豁免名单：现在一条违规都没有，用不到。哪天真要豁免再加，而且只减不增（`00-设计理念.md` 第四节说的棘轮）。
- 纯逻辑 crate 的开发依赖不查：测试用什么库都行。但 `src/` 里的单元测试照样不许 I/O。
- 「吞掉的错误」不另写门禁：0-1 的 lint 已经在查，`check` 会跑 clippy。

### 要拍板的

1. **文件行数上限定多少。** 推荐 500 行，测试也算在内。旧仓库是目标 800、上限 1500。
   - 定了：500 行。
   - 理由：Miyu 的代码要让中等模型只读局部就能改对（`00-设计理念.md` 第四节）。上限低，模块长到一半就得拆，拆的时候它还只做一件事。
   - 代价：测试多的模块，要把测试挪到单独的文件里。

### 我定的

- **图纸就是真相源。** 门禁直接读 `01-架构.md` 第九节，代码里不另写一份层序表（D4 未选 A）。图纸的格式被改坏了，门禁说清楚读不出来的是哪一行。
- **六层怎么分**，见图纸。驱动的编码和解码、协议的消息类型放在第 2 层，它们是纯函数；真正发请求、开套接字的放在第 3 层。依据是 `05-内核接口.md` 第七节：驱动是纯粹的翻译器，真正发请求的是执行器。
- **白名单现在是空的。** 从 1-1 起，内核要用 serde 这类库时，在那一步的施工单里写明理由，同时改图纸里的白名单。
- **纯逻辑的扫描按文本找**：`std::fs`、`std::net`、`std::process`、`std::env`、`std::thread`、`std::os`、`SystemTime`、`Instant`、`stdin()` 这类标准输入输出、`println!` 这一类。注释里的不算。它防的是手滑，不是存心绕过；存心绕过要靠 review 发现。
- **施工中加的一条：纯逻辑的层里不许用 `HashMap`、`HashSet`**，图纸规则 3 已经补上。它们遍历的顺序每次运行都不一样（哈希的种子取自系统的随机数），内核里只要遍历一次，同样的输入就会得出不同的字节。要用映射，用 `BTreeMap`、`BTreeSet`。编译期读环境变量的 `env!`、`option_env!` 也一起拦下。
- **`cargo xtask check` 一条命令跑完全部**：格式、clippy、三道门禁、测试。以后每一步的验收、0-3 的 CI 都用它。里面的 cargo 一个接一个跑，不并行。
  - 2026-09-26 补（施工 1-4 顺带，项目主人同意）：clippy 后面加了一道「文档」，一共七项。`cargo doc` 把私有的也一起生成，有一条警告就算没过：注释里的链接断了、写法坏了，都在这里拦下。只生成公开的，私有代码注释里的断链查不出来，试过。
- **门禁的报错写中文**，说清是哪个文件、哪一行、违反了图纸的哪一条。测试名照「名字用英文」的规矩写成英文，名字本身说明它证明了什么，例如 `pure_crate_depending_on_tokio_is_rejected`。
- **xtask 自己也守 0-1 的 lint**，例如不许 `unwrap`。
- 工作树是 `.worktrees/0-2-gates/`，分支是 `step/0-2-gates`。

### 验收

1. 在仓库根目录下：`cd .worktrees/0-2-gates`
2. `cargo xtask check`：结果表六行全是 ✓（格式、clippy、分层、纯逻辑、行数、测试）。
3. `cargo test -p xtask`：门禁自己的测试全过。
4. 亲手违规一次：
   - `printf 'pub fn hello() {\n    println!("hi");\n}\n' >> crates/miyu-kernel/src/lib.rs`，再跑 `cargo xtask check`：只有纯逻辑那一行变成 ✗，并指出是 `lib.rs` 的第 10 行。
   - `git restore crates/miyu-kernel/src/lib.rs` 改回去，再跑一次，全部 ✓。
5. 读 `01-架构.md` 第九节，看图纸画得对不对。

### 风险

- 按文本扫描会误报，例如某个字段恰好叫 `stdout`。缓解：只找 `stdout()` 这样的调用、`std::io::stdout` 这样的路径，不找单独的词。真误报了，就改扫描规则、补测试，不加豁免。
- 图纸是给人看的文档，门禁又要读它，它的格式就不能随便改。缓解：门禁读不出来时说清是哪一行，改图纸的人一看就知道。
