## 施工单 R-3（四补）：`/remember` 的回执不露编号

状态：施工中（2026-10-10 写；网页的会话接 `/dream` 时提：`/remember` 的回执「记下了：m4」把记忆的编号露给了人，用户看不懂；项目主人 2026-10-10 定改成「记下了：<那句话>」）。

### 目的

界面上不露存储结构（2026-10-08 项目主人定的设计原则，`16-人格与预设.md` 第 209 行）：`m4` 是给程序、给命令行 `miyu memory edit`、`forget` 用的，聊天里打 `/remember` 的人要的是「她记下了什么」。终端、网页显示的是同一句回执，改核心一处两边都对。

### 蓝图改哪几节

- `protocol.md`「`command.run`」第 8 条：回执带编号 → 回执带记下的那句话。
- `memory.md`「协议」`/remember` 那一条：同上。

### 定了的

1. 回执 `commands/remembered`：中文「记下了：{text}」，英文「Remembered: {text}」，日文「覚えました：{text}」；`{text}` 是记下的那一句（去掉前后空白以后的，最多 120 字，不用截），后面不再加句号（那句话自己多半带着）。
2. 那句话里的换行、制表这些控制字符在回执里换成空格（常驻那一块写正文也是这样，`memory.md` 第三条），记下的原文不动。
3. 命令行 `miyu memory add` 照旧印「记下了：m12」：命令行的 `edit`、`forget` 要用编号（`cli/memory.md`，项目主人这次定的只是聊天里的回执）。

### 不做什么

- 不动协议的 `memory.remember` 回应（`{"id"}` 是给程序的）。

### 验收

1. 测试先写，没改时红：`/remember` 的回执逐字是那句话；带换行、花括号的照换、照原样；同一个编号再发回执一样。
2. 手写变异几个，全被逮住；`cargo xtask check` 全过；三台机器的 CI 全绿。
3. 合了告诉两个头：回执的字变了，不用改代码。

### 风险

- 头要是照回执里的编号做了什么（例如点了跳到那一条），会断：两个头都只原样显示 `said`，没有用它。
