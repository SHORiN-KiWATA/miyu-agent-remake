## 施工单 6-8：手动压缩

状态：已完成（2026-09-29：变异全逮住；CI 全绿；「拍板的」2026-09-29 项目主人定；真模型走一遍由主会话合并前做）。

### 目的

人能自己叫她压缩：协议上 `session.compact`，命令行上 `miyu compact [要求]`（命令名 2026-09-29 项目主人定）。单开一轮只做压缩，可以附一句要求（例如「重点保留数据库设计的讨论」）；自动压缩暂停着也能压，压成了自动压缩跟着恢复。

### 蓝图改哪几节

真正的改动写在蓝图里，这里只列要点和为什么（技术细节照施工方案第一节第 6 条按推荐定）。

- `compaction.md` 第七条写实，「对外的样子」「样子」「给人看的字」「守着它的」跟着改：
  - **要求放在哪**：照 Claude Code（openclaude `getCompactPrompt`）夹在摘要指令的正文和最后那句「不许调工具」中间，前面一行 `Additional Instructions:`：最后一句还是提醒不许调工具，她读完要求不会顺手去调。为此 `summarize-task.txt` 拆成正文和结尾 `summarize-end.txt` 两份，说明那一行是 `summarize-instructions.txt`；自动压缩拼出来和原来一字不差（照 6-5 拆 `checkpoint-close.txt` 的做法）。
  - **要求原样进请求，不转义**：是人亲口说的，和 `message.user` 一样原样发（Claude Code 也原样接）；末尾没换行的补一个；去掉前后空白是空的当没写，事件里也不写。
  - **替代到哪**：和自动压缩同一套（第三条第 2 条），尾巴一样留；「这一轮要回应的话」换成还没有哪次请求看到过的人的消息；单开的这一轮自己不压进去。收下命令时就定，重试照同一个 N。
  - **`nothing_to_compact`**：照上面定出来的 N 以前没有能压的：上一次压缩以后没有新的消息、回复、工具结果，或者全在尾巴里（照 Claude Code 的「Not enough messages to compact」）。策略里没有压缩的旧快照（6-2 以前造的，连摘要指令都没有）、执行器没交过限额的，也回它：只在开发时的旧会话、内核测试里有，不另开原因码。
  - **没报窗口的模型也能手动压**：没有压缩线，尾巴的预算就是策略的 16000。
  - **那一轮**：`turn.started` 没有 `trigger`，`by` 是内核，`cause` 是命令，`cwd`、`dirs` 照写；不注入事实、不换实际生效的权限、不跑回合开始的挂接点（这一轮不请求主模型、不调工具），回合结束的挂接点照常。开头落了盘就发摘要请求。
  - **成了**：`context.compacted`（`trigger` 是 `manual`，`instructions` 原样，不写 `refills`）、推 `compaction.done`、`turn.ended`（`completed`）在同一批；这一轮不注入事实，下一轮开头照常比着注入。排着的接着开下一轮。
  - **失败**：照「出错再来」重试；不再来的，这一轮 `error`。不数进熔断（`breaker.rs` 的 `after_failure` 看是哪一种压缩：6-6 上注释里留的，这一步连同测试加回来），不写暂停。
  - **打断**：摘要请求照打断的规矩记 `model.called`（`interrupted`），不写 `context.compacted`。**重启**：`restarted` 结束，载入时不接着干（没有 `trigger` 的那一轮）；排着的留在日志里，人下次开口她一起看到。
  - **熔断**：暂停着也收；成了，检查点换了，暂停和失败都在它前面，自动压缩恢复。手动的不算「压完很快又到线」，下一次自动压缩的 `refills` 从头数。
  - **度量**：`compaction.done` 多一格 `trigger`，运行日志 `compacted` 那一行照它写（现在写死 `auto`）。
- `kernel/events-bodies.md`：`turn.started` 的 `trigger` 改成可以没有；`context.compacted` 多 `instructions`，`trigger` 会写 `manual`；`model.called` 的 `compaction` 会有 `manual`。`kernel/events.md`：`compaction.done` 多 `trigger`。
- `kernel/session.md`：命令多 `Compact { instructions }`，原因码多 `nothing_to_compact`；「回合」写手动压缩那一轮怎么开、怎么走；「载入和崩溃」第 5 条不接着干没有 `trigger` 的；「还没有的」去掉 6-8。

- `protocol.md`：方法表、`session.compact` 一节、原因码 `nothing_to_compact`、`turn_running` 也管压缩、「还没有的」去掉它。
- `session/actor.md`：`compacted` 那一行的 `trigger` 照 `compaction.done`。
- `policy.md`、`store/resources.md`：快照的 `compaction` 多 `summarize_instructions`、`summarize_end` 两份字；以前的快照没有，读成空的。

### 拍板的

给人看的几样，2026-09-29 项目主人定。

**A. 命令怎么写**

- `miyu compact [要求]`：要求是位置参数，几个词用空格连起来，不写就是没有要求（照 Claude Code 的 `/compact [instructions]` 和 `miyu ask`）。未选：`--instructions <要求>`，多敲一截。
- 找会话照 `miyu undo`：不写是上一次 `miyu ask` 开的，`-s`、`--session <编号>` 指定别的。
- 不做 `--format json`：不是查询类的命令，和 `miyu undo` 一样。
- 要请求模型，照 `miyu ask` 的规矩连核心：没设 `DEEPSEEK_API_KEY`、核心也没在跑的，不拉起，说「没有可用的模型：设环境变量 DEEPSEEK_API_KEY」，退出码 5。

**B. 印什么、印在哪**：照搬 `miyu ask` 压缩那一行和用量那一行，全在标准错误上。

压缩那一行是 2026-09-29 定过的样子，这里原样复用，后面接一行这次摘要请求的用量（缓存命中就是钱，压缩一次看得到花了多少）：

```text
$ miyu compact 重点保留数据库设计的讨论
· 正在压缩上下文… 已写 3,120 字
```

终端里这一行原地刷新，压好了换成：

```text
$ miyu compact 重点保留数据库设计的讨论
· 上下文压缩好了：812.3k → 31k token
· 输入 812,457 · 命中缓存 810,112（100%）· 输出 2,412
```

失败（红的是「压缩失败」那一行；最后一句照 `miyu ask`，带着供应商的原话）：

```text
· 压缩失败：取不出摘要
· 输入 812,457 · 命中缓存 810,112（100%）· 输出 2,412
出错了：取不出摘要：no summary in the reply
```

按 Ctrl+C：

```text
· 正在压缩上下文… 已写 1,024 字
打断了
```

- 标准错误不是终端的，压缩中不印，只印结果和用量；标准输出上什么都不印。
- 未选：「压好了」那一行走标准输出（照 `miyu undo` 的「结果走标准输出」）。那一行是一句旁白，脚本看退出码就够；分两条通道，终端里还得先在标准错误上擦掉进度再往标准输出写。
- Ctrl+C 第一次打断、等这一轮收尾，第二次不等了（照 `miyu ask`）。打断时别的头在压缩期间排着的话接着发（`queued: "send"`）：`miyu ask` 退回，退的是自己那一轮排着的；这里排着的多半是另一个终端里 `miyu ask -c` 说的，退回了那边就一直等不到自己那一轮。

**C. 退出码**：0 压好了；1 被拒绝（有回合在进行、没有能压的、找不到会话……）、压缩失败、核心断开；3 被打断；5 没有可用的模型。

**D. 核心拒绝时说的话**

- `nothing_to_compact`（新）：
  - 中文：`没有能压的：还没压过的内容都在原样留着的最近一段里。`
  - 英文：`Not enough to compact: everything not yet compacted is in the recent part that stays as it is.`
  - 未选：原来蓝图里写的「上一次压缩以后还没有新内容」：上一次压缩以后有新内容、但全在尾巴里的（最近一段 16000 token 以内），也是这一种，那样说不对。
- `turn_running` 原来只说撤销（「有回合在进行，撤销不了：先打断再撤。」），压缩也回它，改成两边都对的一句，`miyu undo` 那边跟着换：
  - 中文：`有回合在进行：先打断，或者等它做完。`
  - 英文：`A turn is running; interrupt it or wait for it to finish.`
  - 未选：照命令分两句。原因码一种一句，核心配话的地方不知道是哪个方法，要多一套。

```text
$ miyu compact
没有能压的：还没压过的内容都在原样留着的最近一段里。
```

**E. 帮助页**（英文照 80 列收短，要求写 `[words]`，和 `miyu ask <words>` 一样）

`miyu compact -h`：

```text
用法：miyu compact [选项] [要求]

把上下文压缩成一份摘要，最近的一段原样留着。后面写的话是给摘要的要求。

选项：
  -s, --session <编号>  哪个会话；不写就是上一次 miyu ask 开的
  -h, --help            印帮助
```

```text
Usage: miyu compact [options] [words]

Compact the context into a summary; the most recent part stays as it is.
Any words are instructions for the summary, such as what to keep.

Options:
  -s, --session <id>  Which session; default is the one the last miyu ask opened
  -h, --help          Print help
```

`miyu -h` 改动的几行（命令表加一行、选项那一节带上 `compact`、说明那一句、例子加一个）：

```text
  compact [要求]        把上下文压缩成摘要，可以附上要求
undo、restore、compact 的选项：
每次 miyu ask 都新开一个会话；-c、undo、restore、compact 管的是上一次开的那个。
  miyu compact 重点保留数据库设计的讨论
```

```text
  compact [words]       Compact the context into a summary
undo, restore, compact options:
Each miyu ask opens a new session; -c, undo, restore, compact use the last one.
  miyu compact keep the database design discussion
```

### 不做什么

- 撤销能撤掉压缩、`miyu undo` 撤掉压缩时说一句：6-9（先合进 main；手动压缩那一轮是一轮，撤掉它压缩跟着撤掉，这一步只加一个场景测试证明接得上）。
- 摘要请求超长截掉最老的几组再试：6-6（中）；调了工具改走隔离式：6-6（下）。两步都先合进 main，手动压缩走同一条路：截过的、隔离式的摘要请求照样夹着要求，记 `manual`（`Assembler::summarize_isolated` 也多一个参数 `instructions`）。
- 终端界面里的 `/compact`、局部压缩（压到选中的那一条）：M8。
- `--format json`：见 A。被动压缩：6-7。换模型以后解不解除暂停：随换模型那一步。
- 施工图、施工方案第三节的表和第五节：主会话改。

### 验收结果（2026-09-29）

1. **测试**（rebase 到 6-9、6-6（下）、6-7 以后，整个工作区 1534 个全过）：
