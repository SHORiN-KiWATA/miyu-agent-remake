# TUI：预编辑同步刷新

状态：施工中（2026-10-04）。技术细节按推荐定；尚未真人验收。

## 目的
AI 输出时，fcitx5 预编辑和输入框 tips 不再交替闪现。直接运行 TUI 也会出现，隔离 kitty 0.49.2 + fcitx5/Rime 复现了同步暂停期间预编辑消失。

## 蓝图改哪几节
`docs/blueprint/tui.md`「每一帧」：原来先发送开始同步刷新，再计算和输出；改成在内存中准备完整帧，再一起发送首尾、画面和光标。保留同步输出与现有光标规则。

## 要拍板的
技术细节按推荐定（2026-10-04）：只改 TUI 输出边界，不改核心或输入框体验。启用现有 ratatui 的 unstable-backend-writer 入口，版本照现有锁文件；未添加新的直接依赖。Cargo 更新锁文件时纳入 ratatui 的可选 termion 包（MIT / Apache-2.0 许可兼容），当前构建仍只使用 crossterm。新终端 writer 只暂存正在准备的一帧；帧外仍直接写。画面准备失败也发送同步结尾，I/O 错误照实返回。

## 不做什么
不修改用户 kitty、fcitx5 或 herdr 配置，不去掉 tips，不改变刷新节拍。

## 验收
先补 writer 回归测试，旧的直写行为必须红；修后绿。覆盖中间 flush、超过通常缓冲容量的图片字节、相邻帧、帧外输出、写失败。PTY 测试及隔离 kitty/fcitx5 同步骤验证，仓库门禁和 TUI 三平台 CI；真人直接运行及 herdr 中验收后才合入 proto/tui-demo。

## 风险
大帧仍可能被操作系统分段传输；单次 write_all 不能承诺终端一次 read 完。消除应用计算与中间 flush 留出的暂停窗口，实际终端验证效果。单帧缓冲复用容量，不缓存历史帧。

验证记录（2026-10-04）：直写版本的回归测试红，整帧缓冲后绿；Linux 完整 TUI 测试通过（647 通过、11 ignore），clippy 全目标通过。隔离 kitty 0.49.2 + fcitx5/Rime 实测：暂停期间预编辑消失，整段同时发送则不变；修复版真实 TUI 接测试核心，回合保持进行中、运行状态持续刷新，60 张连续截图的预编辑区域无变化。核心使用 Play::Holds，不调用真模型；这项证明刷新期间的预编辑稳定，真人流式输出场景仍待验收。证据保存在 ~/.cache/miyu-tui-ime/evidence/。试用入口 ~/.cache/miyu-tui-ime/try 使用已经验收过的卡片试用数据根和配置。
