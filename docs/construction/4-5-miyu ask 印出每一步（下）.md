状态：进行中。

### 目的

4-5（上）让每次调用的结果带上了给人看的说法，中文、英文的字也备齐了。这一步让 `miyu ask` 照项目主人 2026-09-28 定的样子，在标准错误上印出她做的每一步：

```text
$ miyu ask "glob 和 grep 在哪登记的？"
先搜一下登记工具的地方。
· 搜内容 fn tools → 2 个文件
· 读取 crates/miyu-basesystem/src/lib.rs → 37 行

在 crates/miyu-basesystem/src/lib.rs 的 tools() 里，
和 read 一起造好，核心起来时登记进工具目录。
· 输入 3,210 · 命中缓存 2,944（92%）· 输出 186
```

做完这一步，M4 读的那一半就能用了：让她在工作区里读代码、搜代码，看得见她每一步做了什么、做成了没有。

### 不做什么

- 核心的视图投影、视图流：做前端时。
- 跑得久的一步先印一行「在做」：做 `shell`（4-8）时看要不要。现在做完才印，几件同时跑的照做完的先后印。
- 为什么要确认（例如「在工作区外面」）：确认在 4-9 做，那时要问的原因跟着确认一起来。现在没人能确认的只说「要确认，这里没人能确认」。
- 英文的单复数（「1 files」）：做前端时。
- `--format json` 不印步骤，照旧只在最后印一行。

### 我定的

- **回应里带上实际的工作目录**：
  - `session.create`、`session.send` 的回应多一格 `cwd`：会话这会儿实际在哪个目录里干活。就是头报的那个；太宽的，是账号的工作区。
  - 头报的和它不一样，就是退回了。核心只在目录太宽时换（11 第四节），头照这个写「目录太宽」。以后有了别的原因，再加一格说为什么。
  - 为什么不让头自己判断宽不宽：那得把核心的规矩抄一份，还得知道数据根在哪。从回应拿，规矩只有一份。
  - 说话的回应也带：`--continue`、`--session` 接着说时，头报的目录是跟着这一句送进会话的。
  - 回应排在它产生的推送后面（04 第六节第 2 条）。结果要等模型回话、工具跑完才有，回应早就到了，所以这一句在第一步前面。
- **目录太宽那一句**：
  - 例如 `· 目录太宽（~），这次在 ~/.miyu/home/admin/workspace 里干活`，家目录写成 `~`。
  - 一次 `miyu ask` 只说一次：造会话的回应里说过了，说话的回应里一样的，不再说。
- **一步那一行**：
  - 写成 `· 显示名 参数的值 → 结果那一句`。
  - 显示名、跟哪个参数，照给人看的字里这件工具的 `name`、`subject`。没有的（第三方的工具，或者没有这件工具），照她写的工具名，后面不跟值。
  - 结果那一句，照说法换成字。没有说法的、换不出来的，照状态写最泛的一句。
  - 没做成的：出错的写「出错：原因」，被拒的写「没做：原因」。「出错」「没做」这两个词是红的；没有原因的只写这两个词。
  - 打断了、跳过了的，说法本身就是「打断了，没跑」「跳过了」，不再加词；没有说法的写「打断了」「跳过了」。
  - 做成了、又没有说法的：不写箭头和结果，只写做了什么。
- **路径照工具结果的规矩写**（10 第十节）：
  - 参数叫 `file_path`、`path` 的是路径，这两个名字是规范定的。在工作目录里的写相对的，工作目录本身写 `.`；在家目录里的写 `~/…`；别的照原样。
  - 别的参数（`pattern` 之类）照原样，不当路径改：以后 `shell` 的命令里也有路径，改成相对的，命令的意思就变了。
  - 参数用了别名的（例如 `read` 写成 `path`），显示名后面不跟值：别名是工具自己认的，头不知道。做前端时，核心的视图投影照工具自己认的参数给。
- **印之前收拾一下**：
  - 参数的值只取第一行，有第二行的后面加 `…`；
  - 控制字符换成 `�`，和说法里换进去的字段一样（施工 4-5 上）；
  - 太长的截断，加 `…`：参数的值 80 个字，结果那一句 120 个字，没有显示名的工具名 40 个字。
- **灰的、红的**：
  - 整行包在灰色里，「出错」「没做」换成红色，写完换回灰色，行尾回到原色：中途退出也不会把终端留成灰的。
  - 标准错误不是终端、设了 `NO_COLOR` 的，一律不上色，红的也不上。
- **旁白和回答隔开**：思考、步骤、目录太宽那一句，都是写在标准错误上的旁白。
  - 旁白之间不空行；旁白和回答之间空一行，写在回答的第一段前面（施工 3-9 下）。
  - 回答那一行还没完就来了旁白（例如她先说「我先看看」再调工具），先在标准输出上换行。这样终端里旁白不接在回答后面，重定向进文件的，前后两段回答也隔开了。
  - `--format json` 里一轮的 `text` 也照这个：一轮里几次回复的正文，没换行的中间补一个。
- **没见过的调用不印**：结果对不上她调过的哪一次（掉队重订以后前面的推送没看到），不猜。
- **给人看的字从资源目录读**：`miyu ask` 照界面语言读一份；读不出来的当没有，照状态写最泛的。出厂的字测试都对过（施工 4-5 上）。

2. `cargo test`：

     - 读工作区外面的，「没做：要确认，这里没人能确认」；
     - 在 `~` 里问的，开头说目录太宽。

### 风险

- **行太长**：终端窄的会折行。现在只截参数的值和结果那一句，不量终端多宽；做前端时照终端宽度排。
- **回应里多一格**：头不认这一格照样能用，字段只加不改（04 第九节）。
