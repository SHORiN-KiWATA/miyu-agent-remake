## 施工单 D-1：回答确认和提问

状态：待验收（2026-10-07 写、施工完；项目主人同一天定：确认、提问、待办三样提前做，做好了通知头去适配；「这个工作区以后都允许」照 2026-09-28 定的先不做；技术细节主会话定）。

D 是「抽屉」这条线，和 W、C 一样不占里程碑的号：D-1 回答确认和提问，D-2 提问工具 `ask_user`，D-3 待办 `todowrite`。

### 目的

头看得到 `tool.approval_requested`、`question.asked`，却回答不了：核心不收 `session.answer`。这一步协议收它，内核早有的 `Command::Answer` 接上；人选了「本会话都允许」的，这个会话以后落在那个范围里的写入不再问。

### 蓝图改哪几节

- `protocol.md`：方法表加 `session.answer`，新开一节写参数、回应、规则；「出错」里 `not_asking`、`unknown_decision`、`no_rule`、`unexpected_reason`、`bad_answer` 从「碰不到」挪进表里，配中英文的话；「还没有的」去掉 `session.answer`。
- `kernel/asking.md`：新一节「本会话放行过的」：每追加一条记一次，载入照日志重算；交给链的动作带上它；「还没有的」改。
- `session/guard.md`：判法加一步，要问人的写入落在本会话放行过的范围里的，放行；提规则时，目录是家目录本身或者更上面的，写那一条路径本身；「还没有的」改。
- `kernel/session.md` 命令表那一行指到协议。

### 定了的（技术细节，主会话定）

1. **参数**：`session`、`call`（调用编号）；回答确认的写 `decision`（`once`、`session`、`deny`），拒绝的可以带 `reason`；回答提问的写 `answers`（照题目的先后，每道 `{"picked": [选项的标题], "text": 自己写的}`，两样都可以不写）。`decision`、`answers` 两样都写、都不写：`bad_params`。`decision` 写 `workspace`：`bad_params`（「这个工作区以后都允许」2026-09-28 项目主人定以后再加，协议先不认）。
2. **回应**：`{"events": [序号]}`，这一次追加的都落了盘才回，和 `session.send` 一样。
3. **放行的范围**（`11-权限与沙盒.md` 第二节「放行规则管多大」）：放行的是请求里规则的 `write` 那几条，连同它们下面的；规则里的一条是家目录本身或者更上面的，换成那一条路径本身（提规则时就换，规则里写的就是要放的）。读取现在不问，所以只有写入。不分工具：写入、编辑、删除都算（同一节「允许改的」）。
4. **记在哪**：内核每追加一条记一次，载入时照日志一路算回来，不进上下文、不怕压缩；不另开事件，照 `tool.approval_requested` 的规则和 `tool.approval_decided` 的 `session` 算。
5. **撤销不收回**：放行是人的决定，不是她说的话，撤哪一轮都还在（Claude Code 回退也不收回权限）。
6. 只读开着的照旧拦写入：只读压过放行。子会话不继承父会话的放行，各记各的。

### 不做什么

- 「这个工作区以后都允许」：要存进工作区的配置，存哪还没定（2026-09-28）。
- 提问工具、选项的 `preview`、回答的 `notes`：D-2。
- 照命令开头放行（`shell`）：要先拆得开 `a && b`，随以后。

### 验收

1. 测试先写，退回改之前要红：
   - 内核：放行过的照日志算出来，载入以后、压缩以后、撤销以后都在；交给链的动作带上；只认 `session` 的决定。
   - 守卫：写入落在放行过的目录下的放行，不在的照旧问；家目录那一条只放它本身；只读照旧拦。

4. 合进 main 以后告诉两个头：`session.answer` 的形状、四个原因码。

### 风险

- 范围判错就是放大权限：路径一律换成真实的位置再比（守卫本来就这么做），按路径的段比，不按字符串前缀（`/a/b` 不能放行 `/a/bc`）。
- 内核多一份状态：载入、撤销、压缩各测一遍，和照日志从头算的一样。
