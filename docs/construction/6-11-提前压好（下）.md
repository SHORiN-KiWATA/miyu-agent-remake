## 施工单 6-11（下）：到线时在路上的，等它回来

状态：施工中（2026-10-08 写；做法 2026-10-07 项目主人定，`09-压缩.md` 第十节；技术细节主会话定）。

### 这一步做什么

6-11 上到线时提前那一次还在路上，就扔下它当场压。照设计改成等它：

1. **到线**（自动压缩、手动压缩没附要求的），这一轮开着，提前那一次在路上、起压时的指纹和这时的一样：不当场压，回合进「等它」（`Stage::Awaiting`），推一条 `compaction.progress`：`seen` 是那一次的 N，`written` 是已经收到的正文字数（不一定是 0），`expected` 照当场压的算法（压之前的用量夹在两头之间）。指纹不一样的：扔掉它，当场压。
2. **等的时候**：那一次每来一段正文，照当场压一样推 `compaction.progress`（`written` 往上加）。别的旁路请求照旧。
3. **它说完了**：照 6-11 上记它的 `model.called`（不带回合编号，`purpose` 是 `compaction`，不带 `compaction`）。
   - 取到了摘要、还用得上（指纹、切得开、尾巴不超过 T + G）：照「换上」走（重读、写 `context.compacted`、推带 `prepared` 的 `compaction.done`；`usage`、`duration_ms` 是这一次的）。
   - 出错、取不出、调了工具、用不上了：扔掉，照现在的办法当场压，`compaction.progress` 的 `written` 从 0 起，`seen` 是到线时切的 N（可能和刚才的不一样）。调了工具的不再照隔离式补发一次提前的：当场压自己会改走隔离式（第五节）。
4. **等的时候打断**：回合照「准备好」那样收尾（这一轮自己没有在路上的请求，不补 `model.called`）。那一次接着在后台跑，回来了照 6-11 上放着，下一次到线还用得上的照用。
5. **等的时候重启**：照「换上」那样收尾。

### 主会话定的技术细节

1. 等的那一会儿是回合的一个阶段 `Awaiting`，带着到线时的 `Due` 和进度的计数；那一次照旧是旁路请求、照旧在 `Prepare` 里，回报照旧走旁路的三条输入，不改成主请求：执行器、`model.called` 的写法都不动。
2. 已经收到的字数照那一次的累积器里正文块的字数算（和当场压数 `written` 的规矩一样：思考不数）。
3. 打断、重启时不叫停那一次：它是旁路请求，叫停它要动执行器；回来了放着，还用得上的下一次照用，和 6-11 上「压好了没到线」一样。

### 不做什么

- 真会话量 G、省下的等、白花的次数：照「验收」第 3 条量，量完写进 `09-压缩.md` 第十节「要实测的」，G 改不改另说。

### 头要知道的

- 到线时提前那一次还在路上的：先推 `compaction.progress`，第一条的 `written` 可能不是 0；收完推 `compaction.done`（`prepared: true`）。它出了错的，接着推的 `compaction.progress` 的 `written` 从 0 起、`seen` 可能变了。设计第十节「头要知道的」早写了，6-11 上的头照它接，形状不变。

### 验收

1. 测试先写，退回改之前报红：到线时在路上的等它、第一条进度带已经收到的字数、等的时候每段正文推进度；回来了用得上的换上（`prepared`、用量照它的）；出错、取不出、调了工具、尾巴超了的改当场压（进度从 0 起、`seen` 是新的 N）；指纹变了的当场压；手动压缩没附要求的也等、附了要求的不等；等的时候打断、重启；打断以后它回来了，下一次到线照用。随机测试：等的阶段和打断、重启、旁路回报随机交错，看守照规矩查。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 真会话：开发端点、小窗口，跑长任务，从运行日志和 `model.called` 量起压到到线之间长了多少、多少次在路上、多少次超了 T + G、到线那一步等了多久。

### 验收结果（2026-10-08）

1. **测试**：`scenario/prepare_wait.rs` 八条，改之前七条红（另一条是「不该等」的，改前改后都过）：到线时在路上的等它、第一条进度带已经收到的字数、等的时候每段正文推一次、回来了换上；出错、取不出、调了工具的落了盘再当场压、进度从 0 起、不补发隔离式；尾巴已经超了、N 以前变了的不等；手动压缩没附要求的也等、附了要求的不等；等的时候打断留着下一次照用、重启照当场压；等的时候切了级别，下一次请求以前注入。6-11 上那条「在路上的不等」照新的办法改写进这里。替身多 `Line::held_after`；随机测试里慢的提前压到线时还在路上（三百例里走到两次等、三次等的时候推进度），看守查进度是它收到的字数、等的时候不发请求；随机测试的提前量从 20 放到 40（窗口 300 的 G 才放得下尾巴）。
