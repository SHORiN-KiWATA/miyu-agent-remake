## 施工单 C-5：发给别的会话

状态：待施工（2026-10-01，图纸 `docs/blueprint/cross-session.md` 项目主人批准）。

### 目的

她能给你别的主会话发话：
- 留言的工具 `message_agent` 改名 `send_message`（照 Claude Code 的 `SendMessage`，项目主人定）。以前造的会话快照里冻着 `message_agent`，照认。
- `to` 多认会话编号（整个或至少 8 位后缀，用 C-3 的 `find_session`），`message` 还是必填（C-6 才改成可以不写）。
- 一句话长度上限 `peers.message_chars`（100000），父子之间的留言一起管。
- 每种拒绝都有回执：找不到、撞了、是自己、子会话和群里不能用、太长、限速、一字不差、对方没听到的太多。发给没人看着的一次性会话只存下，回执说清。
- `sessions` 的说明补上「to use with send_message and history」（C-3 记的，图纸「起草时定的」第 40 条），和改名同一次冷启动。

### 蓝图改哪几节

图纸是 `cross-session.md`，只读标着 C-5 的这几处（`grep -n 'C-5'`）：
- 「在哪」：`miyu-endpoint/src/spawn.rs`（发话时交回对方有没有人看着）、`miyu-tool/src/messages.rs`（`Recipient` 多 `Session`、`NotSent` 多几种）、`miyu-session/src/messages.rs`、`miyu-basesystem/src/send_message.rs`（由 `message_agent.rs` 改名）。
- 「对外的样子」：改名、`to`、策略数据 `peers.message_chars`。
- 「怎么走」：第三条发话、第五条第 4 款（长度上限在工具里查）、第九条谁能用里标 C-5 的。
- 「样子」：`send_message` 的说明和参数，九句回执（`send_message/*.txt`），给人看的显示名和说法（中英日，`message_agent`、`send_message` 两个键都在）；运行日志两行。
- 「守着它的」：标 C-5 的行。
- 页末「要跟着改的别的页」里标 C-5 的。

### 不做什么

- 「空了告诉我」`notify_when_idle`、`message` 可以不写：C-6。
- 跨会话的真模型整体验收：C-7。

### 验收

1. 测试（先写，退回改之前的代码要红）：照「守着它的」标 C-5 的行。
   - 改名以后旧会话的工具面一个字节不变、照认 `message_agent`；新会话只有 `send_message`；
   - `to` 认会话编号，每种拒绝的回执一字不差；
   - 长度上限对父子之间一起管；没人看着的一次性会话只存下；
   - 请求形状探针：新会话的工具面只变 `send_message`、`sessions` 这两件，存档重写，diff 证明别的一字不差。
2. 给模型看的字：`send_message` 的说明和参数、`sessions` 补的那半句、九句回执。写好以后用 SendMessage 交给主会话，主会话量 token 回数，再登记、核工具面预算、跑 `cargo xtask prompts`。
3. 真模型（主会话合并前做）：真核心两个主会话，A 里让她给 B 发一句要它回答的话，B 被叫醒、用 `send_message` 回话，A 被叫醒看到回话。
4. 手写变异 15 个左右，挑关键的，全被逮住；`CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
5. 合了告诉两个头：工具改名、显示名两个键、回执的说法。

### 风险

- 工具面又冷一次：图纸定的先后（改名、`to`、`sessions` 那半句放在同一次），接受。
- 和 8-6 同时做：冲突多半在 `Cargo.lock`、`session/actor.md`，主会话合并时解。
