## 施工单 3-7：运行日志（上）

状态：施工中。

### 目的

照 `docs/designs/28-运行日志.md` 做核心的运行日志：一行一条的英文，像 dmesg；写进数据根的 `state/logs/core.log`，满 10 MB 换一份，留 5 份；默认记到 `INFO`，环境变量 `MIYU_LOG` 改这一次启动的级别；不写对话的内容，不写密钥。会话 actor（下一半）、协议端点、`miyu ask` 都照它记来龙去脉。

### 拍板的

- 项目主人 2026-09-27 定了四条（`28-运行日志.md` LG1 到 LG4）：一行一条的字，像 dmesg，字一律英文；默认 `INFO`，能配置，像 grub 配 `loglevel`；不写对话内容，只写编号；每个软件各写各的，核心记起停。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-log/`（新，第 3 层） | 一行怎么写（时刻、级别、来源、这件事、键值）；按大小轮换的文件；级别从哪来（`MIYU_LOG`，没设是 `INFO`，写错了用 `INFO` 并记一条 `WARN`）；装上以后交回一个守卫，退出时把没写完的写完 |
| `crates/miyu-http/` | `DEBUG` 记发出去、收场：主机名、请求多少字节、状态码、响应头里的限速信息、用时、出错的分类；不写请求体，不写 key，地址只写主机名（有的供应商把 key 放在 URL 里） |
| `docs/designs/01-架构.md` 第九节 | 第 3 层多一个 `miyu-log`；它依赖的 `tracing` 这几个外部 crate 不在纯逻辑的白名单里，纯逻辑的两层不许用 |
| 施工图 | 3-7（上）那一张 |

### 不做什么

- 配置项 `log.level`：配置那一步（`14-配置.md`）。现在只认 `MIYU_LOG`。
- `miyu logs`：随 `miyu` 这个程序一起来（3-9 以后）。现在直接看文件。
- 每个软件的日志：有了子进程（M4 以后）再接，规矩已经定在图纸里。
- 会话开关、回合的来龙去脉，`INFO` 的「请求」「收场」两行（带序号、用量、用时）：会话 actor（3-7 下），它手里有这些；HTTP 这一层不重复记。

### 我定的

- **用 `tracing` 发、`miyu-log` 写**：`tracing` 是 Rust 里通行的日志门面，本身不做 I/O，第 3 层以上的 crate 照它发；怎么写成一行、写到哪，只有 `miyu-log` 管，装在程序的入口。纯逻辑的两层不发日志：内核只交出动作，来龙去脉由执行器照动作记。
- **按大小轮换，自己写**：`tracing-appender` 只会按时间轮换。满 10 MB 在两行之间换，一行不拆开；`core.log.4` 挪成 `.5`，依此类推，最老的删掉。
- **时刻用本机时间**：取系统时区用 `jiff`（纯 Rust，三个平台都认系统时区）；起来的那一行写上时区。
- **来源**：`core`、`session`、`http` 这样的短名字；有会话编号的，写在来源后面，写全。
- **键值照写，不做花样**：值里有空格、引号的加双引号，引号用反斜杠转义；一行里不出现换行，换行写成 `\n`。
- **不写内容靠两道**：接口上不给写内容的口子（`miyu-http` 只记主机名、长度、状态、分类）；测试里拿带 key、带正文的请求跑一遍，查日志里一个字都没有。
- **会话编号跟着 span 走**：会话 actor 开一个带 `session` 的 span，底下 HTTP 发的行也带上它；格式里把它写在来源后面。

### 验收

1. `step/3-7a-log` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 一行：时刻、级别、来源、这件事、键值，照图纸的样子；值里有空格、引号、换行的照规矩写。
   - 级别：`MIYU_LOG` 没设是 `INFO`，`DEBUG` 的不写；设成 `debug` 的写；写错了的（`loud`）照 `INFO`，并记一条 `WARN` 写明写错的值。
   - 轮换：写过 10 MB 换一份，留 5 份，最老的删掉；一行不拆在两份里。
   - HTTP：本机的假服务器上发一次、出一次错，`DEBUG` 各记了该记的行；日志里没有 key、没有请求体里的正文、没有地址的路径和参数。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --workspace --exclude miyu-http --target` 查 Windows、macOS。

### 风险

- **写日志拖慢请求**：一行写进文件用不了多久，可磁盘慢的时候会卡住发日志的那个任务。先同步写、每行一次，实测慢了再换成后台写。
- **多个进程写同一份文件**：核心是一个进程（家目录的锁，`12-进程形态与分发.md`）；子进程各写各的（LG4），不会撞。
