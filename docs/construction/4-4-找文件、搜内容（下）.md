### 目的

基础系统多两件工具：`glob` 按名字模式找文件，`grep` 照正则搜文件内容。两件都用自带的实现（ripgrep 的作者拆出来的几个库），不调系统命令，三个平台的行为和输出一样，都遵守 `.gitignore`。

工具照成熟 harness 的规范来，以 Claude Code 为主（`10-自带软件.md` 第十节）：两件新的照规范做，已经做好的 `read` 也改到规范上。

`read`、`glob`、`grep` 都要说的几句（没有这个文件、读的时候出错了、参数不对、通配写法不对）放进资源目录的 `common/`，一句只存一份。

### 我定的

**三件共用的**

- **参数**：名字照 Claude Code；每个参数一句说明，默认值写成 `Default 100.`。
- **路径参数**：接受绝对路径、相对工作目录的路径、`~` 开头的路径。Claude Code 在说明里要求写绝对路径，其实也认相对路径。我们照实写「绝对的，或者相对工作目录」，这样 `glob`、`grep` 给出的相对路径拿去就能直接给 `read`。
- **可选的字符串参数**：传了 `"undefined"`、`"null"` 或者空串的，当没传。Claude Code 在说明里专门叮嘱过别这么传；我们在代码里兜住，不写进说明。
- **找不到时给相近的名字**：Claude Code、opencode 都这么做。在同一个目录里找，最多列 3 个：只差大小写的，主名一样、扩展名不同的，改一两个字就一样的。
- **找文件、搜内容走目录的规矩**：
  - 遵守 `.gitignore`、`.ignore`，不在 git 仓库里也照样遵守。上级目录里的分两种（施工中定的）：在仓库里时，仓库根到搜的那个目录之间的都算；不在仓库里时，只认搜的那个目录往下的。家目录里要是有一份写着 `*` 的 `.gitignore`（拿 git 管 dotfiles 的常这么配），一路往上找，家目录下面不在仓库里的东西就全搜不到了。pi 也是这样分的。
  - 隐藏文件照找；`.git`、`.svn`、`.hg`、`.bzr`、`.jj`、`.sl` 不进（Claude Code 的名单）。
  - 不跟着目录的链接走。
  - **Miyu 的数据根不进**（施工中加的）：权限策略只核对搜的那个目录，从家目录搜下来会走进 `~/.miyu`，里面有令牌和会话日志。所以交给工具的多一样数据根，走到就跳过。这一轮的工作目录在数据根里的（账号自己的工作区就在 `~/.miyu/home/<账号>/workspace/`），照样往下走，和权限策略里工作区优先的先后一样。
- **叫停时停下阻塞线程里的活**（施工中加的）：叫停一次调用就是丢掉它的 future，可阻塞线程里的活自己不会停，从 `/` 往下走能走很久。future 被丢掉时举一面旗，走目录、搜内容每一步看一眼。
- **路径怎么写**：在这一轮工作目录里的写相对路径，在外面的写绝对路径（Claude Code 的做法，省 token）。分隔符用平台原生的，Windows 上不写 `\\?\` 那个前缀。
- **排序**：按修改时间，新的在前；时间一样的照路径排。

**`read`（改到规范上）**

- 参数 `path` 改名 `file_path`；照 pi 写成 `path`、照 opencode 写成 `filePath` 的也认。
- 行号改成「行号、一个制表符、原文」，行号前不补空格。这是 Claude Code 现在的写法，每行省一两个 token；说明里照它写 cat -n format。
- 说明：`Read a text file, or list a directory. Lines come back in cat -n format, numbered from 1, up to 2000 at a time. Prefer this over cat in the shell: files read here come back after compaction.`
- 没读完的提示改成 opencode、pi 的说法：`(Showing lines {from}-{to} of {total}. Use offset={next} to continue.)`。
- 目录也照 `offset`、`limit` 分页（opencode 的做法），不再固定最多 1000 项：`(Showing entries {from}-{to} of {total}. Use offset={next} to continue.)`；`offset` 过了结尾的说一共几项。

**`glob`**

- 参数：`pattern`（必填）、`path`。
- 说明：`Find files by glob pattern, like **/*.rs or src/*.ts, respecting .gitignore. Returns up to 100 paths, most recently modified first.`
- **模式的规矩照 ripgrep 的 `--glob`**：Claude Code、opencode 都是把模式原样交给它。
  - 不带 `/` 的照文件名在任何一层找；带 `/` 的照相对搜的那个目录的路径比。
  - `**` 跨目录，`*` 不跨，`{a,b}` 是二选一。
  - 模式本身是绝对路径的，拆出前面不带通配的那一截当搜的目录（Claude Code 的做法）。
- **只列文件**，最多 100 个，不给改（Claude Code、opencode 都不给改）。多的照 Claude Code 说：`(Showing {shown} of {total} matching files; {rest} more are not listed. Narrow the pattern or path to see the rest.)`。没找到说 `No files found`。

**`grep`**

- 参数：`pattern`（必填）、`path`、`glob`、`output_mode`（`content`、`files_with_matches`、`count`，默认 `files_with_matches`）、`-i`、`context`、`head_limit`（默认 250，0 是不限）、`offset`。`context` 在的时候压过 `-A`、`-B`（Claude Code 的规矩）；`-A`、`-B` 不声明，写了照样认。
- 说明：`Search file contents with a regular expression (ripgrep syntax), respecting .gitignore. Prefer this over grep or rg in the shell. output_mode picks file paths (default), matching lines, or counts per file.`
- 正则照 ripgrep 的写法（同一个库），分大小写，`-i` 不分。
- **三种输出**：
  - `files_with_matches`：一行一个文件。
  - `content`：`路径:行号:内容`。`context` 带出来的前后行写成 `路径-行号-内容`，不连着的两段之间一行 `--`。这是 ripgrep 的写法，Claude Code 原样给模型。同一个文件里照行号排。
  - `count`：`路径:个数`。
- **分页**：`head_limit`、`offset` 在三种输出里都按条数，分别是文件、匹配的行、文件。多的说还有、下一次从哪接。只列文件和计数时，一共几条是知道的，写上；`content` 搜到够数就停，不数一共多少。
- **超长的行**：一行最长 500 个字，多的截掉补 `…`。这是 pi 的做法；Claude Code 交给 ripgrep，整行都不给，她就看不到那一行在说什么了。
- 二进制文件跳过；带 BOM 的 UTF-16 照认；`path` 是文件的就只搜它。
- **没搜到**：`files_with_matches` 说 `No files found`，`content`、`count` 说 `No matches found`（Claude Code 的说法）。
- 一次的输出最多 64 KiB，跟 `read` 一样，到了就停在那一条，说从哪接。

**共用的字**

- `read` 的「没有这个文件」「读的时候出错了」「参数不对」三句挪进 `common/`，字节一个不改，指纹照旧。
- 新加的：通配写法不对、相近的名字、`No files found`（`glob` 和 `grep` 都说）。
- 新的字先估 token，4-10 实测。

**依赖**：`ignore`、`globset`、`grep-regex`、`grep-searcher`、`grep-matcher`，都是 ripgrep 的作者拆出来的，纯 Rust，三个平台一样（B9）。

### 风险

- **全局的 `.gitignore`**：`ignore` 会读本机 git 的全局忽略设置，不同机器上结果可能不一样。测试只看场地里自己写的 `.gitignore`。
- **按修改时间排**：测试里自己设修改时间，不靠写文件的先后。
- **大目录**：只列文件时要走完整个目录树才能排序、数总数，Claude Code 也是这样。实测慢了再议。
- **带横杠的参数名**（`-i`）：Anthropic、OpenAI 兼容的接口都收。旧版给 Gemini 整形时撞上的是别的（`enum` 里的空串、不认 `additionalProperties`），没见过参数名出问题。接 Gemini 时实测，不行就在驱动里改名。
- **`read` 改了参数名和行号**：还没发布，没有老会话要背；测试和探针存档跟着改。
