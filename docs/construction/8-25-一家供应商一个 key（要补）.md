## 施工单 8-25（要补）：一家供应商一个 key

状态：已完成（2026-10-09 写，同一天合进 main，1c2b3fc0，CI run 1281；方向 2026-10-07 项目主人定（`15-模型与供应商.md` M10，`00-设计理念.md` 第一节「别人的活不揽」），2026-10-08 照推荐定「老的 `keys` 不兼容」；删什么照下面的清单，技术细节主会话定）。

### 目的

一家供应商配几个 key、按会话钉一个、出错换下一个、每个 key 单独冷却，是替供应商分摊限速。M10 定了不揽：一家一个 key，几份额度要一起用的配成几家、放进池里。这一步把配置、路由、冷却、协议、`miyu setup` 都改成一家一个 key，删掉多 key 的那一套。

### 这一步做什么

1. **配置**：`providers.<id>.keys`（密钥的列表）换成 `providers.<id>.key`（一个密钥的引用 `{ secret = … }` 或 `{ env = … }`，可以不写：不写的不带认证头）。名字、说明跟着改，三种语言。生成的 Schema、参考文件、`config.md` 里嵌的样本跟着生成。
2. **不兼容**：配置里还写 `keys` 的，当不认识的键报错（`unknown_key`），这一家照没写 key 办；不悄悄认。
3. **路由**：一家的候选是这家的这个模型，一个；不再照会话编号钉 key、不再出错换到同一家的别的 key。池的钉住、轮换、出错换下一个成员都留着。
4. **冷却**：只管模型（端点）。认证失败（额度用完的也在这一类）停整家供应商（就是它那一个 key），别的停这家的这个模型。失败次数、翻倍、上限照旧。配置项 `models.cooldown.auth.*` 的说明从「整个 key」改成「整家供应商」。
5. **协议**：
   - `model.list` 每家的 `keys`（`[{ref, set, state}]`）换成 `key`（`{ref, set, state}`），没写 key 的没有这一格。
   - `provider.detect` 的 `configured` 照「`key` 引用了这个变量」认。
   - `secret.list` 的 `used_by` 写 `providers.<编号>.key`。
6. **`miyu setup`**：写 `key`（找到的环境变量 `{ env = … }`、贴的 `{ secret = … }`）；本机的服务不要 key，写 `local = true`（原来写空的 `keys = []` 让这一家算配好了）；自定义的不要 key 的什么都不多写（`driver`、`base_url` 已经让它算配好了）。
7. **开发用的数据根**（`xtask dev-home`）、测试里的配置都照新写法。

### 删掉的（清单）

- `miyu_models::keys` 里的 `pinned`、`order`（会话钉 key、候选的先后）；`name`（引用的写法 `secret:<名字>`、`env:<变量>`）留着，挪到引用旁边，`model.list` 的 `ref` 还用它。
- 路由里记「出错换过去、成了的那一个 key」的那一份（`moved`），候选里的第几个 key。
- 冷却的单位里的 key（`Candidate::key`、`Unit::key`），「整个 key」那一个单位换成整家供应商。
- 配置项 `providers.<id>.keys`。清单的「密钥的列表」这种类型留着：软件包的列表配置项还用，宏的 `secrets` 写法也有自己的测试。
- 测试：钉 key 的算式、同一家几个 key 的先后、换 key、每个 key 单独冷却的几条；照新写法改不了意思的删，别的改写法。
- 图纸里讲多 key 的段落：`models.md`「怎么走」第一条第 6 条、`keys.rs` 那一行、示例配置里的两个 key。

### 主会话定的技术细节

1. `name` 不删：`model.list` 的 `ref` 和冷却的日志都要一个认得出是哪个 key 的写法，挪到 `miyu_models::provider` 引用旁边。
2. 认证失败停整家：一家只有一个 key，停「整个 key」就是停这一家；单位写成供应商，不留一个永远相同的 key 字段。
3. 本机的服务写 `local = true` 当「配好了」：它本来就是本机的（价格当 0），不是为了占位造的一格。第一次接入试的候选（`miyu_models::onboard::Candidate`）照同一个办法写，试的和写进去以后真用的一样；原来试过写 `catalog = <编号>`，会把认目录的方式从 `id` 变成 `config`，不行。
4. 测试里原来只为「算配好了」写的 `keys = []`：这一家的表里还有别的格的删掉，只有它的换成 `local = <照地址推的那个值>`（目录、档案里地址在本机的几家是 `true`），和不写一样。多个 key 的测试（照会话钉 key、换 key、一次性调用照用途钉 key）改成池里几家，换端点本来就是池的事。

### 不做什么

- 池、成员、分法：不动。
- 两个头的设置页、第一次接入的界面：头那边照新形状改（合了以后把形状发给它们）。

### 验收

1. 测试先写，改之前红：配置写 `key` 认得、写 `keys` 报不认识；一家一个候选；认证失败停整家（同一家的别的模型也停）、别的错只停这个模型；`model.list` 的 `key`；`provider.detect` 照 `key` 认 `configured`；`miyu setup` 写 `key`、本机的写 `local = true`。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合了把形状改动发给终端界面、网页（`model.list`、`provider.detect`、`secret.list`、`config.schema` 里的键）。

### 验收结果（2026-10-09）

1. **测试**：`miyu-session` 的 `tests/route.rs`：写了 `key` 的请求带它、重启还是它；老的 `keys` 报不认识的键、最终值里没有它（改之前红：`key` 不认识，请求不带认证头；`keys` 照旧被读）。`miyu-models` 冷却：认证失败停整家、别的一家不停、成了一起清；供应商的 `key`；第一次接入的候选写成的最终值和写进配置以后的一样。`miyu-endpoint` 的 `model.list`：`key` 一格、限速只停这个模型、认证失败停整家（key 和别的模型都是 `cooling`）、取不到值的模型是 `no_key`。`miyu setup`：环境变量写 `key = { env }`、贴的写 `{ secret }`、本机的服务写 `local = true`。换端点、冷却表两个入口共用、一次性调用的几条改成池里几家。
2. **改的过程中查出来的**：迁测试配置的脚本把一个 `assert!(config.contains("keys = []"))` 改成了 `contains("")`，恒真；改回真断言（本机的写 `local = true`、不写 key）。冷却表两个入口共用那两条原来靠「两个入口都从池里第一家起」，钉住的池新会话、一次性调用会把指针往前推，改成两个成员一样的池各用各的指针。
3. **变异**：手写 12 个全逮住（选的 key 不发、写了 key 也当没写、认证失败只停这个模型、成了不清整家、供应商不带 key、key 的状态不看冷却、取不到的不算 `no_key`、配好的认不出环境变量、本机的不写 `local`、环境变量写成密钥、试的本机候选不算配好、拉列表不带 key）。
