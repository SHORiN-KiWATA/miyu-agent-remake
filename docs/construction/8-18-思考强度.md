## 施工单 8-18：思考强度

状态：施工完，待主会话实测（2026-10-02 施工；2026-10-01 项目主人定：照 opencode 的做法，思考强度是每个模型的一项配置；技术细节主会话定）。

### 目的

人能给每个模型定思考强度，也能把能关思考的模型关掉。项目主人 2026-10-01 定的（终端界面的会话转来，同一天细化过一次，以细化后的为准）：
1. **配置里的默认**：配供应商和模型时，一个模型可以有默认的思考强度（`providers.<id>.models.<model>.effort`）。没写的照供应商的默认：请求里根本不带思考强度。有哪几档照 models.dev（`facts.reasoning`，来自 `reasoning_options`），配置里的 `reasoning` 能手写盖掉。
2. **会话里改**：在会话里换思考强度，只改这个会话里这一个模型的那一格。会话给每个模型记一格（opencode 那种「每个模型记自己的」，只在这个会话里）。别的会话、配置里的默认都不动。
3. **一次请求用哪一档**：这个会话给真发给的那个模型记的一格；没有的，照配置里这个模型的默认；再没有的，什么都不带（照供应商的默认）。所以换模型不用「退」，轮换的池里每个成员用自己的那一格。
4. 换模型、换强度都不出提示：头只当场改底栏。核心只给数据，不给提示的字。
5. 能关思考的模型多一档 `off`（网页那边转来，项目主人提的）；只有开关的模型是 `off`、`on` 两档；不能关的不带 `off`。`off` 和「没写」是两回事。

（之前问过的「换了模型、新模型没有那一级怎么退」三个选项都没选，这个问题随这个定法没了。别的工具怎么做的，终端界面的会话查过：opencode 每个模型记自己的；Claude Code 一个全局的、每次请求照它解析；codex 选模型时紧接着选强度；pi 在一条固定的档位上取最近的。）

技术细节（主会话定）：
- 配置 `providers.<id>.models.<model>.effort`：这个模型的一档，系统、个人两层，`next_turn`。写进 `[providers.<id>.models."<模型名>"]` 那张手写资料表（8-7），和 `window` 并列。写的那一档不在档位里（目录变了、写错了）：照挂空的引用办（8-8 的 `bad_reference`），算进 `config_errors`、`config check` 报出来，原因码 `unknown_effort`；请求照「没写」发，不改配置。
- `session.configure` 多一个参数 `effort`：`{"model": "<供应商>/<模型>", "level": <一档> 或 null}`。`model` 是具体的模型（不是池），`level` 照这个模型这时的档位查，不在里面回 `unknown_effort`；`null` 是把会话这一格清掉、回到配置的默认。和 `model` 能一起换，也能只换一个；一样的不记。下一轮生效。
- 记进 `session.policy_changed`：多一格 `effort`（`{"model", "level"}`），`by` 是人，回合进行中的带上这个回合；撤掉的回合里改的也算（照 8-10 的 `model`）。内核载入时照日志拼出每个模型的一格，只记不解读，回合开始交给 actor。
- 会话记的那一档后来不在档位里了（目录变了）：那一次请求照配置的默认，再不行照「没写」，记一行 `WARN effort not available model=… level=…`，日志里那一格不改。
- 档位名：照目录 `reasoning_options` 原样（`minimal`、`low`、`medium`、`high`、`xhigh`、`max` 这些）；能关的多一档 `off`，目录里写成 `none`、`disabled` 的规整成 `off`；只有开关的写 `off`、`on`。能不能关、关和开怎么写，照驱动和档案（下一条）。
- 驱动：调用多一格 `effort`（照上面第 3 条算出的，没有就没有）。`openai-chat` 照档案的 `compat`：
  - 档位：发 `reasoning_effort`，只在目录列了档位时发；
  - 开关：照档案写的字段，例如 DeepSeek 是 `thinking: {"type": "enabled"|"disabled"}`（2026-10-01 主会话在开发端点实测：`disabled` 时思考 token 是 0；`reasoning_effort` 能收下，效果这台端点上看不出来，不算验证过）；
  - 没有 `effort` 的什么都不加，请求和现在一个字节都不差。
  Anthropic（8-12）、Responses（8-13）的写法随那两步，写进「驱动要守的约定」。
- 空闲超时照强度放大：`off` 照不思考的，档位越高放得越大，具体的倍数施工时定、写进「施工时定的」。
- 头看得到：`model.list` 每个模型的 `facts` 多一格 `effort`（配置的默认和来源，没写的是没有）；`subscribe` 回应的 `model` 和 `model.changed` 多 `effort`（会话接下来请求的那个模型真用的那一档，连同从哪来：`session`、`config`；什么都不带的不写）。强度变了也推 `model.changed`（`why: turn`），轮换的池没有单一的模型，不带 `effort`。
- 缓存：Anthropic 换了思考设置，前面对话的缓存作废（system 和工具的照旧），人自己改的，认这一次的钱。
