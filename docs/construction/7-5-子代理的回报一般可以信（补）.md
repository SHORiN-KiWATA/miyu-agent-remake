## 施工单 7-5（补）：子代理的回报一般可以信

状态：撤回（2026-10-01：实测加了这一句她照旧复核，照施工单撤掉；没有合进来）。

### 目的

子代理报回来以后，她不再每次都自己把活复核一遍。M7 验收自测里 3 次有 3 次，她都把子代理读过的文件自己又读了一遍（2026-10-01）。照 Claude Code 在派子代理那件工具的说明里加一句（项目主人定）。

### 蓝图改哪几节

- `tools/agent.md`、`resources/software/basesystem/tools/agent.json`：说明后面加第三句「Its report can generally be trusted.」（Claude Code 的 Agent 工具说明里是「The agent's outputs should generally be trusted」）。
- 登记：主会话量，单独量多 7 个 token（2026-10-01），整张工具面重量以后写边际份量和合计；`cargo xtask prompts` 重新生成；工具面的预算照新的数核对。

### 验收

1. 测试：登记簿的指纹、工具面的预算门禁照新的过；原来守着说明的测试照新的一句改。
2. 真模型（主会话做）：同一个场景（派一个子代理读几个小文件、报回标题）加之前、加之后各跑几次，数她报回来以后还自己读不读那几个文件。加了也照旧复核的，照实记，撤掉这一句。
3. `CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 全绿。

### 实测（2026-10-01，主会话，开发端点的 `deepseek-v4.1-flash`，同一个程序只换资源目录，每次新的数据根）

| 场景 | 不加这一句：子代理报回来后她又去读文件 | 加了这一句 |
|---|---|---|
| 派子代理读 `notes/` 三个文件、报回标题和行数 | 3 次里 0 次 | 3 次里 0 次 |
| 派子代理把 `config.txt` 的 port 改成 8080 | 3 次里 3 次（`read`） | 3 次里 3 次（两次 `read`、一次 `shell`） |

六次文件都改对了。子代理只是读的，她本来就不复核；子代理改了文件，她加不加这一句都要自己看一眼。这一句（7 个 token）对这个模型不管用，照施工单撤掉，`agent.json` 不动。M7 自测里那三次复核，也都是在她自己先读过、或者子代理改过东西之后。
