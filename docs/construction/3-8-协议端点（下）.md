## 施工单 3-8：协议端点（下）

状态：施工中。

### 目的

核心有了真的本机入口：Linux、macOS 上的 Unix 域套接字。核心起来先拿单实例锁，换一个本机令牌写进 `run/token`，在套接字上等连接，把实际位置写进 `run/socket`；头读这两个文件就连得上、握得了手。一个数据根一个核心，测试里同时开几个数据根也不撞。Windows 的命名管道是 3-8（补）。

### 拍板的

- 项目主人 2026-09-27 定：Windows 的命名管道只对本人开放，要调 Windows 的安全接口，单开一个小 crate 放开 `unsafe`（3-8 补）。
- 项目主人 2026-09-27 定：管理员的账号固定叫 `admin`（`06-多用户与身份.md` U13）。这一步用不上，3-9 首次运行时用。

### 图纸

- `04-核心协议.md` 第二节「各平台的坑」：套接字放在短路径、只有本人能进的目录里，连之前核对属主；第四节：本机连接出示本机令牌。
- `07-存储.md` 第二节：套接字、本机令牌放在哪、怎么写（这一步补）；第十节「单实例与锁」：`run/core.lock`，锁拿到核心退出（这一步补）。
- `11-权限与沙盒.md` 第五节：本机令牌放在数据根里，沙盒读不到。
- `27-从旧版迁过来.md` 第二节：新版的套接字按数据根分开，不和旧版的 `$XDG_RUNTIME_DIR/miyu/` 撞。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-ipc/`（新，第 3 层） | 套接字放哪（数据根的指纹、`$XDG_RUNTIME_DIR`、`run/`、放不下时的 `$TMPDIR/miyu-<uid>/`）；在套接字上等连接、连过去；本机令牌文件；单实例锁；`run/socket` 记实际位置 |
| `crates/miyu-endpoint/` | `run`：在监听器上一个个接连接，每个连接交给 `serve` |
| `docs/designs/07-存储.md` 第二、十节 | 套接字、本机令牌、锁怎么写 |
| `docs/designs/01-架构.md` 第九节 | 第 3 层多一个 `miyu-ipc` |
| 施工图 | 3-8（下）那一张 |

核心起来的先后：

1. 拿 `run/core.lock` 的锁：拿不到，就是已经有一个核心在跑，报「已经在跑」。
2. 换一个本机令牌，写进 `run/token`（先写临时文件再改名，头读不到半个）。
3. 算出套接字放哪；上一个核心崩了留下的旧套接字文件删掉（锁在手里，没有别的核心在用它）；绑定、监听。
4. 实际位置写进 `run/socket`。
5. 一个个接连接，每个交给 `serve`。

### 不做什么

- Windows 的命名管道：3-8（补）。这一步在 Windows 上监听回「还不支持」。
- 头拉起核心、拉起锁、管道里写一个字节的握手（`12-进程形态与分发.md` 第二节）：头是 3-9 的 `miyu ask`，一起做。
- 核心空闲一段时间自己退出：随 3-9，那时有了头，知道什么叫没人用。
- `miyu doctor` 查权限：以后。

### 我定的

- **新 crate `miyu-ipc`**：第 3 层，核心和头都用它（核心监听、头连过去），所以不放在第 4 层的协议端点里。
- **数据根的指纹**：数据根绝对路径的 SHA-256 前 8 位（十六进制）。同一台机器上几个数据根各算各的，旧版的目录叫 `miyu`，不撞。
- **路径的上限**：Linux 108 字节、macOS 104 字节，都要算上结尾的零，所以分别最多 107、103 个字节；放不下就改放 `$TMPDIR/miyu-<uid>/<指纹>.sock`，那个目录新建时权限 0700，已经有的核对属主是不是自己、权限是不是 0700，不对就不用。
- **`$XDG_RUNTIME_DIR` 的子目录**也照样：新建 0700，已经有的核对属主。
- **令牌**：32 个随机字节（`getrandom`，取系统的随机数），64 位十六进制；先写 `run/token.tmp`、同步、再改名，Unix 上 0600。每次核心起来换一个。
- **锁**：Rust 标准库的 `File::try_lock`（1.89 起有），拿到的锁放在监听器里，监听器在锁就在。
- **旧套接字文件**：锁拿到了才删；删之前看清是套接字文件，不是别的文件就不动、报错。
- **`run/socket`**：一行，套接字的路径。头读它连；读不到、连不上，就是核心没在跑。

### 验收

1. `step/3-8c-ipc` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`（套接字的测试只在 Linux、macOS 上跑）：
   - 放哪：Linux 上有 `$XDG_RUNTIME_DIR` 的放它下面的 `miyu-<指纹>/`；没有的放 `run/`；路径太长的放 `$TMPDIR/miyu-<uid>/`；两个数据根的指纹不一样。
   - 起两个：第二个拿不到锁，报「已经在跑」；第一个放下以后，第二个拿得到。
   - 令牌：64 位十六进制，Unix 上 0600；再起一次换了一个。
   - 旧套接字：上一个核心没删掉的套接字文件，这一次照样起得来；同名的不是套接字的文件，不动，报错。
   - 端到端：在真的套接字上起核心，头读 `run/socket`、`run/token` 连上、握手、造会话、说一句，这一轮说完。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --workspace --exclude miyu-http --exclude miyu-session --exclude miyu-endpoint --target` 查 Windows、macOS。

### 风险

- **macOS 的临时目录路径很长**（`/var/folders/...`）：测试用的数据根放在它下面，套接字多半放不下，正好走 `$TMPDIR/miyu-<uid>/` 这条路；CI 上 macOS 真跑。
- **CI 的 Linux 上没有 `$XDG_RUNTIME_DIR`**：放 `run/` 的那条路也有人走；「有 `$XDG_RUNTIME_DIR`」的情形在测试里自己造一个目录指过去。
