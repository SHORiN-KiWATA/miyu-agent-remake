## 施工单 4-9：驱动、HTTP（再补三下）

状态：施工中。

### 目的

补蓝图时查出驱动和 HTTP 执行器有几处靠不住，这一步修好：
- 流里的 `"error": false`、`0`、`[]` 也当成出错。
- 流里报的限速说了「try again in …」，算出来的要等多久被丢掉，内核照自己的退避。
- 端点另配的头和默认的同名时加了两份。
- 地址、另配的头写得不对，当成可以重试，白等 5 次。
- `finish_reason` 已经到了、只差 `[DONE]` 时停住，算成空闲超时出错。
- 端点的调试输出打出全地址：有的供应商把 key 放在地址里。

### 蓝图改哪几节

- `drivers/openai-chat.md`：
  - 解码器多一个问法 `finished()`：`finish_reason` 到了没有。
  - `Ending` 多一格 `retry_after_ms`。
  - `error` 是 `false`、`0`、`[]` 的也是噪声。
  - 流里报的错，要等多久一起留下。
- `http.md`：
  - 另配的头换掉同名的；名字、值写得不对的不发，出错 `other`。
  - 地址写得不对，出错 `other`，不重试。
  - `finish_reason` 到了只差 `[DONE]` 时停住，当说完了。
  - 流里报的错带着要等多久。
  - 端点打印出来只写主机名。

### 要拍板的

- 没有，都是技术细节。

### 不做什么

- 驱动和设计 `05-内核接口.md` 第七节的其余差异（`finish_reason` 多认的几种、内容策略要 4xx、限速多认 400 Throttling、原话多取几处、工具参数不是对象的写 `{}`）：代码是对的、更宽，收进 4-9（四补）改设计。
- 空闲超时按思考强度放大、等第一个字时的心跳：随 `15-模型与供应商.md` 第五节那一步。

### 验收

1. `step/4-9g-http` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 驱动：`"error": false`、`0`、`[]` 的照常解，不算出错；`true`、非零、不空的数组照旧算。流里报的限速带着 `try again in` 算出的毫秒数。
   - HTTP：另配一个 `Accept`，请求里只有一个、是另配的那个；另配的头名字写得不对、地址写得不对，出错 `other`；说完了只差 `[DONE]` 时停住，算说完，增量、用量照交；流里报的限速，交回的要等多久是供应商说的；打印端点只有主机名。
3. 故意改坏几处，都有测试变红（施工时列清单）。
4. `cargo xtask check` 七项全过；推之前用交叉 clippy 查 Windows、macOS。

### 风险

- 说完了只差 `[DONE]` 就当说完：有的供应商在 `finish_reason` 之后还会补一段用量，停在那之前的，这一次没有用量。比当成出错重来一遍划算。
