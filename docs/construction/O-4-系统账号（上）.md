## 施工单 O-4（上）：会话认自己的属主

状态：已完成（2026-10-09 写，同一天合进 main，9fe0d45f，CI run 1267；O-4 的方向 2026-10-07 项目主人定（`06-多用户与身份.md` U14、`18-通讯平台.md` Q19），2026-10-08 照推荐定「读到声明了系统账号的包时建系统账号」；主会话拆成上、下，技术细节主会话定）。

### 目的

O-4（下）要让通讯平台的场所会话归系统账号 `onebot`，它们的日志、blob、回收处在 `home/onebot/` 下。现在端点里会话相关的地方一律照管理员找目录（`core.admin`），系统账号的会话一碰就找错地方。这一步先让每个会话认自己的属主，管理员以外的账号还没有会话，外面看不出变化。

### 这一步做什么

1. **会话的属主**：
   - 在跑的：会话的把手记着造它、载入它时的属主（`Handle::owner`）。
   - 没在跑的：照数据根里哪个账号的 `home/<账号>/sessions/<编号>/` 在（`DataRoot::owner_of`）；会话编号是 UUIDv7，不会两个账号各有一个，真有的照账号名的先后取第一个。都没有的照没有这个会话办。外面问属主的（读页、订阅、撤销、派子代理读子会话的日志）不拿会话表的锁、直接照家目录找：删会话拿着锁时父会话经端口读子会话的日志也要问它，在跑的会话的目录本来也在那里。
2. **照属主找的**：载入、读日志补工作目录、删会话（回收处、子会话）、收派到一半的空子会话、`view.page`、撤销读文件和 blob、订阅时补发的日志、派子代理时子会话的目录：一律照这个会话的属主，不再照 `core.admin`。
3. **还是照连接的**（不动）：握手报的账号、登录、人格和预设的目录、软件包、上传的 blob、连接的工作区：是「谁连进来」，多用户那一段再说。造会话的属主照旧是连接的账号（现在就是管理员）。
4. **账号的家底**（回合库、用量、记忆）：`index_for`、`usage_for`、`memory_for` 照旧只有管理员有；别的账号的会话这几样是没有（O-4 下给系统账号建）。

### 主会话定的技术细节

1. 属主放在把手上，不另开一张「会话 → 账号」的表：把手本来就是造、载入时拿属主造的，表和磁盘不会对不上。
2. 没在跑的照目录找，不建索引：账号就几个（管理员加每个软件包一个系统账号），一次 `stat` 几次的事。
3. 列会话（`session.list`、会话列表的推送）照旧只列管理员的：系统账号的场所会话不出现在本机的头的会话列表里（U14）。

### 不做什么

- 账号名单、系统账号、场所会话归系统账号：O-4（下）。
- 连接的身份不是管理员（多用户）：随多用户那一段。

### 验收

1. 测试先写：把一个会话的目录挪到另一个账号的家目录下（造的时候还只能是管理员），核心重启以后照编号找得到、载入时属主是那个账号；`view.page` 读得到它的日志；撤销照它的 blob；删掉以后进那个账号的回收处、管理员的家目录一个字没动；在跑的、载入的属主一样。改之前红（照管理员找，找不到）。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。

### 验收结果（2026-10-09）

1. **测试**：`miyu-endpoint` 的 `tests/owner.rs`：会话造好以后目录挪到 `bob` 的家目录下（策略快照这些 blob 一起拷过去：系统账号的会话本来就在自己的家目录下造），换一个核心：读页、另开连接订阅（回应的 `preset` 照属主的日志读）、接着说话（第二轮写在 `bob` 下）、删掉（进 `bob` 的回收处），管理员的家目录一个字没动。改之前红（`session_not_found`）。`miyu-store` 的 `the_owner_of_a_session_is_the_account_holding_it`。整个端点的测试都过。
2. **第一次跑查出来的**：外面问属主拿了会话表的锁，删子会话时父会话经端口读子会话的日志又来问，死锁（`delete_children` 三条卡住）。改成外面问的不拿锁、照家目录找。
3. **变异**：手写 7 个全逮住（任何账号都算、载入照管理员、读页照管理员、删进管理员的回收处、在跑的照管理员、订阅照管理员读、把手的属主照管理员）。派子代理读子会话的日志、撤销照属主这两处这一步没有测试守着（要在别的账号下派子代理、改文件），随 O-4（下）系统账号的会话补。
