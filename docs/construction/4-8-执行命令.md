### 我定的

- **参数**：照 Claude Code，`command`（必填，名字就说清了，不写说明）和 `timeout`（毫秒）。
  - `description`、`run_in_background` 这一步不声明。`description` 现在没有地方用：`miyu ask` 印的是命令本身；4-9 做确认要给人看、M7 后台命令要当任务名的时候再加。
  - 模型照 Claude Code 的习惯写了 `description`，照样认，不用它；写了 `run_in_background: true` 的，不跑，说还不能放到后台，让她在前台跑。
- **说明三句**：用哪个 shell 执行一条命令、交回输出；编译、测试、git 这类用它，读、搜、改文件用专用的工具；每次都从工作目录起，`cd` 不带到下一次。说明里的 shell 名字在核心起来时定下（`bash`、`zsh`、`PowerShell 7`、`Windows PowerShell 5.1`），工具面造会话时存进快照，会话里不变。
- **用哪个 shell、怎么起**（B8）：
  - Linux 在 `PATH` 里找 `bash`，找不到用 `/bin/bash`；macOS 用 `/bin/zsh`；Windows 在 `PATH` 里找 `pwsh.exe`，找不到用系统自带的 Windows PowerShell。
  - 不读用户的启动文件：bash 加 `--noprofile --norc`，zsh 加 `-f`，PowerShell 加 `-NoProfile`。启动文件里可能 `export` 了密钥，读了环境变量白名单就白设了；`PATH` 照白名单从核心的环境带过去，装在家目录里的工具链照样找得到。
  - PowerShell 用 `-NonInteractive -EncodedCommand`：命令编成 UTF-16LE 的 base64 传过去，引号、换行不会被命令行拆坏。命令前面加一句把输出编码设成 UTF-8、把进度条关掉（Windows PowerShell 5.1 默认用系统代码页输出，进度条会变成一段 XML 写进标准错误）。
- **在哪跑**：这一轮的工作目录。每次调用起一个新的 shell，`cd`、变量都不带到下一次。Claude Code 会记住 `cd`，这里不记：工作目录是回合开始时定的，权限策略也照它判；opencode、pi 也不记。
- **环境变量**（11 第四节）：只传白名单上的，名字 Windows 上不分大小写，`LC_` 开头的都传；另外设上 `GIT_TERMINAL_PROMPT=0`，git 要密码时直接失败，不去等人输入。第一版的名单是策略数据，写在代码里，配置那一步能改（和 `miyu-fs` 里的边界清单一样）：
  - 找程序、家目录、临时目录、用户：`PATH`、`HOME`、`USER`、`LOGNAME`、`SHELL`、`TMPDIR`、`TMP`、`TEMP`；
  - 语言、时区、终端：`LANG`、`LANGUAGE`、`TZ`、`TERM`，和 `LC_` 开头的；
  - 工具链：`CARGO_HOME`、`RUSTUP_HOME`、`GOPATH`、`GOROOT`、`JAVA_HOME`、`NVM_DIR`、`PNPM_HOME`、`VIRTUAL_ENV`；
  - Windows 自己要的：`PATHEXT`、`SystemRoot`、`SystemDrive`、`windir`、`ComSpec`、`USERPROFILE`、`USERNAME`、`HOMEDRIVE`、`HOMEPATH`、`APPDATA`、`LOCALAPPDATA`、`ProgramData`、`ProgramFiles`、`ProgramFiles(x86)`、`ProgramW6432`、`CommonProgramFiles`、`CommonProgramFiles(x86)`、`CommonProgramW6432`、`PUBLIC`、`ALLUSERSPROFILE`、`NUMBER_OF_PROCESSORS`、`PROCESSOR_ARCHITECTURE`、`OS`、`PSModulePath`。
  - 不传的里面有两样是有意的：`SSH_AUTH_SOCK`（本机的 ssh-agent）、`DISPLAY`、`WAYLAND_DISPLAY`（桌面）。沙盒里的命令本来就连不上本机的套接字（11 第四节）。
- **输入**：标准输入接空的。要人输入的命令读到结尾就退出，不会一直等到超时。
- **输出**：
  - 标准输出、标准错误接到同一根管道上，照写出来的先后；边读边推给头（不落盘，`03-事件模型.md` 第五节）。
  - 照 UTF-8 解，解不开的字节换成 U+FFFD；Windows 的 `\r\n` 换成 `\n`。
  - 最多 30000 个字（照 Claude Code）。多了留头尾各一半，能截在行尾就截在行尾；中间写一行省略了多少个字，末尾照规矩用括号说一句：一共多少个字，要看全就写进文件再读。内存里只留头尾各 64 KiB，输出再多也不涨。
  - 什么都没输出、退出码是 0 的，说一句 `No output`，照「没找到」的规矩。
- **退出码**：不是 0 的，结果标成出错，末尾写 `Exit code N`；被信号杀掉的（Unix）写 `Killed by signal N`。耗时由执行器量，每件工具都量。
- **超时**：默认 120000 毫秒，最多 600000（照 Claude Code）；写了更大的按上限算，写 0 的按默认算。到时整组杀掉，结果标成出错，说超时了、要多久可以写多大的 `timeout`。
- **整组杀**：
  - Unix 上命令自成一个进程组（`process_group`），超时、叫停时用 `rustix` 的安全接口 `kill(-pgid, SIGKILL)` 杀整组。命令退出以后，组里还在跑的（`&` 放到后台的）也一起杀掉：前台命令做完了，它起的东西不留，也不会一直占着管道（后台命令随 M7）。
  - Windows 上用系统自带的 `taskkill /T /F` 杀整棵进程树，只在命令还在跑的时候杀：Windows 的进程编号回收得快，命令退出以后再按编号杀，可能杀错。
  - 都用不着放开 `unsafe`：`rustix` 的接口是安全的，`taskkill` 是系统自带的程序。
  - 命令退出以后，管道最多再读 0.5 秒：还有东西（例如 Windows 上它放出去的孙进程）拿着管道的，不等它，读到的交回。
- **叫停**：丢掉这次调用的 future 时整组杀掉（施工 4-2 的叫停就是丢掉 future）。
- **权限**：访问类别是执行命令，工作区这一级放行，只读时问人（施工 4-3 下）。M5 之前不进沙盒。
- **给人看的字**：显示名「执行命令」（`Run`），后面跟 `command`（只取第一行，太长的截断，施工 4-5 下）；结果「输出 12 行」「没有输出」「退出码 1」「超过 120 秒，停掉了」「被信号 9 停掉了」「执行不了：…」「还不能放到后台跑」。

### 风险

- **macOS、Windows 只能在 CI 上跑**：本机只有 Linux。
- **命令还能打开核心的终端**：核心是从终端拉起的，没有脱离那个终端，`sudo`、`ssh` 要密码时会直接在那个终端上问。要让命令脱离终端得在子进程里调 `setsid`，安全的 Rust 做不到。git 用 `GIT_TERMINAL_PROMPT=0` 挡住；别的等 M5 的沙盒让命令在自己的会话里跑。
- **Windows 上命令退出以后留下的孙进程不杀**：按编号杀可能杀错，不杀又会留着。要干净得用 Job Object，要调 Windows 的接口（`unsafe`），放在 M5 的沙盒里做。
- **白名单太紧**：有的构建要 `PKG_CONFIG_PATH`、`LD_LIBRARY_PATH` 这类，现在不传。配置那一步能放行；4-10 实测时看。
- **工具面又多一件**：前缀从下一个会话起变。登记簿记下；预算 4-10 定。
