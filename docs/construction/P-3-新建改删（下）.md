## 施工单 P-3（下）：改、删人格，读提示词的原文

状态：施工中（2026-10-08 写；方向是设计 16 第四、九节（2026-09-25 项目主人定）；形状和终端界面、网页的会话对过（2026-10-08）；技术细节主会话定）。排在 P-3 中（预设）后面。

### 目的

设置页的「人格」一页能新建、改、删人格：名字、说明、以谁为底照项改，人设、示范对话、角色扮演提示在大文本框（网页）或者编辑器（终端，同 Ctrl+G）里整份改，两个头同时开着不互相盖掉。

### 蓝图改哪几节

- `protocol.md`：多 `persona.set`、`persona.read`、`persona.delete`；拒绝多 `persona_conflict`。
- `personas.md`：多「改」一节。
- `store.md`、`core.md`：回收处多人格的那一份，起来时一起清。

### 定了的（形状和两个头对过；技术细节主会话定）

1. `persona.set {"persona", "changes"?, "prompts"?}`：`changes` 改 `persona.toml`（同预设的写法，`toml_changes` 两边共用）；`prompts` 是提示词名到整份的字或删掉（网页、终端都要整份换，不按段改）。对还没有的编号写就是新建，一次带上底、名字、提示词。
2. `persona.read {"persona", "prompt"}` → `{"text", "from", "version"}`：叠好的那一份的原文、来自哪儿、你那一层这一份的版本（两个头都要：编辑器要在原文上改）。`persona.get` 照旧不给原文。
3. 防覆盖（终端的会话提的）：提示词每一份可带 `expect`（`persona.read` 给的版本，`null` 是你那一层还没有），对不上 `persona_conflict`，`data.current` 是现在的版本。
4. 几样一起查（改完的 `persona.toml`、示范对话、叠好以后的底），有错什么都不写。
5. 写盘照配置文件的规矩，一份一份写，只试一次：几份要是撞上有人手改了重来，重来时读到的已经是自己写进去的那几份，拿着头给的旧版本一比就成了「撞上了」；所以写到一半撞上的直接回 `persona_conflict`，前面写了的不撤（只会是那几份改完的样子），头重读再来。预设只有一份，照旧重来三次。
6. 删：整个目录挪进回收处 `home/<账号>/trash/personas/<编号>.<删的时刻，毫秒>/`，留 7 天、核心起来时清（同会话，2026-09-30 项目主人定的 7 天）。人格目录里有人自己写的人设，直接删了找不回来；预设只是一份小文件，直接删（P-3 中）。
7. 回应同 `persona.get`（终端的会话要的）；`delete` 回 `{"remains"}`；扩展进程调了回 `local_only`；不推 `persona.changed`。

### 不做什么

- 系统区那一层（大家共用的）的改、删：等多用户那次专门讨论。
- 从回收处恢复人格：要的时候再加（会话的回收处现在也没有恢复的方法）。

### 验收

1. 测试先写：新人格一次建好、开会话用得上；读原文、版本；旧版本撞上什么都不写；删提示词回到下面的；写错的什么都不写；参数不对；删了挪进回收处、回到出厂；回收处清的时候满了的删。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉两个头。
