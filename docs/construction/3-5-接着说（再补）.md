### 不做什么

- 别的供应商的接着写：有 key 实测过再开。
- 配置里开关接着写：配置那一步。
- 准备进 system 的两条规则（检查点、权限）怎么改：按 J12 列出清单，等项目主人拍板（见「风险」），这一步不动。
- 换了端点以后还接不接着写：资源调度器（以后）。

### 我定的

- **内核不动**：照旧追加事实、照旧重试。会不会接着写是驱动的事：驱动只管翻译（05 第七节）。
- **记号由组装加**：在等的时候来了新消息的，最后那条 user 里不只有提示，不加记号，照不会接着写的发。
- **不带记号的请求字节不变**：`continuation` 是假的，不写进规范字节，以前的哈希不变。探针存档变的只有那一句提示的字，和接着写的那一次的记号。
- **开关默认不会**：出厂只开 DeepSeek。不猜，也不发请求去探测，照实测配。
- **路径跟着编码结果**：接着写的发到另一条路径（DeepSeek 的 `/beta/chat/completions`）；驱动的 `path()` 去掉，免得两处各说各的。
- **指纹用 SHA-256 的前 8 位**：改一个字就对不上，门禁逼着改登记簿；8 位够分，表也不宽。
- **token 用 DeepSeek 实测**：`deepseek-flash`，字段按典型值填。仓库里没有分词器，门禁不查 token、只查指纹：字改了就对不上，要重新量。
