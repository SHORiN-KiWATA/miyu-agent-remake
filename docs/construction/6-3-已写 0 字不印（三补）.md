## 施工单 6-3（三补）：已写 0 字不印

状态：施工中。

### 目的

压缩刚开始、摘要请求还没收到字时，`miyu ask`、`miyu compact` 那一行只印「· 正在压缩上下文…」，不印「已写 0 字」（2026-09-30 项目主人定：终端界面里那个数是 0 的时候不显示，两个头一致）。

### 蓝图改哪几节

- `cli/ask.md`「压缩」那一段和给人看的字的表、`cli/compact.md` 的输出表：字数是 0 的时候不写字数，中文 `· 正在压缩上下文…`，英文 `· Compacting the context…`。

### 不做什么

- 进度的推送（`compaction.progress` 照旧先推一条 0 字的）、压好了那一行、失败那一行不动。

### 验收

1. 先改期望（命令行两处终端里的测试，加中英两种语言 0 字的单元测试），改代码以前要红；再改代码。
2. `CARGO_BUILD_JOBS=5 cargo xtask check` 八项全过；三台机器的 CI 全绿。

### 风险

没有：只动一句给人看的字。
