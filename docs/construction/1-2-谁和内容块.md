## 施工单 1-2：「谁」和内容块

状态：已完成（2026-09-26 项目主人验收通过）。

### 目的

事件的两块零件能读写了：`by`（这件事由谁引起）和内容块（消息、工具结果由它们组成）。读到新版本才有的种类，不报错，原样留着。

### 图纸

`03-事件模型.md`，这一步补画的三处：

- 第二节：`by` 的七种写法；编号表里补上这一步要用的几种名字。
- 第四节：五种内容块的写法、驱动私有数据、不认识的种类怎么办。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-kernel/src/id.rs` | 补上几种名字：模块、驱动家族、场所、外部身份、供应商、模型、媒体类型、文件名 |
| `crates/miyu-kernel/src/origin.rs` | `by` |
| `crates/miyu-kernel/src/block.rs` | 内容块，和驱动私有数据 |
| `crates/miyu-kernel/src/raw.rs` | 原样的 JSON：驱动私有数据和不认识的种类都用它，一个字节都不改；按 `type`、`kind` 分派的读法 |
| `crates/miyu-kernel/Cargo.toml` | 依赖 `serde_json`（原来排在 1-3，提前到这一步） |
| `docs/designs/01-架构.md` | 白名单加上 `serde_json` |
| 施工图 | 1-2 那张图纸 |

测试照 1-1：图纸上的每个例子读写一字不差；每条规则各有一个坏例子；不认识的种类读进来、写出去一字不差。

### 不做什么

- 事件的外壳和各种事件：1-3 开始。
- 字符串枚举（例如工具结果的状态）读到不认识的值怎么办：第一次用到是 1-4，到时候再写。

### 我定的

- **`serde_json` 提前进白名单**：驱动私有数据要一个字节都不改地原样存（03 第九节），不认识的种类也要原样留着，这两件都要用 `serde_json` 的原样 JSON 类型。反正 1-3 做编解码也要它。
- **不认识的种类原样留着，不是丢掉**：丢掉的话，旧版本读了新版本的日志再写出去，就把新东西抹了。原样留着，才谈得上「新版本写的，旧版本也读得懂」（03 第八节）。
- **工具名和参数不检查**：模型说了什么就记什么；要是检查，模型说错一次，这本日志就再也读不进来了。
- **图片的宽和高必填**：图片进来的时候执行器就量好了尺寸；量不出尺寸的，就不当图片，当文件。
- **几种名字各是一种类型**：供应商和模型都是字符串，写成两种类型，传反了编译器会拦下。规则只有四种，共用检查函数。
- **读不认识的种类要读两遍**：先看 `type` 或 `kind`，再按种类读。事件不多，多读一遍的开销可以不计。

### 验收

1. `step/1-2-origin-blocks` 分支的 CI：三台机器全绿。
2. `cargo test -p miyu-kernel`：看测试名，每种 `by`、每种块都有「照样本读写一字不差」；有「不认识的种类原样留着」。
3. 读 `03-事件模型.md` 第二节和第四节补画的地方。

### 风险

- 驱动私有数据是任意 JSON，这一步只保证存得住、带得回。它能有多大，以后接驱动时再看。
