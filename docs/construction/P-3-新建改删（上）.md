## 施工单 P-3（上）：以谁为底

状态：撤了（2026-10-08 写、施工完、同一天撤掉：项目主人看了界面定的不要以谁为底，见 `P-3-新建改删（补）.md`；CI run 1185 三台和长跑全绿；方向是设计 16 第四节 Y3「同名覆盖，或者用 `base` 以它为底；都只写改了的项」（2026-09-25 项目主人定）；新建、改、删的形状和终端界面、网页的会话对过（2026-10-08）；技术细节主会话定）。原来的 P-3 由主会话拆成上、中、下：上是 `base`，中是预设的 `preset.set`、`preset.delete`，下是人格的 `persona.set`、`persona.read`、`persona.delete`。

### 目的

人格、预设可以写「以谁为底」：只写和底不一样的几项，底以后的改进照样到得了自己这一份。中、下两步的新建靠它：新建一个预设就是写一份带 `base` 的文件。

### 蓝图改哪几节

- `personas.md`：`[persona] base`、以谁为底怎么叠、三种错、来自底的提示词怎么写来源。
- `presets.md`：`[preset] base`、`bad_base`、指纹不算 `base`。
- `protocol.md`：`persona.get`、`preset.get` 多 `base`，人格的提示词来自底的写成 `base:<编号>/<层>`。

### 定了的（技术细节，主会话定）

1. `[persona] base = "<编号>"`、`[preset] base = "<编号>"`，写法同编号，写错的报 `bad_base`（第几行）。`base` 本身也照几层叠，最上面写了的算。
2. 叠法：先把底照同样的办法找好、叠好（底再写了底的接着找），再把自己的几层盖上去。预设逐格盖；人格的 `persona.toml` 逐项盖，提示词自己的几层有的用自己的、没有的沿用底的。
3. 错：绕成了圈（含指着自己）`base cycle: a -> b -> a`；底哪一层都没有 `base "<底>" of "<自己>" not found`；底的文件写错，预设照它自己的那一句（本来就带编号），人格多说一句是哪个底（`base <底>: <层> <文件>:<行>: …`）。都归 `persona_invalid`、`preset_invalid`。
4. 来自哪儿：人格的提示词来自底的，`persona.get` 写成 `base:<编号>/<层>`（编号是这份字真住在的那个人格）；`layers` 只算自己的；多一格 `base`（直接的底）。
5. 预设的指纹不算 `base` 这一格：底的各格已经叠进来了；算进去会让以前造的快照全对不上，开着的会话白白换一次快照、断一次缓存。人格的指纹照叠好的字算，底改了照样换上。
6. 记忆归哪个账号照旧只看自己有没有家目录那一层。

### 不做什么

- `miyu check` 查底绕圈、底没有：它只查每一份文件自己；开会话、`*.get` 时报。
- 新建、改、删：P-3 中、下。

### 验收

1. 测试先写：盖在底上（预设逐格、人格逐项和提示词沿用）、底的底、来自底的写明、没写底的指纹不变；绕圈、指着自己、底没有、底写错、`base` 写错；`*.get` 带 `base`。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉两个头。

### 施工结果（2026-10-08 主会话）

1. `miyu-policy`：`PresetFile`、`PersonaFile` 多 `base`，读、叠（上面写了的算）；代码多 `bad_base`，给人看的一句加在 `core/human` 的三种语言里。预设的指纹照旧不算 `base`。
2. `miyu-store`：`Presets::find`、`Personas::find` 先叠自己的几层（`stack`），写了底的照同样的办法找底（`find_from` 带着一路找过来的编号查绕圈）、叠上去；错多 `BaseCycle`、`BaseMissing`，人格另有 `BaseInvalid`（说是哪个底）。人格的提示词来自哪儿换成 `Origin`（哪个人格、哪一层）。
3. `miyu-endpoint`：`persona.get`、`preset.get` 多 `base`；人格的提示词来自底的写成 `base:<编号>/<层>`；三种新错归 `persona_invalid`、`preset_invalid`。
