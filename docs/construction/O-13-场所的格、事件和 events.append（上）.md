## 施工单 O-13（上）：场所的格、事件和 `events.append`

状态：施工中（2026-10-09 写；形状照 `docs/blueprint/chat.md` 第七条第 2、3 条（2026-10-07 定稿，项目主人过目），2026-10-09 和通讯平台的会话又对了一遍，补了发的人的名字、媒体的名字、@全体成员、扩展事件的名字能带点；O-13 由主会话拆成上、下，技术细节主会话定）。

### 目的

桥要往场所会话里记群里的每一条消息（不管是不是冲她来的）、撤回、她实际发出去的话，桥自己的判断和出站队列也要记进日志。这一步只做「记」：格、事件、`events.append`，旁听的消息只记下不开回合。怎么渲染成群聊近况、`[you]` 行是 O-13（下）。

### 这一步做什么

1. **`message.user` 多一格可选的 `venue`**（`session.send` 带上，只收带 `as` 的、场所会话的）：
   - `msg`（必写）平台的消息编号；`reply_to` 引用的平台编号；`name` 发的人此刻在这个场所里叫什么（群名片，没有的用昵称，最多 64 个字符）。
   - `mentions` @ 了谁（平台身份的列表）；`mentions_me` @ 了她没有；`mentions_all` @ 了全体成员（不算 `mentions_me`）。
   - `media` 带的图、文件、语音、视频、表情：每项 `{kind, id, name?}`，`kind` 是 `image`、`file`、`voice`、`video`、`sticker`，`id` 是平台给的编号（懒下载，不进内容块），`name` 是文件名、表情的字（最多 200 个字符）。
   - `ambient` 旁听：只记下，不开回合，回合进行中也不排进这一轮；`asleep` 睡着时收到的（桥照样带 `ambient`）。
   - 原样记进事件，假的、空的、没写的不写。写错的整条 `bad_params`，什么都不记。
2. **两种新事件**（桥经 `events.append` 写，核心认得、照格查，O-13 下渲染）：
   - `venue.recalled`：`{msg, by}`，被撤的平台编号、谁撤的平台身份。
   - `venue.delivered`：`{line, turn, to, msg, text, images}`，哪条线（会话编号）、哪一轮（回合编号）、回的人（平台身份的列表）、平台编号、正文、图的内容哈希列表。
3. **`events.append {session, kind, body}`**，回应 `{"seq": n}`：
   - `kind` 是 `ext.<包>.<名字>`：`<名字>` 一段或几段、点隔开，每段照短名字的写法（小写字母开头，小写字母、数字、`_`、`-`），整个 `kind` 最多 128 个字符；`body` 是 JSON 对象，序列化以后最多 16 KiB。核心拉起的扩展的连接，`<包>` 必须是它自己的包编号；本机的头的连接都收。
   - 或者是上面两种核心认得的，只收场所会话的，格不对的 `bad_params`。
   - 记成不带回合编号的事件，任何时候都收（回合中途也行），不开回合、不打断。`ext.*` 不渲染，撤销、压缩都不动它（内核本来就把不认识的 `ext.*` 原样留着、投影跳过）。
4. **投影**：旁听的 `message.user`、`venue.recalled`、`venue.delivered` 这一步先都不渲染（O-13 下渲染成群聊近况）。别的照旧，非旁听的场所消息照普通的人的消息渲染。

### 主会话定的技术细节

1. 一个方法写三种：`events.append` 收 `ext.*` 和那两种核心认得的，桥只认一个方法；核心认得的那两种照格查，`ext.*` 只查大小。
2. 内核里是两样：`Command::Send` 多一格 `venue`（旁听的只记事件、不进排队的那条队、不开回合）；新命令 `Command::Append` 记一条不带回合编号的事件。
3. `turn.started.triggers` 随 O-14 的 `session.respond`：这一步没有谁写它，不为以后写代码。
4. 能力（`events.write`、`sessions.drive`）这一步照旧不挡，随多用户。

### 不做什么

- 渲染群聊近况、撤回的标记、`[you]` 行、`show_ids`：O-13（下）。
- `session.respond`、`turn.started.triggers`：O-14。

### 验收

1. 测试先写，改之前红：
   - 内核：带 `venue` 的 `message.user` 读写一字不差，假的、空的不写；两种新事件的样本；旁听的发进空闲的会话不开回合、发进跑着的回合不并进这一轮、下一轮也不当触发；`Append` 回合中途照记、不带回合编号、不开回合；旁听的消息、两种新事件不进请求。
   - 端点：`session.send` 带 `venue` 记下、旁听的回应照旧交序号、不带 `as` 的带 `venue` 拒、格写错拒；`events.append` 的 `kind` 写法、16 KiB、扩展只能写自己的包、核心认得的两种照格查、本机的会话不收那两种、回应带序号、回合中途也收。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合了把形状发给通讯平台的会话。

### 验收结果（2026-10-09）

1. **测试**：
   - 内核 `session/tests/venue.rs`：旁听的发进空闲的会话只记一条、不带回合编号、不开回合，不旁听的场所消息照常开；发进跑着的回合不带这一轮、说完了不接着开；`Append` 记的不带回合编号、不开回合、回合中途照记；只有 `ext.` 开头的能当扩展的事件。随机测试多两种输入（旁听的一句、桥记的一条），每一例最后各送一次，看守的不变量都过。两种新事件、带 `venue` 的 `message.user` 的样本，读写一字不差。
   - 组装 `render/tests.rs`：旁听的消息、`venue.recalled`、`venue.delivered` 不进上下文，不旁听的场所消息照常。
   - 端点 `tests/venue_records.rs`：`venue` 原样记下（假的不写）、旁听的不开回合、写错的八种什么都不记；`events.append` 收三类、回应带序号、不带回合编号，拒的十一种什么都不记，本机的会话也收 `ext.*`。`tests/system_account.rs`：扩展只能写自己的包那一段，记成这个包（模块）写的。

3. **变异**：手写 12 个全逮住（旁听的照常开回合、不带回合的也带上回合、不查 `ext.` 开头、旁听的照常渲染、不带 `as` 也收 `venue`、`venue` 不交给内核、扩展能写别的包的、不查大小、本机的会话也收场所事件、包后面不要名字、名字不查长短、记成管理员写的）。
