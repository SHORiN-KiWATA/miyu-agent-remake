状态：已完成（2026-10-08 写、施工完；CI run 1135 三台和长跑全绿；方向是施工方案第三节 P-2 那一行和人格与预设走查 `docs/reviews/2026-10-07-人格与预设走查.md`（C 组、D2 照推荐，项目主人 2026-10-07 定），Y12（预设必选，同一天定）；出厂编号 `full`、`dev` 和 `preset.default` 出厂 `full` 和通讯平台的会话对过（`chat.md` 施工时定的第 16 条）；原来的 P-2 由主会话拆成上、中、下：上是文件、找法、协议、会话带上预设，中是照预设挑工具面、装了没开的那一行（Y8）、开不开记忆和角色扮演提示，下是人格、预设两层进配置（D1）、子代理选人格和预设（C5）；技术细节主会话定）。

### 目的

预设成为数据根里的一份文件：出厂「功能全开」「开发」两个，主人能在系统区、自己的家目录里写同名覆盖或新的；开会话必须有预设，没写的照默认；会话列表、界面看得到每个会话用的哪个预设。这一步预设还不改变她能做什么（中做），先让文件、找法、协议、会话上的那一格定下来，头可以先接。

### 蓝图改哪几节

- 新页 `presets.md`：预设文件、三层找法、同名叠加、格式、默认预设、找人格的先后、`preset.list`、`preset.get`。
- `protocol.md`：方法表多 `preset.list`、`preset.get`；`session.create`、`venue.session` 多 `preset`；会话列表、`subscribe` 的回应多 `preset`；原因码 `unknown_preset`、`preset_invalid`。
- `config.md`：清单多 `preset.default`。
- `personas.md`「怎么走」第 1 条：找人格的先后多预设的默认人格。

- `kernel/events-bodies.md`：`session.created` 多 `preset`。
- `store/resources.md`、`store.md`：资源目录、数据根里预设的位置。

### 定了的（技术细节，主会话定）

1. **三层**：出厂 `<资源目录>/presets/<编号>.toml`、系统区 `system/presets/<编号>.toml`、管理员家目录 `home/<管理员>/presets/<编号>.toml`，和人格同样的三层（Y9）。一个预设一份文件（16 第三节），编号就是文件名，写法同人格的编号。同名的后面的叠在前面的上面，逐格盖：`[preset]` 逐格（`name`、`summary` 逐种语言），`[software]`、`[tools]` 逐个键。`base` 以谁为底、新建、改、删随 P-3。
2. **格式**（只收下面这些，不认识的表、键报错，写明第几行）：
   - `[preset]`：`name`、`summary`（语言到一句话，和人格、清单共用一份读法）；`default_persona`（人格的编号，写法查、在不在开会话时查）；`unlisted`：`on`、`off`，没列在 `[software]` 里的软件（包括以后新装的）开不开（Y7）。三层都没写的照 `on`：「功能全开」是默认，`[tools]` 里只关一两件的写法也是建在「其余都开」上的。
   - `[software]`：`<软件的编号> = true | false`，软件的编号是软件包的编号（基础系统 `basesystem`、联网 `net`、长期目标 `goal`、记忆 `memory` 这些自带的，和清单装的包），写法同包的编号（C1）。这一步只查写法，装没装、哪几件工具归它由中查。
   - `[tools]`：`<工具名> = false`，在开着的包里关掉单件工具（C1：单件打开某个包里的一件先不做，写 `true` 报错）。工具名：字母、数字、`_`、`-`，最多 64 个。
   - 权限级别、压缩模板、强调色这些配置值随下（D1、C3）：配置清单标好跟着谁走以后再放。
3. **出厂的两个**（Y6、Y7、10 第四节）：
   - `full.toml`：「功能全开」，`unlisted = "on"`。
   - `dev.toml`：「开发」，`unlisted = "off"`，`default_persona = "engineer"`，`[software]` 开 `basesystem`、`net`、`goal`。
   - 三种语言的名字、说明写全。
4. **默认预设**（Y12）：配置项 `preset.default`（名字，系统配置、个人设置，出厂 `full`，新会话生效），写法同 `persona.default`。新会话的预设照「开会话时指定的（`session.create` 的 `preset`；场所会话是桥交来的 `venue.session` 的 `preset`）、个人设置、系统配置」找；指定的、默认指着的预设哪一层都没有：`unknown_preset`，不悄悄换成别的、不造会话；文件写错：`preset_invalid`，写明哪一层第几行。
5. **找人格的先后多一步**：开会话时指定的人格 → 预设的 `default_persona` → `persona.default`。开发预设开出来的会话不写人格就是软件工程师（16 第六节）。预设的默认人格不存在照 `unknown_persona`。
6. **钉在会话上**（Y5）：`session.created` 记下预设的编号（和人格一样，可以没有：以前造的会话没有这一格），会话列表、`subscribe` 的回应照它写 `preset`。子会话照父会话的预设（C5 的默认，子代理能选别的随下）。这一步预设不进快照：它还不改变请求，快照字节、前缀一个字节不变；中让它改工具面时一起进快照、照 K3 改了下一个回合换上。
7. **协议**：
   - `preset.list`：不带参数，照编号排，每项 `preset`、`layers`（`shipped`、`system`、`home`），读成了的有 `name`、`summary`（照连接的语言挑，挑法同 `persona.list`），写错的只带 `problem`。
   - `preset.get {preset}`：叠好的各格（`name`、`summary` 各种语言原样）、`default_persona`、`unlisted`、`software`、`tools`、来自哪几层。
8. **`miyu check`**：每一层里每一份预设各查各的，种类 `preset`，写法同人格；写了文件的认得出是不是某一层 `presets/` 下的 `<编号>.toml`（两边换成真的路径比，照 8-30）。
9. **给人看的字**：`preset-problems/<code>` 三种语言；`preset.default` 的名字、说明进 `core/human`。
10. **登记**：预设这一步不给模型看任何字，不登记。出厂的 `presets/*.toml` 是给人看的，登记簿门禁照 `packages/` 那样豁免。

### 不做什么

- 照预设挑工具面、装了没开的那一行（Y8）、开不开记忆和角色扮演提示、预设进快照、改了下一个回合换上：P-2（中）。
- 人格、预设两层进配置（D1），预设里写权限级别这些配置值，子代理选人格和预设（C5）：P-2（下）。
- 新建、改、删、`base`：P-3。
- 场所规则里的 `preset` 怎么交给核心：桥的事，规则那一格（`chat.md`）已经有了；桥照 `venue.session` 的 `preset` 交就行。
