## 施工单 1-14：请求形状探针

状态：已拍板（2026-09-26），施工中。

### 目的

M1 的最后一步：同样的日志一定投影出逐字节相同的请求，由探针守住（`08-上下文投影.md` 第七节「测试门禁」，`26-提示词.md` 第七节）。

- 一份终端会话的假日志，照每一次请求当时看到的样子组装出完整的请求，和存档逐字节比对。
- 每一次请求都是上一次的前缀延伸，只有压缩、撤销这类记了原因的改写点除外。
- 随机生成合规的日志，每一次请求都查同样的几条性质。

### 推演时查出来的一处

写这张施工单时，照「每一次请求都延伸上一次」推演了现在的拼法（1-12 的第 4 条：事实一律排在人的消息前面），有一种情形会断：一个回合的第一次请求出了错，没等到回复。

- 那次请求的最后一条：`user：看看 src 目录`
- 下一个回合的第一次请求里，这一条变成：`user：This turn stopped on an error. ｜看看 src 目录｜再试一次`。上一次发过的「看看 src 目录」被挤到了第二块，前缀从这里断开；读起来也像是先出错、后说话。
- 改成照有效历史的先后，只把回合开始时注入的事实挪到触发它的那条前面：`user：看看 src 目录｜This turn stopped on an error. ｜再试一次`。上一次的那一块原样排在最前，后面接着加，前缀接得上，先后也对了。
- C2 要的「本轮的事实在前，触发消息在最后」照样成立：回合开始时注入的事实本来就排在触发它的那条前面。两份样本请求都不变。1-12 的测试里只有一个要改：先来两条消息、由第二条开回合的那种，事实从两条消息前面挪到第二条前面。

动手时先写一个照现在的拼法会红的测试，证明它真的会断，再改（`AGENTS.md`「先证明会出现，再修」）。

### 不做什么

- 别的场所：网页、命令行、QQ 群、QQ 私聊、桌面语音、子代理，各自做出来时加进探针。
- 真的回合状态机：假内核只在测试里，照图纸造日志。2-x 做出真的以后，探针改用真的，存档照「字节变了写明原因」重写。
- `model.called` 和「第一处不同」的登记簿：2-3。
- 急着插话、打断这一轮的情形：那条消息和「回合结束」谁先记进日志，2-5 定。这一步推演出一条留给 2-5：消息记在回合结束之后，触发消息才排得到最后（C2）。
- 真的工具面和 system：探针用两件假工具和一句 system，真的等 3-6。

### 要拍板的

1. **人这一边的块怎么排**，就是上面「推演时查出来的一处」。

   - 不改的话，就把「第一次请求出错、没等到回复」登记成一种改写的原因，探针在那里放行。

### 我定的

- **前缀延伸在统一的请求这一层算**：工具面、system 不变；上一次的每条消息原样都在；只有最后一条可以在后面多出几块（上一次请求没等到回复，后来的块合进了同一条 user 消息）。发出去的字里前面那几块还是原样，缓存照样命中。统一的请求写成 JSON 时，上一次的字节不是下一次的开头（末尾的括号不同），所以按消息和块比，不按整串字节比。
- **放在 `miyu-assemble` 的集成测试里**：探针要用默认的组装。假内核两个测试共用，放在 `tests/support/`。
- **存档一次请求一个文件**：写的是规范字节，末尾一个换行。哪一次请求变了，一眼看得出是哪个文件。重写存档用 `MIYU_PROBE_WRITE=1`，平时只比对。
- **假日志的剧本**，八个回合，把 1-12、1-13 画过的走法都走一遍：
  1. 第一轮：环境、权限两块事实；调一次工具，结果回来，再回一句。
  2. 调两次工具，结果倒着回来；回合中途来了一句话。
  3. 过了整点，环境重新注入；回复到一半被打断，收全了的那次调用补「已取消」。
  4. 两轮之间换成只读，权限重新注入；一次调用被拒绝。
  5. 第一次请求就出错，没等到回复。
  6. 走到步数上限。
  7. 撤销第 6 轮以后，再说一句。
  8. 压缩以后，两块事实重新注入。
- **随机日志查五条**：同样的日志出同样的字节；是上一次的前缀延伸，除非中间压缩过、撤销过；工具调用和结果成对，结果按调用的先后紧跟在调用后面；没有连着的两条 user 消息；每个回合第一次请求的最后一块，是触发它的那条消息。
- **随机数自己写**：SplitMix64，十来行，不加依赖（纯逻辑那两层的白名单里没有随机数的 crate，测试也照这个来）。种子固定，每次跑都是同样的五百份。
- **工具面和 system 用假的**：探针守的是拼法；工具说明和 system 的字，3-6 有了真的以后换上。

### 风险

- 存档一次请求一行 JSON，人读要排版。验收流程里给一行命令，把某一次请求排好版打出来。
- 假内核是照图纸推的回合行为。2-x 做出真的以后，日志的样子可能会变，存档跟着重写，写明原因。
- 随机日志只覆盖假内核造得出的走法。急着插话、子代理的回报这些，等做出来再加进去。
