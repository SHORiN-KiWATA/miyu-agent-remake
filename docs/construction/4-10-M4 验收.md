### 验收（项目主人照着做）

下面的命令都在一个新开的终端里跑。数据根放在 `/tmp/miyu-m4/home`，不碰 `~/.miyu`；程序用仓库里编好的 `target/release/miyu`，不用装好的旧版。

1. 准备临时仓库。里面是一个故意写错的小 Rust 项目：`add` 写成了减法，`cargo test` 过不了。

   ```bash
   bash ~/.cache/miyu-m4/setup.sh
   export MIYU_HOME=/tmp/miyu-m4/home
   export MIYU_RESOURCES=~/Documents/github/miyu-agent-remake/resources
   M=~/Documents/github/miyu-agent-remake/target/release/miyu
   cd /tmp/miyu-m4/repo
   export DEEPSEEK_API_KEY=你的 key
   ```

2. 让她干活：

   ```bash
   $M ask "cargo test 没过，找出原因修好，再跑一遍测试确认"
   ```

   看：她一步步搜、读、改、跑测试，每一步在标准错误上印一行灰的（例如 `· 读取 src/lib.rs → 23 行`、`· 执行命令 cargo test → 输出 N 行`），路径写相对的；最后说修好了，退出码 0（`echo $?`）。

3. 看改了什么，再撤销、恢复：

   ```bash
   git diff          # add 改回了加法
   $M undo           # 印出「改回 src/lib.rs」，还有「这一轮执行过 N 条命令」那一句
   git diff          # 空的：改回去了
   $M redo           # 又改了回来
   git diff          # 又是她改的样子
   ```

4. 看缓存命中和日志：

   ```bash
   grep -E ' (request|ended) ' $MIYU_HOME/state/logs/core.log
   ```

   `ended` 那几行的 `hit` 是命中缓存的 token：第二次请求起应该不是 0。日志里的路径家目录写成 `~`，没有 key：

   ```bash
   grep -c 'sk-' $MIYU_HOME/state/logs/core.log       # 0
   ```

5. 看她的回答里有没有漏 DSML：

   ```bash
   grep -c 'DSML' $MIYU_HOME/home/admin/sessions/*/*.jsonl    # 都是 0
   ```

6. 量 token（同一个终端，key 还在）：

   ```bash
   python3 ~/.cache/miyu-m4/measure.py
   ```

   印出七件工具各多少、七件一起多少、`aborted.txt` 多少，也写进 `~/.cache/miyu-m4/tokens.json`（只有数字）。

7. 收尾：

   ```bash
   unset DEEPSEEK_API_KEY
   ```

   她起的核心不跟着终端退，空闲 10 分钟自己退；在那之前它的环境里还有这个 key，只在这台机器的内存里。

照第 2 到 5 步看到的样子、第 6 步的数告诉我。我把数填进登记簿、定预算，照拍板的办法加测试，走一遍合并的流程。
