## 施工单 P-1（下）：空人格、会话带上人格

状态：已完成（2026-10-07 写、施工完；CI run 1083 三台和长跑全绿；空人格由项目主人同一天定（16 Y11，网页转来、主会话当面确认）；「会话带上人格」网页、终端两个头要；原来的 P-1 下由主会话拆成三步，这是头一步；技术细节主会话定）。

### 目的

头能显示一个会话用的是哪个人格，也能开一个「不用人格」的会话。

### 蓝图改哪几节

- `personas.md`：出厂的空人格、`session.created` 记人格、状态行。
- `kernel/events-bodies.md`：`session.created` 多 `persona`。
- `store/index.md`：一行多 `persona`，版本 4。
- `protocol.md`：`session.list` 的一项、`sessions.changed`、`subscribe` 的回应多 `persona`。

### 定了的（技术细节，主会话定）

1. **空人格**：出厂 `resources/personas/none/persona.toml`，只有名字（不用人格、No persona、ペルソナなし）和说明，没有提示词；system 照拼 system 的规矩不留空块。它是一个普通的出厂人格，没有特判。
2. **`session.created` 多 `persona`**：造会话时照快照的人格编号写（`Snapshot::session_created` 里填，`open.rs` 不动：它到了 500 行，记忆的会话正在拆它）。以前的日志没有这一格，照没有读。
3. **会话列表**：索引一行多 `persona` 列，版本 3 → 4（老的照版本不对删掉重建，照日志补）；一项写 `persona`，没有的不写；推送照同一个写法。
4. **`subscribe` 的回应**：照日志第一条 `session.created` 读（一行），不往会话的 `Handle` 里加：同样是为了不动 `open.rs`。

### 不做什么

- 角色扮演提示：P-1 补。改了人格下一回合换上：P-1 再补。
- 预设：P-2。

### 验收

1. 测试：空人格的 system 里没有人设、`session.created` 记着 `none`；会话列表、`subscribe` 写着人格；以前的日志没有这一格的不写；索引的 `persona` 列读写；`persona.list` 多出厂的 `none`。
2. 手写变异 8 个左右；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉两个头（`persona` 出现的三处、`none`）。

### 施工结果（2026-10-07 主会话）

1. 出厂 `personas/none/persona.toml`：三种语言的名字、说明，没有提示词。
2. `session.created` 多 `persona`，在 `Snapshot::session_created` 里填；索引多 `persona` 列，版本 4；会话列表、推送、`subscribe` 的回应带上。
3. 测试撞出一处真毛病：索引加一列以后，「没改过才换」那句的条件占位要往后挪一位（`?16` 到 `?18`），原来写死的 `?15` 会让写回失败。
4. 登记簿的门禁原来把 `personas/<编号>/persona.toml` 当成给模型看的字；它是给人看的名字、说明和配置，不发给模型，门禁改成不扫它（`prompts/` 下照查）。
5. 顺带：项目主人同一天定「默认人格」的说明只留一句（「新会话默认用哪个人格。」），三种语言、配置样本跟着改。
