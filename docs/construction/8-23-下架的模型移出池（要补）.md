## 施工单 8-23（要补）：下架的模型移出池

状态：施工中（2026-10-09 写；2026-10-04 项目主人转来（网页演示要）；2026-10-08 照推荐定「列表和报错都说没有才算下架」；技术细节主会话定）。

### 目的

供应商下架了一个模型，池里还点着它：每次轮到它都白发一次、出错、换下一个，钉住的池还可能一直钉在它上面。核心确认它下架了，就从所有池的成员里删掉，写回配置，各个头读到的一致。

### 怎么算下架（2026-10-08 定）

两样都说没有才算，只看一样会误删：

1. **报错**：发给这个模型的请求回了 404（模型不存在；`model.called` 的 `error.status` 是 404）。
2. **列表**：报错以后当场再拉一次这一家的模型列表（`route/lists.rs` 那一套），拉成了、里面没有这个模型。拉不成的（连不上、这一家列不出模型）不算。

只有池的成员算：`models.chat`、`models.vision` 直接写着的模型不动（那是人明着写的，撞上了照旧报错，人自己改）。

### 这一步做什么

1. **认**：路由在一次请求出错收场时（会话的请求、一次性调用都算，`route/retire.rs`），这个候选是池的成员、状态码 404 的，交给后台去确认（不挡这一次：404 是 `other`，照旧收场、不换端点）。同一个模型同一时间只确认一次。
2. **确认**：后台当场再拉这一家的列表（`refresh_list`，拉成了照常换上）；拉成了、里面没有它的算下架，记一行 `INFO model gone`；列表里还有、拉不成的不算（不照以前拉过的旧列表算）。确认完了交给端口 `miyu_session::Retirement`（端点在核心起来时装上，`Core::start_retirement`），在阻塞线程里调。
3. **写**：端点照两层（系统配置、个人设置）的文件里写着它的 `pools.<名字>.models`，一层一次 `config.set` 那一条路写（手改保护、推 `config.changed`、日志），`by` 是 `{"kind":"kernel"}`（`config::set::set_by`）；记一行 `INFO model retired model=… pools=…`。写不成的 `WARN model not retired`。
4. **删空了的池留着**：`model.list` 的 `pools` 里成员是空的池多一格 `usable: false`；照它挑的请求照旧 `no_model`（原话说池是空的）。不删池：池的名字可能还被 `models.chat`、预设、派子代理引用着。
5. **只记在内存里的**：已经确认过、写掉了的，不再确认；写不成的（文件被手改、冲突）记一行 `WARN model not retired`，下一次再撞上再来。

### 主会话定的技术细节

1. 判 404 照状态码，不照报错的原话：几家的原话各不一样，状态码一样。
2. 确认放后台、经端口写：路由在会话那一层，写配置在端点，照「下层要上层的能力一律走端口」。
3. 写配置走 `config.set` 那一条路：手改保护、推送、日志都现成。

### 不做什么

- 直接写着的 `models.chat`、`models.vision`：不动。
- 模型重新上架以后加回池里：不做，人自己加。
- 头上的提示（「某某模型下架了，已从池里删掉」）：头照 `config.changed` 和 `model.list` 自己画。

### 验收

1. 测试先写，改之前红：池里两个成员，第一个回 404、列表里没有它：换到第二个答完；配置文件里那个池只剩第二个，推了 `config.changed`（`by` 是核心）；再请求不再发给第一个。回 404 但列表里还有它的：不删。拉列表失败的：不删。只剩它一个的池删空了留着，`model.list` 里 `usable: false`，照它挑的 `no_model`。直接写在 `models.chat` 的不动。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合了把 `pools[].usable` 的形状发给终端界面、网页。

### 验收结果（2026-10-09）

1. **测试**：`miyu-session` 的 `tests/route_retire.rs`：池的成员回 404、当场拉的列表里没有它，端口收到「下架了」，发了一次、拉了一次列表；列表里还有它的、拉不成的（以前拉过、里面没有它的旧列表还在也不算）交「没下架」；直接写在 `models.chat` 的、不是 404 的不拉列表、不交。`miyu-endpoint` 的 `tests/models_retire.rs`：真路由，`model.call` 照池发，系统配置、个人设置里写着它的池都拿掉它，两层各推一条 `config.changed`（`by` 是内核），没写它的池、`models.chat` 不动，删空了的池留着、`model.list` 里 `usable` 是假；列表里还有它的配置不变。`model.list` 的 `pools` 多 `usable`，原来比整份的一处跟着改。
2. **变异**：手写 10 个全逮住（任何错都查、直接写着的也查、拉不成也算下架（第一遍漏了：拉不成时根本没有列表；补了「旧列表还在」那一条）、不看列表里有没有、会话的请求不查、一次性调用不查、没下架也拿掉、只改系统配置、记成管理员改的（这一个改出了死锁，测试停不下来，算逮住）、空池也算能用）。
3. **没有测试守着的**：`miyu-core` 起来时调 `start_retirement` 那一行（端点的测试自己调它）。
