## 施工单 4-7：miyu undo、miyu redo（下）

状态：已完成（2026-09-28：三台机器的 CI 全绿、长跑也绿、测试全过，照施工方案第一节第 1 条算验收通过）。

### 目的

4-7（上）让会话在撤销、恢复时照效果把文件改回去，协议上能撤销、恢复。可前端（M8）做出来之前，人没有办法发这两个命令。这一步给 `miyu` 加两条命令：`miyu undo` 撤掉当前会话的最后一轮，印出改回了哪些文件，之后又被改过的不覆盖，印出路径和差异；`miyu redo` 在发下一句之前恢复。4-10 真人实测时用得上；做前端时换成 `/undo`、`Ctrl+R`，这两条命令留给脚本用。

### 拍板的

- 加这两条命令（2026-09-28 项目主人定 A）。
- 印出来的样子（2026-09-28 项目主人定：照推荐）：

```text
$ miyu undo
· 撤销「把 README 改成中文」这一轮
· 改回 src/a.rs
· 移回 docs/old.md
· 删掉 notes/new.txt → 移进了回收站
· 改回 src/b.rs → 没动：之后又被改过
    --- 她改完的
    +++ 现在
    @@ -3 +3 @@
    -fn main() {}
    +fn main() { println!("hi"); }
· 这一轮执行过 2 条命令：命令改的文件撤不回
发下一句之前，可以用 miyu redo 恢复。
```

  - 差异由核心算好交给 `miyu undo`，每个文件最多印 20 行，多了说一句还有几行；方向是「她改完的 → 现在」。
  - `miyu redo` 用同一种写法。
- 别的只有技术细节，照施工方案第一节第 1 条直接做。

### 不做什么

- 撤到更早的某一轮、挑着撤：一次撤最后一轮，要往前就再撤一次。「从这里撤」做前端时做。
- 冲突的文件帮人合：只印差异，人自己决定（B7）。
- `--format json`：撤销不是查询类的命令（22 第二节），先不做。
- 撤掉的那几轮派出去的子代理、后台命令一起停下：M7。

### 我定的

- **哪个会话**：和 `miyu ask --continue` 一样，最新的那个一次性会话；`--session` 指定别的。一个都没有的，说「还没有 miyu ask 开过的会话」，退出码 1。
- **撤哪一轮**：还在有效历史里的最后一轮。`session.revert` 不写 `turn` 的就是这个意思，内核照账本找：撤销当时就定，不会撤错。一轮都没有的（没说过话、都撤掉了、都压缩进了摘要），拒绝，原因码 `nothing_to_revert`（新）。
- **核心没在跑的**：拉起来。撤销、恢复用不着模型，没设 key 也拉起（核心没有 key 也起得来，只是请求模型时说没有模型）。
- **印到哪、上不上色**：结果走标准输出。标准输出是终端、没设 `NO_COLOR` 才上色：整行灰，「没动」「出错」红，差异里删掉的行红、加上的行绿，写完换回原色。
- **印什么**（照定的样子）：
  - 第一行 `· 撤销「……」这一轮`，恢复是 `· 恢复「……」这一轮`，引号里是那一轮人说的那句话的第一行，太长的截断。那一轮不是人开的（子代理的回报之类），写 `· 撤销最后一轮`；恢复几轮的写 `· 恢复「……」起的几轮`。
  - 每个文件一行，照改回的先后：写回的 `· 改回 路径`；移进回收站的 `· 删掉 路径 → 移进了回收站`；从回收站移回来的 `· 移回 路径`。
  - 没动的同一行写原因，「没动」是红的：之后又被改过、文件没了、原处有了别的、回收站里已经没有了、改前的内容当时没存下来、回收站收不了。出错的写 `→ 出错：系统的原话`，「出错」是红的。
  - 之后又被改过的，下面缩进四格印差异：`--- 她改完的`（恢复时是 `--- 撤销以后的`）、`+++ 现在`，接着是差异的几段，一个文件最多 20 行，多了说一句 `还有 N 行`。不是文本的、太大的（任一边超过 1 MiB）、要对照的内容当时没存下来的，不印差异。
  - 撤掉的那几轮执行过命令的（访问类别是执行命令的调用，照工具目录认），`· 这一轮执行过 N 条命令：命令改的文件撤不回`（B7：界面上写明）。恢复时不说。
  - 撤销的最后一行 `发下一句之前，可以用 miyu redo 恢复。`，灰的。
  - 路径照施工 4-5 下的规矩：在会话的工作目录里的写相对的，在家目录里的写 `~/…`，都不是的写绝对路径。
- **差异在核心里算**（01 D1，04 第五节）：`session.revert`、`session.unrevert` 的回应在 `events` 以外多几样。
  - `cwd`：会话的工作目录，头照它写路径。
  - `said`：那一轮人说的那句话，没有的不写。恢复时是恢复的第一轮的那句。
  - `commands`：撤掉的那几轮执行过几条命令，撤销时才有。
  - `files`：每一步的 `path`、`action`、`outcome`，出错的 `error`，印差异的 `diff`（几行，照统一格式，不带 `---`、`+++` 那两行）和没印出来的行数 `more`。
  - 做视图投影（M8）时这几样挪进视图，字段只加不改。
  - 要对照的内容：撤销时是她改完的（`file.changed` 的改后），恢复时是撤销以后的（改前），从 blob 里取；现在的内容照路径读。差异用 `similar`（Rust 里通用的那一个），上下文 3 行。
  - 没改回文件的（撤掉的那几轮没改过文件），`files` 是空的。
- **退出码**：被接受的 0，有文件没动也是 0：撤销本身成了，没动的都写明了。被拒绝的 1，原因照头的语言印在标准错误上。
- **`--help`**：跟着界面语言。

### 风险

- **回应变大**：差异放在回应里，改了很多文件、文件很大的时候回应会长。每个文件最多 20 行，任一边超过 1 MiB 的不算差异。
- **新加一个 crate**：差异用 `similar`，只在端点里用。
- **撤的时候正好有人开了一轮**：内核照账本判，那一轮在跑的拒绝，原因码 `turn_running`（施工 2-8 下就是这样）。
