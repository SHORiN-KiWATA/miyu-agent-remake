## 施工单 9-6（下）：`view.page` 按页读

状态：已完成（2026-10-08 写、施工完；CI run 1167 三台和长跑全绿；方向是施工方案第三节 9-6 那一行，页的形状和终端界面、网页的会话对过（2026-10-08）；技术细节主会话定）。上一步 9-6（上）让订阅的回应带上「当前的」几样，头不用再从整份日志算。

### 目的

头接一个老会话时不用再从 0 补整份日志：先拿最新一页画出来，再接着订阅新的；往上翻到顶再要更早的一页。

### 蓝图改哪几节

- `protocol.md`：方法的表多 `view.page`，多「`view.page`」一节，`bad_params` 那一行。

### 定了的（技术细节，主会话定；形状和两个头对过）

1. `view.page {"session", "before"?, "turns"?}` → `{"events", "more", "first"?, "last"?, "capped"?}`；`turns` 1 到 50，默认 20；`events` 是原始事件，同补发的写法，核心不做视图投影（随以后的视图流）。
2. 页的边界落在回合之间（从 `before` 往前数 `turn.started`），数到第一轮的连前面的一起给；到 1 MiB 就在回合之间提前切、至少一整轮，提前切的带 `capped`。
3. 触发消息在切点前的也带上，头照序号去重（两个头都选这个：不把上一轮的半截尾巴带进来）。
4. `around`（跳到某个序号附近）先不做：头还没有搜索、跳转的入口，形状以后再加。
5. 只读地读会话目录（`read_events`），不为翻历史载入会话。

### 不做什么

- 视图投影、视图流：以后。
- `around`。

1. 测试先写：切页的纯函数（轮数、上限、至少一轮、触发消息、开头、空的）；真核心翻到头拼起来是整份日志、接着 `after = last` 订阅什么都不补；参数不对、没有这个会话。
2. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
3. 合进 main 以后告诉两个头：接老会话改成「最新一页 → `subscribe after=last`」，往上翻要更早的一页。
