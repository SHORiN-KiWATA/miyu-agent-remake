## 施工单 2-6：排队的消息

状态：施工中。

### 目的

她干活的时候你发的话排着队：还有下一步的，下一次请求里就有；在最后一步里排着的，她回复完了接着开一轮回你。打断分两种：接着发，排着队的马上开一轮；退回，排着队的撤回来，回到你的输入框。

### 拍板的

- 最后一步里排着队的，回复完了接着发：项目主人 2026-09-26：「那当然是在这步结束后发送呀。AI 回复结束后发送。」走完、出错、到步数上限结束的都一样。
- 打断：项目主人 2026-09-26：「esc两次打断，排队的马上发；ctrl+c打断，排队的回到输入框」。
- 先查了四家的做法（2026-09-26，都是读源码）：
  - codex：Esc 打断，排着的马上作为新一轮发；Ctrl+C 打断，排着的放回输入框。和你定的一样。
  - opencode v2：Esc 按两下打断，排着的马上发；Ctrl+C 不碰队列。
  - Claude Code：Esc、Ctrl+C 都打断，排着的接着发；↑ 拉回来改。
  - 旧 Miyu：两种打断都把排着的删掉。

### 不做什么

- 键位：按两次 Esc、Ctrl+C、↑ 拉回来改，都随终端界面（M8）。这一步只有核心的两种打断。
- 单独撤回一条排着队的（↑ 拉回来改用的）：M8 定了键位再加命令。撤回的机制这一步就有了。
- 「等这一轮完了再发」的另一种排队（opencode 的 queue、codex 的 Tab）：头自己就做得了，要的话 M8 再说。
- 子代理、后台命令的回报：M7，照同一条走。
- 群里没冲她来的消息：做通讯平台时。

### 我定的

- **排着队的就是日志里的消息**：来了就记，下一步自然在请求里；撤回用一条新事件，不删日志。opencode 另开一张收件箱表，重制版的日志只追加，撤回事件做得到同样的事，还少一份存储。
- **听到没听到看请求**：这一轮里、最近一次请求看到的之后来的，才算排着队。
- **接着发另开一轮**：这句话有自己的一轮，撤销能单独撤，步数上限重新算，回合开始的挂接点也照它跑。codex 和旧 Miyu 是在同一轮里接着请求；Claude Code 是另开一轮。
- **由最后一条触发**：离生成位置最近的是最新的那句（`08-上下文投影.md` C2）。
- **两个回合同一批追加**：上一轮结束、下一轮开始，一次写入、一次同步。
- **撤回写在回合结束之前**：撤回的消息属于这一轮，撤回也记在这一轮里。
- **回合的触发不算排队**：它开了这一轮，不在队里；Ctrl+C 不会把它撤回来。
- **撤回的规矩交给账本守**：撤了听到过的，前缀就断，这是内核的 bug，账本当场拦下。

### 验收

1. `step/2-6-queued` 分支的 CI：三台机器全绿。
2. `cargo test`，新加的测试：
   - `message.withdrawn` 的写法；账本拦下撤回听到过的、不是消息的、别的回合的、撤过的；有效历史去掉撤回的消息，撤回这一条自己也不留。
   - 最后一步里来了消息：回复完了，同一批追加上一轮的结束和下一轮的开始，触发是那条消息；两轮的挂接点先后对；下一次请求里有它。
   - 来了两条：由后一条触发。出错、到步数上限结束的：一样接着开。
   - 还有下一步时来的：进了下一次请求，回合结束时不再接着开。
   - 打断接着发：排着队的马上开一轮；没有排着队的，照 2-5。
   - 打断退回：追加 `message.withdrawn`，列出排着队的那几条，`by` 是打断的人，写在回合结束之前；它们不再出现在请求里；不接着开；回应附上这一条的序号。没有排着队的，不写这一条。
   - 样本会话接着往下的几条读写一字不差；压缩以后注入的两块就是样本里的那两条；整个会话组装出来的请求里，没有撤回的那句。
   - 随机一串输入加上两种打断：原来的规矩照查，再查回合结束时有排着队的就接着开、触发是最后一条；退回的撤回的正好是排着队的那几条；还要走到过接着开了一轮、打断后接着发、打断后退回。
3. 故意改坏几处，每一处都有测试变红（施工时列出清单）。
4. `cargo xtask check` 七项全过。

### 风险

- **两个回合挨在一批里**：账本要先见上一轮结束，再见下一轮开始；挂接点的先后也要对，上一轮结束的在前。测试照动作的先后查。
- **样本会话接着往下写**：「整个会话压缩以后」那份样本请求原来是全部喂进去，改成喂到压缩那一条为止，后面的另外查。
