## 施工单 5-1：沙盒的规格和助手

状态：已完成（2026-09-28：变异全逮住；真模型自测对；CI 全绿）。

### 目的

把沙盒的路接通，还不收紧任何东西：
- 核心给要关起来的命令写一份规格；
- 新的小程序 `miyu-sandbox` 照规格收紧自己，再换成那条命令；
- `shell` 带了规格的经它起命令；
- 核心起来时探一次这台机器能收紧到什么程度。

5-2 起各平台一件件加上真正的收紧。

### 蓝图改哪几节

- 新的一页 `sandbox.md`：规格的每一格、助手的命令行和退出码、探测、找助手；蓝图 README 的分页表加这一行。
- `tools/interface.md`：一次调用带的 `sandbox`。
- `tools/shell.md`：带了规格的经助手起命令。
- `core.md`：起来时探一次，记一行日志。
- 设计 `01-架构.md` 第九节：第 3 层加 `miyu-sandbox`。和 crate 一起提交，门禁两边都查。

### 我定的

- 助手是单独的小程序，放在主程序旁边，照 `11-权限与沙盒.md` 第六节：Ubuntu、Mint 上只给它开命名空间。
- 规格用 JSON，经命令行的 `--spec` 交给助手，里面只有路径和网络怎么走，没有密钥。
- 助手成了什么都不印：它的标准错误就是命令的标准错误，印了会混进给她看的输出。
- 退出码照 `env`、`timeout` 的约定：125 是助手自己出了错，126 是命令执行不了，127 是找不到命令。
- `miyu ask` 开头说「沙盒用不了」那一句挪到 5-4：那时沙盒才生效，说得准。
- 助手里收紧的代码各平台一个文件（`src/bin/miyu-sandbox/` 下的 `linux.rs`、`macos.rs`、`windows.rs`、`other.rs`），蓝图各平台一页，随那一步写；收紧不成时说的那一句现在就定下（`cannot confine: <原话>`，退出 125）。这样 Linux、代理、macOS、Windows 几条线可以同时施工，各改各的（2026-09-28 项目主人同意分线并行）。

### 不做什么

- 任何平台上的真正收紧：Linux 5-2、5-3、5-6，macOS 5-7，Windows 5-8、5-9。
- 权限策略接上沙盒、核心给调用带规格：5-4。
- 代理：5-5。

### 验收

只有技术细节，照施工方案第一节第 1 条直接做：

1. 助手的测试：命令照常跑，输出、退出码、工作目录、环境变量都和直接跑一样；规格写坏了、没给命令、找不到命令，各自的退出码和那一句；`probe` 说的是这台机器的平台。
2. `shell` 带了规格的经助手起命令（测试里用一个假助手，看它收到的参数），不带的和原来一模一样。
3. 核心起来时的日志里有 `sandbox` 那一行。
4. `cargo xtask check` 八项全过；三台机器的 CI 全绿。

### 验收结果（2026-09-28）

1. **测试**：
   - 助手真跑：经它跑的命令，输出、退出码、工作目录、环境变量都和直接跑一样，它自己什么都不多印；Unix 上是同一个进程，被信号杀掉的照样是信号。
   - 参数不对、规格写坏了、没给命令退出 125，执行不了 126，找不到 127，各带一句。
   - `shell` 带了规格的经助手起：四种 shell 看包出来的参数；Unix 上拿 `/bin/echo` 当假助手真跑一次；规格写不成 JSON 的，命令没跑。
   - 探测：真的助手说的是这台机器；假助手到时杀掉，关了输出不退出的、拿着管道不放的也不等。
2. **实机**：起一次核心，日志里是 `INFO core sandbox helper=~/…/target/debug/miyu-sandbox platform=linux mechanisms=none`，探一次约 1 毫秒；主程序单独拷走的，记 `WARN sandbox unavailable reason="helper not found"`。
3. **真模型自测**（`deepseek-flash`，key 只在命令的环境变量里）：让她看一个小仓库，她跑了两条命令，文件、行数、提交说明都对，两次都写了 `description`；缓存命中 82%。测完停了核心，草稿、仓库、记忆里 key 都是 0 处。
4. **变异**：手写 27 个，全被测试逮住。第一轮漏了一个：找不到助手时不记日志（跑整套测试时助手总在旁边，走不到），补了 `crates/miyu-core/src/sandbox/tests.rs` 直接测。另有三个测试是变异之前先补的：关了输出不退出的助手、Unix 上是同一个进程、写不成不跑。
5. 为分线并行做了准备：助手的收紧各平台一个文件，收紧不成时说的那一句先定下。
6. `cargo xtask check` 八项全过（1138 个测试）；分支 CI 三台机器全绿，长跑也绿。

### 风险

- 只编了 `miyu` 这一个包的时候，旁边没有助手：探测记一行找不到，这一步不影响别的；5-4 以后照「沙盒用不了」办。
- Windows 上助手要起子进程、等它：超时整组杀要连它的子进程一起杀，5-9 在 Windows 虚拟机上实测。
- Windows 上主程序的真实位置带 `\\?\` 的前缀，日志里助手的路径跟着带（蓝图「还没有的」），5-8 起看。
