## 施工单 3-5：试玩台（补）

状态：施工中。

### 目的

先跟真模型说上话：一个进程内的试玩台，内核直接接 DeepSeek 官方，跳过核心进程和协议端点（3-7、3-8）。终端里一行一行地说，思考和回复边出边显示，每次请求后面写一行用量：命中多少、没命中多少、上一次发过的这次重算了多少。连说两轮，量出缓存命中；拿真模型试说到一半断了以后接不接得上（`26-提示词.md` J5）。只能聊天，动不了文件（工具是 M4）。

### 做什么

| 文件 | 装什么 |
|---|---|
| `crates/miyu-try/src/main.rs` | 读参数和 key 文件，接上终端：标准输入一行一句，Ctrl+C 打断这一轮，空闲时 Ctrl+C 或者输入完了就退出 |
| `crates/miyu-try/src/lib.rs`、`config.rs` | key 文件怎么读：三行 `MIYU_TRY_BASE_URL`、`MIYU_TRY_MODEL`、`MIYU_TRY_KEY`；`--model` 可以换模型 |
| `crates/miyu-try/src/policy.rs` | 这一个会话的策略：出厂的组装、事实模板、写给模型的句子，工具一件都没有；system 是占位的一句，`--system <文件>` 可以换成别的 |
| `crates/miyu-try/src/run.rs` | 执行器：照 `02-内核.md` 第四节的表回内核的每个动作。追加的写进会话日志、同步了回「落盘了」；请求模型的交给驱动编码、HTTP 执行器发，增量和结局送回去；到点叫醒的睡够了送回「到点了」；挂接点马上回空的 |
| `crates/miyu-try/src/show.rs` | 往终端写：思考暗色、回复照常；重试的状态；每次请求的用量；这一轮怎么结束的 |
| `crates/miyu-try/tests/` | 本机的假 DeepSeek：连说两轮，第二次请求的字节是第一次的前缀延伸；故意掐断一次，第三次请求带着半截和被打断的那一句 |
| `docs/designs/01-架构.md` 第九节 | 工具 crate 多一个 `miyu-try` |
| 施工图 | 3-5（补）那一张 |

### 不做什么

- 人格、预设、真的系统提示词：3-6 策略快照。
- 工具、权限的确认、提问：M4。只读开关也不接，工具一件都没有。
- 核心进程、会话 actor、协议端点、`miyu ask`：3-7 到 3-9。试玩台是它们的前身，`miyu ask` 能用了以后再定它留不留。
- key 怎么存：M8。这里只是一个仓库外、只有本人能读的文件。

### 我定的

- **是工具 crate，不是哪一层**：它把内核、组装、驱动、HTTP、存储一股脑接在一个进程里，正好是以后核心和头分开做的事，放进哪一层都不对；谁也不依赖它，以后删掉不牵连别的。
- **数据写到哪**：设了 `MIYU_HOME` 的照它；没设的，每次开一个新的临时目录，开头打印路径，日志留着可以翻。不落到家目录的 `.miyu`：那里现在是旧版在用的数据。
- **会话日志照真的写**：3-1、3-2 的数据根和会话日志，一批一次写入、一次同步，同步了才回「落盘了」。会话的属主是 `local`，场所是 `local`。
- **key 文件**：默认 `~/.config/miyu-try/deepseek.env`，`--env <文件>` 可以换。key 不打印，不进命令行参数，打印出来的地址后面不带它。旧版的配置由一次性的脚本抽出 DeepSeek 那一项写进去，不在仓库里，新版的代码不读旧版。
- **驱动的开关照 DeepSeek**：每条 assistant 都带回 `reasoning_content`，要最后一块的用量。输出上限不设，用供应商的默认。
- **时区**：取系统的，用 `jiff`（纯 Rust，三个平台都认系统时区）。会话编号用 `getrandom` 生成，锁文件里本来就有。
- **故意掐断**：输入 `/cut`，下一次请求在思考里掐断；`/cut text`，在回复里掐断。执行器照「读到一半断了」报可以重试的错，内核自己再来。只为实测接着说，别的场合不用。
- **用量那一行**：命中、没命中、输出；第二次起再写「上一次发过的，这次重算了多少」（`08-上下文投影.md` 第七节：看绝对值，不看百分比）。

### 验收

1. `step/3-5c-try` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：假 DeepSeek 上连说两轮，回复照流出来的写，日志里两轮的事件齐全；第二次请求的字节是第一次的前缀延伸；故意掐断一次，内核再来，第三次请求的最后是半截回复加被打断的那一句。
3. 真的 DeepSeek（实测，结果照实写进这里）：
   - 连说两轮，第二轮的命中、重算各是多少；
   - 说到一半断了（在思考里断、在回复里断，各试几次），她是接着说，还是从头说。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --workspace --exclude miyu-http --exclude miyu-try --target` 查 Windows、macOS（试玩台连着 HTTP，带着 ring 的 C 代码，由 CI 在真机上查）。
5. 能试玩了，停下来叫项目主人：怎么起、怎么说、看到什么算对。

### 风险

- **DeepSeek 把之前的思考丢掉**：施工前量过，半截回复后面跟的被打断的提示是一条 user 消息，DeepSeek 照它的规矩把这之前的 `reasoning_content` 丢掉（带不带半截思考，输入都是 85 个 token）；换成它的前缀续写（beta）带上半截思考，接得上（输入 475，从截断处接着想）。「在思考的时候断了，重新请求的时候带上之前的思考内容」在 DeepSeek 上只有前缀续写这一条路，而前缀续写后面加不了给模型的提示。怎么办要项目主人拍板，试玩台照现在的做法搭，叫他试的时候一起问。
- **缓存命中不稳**：施工前的小请求里，550 个 token 的前缀第二轮命中 384，第三轮还是 384。DeepSeek 的缓存按块、建得慢，两轮之间隔多久会影响数字。量的时候记下间隔。
- **key 泄漏**：只从文件读，`Endpoint` 打印出来是 `***`，测试里不用真 key。
