## 施工单 D-3：待办 `todowrite`

状态：待验收（2026-10-07 写、施工完；项目主人同一天定：每次整份换清单，照 Claude Code、codex、opencode 的基本款；只在工具结果里给她看、压缩后原样带上、不每轮提醒；工具名 `todowrite`；技术细节主会话定）。

### 定了的（技术细节，主会话定）

1. **参数**：`todos`（必填），每项 `content`（一句话）、`status`（`pending`、`in_progress`、`completed`）。整份换，没有编号。不要 Claude Code 的 `activeForm`：头照 `content` 显示就够，多一格每次都多写一遍（「给模型的字克制」）。不强制只有一项在做：说明里点一句，内核不拦。
2. **结果**：一句短话，不把清单原样回给她（opencode 那样会多一份 token）。全部做完的：清单清空（照 Claude Code），结果说清空了。
3. **效果** `todo.written`：`{"todos": [{"content": …, "status": …}]}`，清空的是空列表。随 `tool.result` 落盘，不发给模型。
4. **当前清单**：有效历史里最近一次 `todo.written`；撤销一轮，那一轮写的跟着作废，退回更早的一份。内核另记一份（每追加一条记一次、载入时照整份日志重算，和 D-1 的放行规则一样），压缩不丢；撤销、恢复照有效历史重算。
5. **交给头**：`subscribe` 的回应带 `todos`（当前清单，没有的不写）；变了（写了、撤销、恢复）推一条瞬时的 `todos.changed`（`{"todos": […]}`）。头只认这两样，不自己翻效果。
6. **压缩以后**：当前清单不空的，检查点里代码写的几段多一段，原样列出（`09-压缩.md` 第四节「计划、待办清单原样带上」）。
7. **谁有**：本机的会话，主会话、子会话各管各的；场所会话（群）没有。访问类别 `read`：只改这个会话自己的清单，只读开着也能写。

### 不做什么

- Claude Code 新的 Task 一族（编号、负责人、依赖）：多个代理分工时再加。
- 每轮提醒她看清单：不注入。

### 验收

1. 测试先写，退回改之前要红：
   - 工具：参数不对的、状态不认识的报参数不对；结果那句逐字节比；效果带着整份；全部做完的效果是空列表。
   - 内核：当前清单照最近一次；撤销那一轮退回更早的，恢复回来；载入以后照日志算回来；压缩以后还在；变了才推 `todos.changed`。
   - 协议：`subscribe` 的回应带 `todos`；真核心上她写了清单，头收到 `todos.changed`。
   - 压缩：检查点多一段待办，清单空的不写。
   - 工具面：本机有，群没有。
2. 手写变异 12 个左右，全被逮住；`cargo xtask check` 八项全过；三台机器的 CI 和长跑全绿。
3. 给模型的字：开发端点实测 `todowrite.json`、结果、检查点那一段的 token，登记；工具说明的预算照实测改。
4. 真模型：开发端点上让她做一件多步的活，看她用不用 `todowrite`、清单写得像不像样、做完有没有清空；合进 main 以后告诉两个头：`subscribe` 的 `todos`、`todos.changed`、`todowrite` 的显示名。

### 风险

- 撤销、恢复、压缩和载入四条路算出来的要一样：各测一遍，和照日志从头算的比。
- 工具面又多一件：新会话的前缀变；开着的会话照快照不变。
