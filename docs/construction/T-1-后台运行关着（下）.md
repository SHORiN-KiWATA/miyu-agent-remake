## 施工单 T-1（下）：后台运行关着，子代理前台跑

状态：2026-10-09 合了（54375617，CI run 1468；方向是设计 `30-插件框架.md` 第三节第 7 条，项目主人 2026-10-09 定；技术细节主会话定）。

### 目的

后台运行关着的会话（快照的 `foreground`，T-1 上）派子代理：派出去一直等它交报告再往下走，报告就是这一步的结果；打断连它一起停。开着的照旧在后台跑。

### 这一步做什么

1. **谁算前台的**：内核照策略（快照的 `foreground` 交进策略）记。`subagent` 那次调用的结果里的效果 `job.started` 多一格 `foreground`（真的才写，以前的日志没有这一格照后台）：内核记结果时照这时的策略填上，一份任务开始时定、之后换预设也不变。
2. **这一步等它**：一步里派出去的前台子代理都报回来（`child.reported`）这一步才算齐，再请求下一次；报告照回报的写法排在这一步的工具结果后面（`request.md`「回报」），她下一次请求就看到。等的时候不另开轮、不另叫醒：前台的回报一律不叫醒（排着的回报队不收它）。等不设时限，人要停就打断。
3. **打断**：在等前台子代理的，照「打断」收尾，同时停掉它们（`StopJobs`，`by` 是打断的人，`cause` 是打断的命令）；它们随后交来的回报（`stopped`）只记下、不叫醒，下一轮她看得到。
4. **重启、崩了**：等着的那一步照原来的规矩收尾（重启接着干、崩了等人开口）；子会话照会话的规矩接着干、回报，到时只记下、不叫醒，接着干的那一轮或者下一轮她看得到。接着干的那一轮不重新等它（「还没有的」）。
5. **说明换一份**：`subagent` 的说明在前台的会话里换成前台的写法（`resources/software/basesystem/agent/foreground.txt`，`Tool::foreground_description`：派出去等它，报告在下一步之前送到），登记、量 token（59，后台那一句 57）。派出去那一句（`Started subagent {job}: "{title}".`）不变。
6. 子会话照父会话的预设（`agents.md` 第一条），也是前台的：它派的孙代理一样前台跑。

### 不在这一步

- 接着干的那一轮重新等没报回来的前台子代理。
- 内核的随机测试里的会话都开着后台运行：前台的走法只由 `scenario/foreground.rs` 守着，随机测试加前台的会话随以后。
