## 施工单 F-5（上）：装卸命令、核心手里的清单当场换

状态：施工中（2026-10-09 写；方向是设计 `30-插件框架.md` 第九节，项目主人同一天定；技术细节主会话定。主会话把 F-5 拆成上、中、下：上是装卸的命令、落盘、核心手里的清单当场换；中是工具、查询、扩展当场换，旧会话报已卸载；下是配置项当场换）。

### 目的

能装、能卸，不重启核心：装卸以后 `package.list`、预设的功能当场照新的；开着的会话下一个回合照新的功能换工具面（F-3 上那条路）。

### 这一步做什么

1. `package.install {"path"}`：从本机的一份清单装进管理员家目录那一层。
   - `path` 是 `<编号>.toml`；旁边有同名目录的（包自己的文件）一起拷。
   - 先照规矩读一遍，读不成的不装，报 `package_invalid`，`data.problem` 写哪一行错在哪。
   - 编号和出厂的撞了的不装，报 `package_exists`。
   - 家目录那一层已经有的换成新的（升级）。
   - 拷进去以后照两层重读一遍：这一份撞了别的包（子命令名、功能编号、系统账号）或者是内置包、核心没编进来的，撤回、报 `package_invalid`。
2. `package.install {"package"}`：把卸掉的出厂的包装回来，删掉家目录里记的那一笔。
3. `package.remove {"package"}`：
   - 家目录那一层的：删掉清单和同名目录。
   - 出厂的：在家目录记一笔 `<编号>.removed`，资源目录不动。
   - 必需的（基础系统）：报 `package_required`。
   - 没装的：报 `unknown_package`。
4. 核心手里的清单当场换：装、卸以后照两层重读、标没编进来的、认配置项撞没撞，换掉核心手里的那一份。`package.list`、预设的功能、新开的会话、开着的会话下一个回合都照新的。
5. 卸掉的出厂的包照记的那一笔不算装了，`package.list` 照样列它，带 `removed: true`，好让头给人装回来。
6. 三个方法只给本机的人用：扩展进程调了回 `local_only`。

### 不在这一步

- 新装的、卸掉的包的工具、查询、扩展进程、系统账号当场换，旧会话调到卸掉的工具报「已卸载」：F-5 中。
- 包的配置项当场换：F-5 下。
- 命令行 `miyu package …`：F-5 中、下以后另做一小步。
