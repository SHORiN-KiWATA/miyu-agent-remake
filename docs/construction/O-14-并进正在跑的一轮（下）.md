## 施工单 O-14（下）：并进正在跑的一轮

状态：已完成（2026-10-09 合进 main，`afc6d47a`，CI run 1318；第一次 CI 长跑红在随机测试的看守，补了再跑；2026-10-09 写；照 `docs/blueprint/chat.md` 第七条第 3 条第 1 项「会话正在跑一轮的，`to` 在下一步的边界并进去，和回合中途来的回报排队同一个办法」，形状 2026-10-09 和通讯平台的会话对过；技术细节主会话定）。

### 目的

桥判过要回的几条，她正在说话时也要听到，不能拒了让桥自己排队。O-14（上）里正在跑一轮的 `session.respond` 回 `turn_running`；这一步改成并进这一轮：下一步的边界她就看到那几条和桥的事实。

### 这一步做什么

1. **正在跑一轮时的 `Respond`**：照（上）的规矩查（空的、不是旁听的、当过触发的照旧拒，带上是哪几条），合的：
   - 桥的事实照先后记下，带这个回合，`by` 是发命令的一方；
   - 再记一条新事件 `turn.joined {triggers}`（照序号排好去重的那几条，带这个回合，`by` 是内核，`cause` 是这个命令）；
   - 这一步里在等人的调用作废（和回合中途来的人的话一样）；
   - 落了盘回应，附这一批的序号。
2. **排队**：照回合中途来的回报排：下一次请求就有它；这一轮没再请求就结束的，接着开一轮，`trigger` 是那条 `turn.joined`，没有 `triggers`；打断时不退回、不由它接着开。
3. **账本**：`turn.joined` 只在回合里；`triggers` 不空、照序号排好不重、都是旁听的、都没当过触发；记下以后算当过触发。
4. **渲染**：`turn.joined` 那几条在它自己的位置渲染（群会话里一行一条），放法和回合中途来的人的话一样；接着开的那一轮，它们和开始时注入的事实放在一起。以后的群聊近况不收它们。
5. **样本**：`turn.joined.jsonl`（样本会话里阿杰 @ 她开了一轮，桥把小林前面问的那句并进去）。

### 主会话定的技术细节

1. 并进去的那条照回报排队（`Waker::Joined`）：回报的规矩正好是「下一步听到、没听到就接着开、打断不退回也不接着开」，不另造一套队。
2. `turn.joined` 带回合编号：桥照它认出那几条进了哪一轮（Pending）；接着开的那一轮由它触发，渲染时和开始的事实一组。
3. 桥的事实记在 `turn.joined` 前面：渲染照日志的先后，事实在那几条前面。
