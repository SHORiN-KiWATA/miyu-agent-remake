## 施工单 O-13（中）：群里的一行和格式说明

状态：施工完，待合（2026-10-09 写；格式照 `18-通讯平台.md` 第九节（2026-10-07 定）和旧版的细节（`26-提示词.md` 登记簿「群聊近况的格式、缺口提示：照搬」），和通讯平台的会话 2026-10-09 对过；O-13 由主会话拆成上、中、下，技术细节主会话定）。

### 目的

群里谁都能说话。她看到的群里的话要带上是谁、什么时候、哪一条（引用、撤回都要用平台的编号），格式还要在 system 里说一次。这一步让群会话造的时候 system 多一段格式说明，群里的人说的、开了一轮的那几句渲染成一行一条；旁听的群聊近况那一块是 O-13（下）。

### 这一步做什么

1. **群会话**：`venue.session` 的 `kind` 是 `group` 的，造的时候记进策略快照（`group`），换人格、换预设重拼快照时照留。私聊的不算：一对一的，照现在原样渲染。
2. **格式说明**：群会话的 system 多一块场所说明（26 第四节第 2 块，和子会话的那块同一个位置），原文 `core/venues/group.txt`，只说一行长什么样、编号稳定名字会变、`[you]` 是她自己。只在造的时候拼进去，会话里不变。
3. **时区钉在会话上**：群会话造的时候把这台机器的时区记进快照，一行的 `[HH:MM]` 照它算；换了时区的机器上载入也照记下的，前缀不变。
4. **一行**：群会话里，带 `venue`、不旁听的 `message.user`（开这一轮、排进这一轮的）渲染成一行一条，替掉原来的正文：
   - `[HH:MM] <名字> (id=<平台身份>, <身份>) [msg=<编号>]: <内容>`。`<名字>` 照 `venue.name`，没有的写平台身份；`id=…` 只在这条的 `venue.show_ids` 是真、又有名字时写；`<身份>` 照 `as` 认出的：对应表里的主人写 `owner`，桥报的 `manager` 写 `manager`，`member` 不写（群里多数是它，写了只占地方）；括号里什么都没有的不写括号。
   - 内容：正文去掉前后空白、截到 4096 字节；带的东西接在后面、空一格隔开：`[image]`、`[file: <名字>]`、`[sticker: <字>]`、`[voice]`、`[video]`，有名字的写 `[<种类>: <名字>]`；正文、带的东西都没有的写 `[no text content]`。图片块本身照旧接在这一行后面交给驱动。
   - 缩进的几行（可选，照有没有）：`  reply-to: msg=<编号>`、`  @mentions: …`，逗号隔开：`mentions_all` 写 `@all` 排最前，`mentions_me` 写 `[you]`，`show_ids` 是真的再列 @ 了的人的平台身份。看不到身份的，@ 了谁的名字桥已经写在正文里（`@名字`），不另写；三样都没有的不写这一行。
   - 不可信的字段（名字、正文、编号、带的东西的名字、@ 了的人的身份）照 08 第五节的模板转义成一行（`template::escape`，和旧版 `safe_prompt_field` 一个意思：照 JSON 字符串编码，`"`、`&`、`<`、`>` 写成 `\u` 的样子），伪造不出另一条记录。可信的（时刻、`owner`/`manager`、`@all`、`[you]`）照原样。
   - 回顾、起标题的请求读人这边的话也是这一行（`render.rs` 的 `spoken`，主请求和回顾共用）。
5. **`show_ids` 在每条消息上**：`session.send` 的 `venue` 多一格可选的布尔 `show_ids`（默认假），桥每条照这时的场所规则带上；每一行照它自己那条渲染，规则改了从下一条起照新的，已经进了上下文的不追着改。

### 主会话定的技术细节

1. `show_ids` 放每条消息上，不放 `venue.session`：渲染要是日志的纯函数，放在会话上就得另造一条「换了」的事件、内核记着现在是哪个、找回时比对；放在消息上零额外机制。格式说明写成两种情况都对的一句，不随它换快照（2026-10-09 和通讯平台的会话对过）。
2. 一行的骨架照 18 第九节（平台无关，不写 `QQ:`），细节照旧版：媒体的写法、4096 字节、`[no text content]`、缩进的引用和 @ 行、转义。媒体种类照我们的名字（`voice`，不写旧版的 `audio`）。
3. 一行在组装那一层拼（`miyu-assemble` 的 `group.rs`），句子里的字（`[no text content]`）是资源、登记；方括号、冒号、缩进这些格式是代码，和待办那几行（施工 D-3）一样。
4. 快照多一格 `group {offset, no_text}`：时区记成分钟数，空的那一句原文照抄；换人格、换预设重拼时照旧快照的时区、重读这两份字（和别的核心的字一样：改过字的老会话不换快照）。时区超出 ±14:00 的快照造不出策略（`BuildError::Offset`）。
5. 格式说明第一稿 94 个 token（带外壳标签，另说了 `id=` 什么时候有、身份只写哪两种），删到 50：她看得到的就是那几样，不用另说什么时候没有。

### 不做什么

- 旁听的群聊近况那一块、撤回的标记、`[you]` 行、预算和缺口提示：O-13（下）。
- 私聊的一行格式：一对一的不用（主人的私聊、陌生人的私聊照原样）。

### 验收

1. 测试先写，改之前红：群会话的 system 带格式说明、私聊的不带、换人格以后照带；时区钉在快照里；群里的人说的一行照格式（名字、身份、`id=` 跟着 `show_ids`、主人写 `owner`、编号、带的东西、引用、@、@all、转义、截断、空的写 `[no text content]`）；私聊的照原样。
2. 登记簿：`core/venues/group.txt`、`core/venues/no-text.txt` 照开发端点量 token、写指纹。
3. 手写变异；`cargo xtask check` 八项；三台 CI 和长跑。
