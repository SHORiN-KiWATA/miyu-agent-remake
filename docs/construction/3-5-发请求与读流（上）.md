## 施工单 3-5：发请求与读流（上）

状态：施工中。

### 目的

请求真的发得出去、读得回来：HTTP 执行器照驱动编码好的字节发请求，流式地读回来，边读边交给解码器，解出来的增量马上交出去；多久没收到新的字节就算断了；内核叫停就马上停。每次只发一回，重试和接着说是下一半。测试用本机的假服务器，不花钱、不联网。

### 不做什么

- 重试、退避、接着说、`status` 提示：3-5（下）。
- 选哪个端点、哪个 key，冷却，并发上限：资源调度器，以后。
- 等第一个字时给头发心跳：会话 actor（3-7）。
- 连接预热：第一版可选（15 M5）。
- 按思考强度放大空闲超时：做思考强度时。

### 我定的

- **新 crate `miyu-http`，用 tokio 加 reqwest**：核心本来就是异步的（会话 actor、本机套接字），流式读取、超时、打断在异步里最顺。旧版也是 reqwest，本机的缓存里就有。
- **TLS 用 rustls，证书认两份**：系统里装的（公司网络装了自己的根证书也能用）和 webpki 自带的（精简的系统没有证书库也能用）。不用 OpenSSL：三个平台一样，不依赖系统里装了什么。
- **发之前先报「发出去了」**：带上请求字节的哈希。连不上的也报过了：请求试着发过，`model.called` 里记下发给了谁、发的是什么，查问题用得上。
- **读的时候用 `chunk()` 一片一片地取**，每一片都套上空闲超时；解码器说不用再读了就停。
- **读到一半断了，交给解码器收尾**：它知道见没见到 `finish_reason`、`[DONE]`。说完了才断的算说完了；没说完的，解码器说「流断了」，可重试。
- **不是 2xx 的，读最多 64 KiB 的响应体再分类**：出错页可能很大，分类用不着那么多，原话本来也只留 2000 字节。
- **打断用一个 future**：它一完成，执行器马上停、丢掉连接，交回「打断了」，不再报任何东西。
- **端点里的 key 打印出来写成 `***`**：`Debug` 自己写，测试查打印出来的字里没有 key。
- **测试的假服务器自己写**：几十行的 HTTP/1.1，照剧本回；响应体用关连接来结束，一片一片地写，中间可以停住、可以直接断开。测试的客户端不走代理。

### 验收

1. `step/3-5a-http` 分支的 CI：三台机器全绿，长跑也绿。
2. `cargo test`：
   - 一份流的样本分几片回来：先报「发出去了」，带着请求字节的哈希；增量和直接解这份样本的一样；说完了，有用量。
   - 假服务器收到的请求：`POST`，路径是地址加 `/chat/completions`，四个头都对，另配的头也在，请求体和编码好的一字不差。
   - 429 带着 `retry-after`：分成限速，要等多久对得上，一段增量都没有。
   - 回了一片就停住：空闲超时到了，可重试，原话写着多久没收到；停住之前的增量照样交出来了。
   - 停住的时候打断：马上交回「打断了」，假服务器看到连接断了。
   - 连不上（端口上没人）：可重试。
   - 说到一半断开：可重试。
   - 端点打印出来没有 key。
3. 故意改坏几处，测试变红（施工完照实补上清单和处数）。
4. `cargo xtask check` 七项全过；推之前本机用 `cargo clippy --target` 查 Windows、macOS。

### 风险

- **编译变慢**：tokio、reqwest、rustls 加起来一百多个 crate。只有 `miyu-http` 和用它的 crate 编它们，纯逻辑的几层不受影响。
- **CI 上的 Windows、macOS 本机回环**：假服务器只听 `127.0.0.1`，三个平台都支持；端口用 0，由系统挑。
- **代理的环境变量**：开发机上设了 `HTTPS_PROXY` 的，测试的客户端也不能走它，测试里显式关掉代理。
