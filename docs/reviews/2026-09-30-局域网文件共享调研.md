## 调研：局域网文件共享用什么形式做（2026-09-30）

项目主人问（2026-09-30）：局域网文件共享服务器（旧版就有的功能：把本机的文件经网页递给局域网里的人）在新版用什么形式做。去看了仓库的设计、网页演示、旧版的实现，以及 dsh 的源码和论文。这份是调研记录，只记，不改设计的决定。打算等用户系统做完再做（2026-09-30 项目主人提），到时从第五节的三道题拍板起，再写进设计。

依据：设计 `00`、`01`、`04` 第四节和 P5、P6、`05`、`06`、`07` 第五节、`10`、`12`、`21`、`24`；网页演示（分支 `proto/web-demo`）的蓝图 `web.md`、`web/architecture.md` 和桥；旧版 `crates/miyu-engine/src/tools/share_file.rs`、`crates/miyu-hosts/src/web/shared_files.rs`；dsh 的源码和文档（路径写成 `dsh/…`）；论文 *A Programming Paradigm for Spatiotemporal Composability*（arXiv 2608.25512），读了摘要、引言、6.1 到 6.4 和结论。

### 一、旧版怎么做

- 一件工具 `share_file`，只登记在网页会话里；配置里有总开关。能列出、删除已有的分享。
- 分享进一张全局的表，能打开网页的人（包括局域网里的）凭网页的登录态就能下载。
- 两种模式：引用（默认，零复制，每次下载前核对大小和修改时间，对不上回 410）；快照（复制进托管区，长期有效）。
- 下载按 Range 流式发，大视频不进内存也不进库；只有图片、音频、视频能在页面里直接看，别的一律当附件下载，防止 HTML、SVG 在网页的域下跑起来。

### 二、dsh 怎么做

1. **HTTP 服务器是一个哑载体**（`dsh/docs/subsystems/web-server.md`、`dsh/packages/host/webserver`）：只提供一张具名路由表、一个兜底席位（前端静态文件占着）、改 `index.html` 的钩子；自己不认识任何 harness 的概念，`/api`、插件的包、热重载的事件流都是别的插件注册上去的。注册是可撤回的副作用，同一个路径注册两次当场报错。
2. **信任集中在一处**（`dsh/packages/client/connection/README.zh.md` 的「/api 浏览器信任栅栏」）：每个请求的 Host 要是回环地址或声明过的名字，防 DNS 重绑；Origin 要和 Host 一致。它明说这是可达性策略，不是认证；特权方法钉死在回环上；`dsh web --host 0.0.0.0` 在有认证层之前有意不支持。
3. **附件是内容寻址的**（`dsh/docs/subsystems/attachment.zh.md`）：引用是不透明的编号，不是路径，也不是拿着就能下载的地址；先落盘，再写引用它的事件；每次读都核对摘要。
4. **能力接缝**（`dsh/docs/architecture.zh.md`）：一项能力分声明接口、实现接口、使用接口（给模型的工具）三个角色，换实现工具面不变。

### 三、论文里用得上的

- **撤回的边界（6.1）**：系统独占、能恢复的位置才撤得回。拿到访问（打开连接、登记一条路由）撤得回；把数据推出去（别人下载走的字节）撤不回，只能补偿。
- **服务代理（6.2）**：几个提供者经一个代理，换后端时使用方看不到；跨进程也照这个办法，接口要按异步设计。
- **依赖声明就是能力申请（6.3）**：加载前就知道一个组件要哪些能力，可以在加载时审批；不可信的代码另要进程级的沙盒，经一座桥用宿主的服务。

### 四、对照 Miyu：用什么形式

**推荐：核心的 HTTP 模块当路由载体，文件共享做成一个编进核心的可选软件包，挂在它上面。**

1. **HTTP 模块**（`04-核心协议.md` P5、`21-网页.md` X5 的那一个）只当载体：监听地址（默认只听本机，开局域网手动开，P6）、登录令牌、Origin 和 Host 的检查、失败限流、Range 流式。它对外给一张路由表，作为 `05-内核接口.md` 第一节的一种贡献登记，撤回时路由跟着没；没有启用的模块要它时不构造。网页演示的桥现在顶着的 `/file`、`/blob`、`/upload`，本来就定好了以后交给这个模块（`docs/construction/README.md` 第二节）。
2. **软件包 `share`**，`kind = "builtin"`，和「产物」同一类可选软件包（`10-自带软件.md` 第四节）。按一份清单加一次注册登记：
   - 工具 `share_file`：访问类别 `outbound`（对外发消息）；内核和头要看懂它的结果（分享列表、撤销），照 `10-自带软件.md` B2 做成结构化工具。
   - 斜杠命令 `/share`；事件种类 `share.created`、`share.revoked`：分享是模块的事实，记成事件（`07-存储.md` S1），记在哪本日志做的时候定。
   - 一条路由，例如 `/s/<编号>`。
   - 网页上的分享列表：网页演示里是 `packages/share/`，挂进挂载位；装一次核心、网页两边都有（`web/architecture.md`「发行版」）。
3. **和用户系统的关系**：
   - 分享记录是有属主的资源，照第三节的属主和权限、U12 分享给组或指定的人。
   - 路径先过权限链（`11-权限与沙盒.md` 第七节）。数据根一律不许分享：里面有本机令牌。成员只能分享自己边界里的文件。
   - 开了局域网分享，核心就得常驻（`12-进程形态与分发.md` R1 的「远程访问」）；空闲退出了，链接就断了。
4. **撤销**：拿掉这个包，路由和监听都撤得回；撤销一个分享只能拦住以后的下载，已经下载走的收不回（论文 6.1），界面要写明。撤销创建分享的那一轮，就撤销这个分享（补偿）。
5. **快照放进 blob**（`07-存储.md` 第五节）：内容寻址，自然去重；引用它的事件在，它就不被回收。

**不适合的**：

- 做成外部扩展，自己开端口：等于第二套登录，`24-威胁模型.md` 和 `21-网页.md` X7 都在防这个；`05-内核接口.md` 第三节的能力表里也没有「监听端口」。dsh 的教训是认证只能在载体上集中做一份。
- 做成脚本或 MCP：它们只提供工具，一次调用跑完就退，撑不住一直在的下载地址。
- 现在就做：还没有账号和登录，局域网这一面照 P6 开不了；只能先写一个「只有管理员」的临时版，以后要拆（`AGENTS.md`「不为以后写代码」）。

### 五、做的时候要拍板的（附推荐）

1. **谁能下载**：推荐只有登录的账号能下（U12、P6：安全默认值不因方便而放宽）；另一种是单条分享另开「拿着链接就能下」、带过期时间、默认关，它本质上是一把钥匙，dsh 的附件明确不做这种地址。
2. **路由表第一版对外部扩展开不开**：推荐第一版只给内置模块，外部扩展以后经进程扩展适配器转发（论文 6.2、6.3 的桥），在决定里写明，不算开后门。
3. **引用还是快照**：推荐默认引用，零复制，每次下载前核对大小和修改时间，对不上回 410，照旧版；快照放进 blob。
