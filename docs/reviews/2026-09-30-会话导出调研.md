## 调研：会话导出，各家怎么做（2026-09-30）

项目主人说（2026-09-30），导出「应该是用于保存会话内容，或者发给别的 agent，甚至网页版 chat AI 的」。已定先不做导入，导出随 M8 做。要拍板的是导出给谁用、什么样子。这份是调研记录，只记，不改设计的决定。

依据见下表。源码路径相对各仓库的根，前面加仓库简称。

| `opencode/` | opencode dev 分支 | `696f41bc8e`（2026-09-25） |
| `opencode-v2/` | opencode v2.0.8，布局不同 | `7673ed6`（tag v2.0.8） |

另外看了本机 Claude Code 会话日志一个样本的字段结构（只看字段名和种类的计数，不看内容）。Gemini CLI、aider、ChatGPT、Claude.ai 网页版是上网查的，出处列在最后。

### 一、先看全貌

| 家 | 入口 | 出来什么 | 给谁 | 能导回来吗 |
|---|---|---|---|---|
| dsh | 网页的 `/export`、会话头上的按钮 | ZIP：日志原文、子代理、图片 | 存档、查问题 | 不能 |
| opencode | `opencode export`、网页「导出会话」 | JSON：会话和全部消息 | 存档、搬家 | 能，`opencode import`，同一个格式 |
| opencode | 终端 `/export`、`/copy` | Markdown，存文件后开编辑器，或进剪贴板 | 人读、贴给别处 | 不能 |
| opencode | `/share` | 公开链接，一直同步 | 给人看 | 能从链接导回 |
| codex | 终端 `/export`、`/copy` | Markdown，剪贴板或存文件 | 人读、贴给别处 | 不能，续聊靠自己的 rollout 日志 |
| pi | `/export`、`pi --export` | 单个 HTML 页，或 JSONL | 人读、存档 | JSONL 能，`/import` |
| pi | `/share` | 组织内的链接，或私密 gist 加查看页 | 给人看 | 链接里是 JSONL |
| Claude Code | `/export`、`/copy` | 纯文本（照终端的样子），剪贴板或存文件 | 人读、贴给别处 | 不能，续聊靠会话日志 |
| Gemini CLI | `/chat share` | Markdown 或 JSON | 人读、分享 | 不能，续聊只认 `/chat save` 存的检查点 |
| aider | 不用导，一直在写 | 仓库里的 `.aider.chat.history.md` | 人读、续聊 | `--restore-chat-history` 读回来，长了先摘要 |
| ChatGPT、Claude.ai 网页版 | 设置里「导出数据」 | 邮件发链接，ZIP，整个账号的 JSON（ChatGPT 另带一个 `chat.html`） | 带走自己的数据 | 不能 |

### 二、各家细节

#### 1. dsh

- **入口**：只在网页版有。斜杠命令 `/export` 不带参数，带路径就报错（浏览器自己选存到哪）。会话头上有一个「Session log」按钮，和命令共用同一个下载控制器（`dsh/packages/session-query/session-log-export/src/index.ts`、`README.zh.md`）。终端版、命令行没有导出。
- **怎么交字节**：浏览器先发 `HEAD` 预检，再把 `GET /api/session.export?sessionId=<id>&includeDescendants=true` 交给浏览器的下载管理器，页面的 JavaScript 不缓冲 ZIP。宿主边压缩边流式写出，队列到 64 KiB 就等消费方来取，请求中断就停（`dsh/packages/host/apiproxy/src/session-export.ts`，`dsh/packages/host/apiproxy/README.zh.md` 第 31 行）。
- **格式**：ZIP。根会话是 `session.jsonl`，内容是持久化后端的原文（按物理编码解开的字节，不是从解析后的事件重建的）。每个子代理的后代放 `subagents/<id>/`。日志引用到的图片放 `media/<附件编号>.<扩展名>`，同一张图只出现一次。不写清单，每个文件靠自己的头一行或者媒体类型自描述。
- **有什么**：日志里有的都有，包括流式的增量分片（dsh 把 `assistant/chunk` 也落盘，打包成一行存，`dsh/packages/session/session-persistence-jsonl/README.zh.md`）。活着的会话先强制落盘再读，所以连触发导出的那条命令也在包里。
- **没什么**：工具大输出溢出的文件不在包里（它们在单独的 spill 存储，导出代码没碰它，`dsh/packages/spill/README.zh.md`）。后代缺日志、图片读不出来，整个下载失败，不静默少导。
- **敏感内容**：没看到脱敏、提醒。
- **导回来**：没有导入。续聊是 `dsh --profile tui --resume <session>`，从自己的存储里读。
- **交接**：没有专门导出给别的 agent 的。有一组默认不挂的模型工具 `session_search`、`session_event_read` 这些，让模型去查同一工作目录下别的会话（`dsh/packages/session-query/tool-session-query/README.zh.md`），是「让下一个 agent 自己去翻」的思路。
- **导出不进模型的历史**：`/export` 只在人的命令这一层，不开模型轮次，不动前缀（`README.zh.md`「模型体验」）。

#### 2. opencode

- **命令行 JSON**：`opencode export [sessionID] [--sanitize]`，不写编号就列出来挑，输出到标准输出（`opencode/packages/opencode/src/cli/cmd/export.ts`）。形状是 `{info, messages: [{info, parts}]}`。网页的「导出会话」下载同一个形状，文件名是标题的 slug 加 `.json`（`opencode/packages/app/src/utils/session-export.ts`、`opencode/packages/app/src/components/session/session-context-tab.tsx`）。v2.0.8 改成 `opencode session export [session]`，经服务端的 `SessionTransfer` 做，只导已经结束的消息，非交互时必须写编号（`opencode-v2/packages/cli/src/commands/handlers/session/export.ts`、`opencode-v2/packages/core/src/session/transfer.ts`）。
  - 有什么：全部消息和它们的片段，工具的输入、输出全文，思考，补丁、快照的引用。图片和二进制附件在片段里是 `data:<媒体类型>;base64,…` 内联（`opencode/packages/opencode/src/session/prompt.ts` 第 963 行一带）。
  - 没什么：子代理是别的会话，只留一个 subtask 片段，不跟着导出。系统提示词不在里面。
  - `--sanitize` 不是扫密钥，是把正文、思考、工具输出、路径、文件名、标题全换成 `[redacted:<类别>:<编号>]` 这种占位，只留结构，给报 bug 用。
  - 导回来：`opencode import <文件或分享链接>`，同一个格式（`opencode/packages/opencode/src/cli/cmd/import.ts`）。v2.0.8 的导入遇到同编号的会话拒绝，有父会话的要求父会话已经在（`transfer.ts`）。
- **终端 Markdown**：`/export`（快捷键 `<leader>x`）弹一个选项框：文件名（默认 `session-<编号前 8 位>.md`）、带不带思考、带不带工具详情、带不带助手的元数据、只开编辑器不存。存到当前目录以后用 `$EDITOR` 打开，改了照改的存。`/copy` 照当前界面的显示开关把同样的 Markdown 放进剪贴板（`opencode/packages/tui/src/routes/session/index.tsx` 第 917–1010 行，`opencode/packages/tui/src/ui/dialog-export-options.tsx`）。
  - 写法：开头是标题、会话编号、创建和更新时间，然后一条消息一节，`## User`、`## Assistant (代理 · 模型 · 用时)`（`opencode/packages/tui/src/util/transcript.ts`）。
  - 工具：`**Tool: 名字**`，开了详情才带输入的 JSON 和输出、报错的全文，不截断。
  - 丢掉的：合成的文字（程序替她写的「接着做」这类）、图片和文件、子代理、压缩标记、补丁。压缩的摘要是一条 `summary: true` 的助手消息，会当成一节 `## Assistant` 出现。
  - 撤销：导出用的是全部消息，不是「撤销点之前的」，所以撤了还没被清掉的那几条也会带进去（同一个文件里另有 `messagesBeforeRevert`，导出没用它）。
- **分享**：`/share` 把会话同步到 opncd.ai（企业版是自己的地址），给一个公开链接，之后一直跟着同步会话、消息、片段、差异、模型。第一次分享弹一次确认「Are you sure you want to share it?」，之后不再问。`/unshare` 撤掉。配置 `share` 有 `manual`、`auto`、`disabled`（`opencode/packages/opencode/src/share/share-next.ts`，`index.tsx` 第 467–500 行）。没有脱敏。
- **交接**：没有。

#### 3. codex

- **入口**：终端 `/export`。不带参数弹一个框，「Copy to clipboard」或「Save to file」，存文件默认叫 `codex-session-<线程编号>.md`。带参数的直接存到那个路径（`codex/codex-rs/tui/src/chatwidget/transcript_export.rs`、`codex/codex-rs/tui/src/chatwidget/slash_dispatch.rs` 第 766 行）。相对路径接当前目录，`~` 展开，文件已经有了就拒绝，不覆盖（`persist_noclobber`，`codex/codex-rs/tui/src/app/transcript_export.rs`）。命令行没有 `codex export`。
- **格式**：Markdown。开头 `# Codex conversation`，然后 `## User`、`## Assistant`、`## Plan`、`## Reasoning`、`## Activity`。活动那一类整段缩进四格，当代码块（快照见 `codex/codex-rs/tui/src/app/snapshots/codex_tui__app__transcript_export__tests__markdown_transcript.snap`）。
- **有什么**
  - 历史从服务端完整读一遍，不是只导屏幕上还留着的。临时线程才退回屏幕上的。
  - 命令：`$ 命令`，输出照详细视图的全文（存储层截过的，带省略标记），退出码、用时（`codex/codex-rs/tui/src/exec_cell/transcript.rs`）。
  - 改文件：每个文件的路径和整份 diff。MCP 调用：参数和结果的文字，图片写成「Returned image」。网页搜索、看图写一行。
  - 思考：只有摘要，配置里开了显示原始思考才带原文。
- **没什么**
  - 人发的图写成 `[Image #1]` 这样的标签。
  - 人的话里 IDE 塞进去的上下文剥掉，只留人真说的那段。ANSI 控制符剥掉。
  - 代码审查模式里藏起来的提示不导。导出自己的提示行（「Saved conversation to …」）不导。
  - 压缩只剩一行「Context compacted」，摘要本身不在（`codex/codex-rs/tui/src/thread_transcript/other_items.rs`）。
  - 子代理只剩活动行，不带子线程的内容。系统提示词、用量都不在。
- **敏感内容**：没有脱敏。
- **导回来**：Markdown 不能。续聊、分叉靠会话自己的 rollout 日志（JSONL，现在按 zstd 压着存），`codex resume`、`codex fork`。日志一行一个 `RolloutItem`，有会话元数据、模型可见的条目、压缩、回合上下文、用量记录、事件（`codex/codex-rs/history/src/lib.rs` 第 176 行）。
- **`/copy`**：复制最后一次回答，或者挑其中一部分。
- **交接**：没有。

#### 4. pi

- **入口**
  - `/export [路径]`：默认 HTML，文件名 `pi-session-<会话文件名>.html`。路径以 `.jsonl` 结尾就导 JSONL（`pi/packages/coding-agent/src/modes/interactive/interactive-mode.ts` 第 6261 行）。
  - `pi --export <会话.jsonl> [输出.html]`：命令行把任意会话文件转成 HTML，这条路上没有系统提示词和工具定义（`pi/packages/coding-agent/src/cli/args.ts`，`pi/packages/coding-agent/src/core/export-html/index.ts` 的 `exportFromFile`）。
  - `/import <路径.jsonl>`：确认一次「用它替换当前会话？」，替换并接着聊，日志里没有工作目录的会问（`interactive-mode.ts` 第 6308 行）。
  - `/share`：登录了 Radius 就把 JSONL 传成组织内可见的产物，给链接。没登录就用 `gh gist create --public=false` 传 HTML，给一个查看页链接和 gist 链接（`pi/packages/coding-agent/src/modes/interactive/session-share.ts`）。
  - `/copy`：复制最后一条回答。
- **JSONL**：只导当前分支。重写一个头（新的时间戳），每条的 `parentId` 重新串一遍（`pi/packages/coding-agent/src/core/session-export.ts`）。分享用的那份末尾多一条 `pi.share`，带系统提示词和工具的名字、描述、参数（`session-share.ts` 的 `createShareTrailingEntries`）。
- **HTML**：一个文件自带一切，模板、样式、脚本、marked、highlight.js 全内联，会话数据 base64 编码嵌在页面里（`export-html/index.ts` 的 `generateHtml`）。
  - 整棵会话树都在，所有分支，侧边栏能在分支间切，默认停在当前叶子（`pi/packages/coding-agent/src/core/export-html/template.js`）。
  - 系统提示词和工具定义（从终端导的时候）、思考、压缩和分支摘要、换模型都有标记。
  - 图片 `data:` 内联显示。工具输出全文在页面里，默认只露 5 到 20 行，点开看全部。扩展的自定义工具先用终端的渲染器画成 ANSI 再转 HTML。
  - 页面上有「下载 JSONL」按钮，从嵌着的数据还原出 JSONL。
- **敏感内容**：没有脱敏。gist 是私密的（不公开列出，拿到链接就能看）。
- **导回来**：JSONL 能，和导出同一个格式。HTML 里的数据能下载成 JSONL 再导。
- **交接**
  - 自带的 `serializeConversation` 把消息压成给模型读的纯文本：`[User]: …`、`[Assistant thinking]: …`、`[Assistant]: …`、`[Assistant tool calls]: 名字(k=v)`、`[Tool result]: …`，工具结果截到 2000 个字符并注明截掉多少（`pi/packages/coding-agent/src/core/compaction/utils.ts`）。压缩、分支摘要都用它。
  - 示例扩展 `/handoff <目标>`：取最近一次压缩的摘要、保留的尾巴和之后的内容，用一段「上下文交接」的系统提示词让模型写一份自带背景的提示（背景、决定、涉及的文件、下一步任务），放进新会话的输入框当草稿，人改完再发（`pi/packages/coding-agent/examples/extensions/handoff.ts`）。它自己的说法是「压缩是有损的，交接只挑下一件事要的」。
- **子代理**：没有内建的，示例扩展里有。

#### 5. Claude Code（照 openclaude 分叉读）

- **入口**：`/export [文件名]`。不带参数弹框，选「Copy to clipboard」或「Save to file」，默认文件名是时间加第一句话的 slug，`.txt`（`openclaude/src/commands/export/export.tsx`、`openclaude/src/components/ExportDialog.tsx`）。`/copy [N]` 复制倒数第 N 条回答（`openclaude/src/commands/copy/index.ts`）。分叉里 `/share` 是个空壳（`openclaude/src/commands/share/index.js`）。
- **纯文本**：用终端界面同一套渲染把消息画成字符串，去掉颜色（`openclaude/src/utils/exportRenderer.tsx` 的 `renderMessagesToPlainText`）。不是详细模式，所以工具输出照界面上折叠的样子。它和上游应该是同一条路（分叉的 git 历史是浅的，没法逐行对上游）。
- **分叉另加的 Markdown、JSON**（`--format text|markdown|json`，或者看扩展名，`openclaude/src/utils/exportFormats.ts`）
  - 跳过：进度、附件类消息（Claude Code 注入的上下文都是附件类）、`isMeta` 的、压缩摘要、打断和取消的合成标记、思考。
  - 剥掉 `system-reminder` 和一串内部标签（命令参数、任务通知、跨会话消息这些）。
  - 工具调用写输入的 JSON，工具结果写全文，出错的标一句。图片写 `[Image attachment]`。
- **会话存成什么**：数据目录 `projects/<工作目录编码>/<会话>.jsonl`。样本里的种类：`user`、`assistant`、`attachment`（注入的上下文）、`system`（其中有压缩边界，带 `compactMetadata`）、`file-history-snapshot`、`file-history-delta`（给回退用的文件备份）、`ai-title`、`last-prompt`、`queue-operation`、权限模式这类状态行。每条有 `uuid` 和 `parentUuid`，回退以后的旧分支还在文件里。子代理在 `<会话>/subagents/agent-<编号>.jsonl` 加一份 `.meta.json`，工具的大结果在 `<会话>/tool-results/`。内容块有 `text`、`thinking`、`tool_use`、`tool_result`、`image`（图片内联 base64）。
- **敏感内容**：没有脱敏。
- **导回来**：导出的文本不能。续聊靠会话日志，`--resume`、`--continue`、`--fork-session`。
- **交接**：没有专门的。

#### 6. 网上查的几家

- **Gemini CLI**：`/chat save <标签>` 存检查点，`/chat resume <标签>`（和 `/resume` 同一个）读回，只能在同一个项目里读。`/chat share [文件]` 写成 Markdown 或 JSON，不写文件名它自己起。分享出来的文件不能用来续聊。`/copy` 复制最后一次输出，远程会话走 OSC 52。有人提过加 `/export` 的 PR，文档里没有这个命令。
- **aider**：一直往仓库里的 `.aider.chat.history.md` 追加，存储本身就是 Markdown。`--restore-chat-history` 启动时读回来，超了上限就把老的一段段递归摘要、新的原样留。有人报过文件太大时整份送去摘要的问题。
- **ChatGPT**：设置里「数据管理」「导出数据」，邮件发下载链接（24 小时过期），ZIP 里是整个账号的 `conversations.json` 加一个能在浏览器看的 `chat.html`，删掉的对话不在。上传文件的上限：每个文件 512 MB，文字文档每个 200 万 token，图片每张 20 MB。
- **Claude.ai**：设置里「隐私」「导出数据」，邮件发链接（24 小时过期），ZIP 里是 JSON。上传每个文件 30 MB，每个对话 20 个文件，能收 PDF、DOCX、TXT、HTML、JSON 等。
- **「把对话记录传给网页版看」的常见做法**：导成 Markdown 或纯文本当文件传上去，浏览器扩展（导出成 Markdown、JSON、PDF 的）很多。字节很少是瓶颈，瓶颈是上下文：一段长会话动辄几十万 token，超过多数网页版的窗口，大文件可能被检索着读、不整份读进去（这一条没有找到官方说明，是按常见做法推的）。

#### 7. 旧版 Miyu

- `miyu export` 是整台机器的备份：照一张写死的清单把数据目录打成 tar.gz，有 `--no-secrets` 之类的选项（旧版 `crates/miyu-engine/src/transfer/export.rs`）。重制版 `27-从旧版迁过来.md` 第 44 行记过它漏掉的东西。
- 没有「导出一个会话」。网页上只有每条消息的「复制消息」按钮（旧版 `web/app.js` 第 5344 行）。

### 三、看下来的几条

1. **分成两类，各家都分得很清**：一类无损，给程序、给导回来（dsh 的 ZIP、opencode 的 JSON、pi 的 JSONL）。一类给人和模型读（opencode、codex、Claude Code 的 Markdown 或纯文本）。只有 pi 的 HTML 两头都占：页面给人看，里面嵌着能还原成 JSONL 的原始数据。
2. **能导回来的一律是原始格式**。Markdown 没有一家能导回来。aider 例外，它的存储就是 Markdown，读回来还要摘要。
3. **图片**：原始格式里要么内联 base64（opencode、pi、Claude Code 的日志），要么单独放文件（dsh）。文本格式一律变成占位（codex、Claude 分叉）或者直接丢（opencode）。只有 pi 的 HTML 能看到图。
4. **工具输出**：给人读的文本格式里，opencode、codex 给全文，pi 给全文但折起来，Claude Code 纯文本照界面折叠。专门给模型读的（pi 的 `serializeConversation`）截到 2000 字。
5. **思考**默认不带，或者跟着界面开关（opencode、codex）。
6. **系统提示词和注入的上下文**：文本格式都不带，Claude 分叉专门剥掉 `system-reminder`。带系统提示词的只有 pi 的 HTML 和分享。
7. **子代理**：只有 dsh 的原始包带全部后代。文本格式里只剩一行活动，或者直接丢。
8. **撤销**：没有一家专门处理。pi 的 JSONL 只导当前分支、HTML 带全部分支，Claude Code 的旧分支留在日志里，opencode 会把撤了还没清的带进去。
9. **压缩**：codex 只留一行「压缩了」，opencode 把摘要当成一条助手消息，Claude 分叉干脆剥掉摘要，pi 在树里标出来、交接时从摘要起。
10. **脱敏**：没有一家扫密钥。opencode 的 `--sanitize` 是把内容整个换成占位（报 bug 用）。分享类的只有一次确认（opencode）或私密 gist（pi）。
11. **交接给别的 agent**：内建的都没有。pi 有示例扩展 `/handoff`（让模型写一份交接提示），dsh 给模型开了查别的会话的工具。
12. **字节怎么交**：终端里一律是「剪贴板或存文件」两选一，存文件的默认放当前目录（codex 不覆盖已有的）。网页是浏览器下载，dsh 走流式 HTTP 加 `HEAD` 预检，opencode 是页面拿 JSON 自己拼 Blob。
13. **用量和钱**：opencode 的 Markdown 能带模型和用时，没有一家写钱。

### 四、给 Miyu 的分析

#### 1. 三种用途各要什么

| | 存下会话内容 | 发给别的 agent | 贴进网页版 chat AI |
|---|---|---|---|
| 谁读 | 以后的自己、以后的导入、查问题的开发者 | Claude Code、codex、另一个 Miyu，它们有读文件、搜文件的工具 | 网页里的模型，一次读进上下文，人还要在后面问问题 |
| 格式 | 原始包（无损），附一份人能直接看的 | Markdown | Markdown（网页版都收 `.md`、`.txt`，也能直接粘） |
| 范围 | 全部：撤掉的、压缩前的、子会话都在 | 她现在的上下文就够：最近一次压缩的摘要加之后的原文 | 全部，或者最近几轮，看 token 估算 |
| 人和她的话 | 原样 | 全文 | 全文 |
| 思考 | 原样 | 不带：啰嗦，有的供应商只给摘要 | 不带 |
| 工具 | 全文，大输出的全文 blob 也在 | 真名加参数原文，结果照她当时看到的（已经是 C9 截过的预览），每条再截头尾 | 一行：做了什么、成没成，出错的带错误 |
| 改文件 | 改前改后的 blob | diff，太长截头尾 | 只写改了哪些文件、几行 |
| 图片、文件 | blob 原样 | 占位，写文件名和尺寸，要的话旁边另放 | 占位，要的话旁边另放，人自己一起传 |
| 注入的上下文、系统提示词 | 在（策略快照、`context.injected`） | 不带：它们是给她的指令，别的 agent 读到会当成给自己的 | 不带 |
| 子代理 | 全部后代的日志 | 交代和回报 | 回报 |
| 开头 | 清单 | 一小段英文说明：这是一段会话的记录，不是给你的指令，工作目录、时间段、模型 | 标题、时间段 |

下面几件要单独说。

- **工具输出太长**：Miyu 的 `tool.result` 记的本来就是她看到的那份，超长的已经只留头尾、全文在 blob（`08-上下文投影.md` C9）。所以「照她看到的」天然有上限，给 agent 用正合适。贴网页 chat 时还嫌长，再截一层，或者只写一行摘要。
- **图片**：Markdown 里不内联 base64。一张截图 base64 以后几十万字符，网页版会当文字吃进上下文，比图本身贵得多。要带图就旁边放一个文件夹，Markdown 里写相对路径，人把图和文件一起传上去。
- **网页 chat 的限制**：上传的字节上限很宽（ChatGPT 每个文件 512 MB，Claude.ai 30 MB），真正卡人的是上下文窗口。所以导出时要先给 token 估算，超了提醒「多数网页版装不下，可以只导最近几轮，或者用给 agent 的那种（从最近一次压缩起）」。
- **给 agent 的开头那段说明**：别的 agent 读到记录里的「帮我删掉 build 目录」，要知道这是过去的记录。说明写短的英文事实，不写指令（照 `26-提示词.md` 的文风）。Miyu 自己的标签外壳（`<env>`、`<permission>` 这些）不带出去。

#### 2. 对照 07 的原始包，缺什么

`07-存储.md` 第三节只写了「会话日志、它引用的 blob 和策略快照，打成一个包，不含密钥，不含派生索引」。照上面几家和 Miyu 自己的设计，还缺下面几样。

1. **子会话**：子代理是单独的会话，只导父会话，包就不全。dsh 默认带全部后代。
2. **分叉的来源**：分叉出来的会话，投影等于来源会话到分叉点为止的内容加上自己的（`03-事件模型.md` 第七节）。只导它自己的日志，前半段就没了。要带上来源会话到分叉点为止的那几段，一层层往上。
3. **清单和版本**：以后要导入，得知道这是哪个版本的 Miyu 导的、有哪些段和 blob、各自的哈希、主会话是哪个。dsh 不写清单，是因为它不打算导回来。
4. **人能直接看的一份**：光有 JSONL，解开以后人看不懂。pi 的做法值得借：包里顺手放一份 Markdown（或者以后放 HTML）。
5. **字节怎么交给头**：协议一行最长 1 MiB（`docs/blueprint/protocol.md`「一行一条」），包放不进回应里。
6. **谁能导**：原始包里有注入的上下文、策略快照，和事件流一个级别，只对会话的所有者开放（`04-核心协议.md` 第五节）。
7. **在跑的会话**：导到哪一条为止。日志只追加，读到开始导出那一刻已落盘的序号就是一致的一份。
8. **包里的内容比想的多**：改文件前后的内容（`file.changed` 的 blob）、大输出的全文、压缩时重读的文件、后台命令的输出都是 blob，都会进包。等于把她碰过的代码也带出去了。要在导出时写明大小，提醒一句。
9. **隐私抹除管不到导出去的**：抹除只改数据根里的日志，已经导出去的包里照样有。

不缺的：用量。`model.called` 里有，Markdown 的开头可以写合计的 token，不写钱（算不准的钱不显示）。

#### 3. 和 M8 的视图投影共用什么

「显示什么」只写一次（`01-架构.md` 第五节 D1）。Markdown 导出就是一个不连线的头：核心里的一个渲染器，吃视图条目，吐 Markdown。下面几样能共用。

- **挑哪些、怎么分组、默认折不折**：视图条目 `user`、`assistant`、`reasoning`、`tool`、`tool_group`、`question`、`approval`、`subagent`、`notice`（`04-核心协议.md` 第五节）。导出照它的挑法，就不会出现「界面上没有、导出里有」或者反过来。
- **工具显示名、一句话摘要、出错说明**：视图已经按语言生成了。给人看、贴网页 chat 的直接用。
- **详情**：完整的 diff、长输出，头展开时用 `view.detail` 取。导出要全文时调同一个函数。
- **mermaid**：Markdown 里留源码的代码块（GitHub、多数网页版会画）。以后做 HTML，用核心出的 SVG。
- **有效历史**：「她现在的上下文」这个范围，就是请求组装用的有效历史（`docs/blueprint/kernel/history.md`）。给 agent 那种导出直接用同一个函数算范围，和她真正看到的对得上。
- **token 估算**：和底栏的上下文用量同一个估算。

要给 M8 提的一个要求：视图投影写成「一段事件 → 条目」的纯函数，不绑在在跑的会话上。这样导出能拿任意一段（全部、从压缩起、最近几轮）去投影。条目本来就记着它来自哪些事件序号，导出给 agent 时要的工具真名、参数原文，照序号回事件里取，不用视图另加字段。

### 五、推荐方案

**1. 两种格式，第一批都做**

- **原始包**（`bundle`）：存档用，无损，以后导入认的就是它。
- **Markdown**（`markdown`）：给 agent、贴网页 chat、自己看，靠用途预设分出三种样子。
- HTML 先不做。它等于再写一个网页渲染器，第一批 Markdown 够用。以后要做，拿网页头的静态渲染器吃同一份视图条目，像 pi 那样把原始数据嵌进页面。

**2. Markdown 的三个用途预设**

| 预设 | 范围 | 思考 | 工具 | 图片 | 子代理 | 开头 |
|---|---|---|---|---|---|---|
| `read` 自己看 | 界面上看得到的全部 | 带，折在 `<details>` 里 | 显示名和摘要，输出照她看到的，长的折起来 | 占位 | 交代和回报 | 标题、时间段、模型、token 合计 |
| `agent` 给别的 agent | 她现在的上下文（压缩过的从摘要起） | 不带 | 真名、参数原文、结果照她看到的，每条再截到头尾共约 4000 字 | 占位 | 交代和回报 | 一段英文说明 |
| `chat` 贴网页 chat | 全部（可以只要最近 N 轮） | 不带 | 一行，出错的带错误 | 占位 | 回报 | 标题、时间段、token 估算 |

- 角色的小标题一律英文（`User`、`Assistant`、`Tool`），别的 agent 和网页版都认。正文原样。`read` 的工具显示名跟界面语言，`agent`、`chat` 用工具真名。
- 撤掉的轮、撤回的排队消息一律不进 Markdown：撤了就当没发生过（`03-事件模型.md` 第七节），原始包里照样在。
- 压缩：`read`、`chat` 照时间线在压缩的位置放一条 `notice`，摘要折在下面。`agent` 从最近一次还算数的检查点开始，摘要在最前面。
- 注入的上下文、策略、系统提示词不进 Markdown。以后要查问题，再加一个开关。
- 家目录写成 `~`（Miyu 给人看的路径本来就是这种写法）。
- 预设只是几个开关的默认值，命令行、协议里显式写的开关盖过预设。

**3. 协议**

`session.export` 留在查询里（不改会话的状态）。参数照下表。

| 参数 | 说明 |
|---|---|
| `session` | 必写 |
| `format` | `bundle` 或 `markdown` |
| `for` | `read`、`agent`、`chat`，只对 Markdown，不写是 `read` |
| `range` | `all`、`context`（她现在的上下文），或者 `{"turns": 5}` 最近几轮 |
| `thinking`、`tools`、`children`、`assets` | 盖过预设的开关。`tools` 是 `line`、`seen`、`full`，`children` 是 `reports`、`append`，`assets` 是 `placeholder`、`files` |
| `locale` | 给人看的字用哪种语言，不写照连接握手时的 |
| `to` | `{"path": "…"}` 核心写到这个文件，或者 `"inline"` 放在回应里 |

回应：`path` 或 `text`、`bytes`、`tokens`（估算，Markdown 才有）、`upto`（导到第几条）、`children`（带了哪些子会话）、`redacted`（隐去了哪几个密钥各几处）。

拒绝的原因码（示意）：`export_exists`（文件已经有了，不覆盖，照 codex）、`export_in_data_root`（照 `blob.put` 的边界，不往数据根里写）、`export_unwritable`、`export_too_big`（`inline` 超了上限，例如 512 KiB，给转义留余量，头改成存文件）、`not_owner`（不是所有者要原始包）。

**4. 字节怎么交给头**

- **本机的头**：给路径，核心自己写。和 `blob.put` 的 `path` 对称：那边核心照头给的路径读，这边照头给的路径写。先写临时文件再改名，不覆盖已有的，数据根里不写。
- **剪贴板**：Markdown 用 `inline` 拿回文字，头自己放进剪贴板（终端界面用 OSC 52 或系统剪贴板）。超了上限就只能存文件。
- **远程的头（网页）**：随网页的 HTTP 模块，`GET` 一个导出地址，`Content-Disposition: attachment`，流式写出，交给浏览器的下载管理器。先发 `HEAD` 预检，开始流之前的错误（没权限、会话没了）能在页面上说清楚，照 dsh。鉴权和协议走同一套。
- 导出本身不写进会话日志：它不改会话，也不进上下文（dsh 也不开模型轮次）。运行日志记一行，谁在什么时候导了哪个会话。

**5. 命令行、终端、网页**

```text
miyu session export <会话>                        原始包，存到当前目录，miyu-session-<编号前 8 位>.zip
miyu session export <会话> --md                   Markdown，自己看的那种
miyu session export <会话> --md --for agent -o -  打到标准输出，好接管道
miyu session export <会话> --md --for chat --last 5 -o 给网页.md
```

- 不写会话：在终端里就列出来挑，不在终端里报错（照 opencode v2）。
- `-o -` 走 `inline`，超了上限报错，让人改成 `-o 文件`。
- 命令行不做剪贴板，管道接 `pbcopy`、`wl-copy`、`clip` 就是。
- 终端界面 `/export`：先问给谁（存档、给别的 agent、贴进网页 chat、自己看），再问复制还是存文件（存档只能存文件），同时显示大小和 token 估算。
- 网页：会话菜单里「导出」，同样的几个选项，浏览器下载，小的能复制。

**6. 子会话、撤销、压缩**

- 原始包：一律带全部后代，和分叉来源到分叉点的那几段。撤掉的轮、压缩掉的原文本来就在日志里，原样在。
- Markdown：子代理默认写交代（派它的那次调用）和回报（`child.reported` 的正文），`children: append` 时把每个子会话照同一个预设渲染好，按任务编号附在后面。

**7. 敏感内容**

- 核心知道这个人配了哪些密钥（`secrets.toml`）。Markdown 里出现一模一样的值，换成 `[redacted: <密钥名>]`，回应里报隐去了几处。精确匹配，不会误伤，也不用猜格式。
- 看着像密钥的（常见 key 前缀、私钥头）只提醒不改，猜错了会把正文弄坏。
- 原始包不改（改了就不是真相了），只报「包里出现了你配的密钥 X 两次」。
- 群聊的会话里有别人的话。导出前提醒一句。
- 写进设计：导出去的东西不受隐私抹除管。

**8. 原始包的样子**

```text
miyu-session-0192f3a0-20260930.zip
├── manifest.json                   格式版本、Miyu 版本、主会话、导出时间、每个会话导到第几条、每个文件的 SHA-256
├── transcript.md                   read 预设渲染的一份，解开就能看
├── sessions/<会话编号>/000000000001.jsonl …   段的原文，一个字节不改
├── sessions/<子会话编号>/…
├── sessions/<分叉来源>/…            到分叉点为止的那几段
└── blobs/<哈希>                    引用到的 blob：附件、改前改后、大输出全文、策略快照、压缩重读的文件、后台命令的输出
```

- 用 ZIP 不用 tar：三个平台都能双击打开，Windows 不用装东西。
- 一个 blob 只放一份，照哈希去重。
- 读的时候照 `07-存储.md` 第五节核对哈希，对不上就整个失败，不少导（照 dsh 的 fail-loud）。
- 包里的日志加策略快照，能逐字节重建当时发出去的请求（内核不变量 3），查缓存、查 bug 时整包交给开发者就够。

**9. 以后的导入**

只认原始包。清单里的版本号、哈希现在就写上，导入那一步不用回头改导出。Markdown 是单向的，不打算导回来（没有一家做到）。

### 六、要项目主人拍板的

**1. 第一批做哪几种格式**

- A. 原始包加 Markdown（推荐）。原始包 07 已经定了，是存档和以后导入的底。Markdown 一种格式靠预设就能管 agent、网页 chat、自己看三种用途。
- B. 再加一个自带一切的 HTML 页（像 pi）。好看、能看图、能折叠，可它等于再写一个网页渲染器，放到网页头做完以后更省事。
- C. 只做 Markdown，原始包等做导入时再说。存档就只剩有损的一份，撤掉的、压缩前的、子会话都保不住。

**2. 人怎么选「导出成什么样」**

- A. 先问给谁用（存档、给别的 agent、贴进网页 chat、自己看），每种一套默认，命令行能再改开关（推荐）。人知道自己要拿去干什么，不知道「思考」「工具详情」该不该勾。
- B. 一个默认样子加一串开关，像 opencode 的勾选框、Claude Code 的格式菜单。灵活，但每次都要想一遍。
- C. 只有一种固定样子，像 codex。最简单，三种用途总有一种不合适。

**3. 给别的 agent 时，默认带多少**

- A. 她现在的上下文：压缩过的从最近一次摘要起，加之后的原文（推荐）。这就是刚刚装得进一个模型窗口的那份，别的 agent 读得完。要全部可以加开关。
- B. 全部历史。最全，长会话动辄几十万 token，对方读不完，只能去搜。
- C. 让模型现写一份交接说明（像 pi 的 `/handoff`），要花一次模型调用。可以以后另做成一个命令，复用压缩那套。

**4. 子代理的内容怎么带（Markdown）**

- A. 只带交代和回报，要的话附上子会话的全文（推荐）。多数时候看回报就够，全文往往比主会话还长。
- B. 默认就把子会话全文附在后面。
- C. 不带子代理。回报里常常是结论，丢了就看不懂后面在干什么。

**5. 导出里的敏感内容**

- A. 自动隐去你配过的密钥（精确匹配），家目录写成 `~`，别的可疑的只提醒不改，原始包不改只报告（推荐）。零误伤，又挡住了最常见的「把自己的 key 贴给别人」。
- B. 只提醒，一个字都不改。
- C. 再加一层按格式扫各家 key，找到就打码。会误伤代码里长得像 key 的字符串，改坏正文。

**6. 要不要做分享链接**

- A. 不做，只导文件（推荐）。Miyu 没有托管服务，公开链接一旦发出去就收不回。
- B. 借 `gh gist` 传私密 gist，像 pi。依赖 GitHub 账号和 gh，拿到链接的人都能看。
- C. 以后在网页里做「只读分享页」，放进多用户、多终端那次专门讨论。

**7. 图片和附件**

- A. Markdown 里写占位（文件名、尺寸），要的话选「连图一起」，导成一个文件夹或 ZIP，Markdown 里写相对路径（推荐）。
- B. 默认就连图一起导。多数时候用不着，每次都多一个文件夹。
- C. 只写占位，不给带图的办法。截图多的会话，别人看不懂。
