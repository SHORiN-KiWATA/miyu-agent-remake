# 终端界面演示现状（给拆 M9 用）

2026-10-01，分支 `proto/tui-demo` 的 `2249ffd5`。版式图纸是 `docs/blueprint/tui.md`，「还没有的」一节是完整的待办。

## 1. 结构

- **规模**：`tui-demo/src` 下 230 个 `.rs`，共 37,795 行（含测试）。最大的文件 498 行，全部在 500 行以内。
- **各块大小**（行数含各自的测试）：
  - `ui/`：9,734 行，画法，其中 `ui/timeline/` 1,549 行。
  - `transcript/`：3,912 行，事件记成正文，其中测试 1,986 行。
  - `markdown/`：3,836 行。
  - `app/`：3,057 行，按键、鼠标、各面板状态。
  - `input/`：2,714 行，输入框编辑器。
  - `core/`：2,168 行，连核心、读推送。
  - 其余：`figures/` 1,687 行，`mascot/` 1,672 行，`config/` 1,318 行，`theme/` 1,123 行，`drawer/` 1,108 行，`mention/` 672 行，`notify/` 663 行，`jobs/` 597 行，`clipboard/` 438 行；另有根目录下二十来个小文件。
- **核心的 crate**（path 依赖）：
  - `miyu-ipc`：连接、拉起核心。
  - `miyu-store`：数据根、缓存目录、`Human` 给人看的字、资源目录。
  - `miyu-kernel`：只用了 `event::Said`。
- **外部 crate**：
  - 界面和文字：ratatui 0.30、crossterm（经 ratatui）、unicode-width、unicode-segmentation、pulldown-cmark、similar。
  - 运行：tokio（只在连核心的线程里）、serde、serde_json、jiff、base64、ignore、rustix（unix）。
  - 画图：ratatui-image、image、resvg、mermaid-rs-renderer，公式用 ratex-parser、ratex-layout、ratex-types、ratex-render。
- **资源**：`tui-demo/resources/`，放 JSON 的字和数值、主题、图标、提示音、`languages.json`，以及 `text/{zh,en,ja}.json`。全部编进程序。

## 2. 「显示什么」在哪

### 要搬进视图投影的（从事件算该显示什么）

- **`transcript/`**（不含测试 1,926 行）：
  - 事件记成正文的一条条：回答另起一条，思考、工具记进在进行的那一段（`blocks.rs`、`steps.rs`）。
  - 一轮开始、结束，排队的话进正文（`turn.rs`、`queue.rs`）。
  - 压缩那几行（`compaction.rs`）。
  - 别处来的话和来处标签（`foreign.rs`）。
  - 后台任务结束的通知（`jobs.rs`）。
  - 出错那一句（`failure.rs`）。
  - 「压缩 N 次」「缓存断裂 N 次」（`cache.rs`）。
  - 重做、编辑要找的那一句（`redo.rs`）。
- **`ui/timeline/`**（不含测试 616 行）：
  - 一段怎么收起：说话就收起、多于一个收成一行。
  - 每一步的标题行：显示名 · 对象 · 结果那一句（`step.rs`）。
  - 收起那一行：`Ran N commands · Thought for 4s`（`summary.rs`）。
- **`app/sessions.rs`、`app/sessions/notes.rs`**（661 行）：
  - 子会话。
  - 任务表和别处来的话落进正文的字。
  - 子代理用量往上合到主会话（`tree_usage`）。
- **`jobs/mod.rs`**：照 `job.*` 记后台任务表。`jobs/clean.rs` 洗命令输出（去掉终端转义）；这一步放核心更合适，网页也要用。
- **`app/updates.rs`**：收到消息以后、交给正文之前先办的几件，比如撤回没发出去的话。
- **`diff.rs`**：照工具参数算编辑的差异。设计上归 `view.detail`。
- **`figures/` 里出 mermaid SVG 那一半**：设计上归核心、按源码加尺寸缓存在磁盘上。
- **`markdown/`**：设计 23 批评过「解析和折行都在头里」。但折行跟屏幕宽度走，我建议 M9 先留在头里（见第 5 条）。

### 留在头里的（纯画法）

- 版式和正文：`ui/`（除上面那几处判断）、`body_view.rs`、`ui/row_cache/`。
- 输入：`input/`、`app/` 的按键和鼠标、`caret.rs`。
- 面板和抽屉的画法：`drawer/`、`menu`、`history`、`mention`、`ui/panel`。
- 外观：`mascot/`、`theme/`、`config/`、`pulse.rs` 运行状态行的词。
- 和终端打交道的：`figures/` 里用终端图片协议画图那一半、`notify/`（OSC 99、herdr）、`clipboard/`、`pointer.rs`、`editor.rs`、`crash.rs`、`reader.rs`。
- 排版和语言：`linebreak.rs` 折行、`language.rs` 界面语言。

## 3. 协议

- **用到的方法**：
  - `hello`、`subscribe`（`stream: events`）。
  - `session.create`、`session.send`、`session.interrupt`。
  - `session.revert`、`session.unrevert`、`session.redo`、`session.clear`、`session.compact`。
  - `session.set_permission_level`、`job.stop`、`job.output`、`blob.put`。
- **用到的推送**：
  - 模型和消息：`model.called`、`model.delta`、`message.user`、`message.assistant`、`message.withdrawn`、`tool.result`。
  - 轮：`turn.started`、`turn.ended`、`turn.reverted`、`turn.unreverted`。
  - 会话：`session.created`、`session.meta_changed`、`session.policy_changed`。
  - 后台任务和子会话：`job.started`、`job.reported`、`job.messaged`、`child.reported`。
  - 压缩：`compaction.progress`、`compaction.done`、`context.compacted`、`context.compaction_paused`。
- **顶着的**：头不读核心的存储，下面这些是临时绕过去的。
  - 给人看的字：头照 `MIYU_RESOURCES` 直接读核心资源目录下的 `human/<语言>.json`。本机能这么读，网页、远程的头读不到。要一个按语言取的方法（或者视图流里带上）。
  - 命令列表：头自己的 `commands.json`。`/undo`、`/compact` 这些名字是核心定的，要 `command.catalog`。
  - 编辑的差异、mermaid 的 SVG：头自己算，要 `view.detail`。
  - 后台命令的输出：每秒读一次 `job.output`，等增量推送。
  - 待办、确认和提问的抽屉：只有演示用的假数据（`jobs/fake.rs`、`/demo-todo`、`/demo-ask`、`/demo-approve`）。
- **还缺的**：
  - 抽屉：`session.answer`、`caps.input`，再加上提问、确认的事件。
  - 待办：`todo` 工具的推送。
  - 会话列表和输入历史落盘：`events.read`、`sessions.changed`。
  - 图：按编号读 blob，`read` 读到的图要交给头。
  - 其他：思考用了多少 token；主题的 `theme.get`（P3）；按模型报收哪几种附件。
  - 设计 29 跨会话、04 第六节多终端：别的会话发来的话、先答者胜、别的头收起，这几样的事件形状。
  - M8 新加的 `model.list`、`session.configure`、配置、第一次接入：等你们定了形状。

## 4. 测试

- **单元测试**：497 个，另有 5 个 `#[ignore]` 的量尺。都在 crate 里，不碰网络，也不碰核心。
  - 分布：`ui/` 142 个，`transcript/` 63 个，`markdown/` 58 个，`input/` 50 个，其余零散。
  - 画法的测试直接在 `Buffer` 上断言画出来的行，没有 golden 文件。
  - `transcript/tests`（1,986 行）和 `ui/timeline/tests`（933 行）测的就是「事件到显示」，逻辑搬进视图投影时可以跟着一起搬。
- **真核心 + 伪终端**：大约八十个 pyte 测具，住在我会话的临时目录，**不在仓库里**。它们接真模型跑，照屏幕和终端字节断言。要进门禁，得先做一个仓库里的测具：假的模型端点（内核的测试替身）加伪终端。
- **八项门禁估计**：
  - 格式、clippy：现在就过（lints 抄的根目录）。
  - 500 行：不用改。
  - 分层：新 crate 登记在第 5 层「头」就行，依赖的 `miyu-ipc`、`miyu-store`（第 3 层）、`miyu-kernel`（第 1 层）都合规。
  - 许可证：有一处，`ratatui` 默认功能在锁文件里带进 `ratatui-termwiz` → `terminfo`（WTFPL）。改成只开 crossterm 的功能就行。
  - 文档：没试过，估计要补一些 `missing_docs`。
  - 纯逻辑：只在往第 2 层搬「显示什么」时才碰得到：
    - 那几块要去掉 `Instant::now`（9 处，改用事件里的时刻）和 `HashMap`（`transcript/mod.rs`、`chips.rs`）；
    - 用到的外部 crate 要进白名单。

## 5. 建议怎么并

1. **原样搬成 `crates/miyu-tui`**（第 5 层），接现有协议：
   - 资源搬到仓库的 `resources/` 下，改许可证那一处，登记分层；
   - 演示用的假数据和 `/demo-*` 删掉，或者只留在开发开关后面；
   - 走查用的测具在这一步做进仓库。
   - 主程序怎么进界面（`miyu` 不带参数就开它？）是产品题，要问项目主人。
2. **视图流一块块替换**：每一块都是在第 2 层写投影，连同测试一起搬过去，头这边删掉自己算的那份。顺序：
   1. 正文的一条条（你说的、她说的、通知）；
   2. 时间线的分段和每一步那一行；
   3. 收起规则和收起那一行；
   4. 状态行和用量；
   5. 后台任务、子会话、来处标签。
3. **补协议，替掉「顶着的」**：`view.detail`（差异、mermaid、图）、`command.catalog`、给人看的字、`events.read` 加 `sessions.changed`、`caps.input` 加 `session.answer`、待办。

**该趁机重写的**：
- 计时改用事件里的时刻：投影要确定，重放也要一样。
- `App`（`app/mod.rs` 471 行，字段很多）拆成两份：「视图流给的」和「本地界面状态」（焦点、面板、选区、滚动）。
- `Config` 等 M8 的配置定了以后，和核心的设置并起来。
- Markdown 先留在头里：宽度相关的折行只能在头里做。要不要把解析挪给核心，等量过再说。
